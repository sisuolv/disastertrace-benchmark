# V5 首轮：从规划到六家族真实 instrument

状态：待实施。此文规定下一次执行的工作边界，不是已经完成的结果。总路线见 [整合计划](INTEGRATED_PLAN_CN.md)。工单状态以 [backlog](IMPLEMENTATION_BACKLOG.json) 为准；现阶段全部为 `proposed`。

## 首轮要交付的结果

一周内争取形成一个可以在 CPU 上重建的六家族 instrument：真实证据可追溯，公共输入可解码，参考能够复算，缺失/迟到/重复等情况语义明确，来源和样本计数可信。同时完成 MM-5A 的离线准备，并在它自己的门槛通过后执行 80 次表示对照。短窗口采集按独立门槛有界开始。

首轮不以任何 VLM 的准确率作为数据接入门槛。无法接入的家族交付失败证据和替代路径；不以合成样本补齐“六家族已真实接入”。第一周的日程是目标，遇到真实依赖时顺延该支路。

## D1：固定执行边界与来源身份

1. 读取当前导航、MM-4 接受记录和本规划，确认继承的脏工作区。保存新阶段自己的输入哈希和执行状态，不重建或覆盖历史档案。
2. 把 257 条候选记录按原 ID 保留，先完成六家族及 NHC/USGS/NDBC 结果依赖的产品映射。其余记录维持待核对，不要求一天做完全部产品尽调。
3. 明确一个 provider 的多个产品、镜像下载入口、版本、观测/预报/标签角色。FPA-FOD 6/7、GESLA 3/4、ISD/GHCNh 不靠相似名称合并。
4. 采用分层灾种 schema，保留原机构标签；冻结首批任务的极端定义、时间/空间粒度和开发范围，检查与旧 heldout 的交集。
5. 对首批来源分别记录访问条件、再分发条件、可接受版本、最多请求和字节数。不需要账户的开放源优先；权限未知的源先记录缺口。

交付：`scope.json`、`source_identity_map.json`、`hazard_mapping.json`、`source_readiness.json`、`preservation_before.json`。这些是未来产物名，当前没有生成。

验收：没有把同一来源的两个入口算为两种独立气象证据；没有把事后记录当实时输入；新 scope 没有重新打开旧 claim。

## D2：实现最小共用契约

对应 V5-03、V5-04；公共投影 V5-05 开始。

建议新模块在 `src/disastertrace/active_forecast/`，具体布局可根据现有代码调整，但不同时复制 `active_warning` 和 `source_stream` 两套环境。

最小对象包括内容 Blob、产品版本、捕获、投递、目标、episode、实际读取、提交和后续结果。每个对象有自己的 ID 与 provenance，支持版本关系和完整 locator。

先实现以下规则，再接真实端点：

- issue/observation/valid/historical availability/first_seen/delivery/submit 时间互不代填，所有明确时间带时区。
- 相同字节的重复投递不会丢掉 delivery；同名不同字节是不同内容。
- 值 KEEP 与来源刷新正交；完整坐标、行号、region/span 引用可以持久化。
- 目标匹配包括变量、单位、有效窗口、区域/实体和统计量；仅 issue 更晚不能跨目标胜出。
- 公开白名单不含未来、Gold、隐藏标签、私有 parent metadata；路径不能逃逸公共根目录。

验收需覆盖实际缺陷和科学反例，而非仅测试 dataclass 可以构造：未来有效预报合法、未来发布的旧观测非法、空名单和缺名单不同、same-value/new-source、unknown 三值逻辑、同文件重播、冲突版本、坐标边界、缺失质量标记。

## D3：三个参考视图与确定性控制

对应 V5-05、V5-06、V5-07、V5-12；V5-09 的 MM-5A 离线分支可独立推进。

1. 构建完整合法池、实际已读池、充分性参考三个视图，后续 Outcome 独立存放。
2. 先用有限 fixture 覆盖所有语义分支，再用真实来源切片验证至少文本/表格、图像+几何、栅格/时序三类通道。fixture 的来源类型和真实记录明确分开。
3. 用独立实现复算关键参考：版本选取、表格值、三值逻辑、坐标/掩膜覆盖。两条调用同一核心函数的路径不能宣称独立校验。
4. 运行不读取、恒答、存在性、目标匹配 latest-issued、全合法证据等控制。完整合法池与已读池结论不一致时，同时报告目标完成度与支持性。
5. 预先保存所有候选与排除原因。数据冻结后发生的失败留在原分母；只能在新版本中修复。

MM-5A 准备固定 40 任务，构造原 JSON 与显式字段/行号文本。对每一题检查语义等价、图像字节一致、引用映射、token 上限与实际 processor 曝光；不能只检查失败题。

对应 V5-08；采集分支 V5-13 可在共用储存、时间、公开规则通过后启动，不等待 M3/M4。

首轮真实取数建议总上限：100 HTTP 请求、2 GiB、2 小时、最多 2 个 AOI 和 5 个站点，包含列表、重定向、重试等请求消耗。现有本地资产不计新下载字节，但计入复用 manifest。大文件不适合该 scope 时，使用合法小样/子集或记录阻塞，不静默提高限额。

每个来源都要有原字节哈希、捕获头/时间、版本、正常化结果、真实往返校验、公共投影、任务资格和排除原因。各家族至少两份 slice 的指标只证明处理链覆盖，不等于两个独立灾害。

## D5–D7：独立验收、80 次对照和有界采集

对应 V5-10、V5-13、V5-25 的首轮部分。

### MM-5A GPU 分支

只在等信息、Gold/公共输入、真实 processor、上下文和调度检查通过后冻结新执行。沿用 Qwen3-VL-8B-Instruct 的已绑定快照与 MM-4 设置：2048 输出上限、16384 上下文、贪心解码、120 秒生成上限及既有图像像素范围。

四个一卡 H100 worker，每片 20 次，所有片均混合两种表示和题型。先落提交意图和唯一执行 ID，再提交全部可占用分片；未确认提交占槽，已返回作业只监测，不重复投递。复用修正后的 requested replica 计数思路，对 STARTING 的零实际副本情形做回归。

80 次结果全部保留。模型返回、格式、EOS、语义和来源 locator 分开汇总。数据、执行、请求、raw、processor 与报告哈希绑定；搬迁后 CPU 重建能够得到同一结果。旧 40 个 MM-4 回答只作历史参考。

### 72 小时采集分支

建议最多两个 provider、15 分钟最低轮询间隔、总计最多 768 次 HTTP 请求和 2 GiB 原始字节，72 小时绝对截止。576 个计划轮询机会之外的元数据/分页/重试同样受总上限约束；不存在因重试而自动加预算。

先核对具体 API 的保留、速率与产品更新规则，允许频率更低，禁止超过服务规则。保留 first_seen、ETag/Last-Modified（如提供）、响应哈希、缺口与检查点。72 小时运行可以跨过首周交付时点，报告当时真实状态，不把仍在运行写成完成。

### 第一周交付清单
