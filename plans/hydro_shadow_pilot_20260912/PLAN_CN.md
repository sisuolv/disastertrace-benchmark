# 水文扩展与前瞻影子采集：执行合同

日期：2026-09-12。接续已完成的 ActiveWarning 最小闭环；按用户要求执行下一步，继续排除 GEE。

## 本轮交付

1. 实际获取 NWPS 站点目录，按公开输入和接口覆盖核验多个站点的预报、观测、阈值、单位与站点映射；保存所有候选的通过/失败原因。
2. 优先寻找当前/近期洪水或近阈值站点，同时保留普通对照。风险富集队列仅用于机制与工程诊断，不估计自然灾害发生率。尽量跨河流与 RFC，站点数不等同于独立事件数。
3. 对可配对的水位与流量分别建合同。官方水位阈值只对应同基准水位，不能替换为流量阈值。若 HEFS 流量阈值不合格，连续流量诊断和官方水位预警链分开。
4. 以真实抓取时间为已取得资料的时间上界，建立有界的前瞻影子队列，在目标发生前写入不可覆盖的程序预测，后续自动获取结果并结算；结果尚未成熟时明确保留 pending。
5. 用新数据实际测试时间/版本/质量合同、简单强基线及来源配对。根据准入结果判断是否已经适合新增 LLM 实验，不以更多模型调用代替数据准入。

## 预先声明的选择与预算

- 初查候选上限 12 个；优先有官方阈值、USGS 标识与有效预报的站点。根据目录中的当前状态分层，优先分散 RFC/河流，保留至少两个普通对照（若接口覆盖允许）。不读取模型误差来选站。
- 已发生洪水片段用于历史诊断；当前官网阈值若没有历史版本证明，不作为过去业务警戒线的无条件真值。
- 前瞻站点、目标时间、截止、程序策略、采集频率和终止条件，在运行前另写冻结登记表。仅采集公众数据，不向公众或业务系统发送预警。
- 捕获网络失败、截断、质量不合格、未来目标未成熟与模型失败分别处理。禁止用最近观测替代缺失的精确目标结果并当作成功结算。
- 原 ActiveWarning 数据、评分、模型计划与结果保持原样；新工作使用新 namespace 和新目录。不调用付费模型 API，不训练，不使用人工逐题审核或 LLM judge。

## 研究边界

本轮首先证明多站点完整链和前瞻提交机制。自然极端过程、结果成熟及真实业务可用时间不能通过模拟延迟或 GPU 加速补造。若新增数据仍未显示主动获取的需要，保留这个结论。
