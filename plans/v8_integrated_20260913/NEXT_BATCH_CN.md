## 7. W07 程序臂的唯一身份与去重

以下为待冻结设计，不是新增已运行结果。所有臂使用共同结果、资料宇宙、基线流、价格与可用时间合同。
补证臂固定同一个 CPU 预测器和采纳协议；两种修订协议另分层报告，不混成一个分数。

| arm_id | 唯一作用 | 与其他名称的关系 |
| --- | --- | --- |
| P00_follow | 直接跟随共同基线 B，不主动查询或安装新 override | 当前冻结统计映射已参与 B 的生成时，不再将同一映射另报一个独立对手 |
| P01_base_only | 固定预测器只读 B，按真实动作与处理费得到 f(B) | “不补证”是此臂；只有连动作、状态与费用都相同才可预登记为 P00 别名 |
| P02_one_read | 固定顺序的一次合法补充查询，再用同一预测器形成 f(B,E) | 查询机会和时点提前冻结，不按事后正确性选择那一条资料 |
| P03_batch_shared | 同预算、同权限的强批量共享获取与处理 | all-read 与 complete-batch 若同动作合同则只算一个臂；候选全读不可行时保留未完成记录，不宣称完整全读 |
| P04_risk_shared | 冻结的风险优先选择，global_budget/session_shared | 同预测器、同采纳和相同合法工具下与 P03 比较 |
| P05_coverage_shared | 冻结的覆盖优先选择，global_budget/session_shared | 覆盖依据只能来自合法已知元数据，不能读 evaluator 隐藏答案 |
| P06_qp / P06_qs / P06_gp / P06_gs | 固定同一 selector 的分配与授权 2×2 | q/g 为固定分额/全局预算，p/s 为目标私有/会话共享；不是四种 selector |

冻结统计映射属于 predictor/bank 配置维度，不自动成为独立获取策略。每个臂绑定 allocation、authorization、
selector、predictor、adoption、调度/时延和资源合同；仅名称不同且执行合同相同的臂，在运行前以 alias 显式归并。
概率恰好相同不能用于事后去重。超出共同预算的“无限全读”如用于诊断，另列信息条件，不参与等预算主比较，
也不称 F 上界。私有臂的预测上下文与记忆隔离，selector 可见摘要单独冻结。
