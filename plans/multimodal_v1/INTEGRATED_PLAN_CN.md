## 1. 推荐结论

保留 Text Core，新增一个可独立报告的多模态核心：

> 当官方灾害文本与地图异步到达时，模型能否对齐目标、选择适用版本，
> 只修改应改变的状态与依据，并在后续查询中可靠使用此前保存的视觉信息？

推荐顺序是：**保护已完成结果 → 单个真实图文闭环 → 自动任务与参考 →
单 VLM 分层诊断 → 小规模修订对照 → Streaming 与视觉记忆 → 独立事件/模型扩展。**

首个实施批次做到 MM-0 至 MM-2：交付实际代码、可追溯真实样例、自动参考、独立 CPU
评分与隔离测试。第一阶段结束后才进入视觉模型运行。暂缓全遥感数据集、模型训练、
复杂多 Agent 系统、付费 API 和 heldout 推理。

## 4. 首个真实任务具体做什么

### 4.1 首选来源和语义

优先使用 Francine 开发资料及同版本 NHC forecast wind radii GIS。已核验本地来源收据中
`AL062024` 的 005、007 文字公告为 `received`、`development`；GIS 与原图是否可配准仍待核验。
旧收据不是新下载，也不证明地图层结构已验收。

从以下官方目录重新发现候选，并保存实际目录/响应：

- <https://ftp.nhc.noaa.gov/atcf/gis/fst/>
- <https://ftp.nhc.noaa.gov/atcf/gis/5day/>
- <https://www.nhc.noaa.gov/gis/>

两份输入计划给出的 `al062024_fcst_005.zip` / `007.zip` 可作为首批候选；不能仅据名字
认定有相同绝对有效时刻。5day 包只作为不同产品的结构参照，不替代风圈图层。
首批只取这些小型候选与必要文本；不下载完整 CyPortQA QA/图像目录。

主问题为：在固定绝对有效时刻，指定中性地点是否位于某个明确阈值的预报风圈内？
例如 34 KT 是待按实际图层核验的任务阈值，不是业务预警或实际地面风速标签。
再通过公开演习规则组合文字与空间事实，例如：

```text
inspection_required(site) = watched(site) AND forecast_inside(site)
```

`watched` 若来自自定义名单，应标为 `benchmark_rule`，不称官方停港/撤离公告。
先用固定种子生成的中性点，不把生成坐标称作真实港口。位置和地图范围对模型明确可见。

### 4.2 一个五步闭环的结构

下表是受控教学设计，不表示 Francine 历史恰好发生过这些变化。

| 步骤 | 新交付内容 | 应检验的行为 |
| --- | --- | --- |
| c0 | 适用地图 M1 与公开名单/规则 | 建立 A/B 空间事实、派生条件和依据 |
| c1 | 只更新其他变量的文本 | 不把中心强度变化误当成 A/B 覆盖变化 |
| c2 | 同目标时刻的适用新版 M2 | A 按实际关系更新；B 可保持值同时刷新来源 |
| c3 | 再次交付旧 M1 | 新增交付事件，不创造新版本，不回退到旧依据 |
| c4 | 新名单或此前未询问的地点 C | 使用仍适用的已保存地图；不靠预先给出的 C 答案 |

自然来源序列按实际资料编译。延迟、重放、自定义规则和反事实配对单独标注为受控条件。
候选未出现某类自然变化时如实记录；不能修改官方地图或取样结果来冒充自然修订。

### 4.3 首轮必须作出的四个准入判断

1. **同一语义目标：**事件、产品、变量、阈值、测量类型、空间范围和绝对有效时间相容。
   不同日期的“24H”、滚动 120 小时概率、cone 和风圈不可混为同目标修订。
2. **图片确实可读：**最终 processor 缩放后目标、边界和图例仍可辨；图外、遮挡、无覆盖
   与边界不确定不直接判 `outside`。容差先按像素和地理尺度定义，再准入。
3. **视觉确实必要：**NHC 文字可能已给出位置/象限风圈半径。全文足够解题的样本进入
   `redundant_modalities`；去掉重复文字字段的样本进入 `controlled_modality_partition`。
4. **来源性质明确：**原始官方图为 `native`；真实 GIS 重绘为 `official_data_rendered`；
   合成 fixture 为 `controlled_generated`。文字、图像、规则、交付顺序分别记录性质。

正式“图文联合必要”受控子集需要两类见证：非视觉公开输入完全相同而改图改变答案；
图片和图片元数据相同而改文字改变派生答案。核对整个公开投影，包括别名、alt text、
文件名、版本提示与摘要。它证明给定输入条件下的信息需求，不证明模型内部使用了像素。

## 5. 统一的任务与评分契约

### 5.1 类型和时间

首轮实现 `ArtifactMeta`、`DeliveryEvent`、`FactKey`、`QuerySpec`、`RuleSpec`、
`PublicEvidenceView`、`ModelCommit` 与私有 `TransitionObligation`。
同一 artifact 可对应多个 delivery；旧图重放不改变发行时间、内容或版本身份。

保留 issue、observation、absolute-valid、retrieval、delivery 多时间。
没有历史公开可见证据时，`historical_available_at=null`，使用标明的受控交付回放。
新版本选择先限制已交付资产，再匹配目标作用域，最后按公开版本规则解析。

主模式为 `fixed_valid_target`。后续如需最近一期产品，另设 `latest_product_snapshot`，
明确 cycle 和有效窗口，不将两种模式混在同一修订总分里。

### 5.2 输出和自身历史

首版采用完整状态提交，包含当前已揭示查询的状态/值、适用来源/定位和预算内自有记忆。
默认使用 last-answer 加明确 invalid/missing 标志，原始最终文本始终保存；合法但错误的
值原样进入自己的后续历史。不能把 Gold、最近正确答案或另一方法的历史注入载体。

空间关系先使用 `inside / outside / boundary_ambiguous`，证据不足另有 `unknown`。
派生条件按公开三值逻辑求值：`false AND unknown = false`，而非所有缺模态一律 unknown。
首轮不引入没有来源支撑的撤回/终止/冲突子任务；确需纳入时新增明确契约与测试。

图像定位首选公开固定网格加目标点，记录最终像素坐标和地理变换；网格只表示定位，
不表示整格同值。允许预定义的等价充分支持，限制过宽区域/整图引用。
模型自述 UPDATE/KEEP/“已复核”不作为主要正确性证据。

### 5.3 三层参考和六类义务

```text
官方结构资料/既有标签
    → 根据该分支已交付证据求当前可断言状态
    → 比较相邻参考，求值/来源/依赖层面的更新义务
```

分别记录 `must_change_value`、`must_change_provenance`、`must_preserve_value`、
`must_preserve_provenance`、`must_remain_unknown`、`must_recheck_dependencies`。
这些集合定义在“槽位 × 方面”，不是互斥的整槽位标签。

GIS 参考只在评测进程可见。公开可部署方法不能调用私有参考几何、受影响集合、正确裁剪框
或未来查询。渲染轨尝试用独立的公开像素/图例求解验证几何参考，关键语义不共用同一个
最终 `resolve()`。原图/遥感没有同输入满分程序时，明确只完成可视性或继承标签检查。

证据从未交付时重算分支参考；交付过但方法遗忘时不降低参考要求。延迟、缺证、重放
和无关更新各分支独立编译，只有证明不变后才能引用不变关系。

### 5.4 四组主指标

| 组别 | 主指标与必须保留的分项 |
| --- | --- |
| 当前状态 | 固定计划分母的严格检查点正确率；值/unknown/派生规则分项；支持充分时的作答覆盖 |
| 当前依据 | 合法且适用的来源版本、文字/图像定位充分性；值不变时的依据刷新 |
| 修订质量 | 必要值/依据更新成功率、稳定字段退化、未知情况下的无依据断言 |
| 持续可靠 | 全部检查点均正确的 episode 比例、旧图回退、存在纠正机会后的恢复延迟及未恢复数 |

上一轮模型错、本轮纠正，即使 Gold 前后不变也不能算过度更新。稳定退化的条件诊断只在
上一轮模型正确的合格子集计算，并报告 eligible 数；不替代全分母主表。空集合写 null/0。

结果按风暴/共享来源组、产品、转换类型、来源性质、访问轨道分层。小试点只给描述性
结果；更大规模才考虑按独立事件组的成对区间。地点、瓦片、分支、重复不能当独立风暴。

## 7. 方法、访问轨道和诊断安排

### 7.1 第一组：累计证据参照

先比较 `full_direct` 与轻量 `full_version_filter`。两者有相同合法历史访问权限；后者
仅按公开对象/产品/有效时刻/版本元数据过滤。不得利用私有 Gold 选择“相关图片”。
若过滤已可靠解决任务，这是有价值结果，不人为削弱该基线。

原子读图和 `oracle_visual_facts` 另外报告。Oracle 只给当前已交付图片真正支持的事实，
不给未来、正确下一步状态或私有变化集合；不进入普通系统排行榜。

### 7.2 第二组：增量证据与三种记忆

Streaming 仅开放本轮新证据与预算内自有载体，禁止从文件系统、检索索引、日志或旁路
读回已淘汰旧图。三种方法分别为文字摘要、结构化空间状态、相同空间状态加视觉缓存。
所有提取/摘要/状态均来自该模型实际输出；若增加程序规则推导，作为明确的 hybrid baseline。

空间状态允许保存充分的多边形/分区表示；不为了突出图片缓存而禁止强符号方法获胜。
公布可能查询的区域类型，但不在压缩/裁剪前揭示下一步具体地点。保留图片的策略只能
基于当前公开信息，图例/坐标上下文也计入缓存。图像数量/像素、文字长度和档案读取
分别设预算并报告敏感性，不把不同模型视觉 token 当作等价信息单位。

Full-evidence 与 Streaming 分表；跨表差异包含访问与容量变化。第三条有限档案检索轨
在这两条稳定后再加，避免偷偷将可回查旧图的方法放入“不能回查”的同组比较。

### 7.3 第三组：同前缀载体审计

复用已保存真实前缀，固定本步新增证据，测试 Actual、Masked、Oracle、RelevantEdit、
IrrelevantEdit，另设等结构/近长度 sham。Actual 相同调用已有结果可复用，记录共享身份。
文本状态探针保持视觉缓存相同；整体记忆移除需要清理所有重复副本，另立条件。

RelevantEdit 分为“当前没有纠正依据”和“当前证据明确反驳”两类。跟随错误记忆只是
敏感性表现，不自动计为正确；有依据时修复错误才是可靠恢复。同前缀单步与分叉后的
自有历史闭环另行计数和报告，不能把重新生成的前缀称为完全相同。

## 8. 下载与四卡计算计划

本次规划没有下载新数据/权重或提交 GPU。后续继续使用用户已明确的全局最多 4 张 H100
约束；预检、加载和排队保留都计入。原先结束的 10 小时窗口不续期；任何新运行在启动前
登记自己的槽位、资源、起止、失败规则和执行身份，已有授权无需重复询问。

### 8.1 来源和环境

首批目标是 4 个 NHC 小型候选 ZIP 与必要文本。通用下载上限建议总计 512 MiB、单文件
256 MiB、并发 2、每文件最多 3 次下载尝试，流式记录包括失败/重试在内的实际字节。
上限是护栏，不是需要用满的配额。模型权重与大型遥感包另列大小、revision 和磁盘峰值。

新建独立 CPU GIS/构建环境和 VLM 推理环境，优先复用兼容的已有包；不升级旧冻结环境。
精确锁定模型 revision、processor/chat template、缩放/切图、precision、后端及停止规则。
模型候选来自输入计划，尚未在本机验证。先核验官方元数据和兼容性，不假定旧纯文本
vLLM/XGrammar 环境支持 Qwen3-VL，也不把路径字符串当成实际图片输入。

### 8.2 有界开发预算示例

以下按一个 VLM 举例，均待真实数据量和 processor 预检后写入新的冻结运行清单：

| 批次 | 计算方式 | 最终生成机会 |
| --- | --- | ---: |
| 接口/格式开发预检 | 最多 12 个已选开发请求，失败照录 | ≤12 |
| 原子感知与模态诊断 | 24 个单图问题 + 24 个锚点 × 4 种信息条件 | ≤120 |
| Full-evidence base pilot | 10 episodes × 5 checkpoints × 2 方法 × 2 repeats | 200 |
| 后续 Streaming base | 同样 50 checkpoints × 3 方法 × 2 repeats | 300 |

诊断的四种信息条件为 text-only、vision-only、full-modal、oracle-visual-facts；单模态
按自身信息集重算参考，另报对完整任务目标的可支持作答覆盖。不能直接用这些分数相减
宣称感知的纯因果贡献。

前两项加 Full-evidence base 是最多 332 次最终生成的开发预算例，不含外部干预、
Streaming、载体探针或系统内部调用。只预订当前批次，后续按以下完整公式核算：

```text
闭环机会 = 各已登记 episode/branch 的实际检查点总数 × 方法数 × 模型数 × 重复数
单步探针 = 各保存前缀的新增干预臂数 × 模型数 × 重复数
总调用数 = 唯一最终生成调用 + 提取/摘要/检索路由/复核等内部模型调用
```

共享前缀与可证明相同的已捕获 Actual 调用只计一次；分支重放增加的检查点按清单计入。
输出/推理 token、输入视觉量、全部调用、失败及 GPU 分配时间同时报告，不用最终回答数
替代总成本。输出表示和上限经一次独立开发校准后共同冻结，不按各模型失败单独加码。

### 8.3 四张 H100 如何使用

- 首次硬件/processor 预检先用一张卡；此时没有必要为了占满四卡同时下载/加载四份模型。
- 矩阵阶段优先四个单 H100 worker，各运行独立完整轨迹；单条轨迹内保持严格先后依赖。
  分片和条件顺序提前固定、平衡，不能一个条件占满早期时段、另一个只用截止前剩余时间。
- 用一个持久提交协调器管理四卡预约；GPU 故障后查询原作业身份，只继续证明未提交的机会。
- 以首批实测的图像尺寸、序列长度、吞吐和启动时间估算批次时长并留余量，不承诺固定
  “一张卡多少分钟”。若单 H100 不适配，先修改并冻结并行布局，再运行正式矩阵。
- 主试点优先完整任务准确率，确保比较条件有相同且足够的完成预算。若研究固定资源表现，
  另立等资源实验；截止缺失依然保留，不能把共同返回子集当作已消除截断偏差。

## 10. 故障和科研准入的最低测试

| 类别 | 必须通过的行为 |
| --- | --- |
| 轨迹隔离 | A 超限或格式失败不终止独立 B；各计划槽位保留明确状态 |
| 中断恢复 | 正式提交后无 raw 的请求保留 unknown、不重发；raw 后未解析可从原字节恢复 |
| 记录身份 | 临时 intent/raw 不算正式调用/回答；同一旧图新交付不变成新版 |
| 时间与作用域 | 同 lead 异绝对时间、异产品/阈值/地点不覆盖；同目标旧图迟到不回退 |
| 局部义务 | A 值变化、B 值保持且支持刷新；上游变化但派生布尔不变仍可正确 |
| 未知与评分 | 缺证不一律 false/unknown；上一轮错误被修正不算过度更新；空集合 null |
| 几何与可视性 | CRS/轴序/孔洞/日界线；边界、图外、遮挡；最终 resize 后参考精度仍可支持 |
| 公私隔离 | 正常模型与检索读不到未来正文/元数据、私有 GIS、Gold、未来目标或正确 crop |
| 必要性 | 完整公开投影无答案侧信道；纯文本足够的样本被标为冗余；配对组合性质可追溯 |
| 记忆与载体 | 自身错误原样保留；mask 后重复缓存路径受控；新地点不提前泄漏 |
| 下载/资源 | 错误 HTML、路径穿越、解压膨胀、重复下载、总量/四卡并发限制可核验 |
| 历史保护 | 旧验收清单、分数、失败记录和源码字节不变；新报告独立 CPU 重建 |

增加错误程序对照：最后到达者优先、所有中心强度更新都改局部空间状态、永不更新、
只更新值不更新依据、任何局部变化都改全局、缺证一律 false。它们用于验证测量能识别
已知错误，不是 VLM 成绩。合成测试和真实来源验收分别统计。

## 11. 遥感扩展、拆分与研究退出条件

NHC 主线稳定后，优先评估 SpaceNet 8 的一个完整公开样本：核查实际光学波段、前后
配准、既有洪水/道路/建筑标签及许可，构建小型可见光变化任务。标签“淹水”不升级为
实际道路不可通行或最优撤离判断。两时相只作为两时相，不伪装长自然更新序列。

若采用 GEOID-Flood，固定 HF revision 和逐文件选择；不用 `--sample --list` 当预览。
输入计划指出 sample 的两个 AoI 属于同一 EMSR712，不能当两个独立事件。SAR 显示变换、
无效像素和标签噪声单独处理。不能在获得实际文件前承诺样本兼容或同输入公开满分求解器。

自然事件、共享官方产品和派生图像形成同一 split connected component。SpaceNet 8
Louisiana/Ida 与已有 NHC Ida 共用 global_event_id；不得跨数据集把开发事件变成 heldout。
只读 protected heldout 的 ID/分组元数据，开发不读取其标签；公开历史资料不宣称已去污染。

出现以下情况应先调整任务：没有同目标时刻的真实配对、文字已经泄漏视觉答案、最终
图片无法支持参考精度、单轨故障仍牵连其他轨迹、或独立核验只是重跑同一个语义函数。
若主要瓶颈是感知，结论定位为感知/表征；若版本过滤或符号方法可靠解题，报告其优势。
不以低分、多模态输入或无需人工标注本身宣称创新、无标签误差或内部记忆机制。
