# v7 整体方案：近邻工作、差异和复用边界

日期：2026-09-12。本表服务于 [整体主计划](OVERALL_PLAN_CN.md) 的 C1/C2/C3。它记录已读到的内容与仍需确认的重合，不以未提及某特性证明该工作没有该特性，也不作为“全球首次”的保证。

## 1. 最接近的工作

| 工作与本轮阅读范围 | 已有能力和重合 | v7 应当具体区别的对象 | 必须补上的验证 |
| --- | --- | --- | --- |
| **EarthVerse**：[原始页面](https://arxiv.org/abs/2608.23525)，v1 正文 3.1、3.3、4.1、5.2 | 405 任务、199 事件、19 hazard families；版本化证据包、兼容证据选择、执行计算、细粒度答案与过程评分；已有文件定位 oracle、证据地图、缺失/截断/冲突/单位变化干预 | 连续日历上的多个未来目标、共同业务预报及持有的修订状态；代价/截止约束改变可执行预测；E 有限可达路径与未来结果损失连接 | 不能单凭 evidence perturbation 主张新诊断。需要 X01/X02/X04，特别是成本、可达性和新基线到达如何改变预测状态与分数 |
| **SIREN / SIREN-Bench**：[原始页面](https://arxiv.org/abs/2607.24588)，v1 正文 2.3.4、2.4、Limitations | 600 QA、19 tasks，四预警步骤与完整链；异质数据、工具、经验/建模。质量控制含 LLM 与专家；部分开放回答用 LLM evaluator | 自动结算的严格未来变量、连续共享预算、按版本修订损害；逐题主分无需新人工或 LLM judge | 对照其已声明的延迟、缺失、不断变化的预报和业务约束局限；不把“端到端预警”本身说成新贡献 |
| **Obshazard-bench**：[原始页面](https://arxiv.org/abs/2608.00012)，v1 正文 III-C/E/F、IV-E | 原始多通道遥感、灾害前/中/后；正文为 127 历史事件、4,202 VQA，8 大类/28 子类；时间窗消融、自动与专家 QC | 相同未来结果对应多个证据到达历史；主动查询与共享费用；有真实发行版本的基线；条件表示对照 | 需要 X03/X05/X07；不能把原始影像、生命周期或预测题称为首次 |
| **SentinelBench**：[原始页面](https://arxiv.org/abs/2606.05342)，固定 commit README 与 timing.py | 100 任务、10 个合成网页环境，状态随时间变化；完成、反应时间与资源权衡；明确 wall-clock 和 reaction window | 真实天气证据和未来概率结果；共同预报上跨目标持久状态与事实支持范围 | 比较可测对象与 scoring，而不是声称监测/等待/时间成本是新范式 |
| **FutureSim**：[仓库](https://github.com/OpenForecaster/futuresim)，固定 commit README 与 history.py 的 rescore/restore 部分 | 日期推进的问题市场、按日期可见文章、持续预测、历史动作恢复与重评分 | 细粒度发行/可用/完成时间、原生传感器证据、共同业务预报、目标共享费用和作用域严格的修订 | 继续核查完整 scoring 与配置是否已有相同资源/委托组合；本轮未完成其论文全文或整个运行路径复现 |
| **AFABench**：[原始页面](https://arxiv.org/abs/2508.14734)，固定 commit README 与核心 Protocol 部分 | 代价特征获取，静态/贪心/RL 等方法；可选择特征或停止；标准化预测器/策略接口 | 随时间变化的产品与版本、跨目标重复/派生信息、持续专业预报上的有限期修订 | X01/X04 须有强 AFA/VOI 或有依据的廉价策略，不能把主动特征选择改名当新算法 |
| **Learning to Defer**：[ICML 2020 原文入口](https://proceedings.mlr.press/v119/mozannar20b.html)，页面摘要 | 预测或委托专家，分类器/拒绝器与成本敏感学习 | 基线自行更新，覆盖有作用域/有效期，需同时选择获取、保持、撤销和再次修订 | X02 隔离自动基线回退、校准和门控，说明动态状态在静态委托之外引入什么 |

EarthVerse 正文 4.1 明确将交互、延迟和 token 需求作为诊断统计而不计入主分；本计划拟使时效与预算决定某预测是否能及时生效，并以未来结果量化改善/破坏。这是可以指向的具体差异。它不能推导出对方没有任何预算限制，或其其他版本不可能增加类似机制。

SIREN 的局限原文列出 “data latency, missing data, evolving forecasts, and operational constraints”。这支持问题的重要性；不等于只要加入几个时间字段就解决了局限。

## 2. 天气评测与概率预测方法

| 工作与阅读范围 | 应当承认/借用的能力 | 对 v7 的约束 |
| --- | --- | --- |
| **ExtremeWeatherBench**：[仓库](https://github.com/brightbandtech/ExtremeWeatherBench)，固定 commit README、inputs.py 中配对函数 | 极端事件评测、事件目录、输入/参考组织、影响相关指标；该快照列 329 cases、五类事件 | 多灾害气象评测本身已有。可借用目录/合同思想；不将同一事件的副本计为新独立样本 |
| **RealBench**：[原始页面](https://arxiv.org/abs/2605.24945)，摘要级 | 业务低延迟分析、超过一万地面站、极端事件评测；强调再分析与真实业务条件的差距 | “真实观测＋业务条件”不单独构成贡献；作者对 2025 划分的污染论断不直接适用于我们的 LLM |
| **BLF**：[原始页面](https://arxiv.org/abs/2604.18576)，摘要级，页面对应 v4 入口 | 半结构化概率/语言信念状态、迭代取证、多试验聚合、校准 | 持续信念更新和结构化证据总结已经存在；若借用，需隔离预测器变化与 selector 变化 |
| **LEAP**：[原始页面](https://arxiv.org/abs/2609.01337)，摘要级 | 逐证据似然、显式先验、确定性聚合；连续和离散预测 | 证据贡献或确定性概率合成不是天然新点；同源相关证据不能假装独立相乘 |
| **Interactive Benchmarks**：[原始页面](https://arxiv.org/abs/2603.04737)，摘要级 | 有预算的多轮交互、主动信息获取、长期效用任务 | 主动交互和预算本身已有；需要真实专业基线与结果、证据时空语义及持续监测实验 |

摘要级条目仅用于建立定位和后续阅读清单，不能支撑排除某一具体机制的论断。OpenAlex 宽检索仅为发现辅助，本轮结果不足以称为系统综述或完整查新。

## 4. Novelty 决策规则

| 如果后续发现 | 研究上应当怎样处理 |
| --- | --- |
| 近邻已经同时有共同更新基线、共享预算和同样的修订状态评分 | 收窄 C1 的任务首次性，明确继承，转向新的证据可达性实验或数据贡献；不能只改名 |
| 普通 AFA/批量缓存足以解决全部分配问题 | 保留其作为强基线，减少 LLM 方法收益主张；检验 C2 是否仍揭示真实非平凡失败 |
| E 的可达性只能在不真实的人工例子中成立 | 不把它当主要实证贡献；补真实原生覆盖/缺失任务，否则降为工程诊断 |
| 延迟/重复/版本干预的影响全部由解析 bug 解释 | 先修通用解析并冻结，再重做研究；不能把可修 bug 当模型能力差异 |
| 一个小场景里有收益，跨过程后消失 | 发布适用条件和负迁移；不外推全部极端天气 |
| LLM 没有正收益，但及时性/破坏/证据浪费与传统静态分数不同 | 可以形成 benchmark 结果，但须独立过程复现、有强对照，并证明区别不是人为预算设计造成 |

最小的论文级证据组合是：任务合同与近邻有明确差异；真实多目标资料上至少存在可识别的资源/证据决策；限定 E 参照可核验；未来 F 结果可自动结算；强基线与分组确认能够支持或反驳主张。16 类覆盖作为整体项目目标独立验收。
