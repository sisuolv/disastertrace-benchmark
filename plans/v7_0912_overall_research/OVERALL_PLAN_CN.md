# DisasterTrace v7 整体研究与建设方案

日期：2026-09-12。本文是项目的整体研究主计划；[已有下一步实施计划](../v7_0912_monitoring_optimization/PLAN_CN.md)作为工程附录保留。新监测引擎、下面的实验和完整 16 类任务目前仍待实施。本轮交付的是研究设计、数据合同与文献核查，不是新的模型实验结果。

## 1. 最终要做成什么

**DisasterTrace 要评测：在专业预报持续更新、证据有缺口且多个目标竞争资源时，LLM/VLM 能否选择值得获取的证据，及时修订真正需要修订的预测，并避免破坏已有的好预测。**

推荐论文工作题目：**DisasterTrace: Evidence-Aware Monitoring and Selective Forecast Revision under Shared Budgets**。中文定位为“面向极端天气的证据充分性、主动监测与选择性预测修订评测”。

完整项目保留六组十六类灾害。机场低能见度只是验证监测内核的首个场景。最终产品包括有版本的数据集、可重复回放的环境、自动结果结算器、程序和模型基线、机制实验，以及按灾种和条件分解的公开结果。

模型需要预测，例如“未来 3 小时某站点的报告能见度是否低于阈值”“未来 24 小时某河站流量是否越阈”。模型输出概率、数值或分布，输入为截止时合法可得的预报与观测。我们评测的是专业预报之上的证据利用与修订能力；不训练一个替代数值天气模式的全球天气预报系统。

整体路线贯穿三个环节：

```mermaid
flowchart LR
    A[共同专业预报与可见证据] --> B[判断证据支持和缺口]
    B --> C[跨目标选择查询或等待]
    C --> D[获取有时间与版本记录的新证据]
    D --> E[保持基线或选择性修订]
    E --> F[截止时锁定预测与动作]
    F --> G[独立未来结果自动结算]
    G --> H[改善 破坏 时效 成本与失败诊断]
```

## 2. v7 必须保住的研究内容

下面是研究约束，不是可随工程进度省略的功能清单。

| 编号 | 不可弱化的内容 | 对最终 benchmark 的约束 |
| --- | --- | --- |
| R1 | 共同、持续更新的强预报基线 | 所有策略取得同一份合格基线；不能把“查到最新官方预报”当主动取证贡献 |
| R2 | 多目标共享有限资源 | 一个会话共用时钟、预算和权限账本；一次资料获取可合法服务多个目标 |
| R3 | 可计算的证据支持与可弥补缺口 | 对限定事实任务计算当前支持范围和有限可达证据路径；不只让模型自由回答 unknown |
| R4 | 选择性、具有版本作用域的修订 | FOLLOW/OVERRIDE 是持续状态；同时计算改善、破坏、修订陈旧和自动回退的作用 |
| R5 | 信息历史、谱系和表示的配对实验 | 同一结果配不同合法到达历史；区分新增信息、同源复述、旧版重送和表示变化 |
| R6 | 真正的未来结果与原生多模态 | 未来 F 任务独立结算；多模态声明需要同期、同域、实际进入 VLM 的原生图像 |
| R7 | 六组十六类与跨过程迁移 | 全部有独立数据/目标合同；不能以十六个名称代替十六类合格任务 |
| R8 | 无新增逐题人工复核的主评测 | 主分依靠确定性程序和已存在的合格参考；不依赖 LLM judge、逐题专家打分或人工修正答案 |

R3 来自前期“证据充分性—主动取证—预警收益”的 idea，必须和 v7 的 R1/R2/R4 结合。只实现轮询、缓存、JSON 输出，无法满足本方案。

## 3. Novelty 的定位与验证门槛

### 3.1 文献已经做到哪些事情

本轮核查了原始论文页面、三个近邻的正文相关章节，以及四个固定 commit 的公开仓库文件。完整比较、访问回执和阅读范围见 [RELATED_WORK_MATRIX_CN.md](RELATED_WORK_MATRIX_CN.md)。

需要特别修正的判断：EarthVerse 已经评测多灾种、证据发现、可执行答案单元，并做了相关文件 oracle、证据地图、缺失、截断、冲突及单位变换实验。SIREN 已经覆盖端到端预警流程；Obshazard-bench 已经覆盖原始遥感与灾害生命周期；SentinelBench 已经联合测量监测完成、反应时间和资源；FutureSim 已经有随日期演进的预测环境。AFABench、learning-to-defer、BLF/LEAP 也分别覆盖代价取证、委托、信念更新或证据聚合。

因此，“首次多灾种 Agent”“首次动态监测”“首次证据干预”“首次带成本取证”“首次引用或自动评分”均不作为论文主张。本文的差异定位需要由具体协议和实验支撑，不能仅依赖这些模块的名称。

### 3.2 三项候选贡献

| 贡献 | 拟提出的具体研究对象 | 必须提供的证据 | 不足以支持它的结果 |
| --- | --- | --- | --- |
| C1 持续专业预报上的资源分配与修订任务 | 多个未来目标共享预算、可共享证据、持续更新基线和具有版本作用域的预测状态 | 相同预测器下的分配×共享实验；强批量策略；修订改善/破坏和协议回退归因 | 只胜过不查询预报、没有缓存或逐题独立调用的弱对手 |
| C2 有可达性参照的证据诊断协议 | 在有限证据合同下区分“当前不能断言、可及时弥补但未弥补、已足够但读错、到得太晚”；连接未来预测损失 | E 支持集合与小规模精确路径参照；保持结果不变的信息历史配对；独立 F 结算 | 只有随机删文件实验、自由文本解释，或把所有 F 错误都归因于证据不足 |
| C3 真实多灾种的可复算监测实验体系 | 自然日历与极端富集两种队列，原生多模态、真实版本、跨区域/过程、自动结算 | 16 类资格表、六组迁移、多个独立过程、许可可复现资料、强基线与完整失败账本 | 只增加来源数量，或把传感器产品/报告当成全部物理灾害真值 |

这里最有辨识度的组合是：**可观测证据缺口及其有限可达性，如何在共享预算、不断变化的专业预报和截止时间下转化为预测改善或预测破坏。** 普通 VOI、Brier 分数、缓存、区间运算或委托规则本身不是新算法。

### 3.3 六个研究问题

| 假设 | 核心检验 | 失败时如何处理 |
| --- | --- | --- |
| HYP1 智能分配存在独立于共享缓存的价值 | X01 固定预测器的 2×2 分配/共享实验 | 若轮询、风险优先或批量同样好，报告其优势，不宣称 LLM 调度收益 |
| HYP2 选择性修订可控制错误改写 | X02 对比 FOLLOW、全部修订、规则/模型门控，双覆盖协议并列 | 若收益来自校准或自动回退，归给相应模块；保留负净收益 |
| HYP3 部分失败可以通过支持与可达性参照辨别 | X03/X04 证据路径与到达历史诊断 | 只在可证明的有限 E 合同内归因；无法判定的保持未识别 |
| HYP4 原生多模态对特定证据缺口有增量 | X05 等信息表示与真正新增信息分开 | 若合法数值特征已足够，不宣称 VLM 必不可少 |
| HYP5 静态成绩不足以描述部署约束下表现 | X07 延迟/预算曲线及方法排序，常规与极端分层 | 若排序稳定且约束无影响，如实报告，不能人为挤压预算制造反转 |
| HYP6 上述现象能够跨过程与灾种迁移 | X06 六组迁移与 X08 前瞻补充 | 若仅机场单例有效，收窄经验结论；整体 16 类建设仍按资格推进 |

主张成立的门槛是“有区别明确的任务、可检验机制和真实重复证据”。模型是否赢过专业系统是实证问题，不是预设成功条件。若强程序普遍更好，benchmark 仍可报告清楚的模型局限；但必须证明测试的失败模式非平凡、有区分度且对现有评测构成补充。

## 4. 三种任务和两种基线轨

| 层次 | 问题与输出 | 自动参考 | 在论文中的作用 |
| --- | --- | --- | --- |
| E：证据支持/当前态势 | 当前证据支持什么？输出数值范围、supported/refuted/undetermined、证据 ID | 有类型的规则、区间与覆盖运算、固定版本下的可执行答案 | 诊断证据理解与取证策略 |
| F：未来预测 | 截止时预测未来明确量/事件；输出概率、数值、分布 | 后续观测、合格已有标注或明确命名的产品/报告参考 | 论文的主要效果评价 |
| D：受控预警动作 | 给定成本/损失规则选择提醒、继续监测或不提醒 | 固定研究场景的损失矩阵、未来结果和动作时间 | 衡量预测如何转化为研究场景下的动作价值 |

E 判为 undetermined 不强制 F 输出 0.5，也不禁止 D 采取预防动作。证据不足、未来随机性和行动的成本效益是不同问题。D 不评价开放式疏散建议，不声称确定现实最优处置，也不对外发布预警。

F 分开发布：

- **P 轨：专业基线增补。** 有同目标、同统计支持、同期限的业务预报；原生概率与经过独立校准的业务点预报分别命名。
- **R 轨：研究基线增补。** 尚无匹配业务产品时，用冻结的持续性、气候态、外推或统计/领域模型。它仍可是真未来预测，但不能声称胜过官方同目标预报。

原生概率、校准概率、数值误差各有合格条件。不能为了合并榜单，把 TAF TEMPO 设为 0.5，把季节干旱展望当成下周概率，或把 FWI 当成点火概率。所有基线均保留来源和校准身份；P/R、物理观测/报告/产品参考分别展示。

### 5.1 数据分层和准入阶梯

数据按用途选择，不要求 97 个条目全部成为独立核心数据集。

| 层 | 用途 | 选择规则 |
| --- | --- | --- |
| 核心业务/观测骨架 | 形成历史发行预报—输入观测—未来结果链 | 能同域同窗配对、明确定义、足够持续档案、可冻结版本 |
| 原生补充证据 | 产生覆盖、版本、成本与跨目标关联 | 对至少一个目标存在可说明的关系；实际内容和配准可检验 |
| 已有 benchmark/已标注数据 | 复用事件、工具、可测标签、对照任务或领域模型 | 核验许可证、划分、标签和时刻；不直接合并原论文不同目标的分数 |
| 目录与背景 | 灾害富集、定位和后续分层 | 不当未来输入捷径；目录未收录不构成物理负例 |

准入分为 A0（登记）、A1（原生内容解码）、A2（变量/时间/空间/许可角色合同）、A3（同域连续输入—基线—结果配对）、A4（自动 E/F 任务及强基线）、A5（独立过程确认及可发布复现）。E、F、D 和多模态资格另设字段，A1 绝不自动推出 A4。

截至当前注册表，97 个来源/产品/投递条目中 86 有解析内容、7 只有目录、2 待授权、2 缺原生目标内容。这不是 97 个独立数据集，更不是 86 条合格预测链。新 `monitoring_v1` 尚未准入任何任务。

### 5.2 已授权新数据怎样纳入

- **EM-DAT（D39）：** 17,022 行，核心天气 8,584 条 event-country 记录、6,863 个事件号组。用于索引与富集；日/月/年精度分开，不能用缺坐标记录构造像素监督或无事件负例。
- **CMA（D73）：** 1949–2025 年 77 个文件、2,549 个风暴段、74,370 时次已解码。先核定官方单位、风速平均时长、时区和缺失值；随后扩展西北太平洋结果参考，并寻找同洋盆历史发行预报。原始零风速、可选第七列不能凭经验硬解释。
- **xBD（D44）：** Florence 三组 pre/post、六 TIFF 与六 JSON 已读；这是一个已暴露开发过程。现有 462 个建筑标签中 286 no-damage、176 unclassified，无损伤正类。几何残差最大约 111.44 像素，PNG/TIFF 变换尚未解释，因此暂不进入空间 grounding 分数；修复后用于有边界的影响/证据任务，不直接给机场预测提供答案。
- **GEE：** 已可访问，作为可选数据构建后端。导出必须锁 collection、asset、时间过滤、处理参数、投影和内容哈希；它不是“在历史某刻已公开”的证据。核心链可经原始提供方构建。
- **HKO-7、ESWD、M4Fog、MSETCD/MSCAR：** 保留扩展候选与真实缺口。已有骨架不依赖它们；没有原生内容、历史版本或标签就不以名称补齐覆盖。

### 5.3 原始资料到任务的统一处理

1. 保存原始字节、产品版本、获取回执和许可用途；同一上游的镜像/派生产品建立谱系。
2. 纯解析器输出带单位、统计支持、QC、区间/几何/数组类型的记录，未知代码拒收。
3. 构建站号、气旋 SID、有效区域和时间窗映射；结果的严格兼容合同与辅助证据相关性分开。
4. 先按日历生成目标和机会表，再左连接资料。保留缺口、删失、参考成熟度和实际覆盖。
5. 先按天气过程/区域时间块切分，再生成裁剪、摘要、预算和信息历史变体。
6. 根据版本化目标运算编译 E 参考和 F 结果；独立评估进程才可加载结果。
7. 用确定性/统计/业务基线跑通整个会话，再进行模型实验和确认集冻结。

降水必须检查 startStep/endStep、累计重置、trace、QC；温度允许负值且区分 2m 气温/LST；水位与流量、潮位基准、风速平均时长不能隐式转换；METAR 使用原生 SM/米 token 与删失区间。下载器的 Range 预算检查及无版本头对象校验进入工程修复项，当前静态发现不等于旧数据已损坏。

## 6. 证据充分性怎样成为可执行任务

给定当前合法证据 E_t 和事先公开的测量/标签合同，定义仍可能成立的事实答案集合 `Y(E_t)`。对于“面积是否大于阈值”等命题：若集合中所有答案均满足命题，输出 supported；均不满足则 refuted；跨越阈值则 undetermined；版本/量纲/目标不兼容为独立状态。

可先实现三类规则：

| E 子任务 | 自动支持集合 | 哪类查询可能弥补缺口 |
| --- | --- | --- |
| 空间阈值 | 已知正类面积作为下界；加上有效目标内未知面积作为上界 | 获取未覆盖瓦片、覆盖/质量掩膜；不把同一瓦片复述当新增面积 |
| 时间持续性/累积 | 合格记录定义支持时段，缺测间隔维持未知；有界区间按合同传播 | 补缺失槽位、核验累计窗口；不随意插值或填零 |
| 版本/统计可比性 | 先判同变量、同支持、同基准与合法版本，再算差值或越阈 | 补发行版本、单位、垂直基准、字段说明；不能跨版本直接说灾情变化 |

说明性例子：100 km² 的固定目标区，已覆盖 70 km²，其中标签正类 12 km²，则面积支持为 `[12,42] km²`。对 20 km² 阈值尚不能断言。若合法新增 20 km² 覆盖含 10 km² 正类，支持变为 `[22,32]`，命题已成立。这是同一时刻资料支持变得充分，不能写成洪水增长了 10 km²。数值仅解释规则，未作为真实样本。

进一步定义有限档案中的“预算与截止时间内可达证据集合”。在小规模 fixture 上枚举允许的查询路径，计算是否存在可让命题确定的路径、最早可达时刻和最小费用。大规模近似策略只报告可行路径或界，不能把贪心结果叫精确 oracle。

这个参照由评估侧构建，不能把将来会有利的瓦片内容或最优动作泄漏给策略。事后知道所有档案内容的路径是带标签的乐观上界，不能算现实可执行基线。另设只知道公开覆盖/预定更新时刻、不知道未读内容的可执行 selector，防止混淆。

失败按可识别条件多标签记录：当前缺证据；有限合同内不存在及时可达路径；存在路径但策略未取得；证据已充分但解析/推理错误；形成有效输出太迟。它们可能交互，不构造无依据的互斥“全因果分解”。更不能从 E 的支持不足推出“任何模型都无法预测未来”。

E 与 F 的连接须另外验证：固定预测器，比较合法新增证据前后的 E 支持与 F 损失，并按独立过程配对。某次查询让当前事实可判定，却未改善未来预测，是应当保留的结果。E 已充分不等于进一步取证对 F 没有价值，不能将 E 停止规则直接当作最优预测停止规则。若某份标签仅在事后制作，它可用于 E 的受控表示任务或 F 的结果侧；没有可用时间依据就不能作为当时业务可查的输入。

## 7. 会话、时钟、预测状态与费用

### 7.1 三个身份和四张关系图

- `session_id`：同一区域和连续时段，共用时钟、预算及策略状态。
- `target_id`：固定实体/区域、未来绝对结果窗、变量、统计量、阈值与参考类型。
- `opportunity_id`：目标在某个预登记 cutoff 的评分机会；同一结果可有多个提前量。

分别维护四种关系：物理过程/水网图用于分组和合理联系；来源谱系图用于版本、同源和派生关系；证据—目标支持图用于确定性作用域；预测依赖图记录某次预测实际用了哪些证据与基线版本。相关天气不等于同一份证据，同一厂商不等于同一事实，两个 ROI 不相交也不保证未来概率统计独立。

### 7.2 时间合同

每个资产保存 `valid_time/support`、`issued_at`、`published_at`（若有依据）、`first_seen_at`、`retrieved_at`、`processing_finished_at` 和版本。初始化时间不当作公开可用时间。

- 有可靠发行/档案可用性依据的回放，按依据和可解释延迟建立 as-of 视图。
- 只有内容时间的历史档案，进入明确标记的受控可用性回放；不能声称重现当年的真实网络延迟。
- 前瞻采集记录本系统首次观察时间与轮询间隔；first-seen 是捕获上界，不一定等于首次发布。

事件队列统一处理资料到达、公共 tick、调用完成、基线改变和 cutoff；同一时间的优先级必须冻结。推理开始锁输入快照，推理期间的新资料不能偷偷进入结果。按已冻结策略计入等待、传输、解码、推理和重试；超时仍记费用。历史回放采用明确的虚拟时间模型，真实推理耗时另记；在线时钟单独报告，二者不混成一个延迟数字。

### 7.3 主覆盖协议与敏感性协议

主轨为 `shared_baseline + base_bound_override + archive_costed`。不主动修订的目标默认 FOLLOW，持续跟随共同基线。OVERRIDE 绑定目标及其基线内容版本；影响该目标的新内容到达则失效并回到 FOLLOW。重复投递、无关目标更新不触发失效。

基线已变更而旧快照上的推理才结束，主轨保留回复/费用但不激活。`persistent_override` 敏感性轨保留修订直到显式撤销或目标关闭，可接受截止前完成的旧快照并报告年龄。两轨独立运行、独立命名、不能挑优混榜。自动失效是协议能力，必须报告触发次数和它造成的系统损失变化。

策略输出无效、超时或预算耗尽时，系统依照统一状态机继续持有合法旧状态或 FOLLOW，不删除该机会。基线缺失使用训练/开发期冻结的回退，标记 `baseline_missing_fallback`；原专业基线完整的预登记子表另列。

### 7.4 资源与公平

记录请求、实际获取字节、解码、渲染、输入/输出 token、GPU 时间和等待，费用向量优先于任意混合总分。预注册低/中/高预算由实测合理运行费用确定，包含一个资源不紧张的对照，避免为主动策略人为造优势。

缓存区分物理复用与策略授权。一次下载可让已授权的多个目标复用，同一文件的多个 ROI 不重复收下载费，但各自解码/渲染/推理实际成本应计入。全体策略有同样的批量接口、合理缓存和资源上限；跨策略物理缓存不能给后运行者免费信息或更低的逻辑成本。

默认比较使用固定预测器、一次针对一个目标推理；共同获取的数据可以复用。一个 VLM 同时预测多个目标属于独立的联合推理因素 X09，不能悄悄混入“共享获取收益”。

## 8. 原生多模态和信息历史的建设

每个主线至少尝试“业务预报＋地面/数值观测＋一类有实际空间意义的原生数据”。首线为同期 GOES ABI 与机场群；后续为雷达—对流、卫星/SAR—水文、火场影像—蔓延。资产必须真实重合；仅分别下载过文件不足以准入。

每个图像样本保存传感器/通道、时间、投影、DQF/无效掩膜、ROI、显示范围、渲染代码和 hash；裁剪中心不能依赖事后轨迹或答案。VLM 运行保存实际图片、processor/张量或视觉 token 的可核查摘要，而不是仅记录一个图片路径。

表示实验分为：原生图像输入、从同一合法资产自动提取的完整约定特征、同一信息的结构化/文本表示，以及真正新增模态。自动提取特征的计算费用公开；Gold mask、事后灾损、未来预报分析不允许作为所谓便宜特征。

信息历史包含：自然版本与延迟；同字节重复投递；同源派生复述；合法的新覆盖；旧版重送；受控延迟/失败；仅单位或表示变化。每个变体保留同一个结果参考及干预记录，并同步处理派生摘要、缓存和预测依赖。

两种实验估计不同量：完整会话重跑衡量策略适应后的总影响；固定前缀分叉衡量从相同合法状态出发的局部反应。不能把它们当成同一因果效应。只对确定性事实和确知等价的表示设严格不变性；未来概率允许合理的空间和统计联系。

主确认实验预先选定 HYP1/HYP2/HYP3 的少量主要对比；其余明确为机制或扩展分析，不跑完整指数型笛卡尔积。第一轮文本 Qwen3-8B 及一个确实通过图像输入验证的 VLM；确认阶段增加不同模型家族/规模，开放权重用于复现，API 模型作为可选外部验证。

## 10. 分数、统计与模型失败

### 10.1 固定机会表和共同结果掩膜

所有策略共享完整日历机会表和由数据决定的结果掩膜 `m_i`。模型不查询、没有有效回复或超时都不能使机会消失。未结算结果不补负例；报告总机会数、可结算数及按原因分解的缺口。

在共同可结算集合上，用预登记权重计算损失。二分类优先 Brier，分布用合格 CRPS，连续量用 MAE 等带单位分数；删失参考按各任务合同作区间评价或不结算，不能任意取中点。

```text
L_pi = sum_i w_i m_i loss(p_pi_i, y_i) / sum_i w_i m_i
d_i  = loss(b_i, y_i) - loss(p_pi_i, y_i)
Delta = weighted_mean(d_i)
G_plus  = weighted_mean(max(d_i, 0))
G_minus = weighted_mean(max(-d_i, 0))
Delta = G_plus - G_minus
```

其中 `b_i` 为当时共同系统基线，含有标识的缺失回退。`Delta>0` 表示净改善。G_plus/G_minus、改写率、FOLLOW 比例、成本、迟到率、自动失效与版本年龄同时报告。不能只在主动改过的目标上计算总体收益；该条件子表可以作为额外诊断。

预警动作另报 lead time、事件召回、每监测小时虚警、固定成本/损失矩阵下的损失、重复提醒与冷却规则。单一混合总分不是主榜；若需要展示综合效用，必须公开权重及敏感性曲线。

16 类按参考类型、P/R 轨和单位分表。宏平均只在相容任务和固定权重下产生，并同时展示六组与逐灾种结果；MAE 的摄氏度、m³/s、米不能直接相加。多时距、多次机会的权重在看结果前确定，防止高频灾种支配结论。

### 10.2 划分、独立性和规模

自然日历队列用于发生率、虚警和系统表现；目录富集队列用于极端机制分析。富集样本不估计自然概率；除非有已知抽样概率，不尝试事后加权恢复总体发生率。

先构建父天气过程/区域时间块与来源谱系的分组，再划分训练/校准、开发、方法选择、确认。相邻机场、上下游、同一气旋及其洪水、相邻日期、重复影像与多个 seed 均不能当独立 N。跨边界 purge 覆盖最大输入回看、时距及标签持续规则，受影响的连接组件不得跨 split。

已有公开 fixture 和反复查看过的结果登记为 exposed development。历史盲测只表示对当前开发流程未见，不宣称对 LLM 预训练无污染；无证据输入、事件记忆和前瞻样本作为补充诊断。

开发试点可先收集约 10–20 个独立区域/过程块估计成本、覆盖和成对差异方差；这是建设预算，不是统计保证。确认规模依据最小有意义差异、块级方差、极端正例频率和结果成熟度设计，可用块 bootstrap/模拟功效分析。确认集提前固定，不能看显著性后不断加样本或换日期。主要对比与多重比较策略预注册。

## 11. 软件与数据交付架构

首版只新增一个 `monitoring_v1` 内核；provider、语义转换与目标运算做成可复用纯函数。16 类通过合同和配置接入。第二个实际消费者出现后再抽公共包；已有 `active_warning_v1` 留作历史复现。

| 模块 | 必须交付的内容 |
| --- | --- |
| 数据目录与抓取 | 来源/产品/版本/字节回执、许可角色、失败账本和原始缓存 |
| Provider 与语义 | 原生解析、区间/QC/统计支持、站点映射、纯转换与真实 fixture |
| 任务构建器 | 会话、固定目标/机会、过程分组、E 规则、F 结果、P/R 基线合同 |
| 监测环境 | 单时钟、共享预算、权限缓存、快照、FOLLOW/OVERRIDE、恢复和幂等 |
| 策略与模型适配 | selector/perceptor/predictor/gate 分开；真实文本/图像输入和完整回执 |
| 独立评分器 | 结果隔离、全机会账本、净改善/破坏、E/D 指标、成本和分组统计 |
| 发布包 | manifests、数据/模型卡、冻结协议、可复算结果、脚本、近邻对照与局限 |

不会把 LLM judge 加到主评分路径。已有 USDM、Storm Events、xBD 等参考本身可能来自专家/人工或产品算法，需明确其身份；“无需新增逐题人工复核”不等于“原始标签从未由人制作”。自动规则遇到歧义就记录拒收/未结算，并修改通用合同及重建相应版本，不能逐题偷偷修答案。

## 12. 完整路线、依赖与阶段交付

### 12.1 首个执行批次如何服务整体目标

下一批先做 P0/P1 的离线可核查工作及 P4 的来源/子任务合同；再做 P2。候选开发区域是 KSFO/KOAK，再验证 KSJC，候选时段 2024-01-05 00Z 至 2024-01-08 00Z。已暴露的 KSFO 片段只用于开发，不将异地异时数据拼成自然会话。

三站 × 72 个小时 cutoff × 1/3/6h 对应 648 个名义机会，不是 648 个独立事件。必须获取回看和结算尾窗。完整 TAF、routine METAR 规则、删失语义和同期历史 ABI 通过后，才进入模型层；已有 2026 GOES-19 样例不代表 2024 区域图像已取得。

机场短链只检验实时状态和标签合同，不能代表整篇论文已经具备“极端”或“多模态增量”。随后需要 FG、降雪等正确分层，独立普通/极端过程，以及温度和另一类非机场证据任务的机制迁移。

### 12.2 CPU、四张 H100 与 API

CPU 优先做解码、时空连接、自动结果、程序基线及统计。用户已授权最多 4 张 H100：模型通过预检后，单卡容纳时四个独立 session/条件 worker；VLM 需两卡时采用一个双卡 worker 与两个单卡 worker。每个会话仍只有一个账本写者。

策略/模型交错调度并记录硬件、队列等待、batch 和资源分配，不能让某策略固定运行在更空闲的 GPU 上。GPU 并行加速独立实验，不改变单会话虚拟时钟规则。API 调用在合格本地闭环后补充，固定模型版本、实际费用与失败回执。

数据探查先复用缓存，小范围预登记来源/日期/字节上限；覆盖不足时依据记录扩充数据建设批次。不要为了凑满样本删掉失败，也不需要为已经授权的四卡使用重复请求许可。

## 13. 何时可以说“完成”

| 发布级别 | 可以说什么 | 必须达到的条件 |
| --- | --- | --- |
| 工程可行性版 | 共享监测最小闭环可运行 | 真实连续数据、强程序基线、状态/预算/评分可复算；只列已通过子任务 |
| 机制研究版 | 可以研究 C1/C2 | 首线＋不同证据/灾种过程复现，E 支持与 F 分数分离，主要控制实验完整 |
| 多灾种研究版 | 六组有跨组实验 | 每组至少一个合格未来子任务；多过程、自然/富集分表；不等于 16 类全完成 |
| **完整 v7** | **16 类 benchmark 完整发布** | **每类至少一个自动结算的明确未来子任务，合格 P 或 R 基线；E/F/D/MM 分别列资格；六组机制迁移和确认；至少两类不同物理过程的原生多模态证据链通过** |

最终目标是完整 v7。某灾种若只有目录、当前态势或不匹配代理，必须保持未完成；可以发布有名称的部分版本，但不能无声地用代理替代原目标。每类的全部子灾种不必一次覆盖，发布卡须准确说明已覆盖范围。

完整发布还需：零结果越权访问、全机会/缺口账本、预登记权重、独立校准与分组、两个覆盖协议和负结果、数据/代码许可证与引用、可重新构建的数据配方和成本记录。代码可公开不代表原始产品均可再分发；受限资产用许可允许的 manifest/下载配方与 hash 支持复现。
