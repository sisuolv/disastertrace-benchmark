# 下一阶段执行清单：先让新合同形成真实、可复放的小闭环

日期：2026-09-13。本文是下一批工作规格，尚未执行。
整体研究、16 类数据分工与分级发布见 [OVERALL_PLAN_CN.md](OVERALL_PLAN_CN.md)。

## 1. 下一步的明确目标

用现有 H15 真实资料完成：

`合法可见输入 -> E 支持判断/联合见证 -> 程序预测 -> 及时提交/封存 -> 自动评分 -> 同状态分支复放`。

同步做一个合成准备状态机，验证时间、资源和取消；它不计真实天气效果。
修复后的独立 F-only 接口尽早真实试跑，不等所有准备、第二领域或在途分支完成。

本轮规划只新增文档和核对产物。下述 admission、support、branch、preparation 等报告名称均是拟交付，
不能因它们写在清单中就当作已生成或已通过。全部机器工作包状态保持 planned。

## 2. 第一周 CPU 工作：前 1--2 天优先准入与 provider

### 第一步：CP00 + CP03.1，固定唯一架构和真实任务

读取当前工作区而非 reset 到审阅 commit。记录本地 HEAD、远端发布回执、dirty 状态、相关源码哈希和
已暴露机会。现有工作区 HEAD 为 `36082c42a93e11f67d274d8000c87cd1dc098d74`，发布回执为
`60ebd05723f9483590611976d379da2e4edd85b0`；两者身份不同，不能仅靠 HEAD 推断实际源码新旧。

交付：`BASELINE_STATE.json`、`ARCHITECTURE_DECISION_CN.md`、`MISSION_SPEC.json`、`EXPOSURE_LEDGER.json`。

关键决定：

- 唯一 session 协调者沿用 `monitoring_v1`；fixed 类型/输入/每目标归约通过薄适配接入，旧运行独立冻结。
- 明确多个机会的封存、控制动作合法时段、同刻事件优先级和新 D 事件相位。
- 区分 bundle、可见状态、上游版本、目标基线上下文和评估器 checkpoint 的身份及可见范围。
- 用现有已暴露 H15 fixture 做工程回归；新开发连续日历与最终确认集分开登记。
- 数据选择先冻结来源、区域和日期规则，不按 LLM 赢输筛选；历史 availability 未证实则用显式情景轨。
- 共同完整 TAF 对程序/模型相同公开；R 映射冻结，不依据已看过的两年度成绩挑主银行。

通过条件：目标、结果、共同基线、机会、时间、权限、回退和来源身份完整，旧冻结输入可继续复现。

### 第二步：CP01，补正式评分准入

保留 `paired_scores` 为纯数学函数。拟增 `admission.py` 或等效适配入口，正式分数必须消费截止状态导出的
`AdmittedForecast` 清单，而非任意类型正确的预测表。

交付：`ADMISSION_REPORT.json`、`COMMITTED_FORECASTS.jsonl`、一个真实 fixture 的回放/对账。

必须覆盖：

1. 合法提前提交被计分；迟到、缺回执、自报时间但无日志依据的记录不能回填。
2. FOLLOW、撤销、过期、旧基线在途结果均遵守封存；早机会关闭不误关同目标晚机会。
3. 相同预测标量但相关基线条件变化，仍按目标上下文判断；镜像重排或无关 E 问题变化不误触发回退。
4. 失败保留完整机会分母、原回复和实际消耗；结果缺失与模型失败分开。
5. 目标/单位/点区间/物理未来与产品发布错配被拒绝，正时效不自动授在线资格。
6. 从新冻结日志独立重建有效预测及损失，禁用扩展时旧概率轨结果保持一致。

这里的测试应针对合法性和真实失败边界，不以多写测试数量为目标。

### 第三步：CP02，接通真实 C2 provider

复用 `public_support`、`solve_joint` 和见证检查，新增语义转换层。
先选择少量已有真实资料，形成三类命题：原生删失/缺槽、TAF 条件段覆盖/继承、同目标真实版本替代。
不支持的 TAF 条件或字段显式报告 unsupported，不静默补齐。

交付：`SUPPORT_BRIDGE_REPORT.json`、`E_FIXTURES.jsonl`、`JOINT_WITNESSES.json`。

现有 head 验证器只接受航空邻站存在谓词。新增覆盖/版本命题先做程序支持与见证；进入模型实验前，
还需版本化任务 head/prompt/parser/评分映射，不能把任意新 E_question 塞进旧 head。

通过条件：

- 新旧枚举的转换有字段级依据，单位、端点、范围、时间、版本、误差、权限和父资料均保留。
- 空支持为 inconsistent，缺可靠上界为无穷，订正重建、重复/重叠去重，评估标签不进入模型已知事实。
- 在约 2--4 目标、至多 6 个候选动作的小图上，真实 provider 的 recipe 与同一预算/并发/截止的见证一致。
- “每个目标分别可达但不能共同完成”单独归类；有限 E 参照不伪称最优 F 或 D。
- 所有结果区分真实原始 fixture、人工构造的协议反例和模型回答，不能合并成真实天气样本数。

### 第四步：CP04a，先做无在途状态的真实分支

先将现有 `run_session` 的循环局部状态整理为可步进的唯一协调者；现有 engine export 或 forecast restore
不能单独恢复全部 selector/tick/clock/资源控制。再实现显式 schema 的 session snapshot 和跨进程恢复。
首期只允许无在途任务的安全边界，保留时钟、
日志游标、当前预测、开放/封存机会、已花预算、缓存/授权、策略记忆与 RNG。

交付：`QUIESCENT_BRANCH_REPORT.json`、快照、分支定义和逐事件比较结果。

选一个已有真实会话前缀，预登记至多 4 个合法候选、最多两步：保持基线/等待、获取一条站报、
合法批量读取、使用已存在且合格的工具结果。不存在的归档返回记 not_evaluated，不编造。
第一批用确定性程序和可合法复用的原捕获，不把新输入套进旧模型回答。

通过条件：无动作分支与原继续策略逐事件一致；各分支继承前缀费用一次，后续资源/缓存隔离；
未来/隐藏字段不能改变公共前缀视图；分支损失可独立复算。此时只声称 quiescent 恢复能力。

### 并行支线：CP03.2 + CP07，最小准备状态机

固定一个 research_assumption 场景卡：一类容量资源，每目标一个作业，预登记 deadline/duration/cost/expiry。
先用 CPU 合成 2--3 个作业，不假设现实机场操作或跨地点即时移动。

交付：`DECISION_SCENARIO_CARD_CN.md`、`PREPARATION_SYNTHETIC_REPORT.json`。

必须检查资源不足、恰好截止完成、准备覆盖过期、排队/拒绝、取消沉没成本、清理释放、幂等和恢复；
推理时准备继续，预测回退不撤销已耗准备；同一目标多个 F 机会只结算一次 D 任务。
单步特例用 `p * miss_penalty > preparation_cost` 的解析边界交叉检查，不以该简单算术替代完整状态机。

## 3. 第一批之后立即推进的真实模型试跑

CP06.smoke 只依赖新的合法评分、已支持的 E 合同和固定场景，不等待完整在途快照、多模态或 D。
首个 108 调用 smoke 限定现有可支持的航空邻站存在命题。TAF 覆盖/版本的新 E 要在新增任务专属
head/validator 通过后进入后续开发批，不能声称首批已测三类新 E。

建议上限示例：12 个基础机会 × 3 证据条件 × 3 独立 head × 1 模型 × 1 次 = **108 次实际调用**。
E-only、F-only、joint 都重新实际调用；不要拆旧 joint。先使用同一已安装模型和一套无填值答案示例的提示。
工程 smoke 可用已暴露 fixture，但只能检查链路；后续开发使用未参与提示调试的连续日期，确认集继续保留。

对应产物：输入 manifest、原始回答、完成/提交回执、实际 token/时间、准入与 E/F 分项结果。
调用失败保留，不按输出质量选择性重试。先 1 卡预检，只有更大冻结矩阵才使用最多 4 H100 并行分片。

验收关注：

- F-only 的真实结果存在且输入只有合法天气信息；E-only 不因没有 F 被计 F 失败。
- 严格区分模型改变了概率、准时生效了概率、相对自身有改善、相对共同基线有改善。
- 首批报告已支持的存在量词/删失 E，覆盖/版本明确标未运行；新 head 准入后再逐类报告，不只看总准确率。
- 108 是工程规模，不是独立天气样本量或显著性保证；不要求试跑出现正增益。

## 6. 每批必须回答的五个问题

1. 新实现了什么，哪些只验证合成协议，哪些用了真实数据，哪些真的调用了模型？
2. 每个分数能否找到合法输入、固定机会、截止状态、回执和结果版本？
3. 相对哪个强基线、在哪个资源与时间轨上得出什么差异，有哪些缺失/失败？
4. 哪些数据/日期已暴露，独立过程数是多少，哪些结论仍不能外推？
5. 下一最小可执行动作是什么，依赖是否真的必要，是否有独立工作可继续？
