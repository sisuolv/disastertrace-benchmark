# 多灾种数据源实样验证

本轮先验证来源和样本，再决定扩建哪些 benchmark 任务。用户希望尽可能覆盖不同类型的极端天气，并允许参考已有 benchmark。

## 执行顺序

1. 以 V5 主表的 43 个来源家族为基线，补充实际观测、预报和公开 benchmark。来源家族中的不同产品分别说明，重复入口不计为不同数据集。
2. 每个可访问来源争取取得至少 3 条可识别记录、时间窗口或完整影像样本；优先下载小文件、作者提供的真实样本或可核验的文件成员。已下载的完整样本重新校验哈希并注明继承来源。
3. 检查实际数值、时间、位置、单位、质量/缺测编码及影像与标签配对；下载网页、目录、README、文件头或测试夹具不算真实观测数据通过。
4. 对所有尝试保留响应、失败和字节哈希，离线重建逐来源结论。给出灾种覆盖矩阵、可借用的 benchmark 设计和下一步准入顺序。

## 覆盖目标

优先检查热浪、寒潮、极端降水、河流洪水/山洪、热带气旋、强风、龙卷风、冰雹、雷电、干旱、暴雪/积雪、冻雨/结冰、沙尘、浓雾/低能见度，以及沿海高水位/大浪。海洋热浪、野火和降雨诱发滑坡作为扩展方向；天气、天气相关灾害和灾后影响分别记录。

## 结果边界

- 抽样属于有目的的可行性检查，不代表全库质量、总体灾种频率或独立事件数量。
- 事件目录能提供已发布事件类别，但不能替代观测证据；未报告事件不能自动成为负例。
- 已有人工整理的公开产品可继承并披露来源；本轮不新增逐题人工标注或 LLM 裁判。
- 当前下载时间、文件修改时间、事件发生时间和历史公开时间分别记录；不推定历史可用性。
- 本轮不新增正式题目、模型调用或 GPU 评测。并行网络请求和 CPU 解码用于完成这一步。
- 旧实验、旧评分、冻结代码和数据保持原样。本目录是独立的新验证范围。

`SCOPE.json` 固定采样原则和资源上限；`specs/`、`batches/`、`attempts/` 保存逐次证据，`analysis/` 保存解码与汇总结果。
