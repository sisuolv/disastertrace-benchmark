# DisasterTrace v7：共享预算监测与选择性预测修订优化计划

日期：2026-09-12。状态：整合后的实施建议；本文所列新模块、会话和实验尚未实现或运行。

## 1. 推荐决定

下一阶段的核心交付是 **`monitoring_v1`：同区域、同一时段、多目标共享预算的持续监测评测**。所有方法取得相同的最新完整专业预报，系统决定额外查询什么、服务哪些目标、是否修改预测，以及何时停止取证。

保留六组十六类灾害的最终范围。首个研究主线选择美国机场群低能见度，区域温度作为数值迁移任务，相关流域多站水文作为条件扩展。历史回放承担主实验，有限前瞻用于补充真实到达时间证据。

这轮重点从“更多来源分别可读”推进到“资料在同一区域和时段可以关联，并产生可辨识的监测选择”。EM-DAT、CMA、xBD 已取得内容；CMA 字段与 xBD 配准进入独立支线，不作为首个机场监测闭环的前置条件。

第一轮实施应交付可运行的合同、状态机、共享账本、回放与程序评分，同时核查连续区域资料。先形成无需 LLM 的真实数据闭环，再接入模型。没有新的逐题人工 Gold，也不使用 LLM judge 作为主评分器。

## 4. 将 novelty 收敛为三个可证伪的问题

论文的候选贡献是：**在不断更新的专业预报之上，评测模型如何分配跨目标取证资源，并衡量选择性修订的改善、破坏和成本。** “多灾种”“工具调用”“缓存”本身不足以构成充分创新。

| 假设 | 关键实验 | 需要击败或区分的解释 | 不支持主张时如何处理 |
| --- | --- | --- | --- |
| N1 共享资源下的目标/证据选择有价值 | 相同预测器、相同基础预报、相同预算，比较固定轮询、风险/截止优先、批量与主动分配 | 普通批量 IO、合理缓存、廉价启发式已经足够 | 如主动无增量，报告程序基线优势，降低“智能调度收益”主张 |
| N2 选择性修订能改善预测，同时控制错误改写 | FOLLOW、全部修订、规则门控、模型门控；比较净损失差、改善与破坏 | 单纯概率校准、自动覆盖失效、不同预测器 | 报告自动回退贡献；持久覆盖和版本绑定并列，不挑表现好的协议 |
| N3 时间、来源依赖和表示会造成可定位的失败 | 等内容副本、旧版重送、延迟、合法新信息；完整会话重跑与固定前缀分叉分开 | 实际信息量变化、输入解析错误、空间配准错误 | 只给有控制依据的环节归因，不声称自然灾害的因果机制 |

数据可构建、系统可执行、模型有收益、文献上有新意是四项不同证据。v7 加强了研究问题，但尚未证明“首次”或模型正收益。

文献定位工作纳入第一阶段：按动态资料版本、目标共享预算、专业预报委托、修订损害、原生多模态、自动结果六个维度，对照 ExtremeWeatherBench、AFABench、Sentinel/SentinelBench、FutureSim 及相关主动特征获取/选择性预测工作。包内阅读记录可作为入口，实施时锁定实际源码版本；本轮没有重新在线检索它们或完整复现。若发现高度重合，调整贡献表述与确认实验，不能仅靠更换灾害领域声称新任务。

## 5. 首条数据链：区域机场持续监测

### 5.1 地区、时段和样本单位

首选候选区域为旧金山湾区，先核对 KSFO、KOAK，再考虑 KSJC。KSFO 已有历史 fixture，KOAK/KSJC 的同期 TAF、报告槽位和图像覆盖仍需实际验证。第二候选区域为 Denver 周边，具体机场同样通过元数据审计后冻结；不将旧 KSFO 与 KDEN 的不同日期拼成自然会话。

首次连续开发块可从 **2024-01-05 00Z 至 2024-01-08 00Z** 核查，便于包含已暴露 KSFO fixture；这是开发候选日期，不是已取得完整资料的声明，也不以未来是否有雾来筛选。真实 2 站短联调只使用该日期块中预先固定的一段。独立测试另选未暴露时空块。

身份分为：

- `session_id`：同一区域的一段监测时间，共享时钟、资源和策略记忆。
- `target_id`：固定机场、固定未来报告支持窗、变量与统计量；不能随模型预测改变。
- `opportunity_id`：该 target 在一个固定 cutoff 的评分机会；同一结果可在多个提前量被评分。

3 机场 × 72 个小时检查点 × 3 个时距（1/3/6h）对应 **648 个名义评分机会**，不是 648 个独立事件，也不一定是 648 个唯一 target。先建立完整日历机会表，再左连接输入和结果。窗口末尾需额外获取 lookback、最大时距、结果支持及结算尾窗。

独立数据队列保留两种：自然日历监测用于发生率、虚警和系统表现；按事件目录富集的极端诊断用于压力测试。不能从富集集直接外推自然发生率或在模型得分后替换日期。

### 5.3 数据验收交付

`REGIONAL_JOIN_AUDIT.json` 至少回答：哪些站点/时段；全部机会数；业务基线覆盖；合格参考覆盖；共享资产与多个目标的几何/时序关联；被拒原因；历史可用性模式；暴露与父过程分组。

## 6. 引擎与评分的实现合同

### 6.1 只建一套新内核

建议核心职责为 `contracts`、`state`、`catalog`、`budget`、`scheduler`、`runner`、`scoring`、`replay`，provider 放 `adapters`；真正实现到某项职责才创建模块。旧版本及旧日期产物保留，代码通过显式适配迁移。

数据流为：原字节/回执 → 纯解码与语义校验 → 固定 session/targets/opportunities → 按时刻公开资料包 → 共享预算运行与追加提交 → 私有结果独立结算。来源能力表继续使用 Dxx/AW-xx，不复制第二份不一致的 97 项清单。

结果要求严格同目标、量、单位、时间统计支持和基准；额外证据允许跨变量、邻站和区域图像，但必须有可核查关联。不同机构产品可以同时存在，只有明确的同产品版本链才执行替换。

### 6.2 预测状态与例子

默认 `FOLLOW_BASELINE`。A 的共同基线从 0.20 更新到 0.35，A 未行动，则系统输出 0.35，模型调用和主动修订数仍为零。

B 基于版本 v1 提交 0.60：在 v1 仍适用且修订未到期时保持 0.60。若 B 对应的基线内容变为 v2 的 0.35，主协议使该覆盖失效，恢复 FOLLOW。另一个目标的基线改变，或相同内容从镜像重送，不应让 B 的覆盖失效。

持续覆盖对照在同样事件下保持 0.60，直到显式撤销或截止。`NO_CHANGE` 只是没有新动作，不能与 FOLLOW 混同；`STOP_ACQUISITION` 结束本 session 主动获取/推理，但不删除机会或停止合法基线更新。

修订有效性绑定 target、基线内容版本、提交时刻、有效期限与已读引用。不自动把旧修正量加到新预报，也不按后验误差选择保留哪个值。

### 6.3 时间、缓存、成本和恢复

单 session 一个逻辑写者、一个 UTC 微秒事件队列。请求与推理开始时各自锁定快照；外部事件继续推进。cutoff 前完成的合法提交才生效；公共唤醒在 cutoff 封存后发生时，新动作只能影响后续机会，不能用零耗时推理回写本次检查点。

同刻顺序采用明确总序：公开产品发布 → 已在途完成/收据 → 基线版本一致性处理 → cutoff 封存 → 恰好到期修订清理 → 公共唤醒。有效期限包含 cutoff 端点。真实模式只接受实际持久化收据，不能用虚拟优先级回填迟到。

三层缓存分开：研究端原文件、策略 session 的授权获取/派生缓存、模型输入或真实实现的特征/KV 缓存。相同产品可跨目标共享获取费，新裁剪和再次送入模型仍计费用。另一策略的磁盘缓存命中不授予免费知识。

分别记请求/字节、解析与图像处理、selector/predictor 调用、文本/视觉/输出 token、实耗与逻辑费用。并发先原子预留，始终满足 `spent + reserved <= limit`；实际 Range 包含预读；失败和重试不从账本消失。

先持久化 intent，原始回复落盘后再解析；未知在途调用不自动重新采样。replay 使用已保存回复，不重新生成。活跃状态由单 writer 管理，若用 SQLite 则放节点本地，AFS 保存封存分片；不在 AFS 多节点共享写 WAL。

被测执行环境只见公共输入及已授权交付，不挂载全时段原数组和私有结果；测试缓存、符号链接、错误回包和目录名。仅在 Python 对象里删去 Gold 字段不足以证明隔离。

### 6.4 完整分母与指标

主结果对完整机会表连接同一资格掩膜。报告数据可结算率、基线缺失、默认委托、主动修订率、非法/超时与实际成本。连续变量先按变量/站点尺度报告 MAE；合法二元结果在概率基线通过后报告 Brier 与校准。

对相同权重与可结算机会：

```text
Delta   = weighted_mean(loss_baseline - loss_system)
G_plus  = weighted_mean(max(loss_baseline - loss_system, 0))
G_minus = weighted_mean(max(loss_system - loss_baseline, 0))
Delta   = G_plus - G_minus
```

这是一种改善/破坏的算术分解，不是获取、感知、状态的因果百分比分解。主分不能只看模型主动修改的子集。D 层待概率、公开成本/准备时间和告警去重定义完整后单列；免费等到截止必须是合法对照。

## 10. 数据/GPU 资源的使用计划

解码、校验、程序策略与评分主要在 CPU 完成。新抓取先检索本机缓存，再写明站点/产品/日期/请求和字节界限；失败计入同一预算。首个新数据探查建议每来源最多 20 个逻辑请求、256 MiB，整个短链探查最多 200 请求、2 GiB；这是有界探查，不保证足够覆盖 72h。若不足，先写覆盖/预计体积，再扩大建设批次，不能截断会话后把缺口隐藏。

你此前已允许使用最多 4 张 H100 并行。数据和离线门槛通过后，在该范围内按预检结果调度，不因计划模板写着“待批准”而重复请求同一资源授权。本次请求是规划，因此本轮没有启动新 GPU、API 或采集任务。

GPU 并行单位是独立 session/策略/条件，单 session 仍只有一个账本写者。模型每卡放得下时使用四卡独立 worker；VLM 需两卡时改为一个双卡 VLM worker 加两个单卡 worker。按策略交错分配，避免某一方法总在更空闲硬件上测时。真实模型以本机已验证的文本 Qwen3-8B 和一个加载/图像 smoke 通过的 VLM 起步，准确 revision 由预检确定。

先 2 站短链，每 run 小于等于 16 次模型调用；3 站 72h 扩展 run 建议模型总调用上限 144，**包含 selector、predictor 及额外完成回调触发调用**。固定程序选择器没有模型调用，但 CPU 计算仍记账。token/视觉/字节上限由序列化 dry-run 冻结，不能保留 null 上限运行。

模型开发矩阵可从 1 个 session × 3 个策略 × 2 档预算 × 2 个后端 × 1 seed = 12 runs 起步；在每 run 144 次上限下，合计最多 1,728 次调用。这是后续 smoke 的上界估算，不是已经提交的作业，不是确认性样本量。程序对照无需凑同样的模型调用数。先完成 clean，再加入一个扰动，避免 16 灾种全因素笛卡尔积。

历史 `archive_costed` 使用固定逻辑到达/处理时钟，并另记实际 GPU 实耗；`wall_clock_shadow` 用真实到达与持久化收据。不能把历史加速或本地文件读取称为真实业务预警延迟。旧水文后台任务保持原身份，新监测适配不重新启动或接管它。
