## 1. 总体决定

**保留六组、16类灾害；建设一条共用数据生产线和一套共用交互环境；用灾种合同而非16份独立代码规定各自变量、未来目标与结果。**

唯一主问题保持为：在相同的最新合法专业预报、信息访问权限和预算下，主动选择额外证据能否改善固定未来风险的预测与截止前研究决定？

实施时采用：

1. **历史多事件回放为主体。** 使用真实历史预报与观测；可用性无法证实时声明受控回放，不伪造历史发布时间。
2. **前瞻捕获作为时间证据补充。** 复用已有有限水文采集，不把等待新的灾害成为研究推进条件。
3. **GEE不是核心依赖。** 优先使用已有冻结资产和可许可访问的直接来源；GEE可在将来作为有明确版本及处理记录的可选构建后端。
4. **E/F/D三层独立。** E判资料事实，F判未来结果，D判公开情景内的决定。产品证书不能认证未来概率，更不能证明自然界不可预测。
5. **方法必须允许零收益结论。** 不删去专业预报/全读较强的任务，不把模型胜出作为数据准入条件。

### 1.1 最终交付形态

- 有审计依据的来源注册表和变量字典。
- 16类灾害配置、相应的任务资格/阻塞状态、可复用的来源适配器。
- 可冻结、可恢复、可隔离的历史资料回放环境。
- 分开的公开资料包、结果包、诊断包与重建配方。
- 专业预报、数值融合、固定/随机/主动取证和原生多模态基线。
- E/F/D结果、资源曲线、事件组不确定性和失败诊断。
- 每个子轨明确地区、时间、结果类型、可用性模式、许可和限制的发布说明。

“16类范围确定”不等于“16类均已具备业务预报增益主榜资格”。缺少同目标专业基线的任务可以是研究基线轨或E诊断轨，但状态不能伪装成完整F/D完成。

## 4. 统一数据合同：目标严格，关联证据多样

### 4.1 最关键的设计分离

`OutcomeCompatible(record, target)`：结果必须匹配目标实体、量、单位、基准、空间和统计支持。

`EvidenceAdmissible(record, target, t)`：证据可以是其他站点、其他变量、地图或时段，只要来源、关联、可用性和权限有明确依据。

例如下游流量目标可以合法使用上游流量、流域雨量和水文连接图。它们不是下游流量的重复观测，也不允许直接逐值比较。关系使用显式EvidenceLink记录，不让LLM自己决定某资料是否有资格进入测试资料池。

### 4.2 逻辑表和对象

小规模采用JSONL元数据+Parquet序列+内容哈希资产，较大数组按已有格式或版本化分块保存。暂不强制部署数据库、知识图谱服务、Kubernetes或复杂任务平台。

| 对象 | 必须表达什么 |
|---|---|
| `SourceSpec` | 原生产品、版本、端点、可用变量、合法用途、许可和能力 |
| `CaptureReceipt` | 请求参数、开始/结束、状态、字节、Range/CRC检查、原始hash |
| `Entity` | 风暴/站点/区域身份、别名、坐标、基准、映射来源及有效期 |
| `ProductRevision` | 产品系列、发行版本、输入依赖、签发/有效/可用性证据 |
| `ScientificRecord` | 标量/区间/类别/集合/序列/栅格引用；变量、单位、空间时间支持、QC |
| `PresentationAsset` | 原生图、重绘图、表格、摘要、裁剪；父产品与处理配方 |
| `EvidenceLink` | 同目标、上游连接、流域重合、背景相关、范围不兼容、关系未知 |
| `TargetSpec` | 固定实体、变量、比较符、窗口、聚合、阈值及质量/缺失政策 |
| `OutcomeRecord` | settled/unresolved、值或区间、reference_kind、QC、修订版本 |
| `ExposureAndSplit` | 已暴露、原始split、物理过程组、重叠时间块和共享资产 |
| `Delivery/Acquisition` | 请求、选版、完成、可读、读到、失败和费用 |
| `Forecast/DecisionCommit` | 服务端时刻、目标、合法引用、原文hash、解析状态和预测 |

未知时刻保留null+reason。不得把“缺测”“资料还未送达”“当前证据不能确定”和“未来结果无法结算”塞进同一个unknown。

### 4.3 测量值不是只有float

- 负温度、相对基准下负水位可合法存在；由变量字典决定合法域，不统一裁剪非负。
- `P6SM` 等上下界、原文能见度、trace降水分别保存数值区间和开闭边界。不能用任意小偏移伪造精确测量。
- 连续变量判定使用 `gt/ge/lt/le` 明确比较符，低能见度与低温不强行套 `>=`。
- 集合保存member_id、weight、cycle和有效时刻；缺成员状态显式，不能把缺失当不发生。
- 栅格保留变量、编码表、mask来源、CRS、transform、像元面积约定。标签派生mask不进入普通输入。
- 动态空间/时间转换需要保存输入、变换参数和版本，禁止只保留最终一列数值。

### 4.4 角色按用途与版本定义

不要把某个来源永久标成“只能结果”。历史上已公开的某周USDM可作为后来任务的输入；后来订正的同一周版本不因此合法进入早期输入。资格由版本、目标和时间共同决定，不只由来源类别决定。

## 5. 数据生产线：将已有脚本抽成可测纯函数

### 5.1 来源IO

优先读原环境已冻结文件，不重复下载。新请求只在授权清单内执行，保存每主机限流、重试、退避、预算、实际响应和失败；不能把HTTP200的索引页算成科学样本。

HTTP Range须核对Content-Range、远端对象身份与长度；发现对象改变不能拼接不同版本。压缩前缀可用于有限探查，但不能通过整体CRC或全包完整性验收。相同字节的镜像保留交付记录，不重复计观测。

### 5.2 纯解码与语义检查

从已有 `build_chains.grib`、CSV读写、原始TMP、METAR/TAF、水文解析和各来源审计中提取可测试函数。输入为原始字节与声明的产品合同，输出规范记录+拒绝/警告记录，不直接生成最终问题。

`BuildContext` 传入source_store、记录集合、版本配置与输出位置；避免多次构建共享模块全局列表导致重复/状态污染。该风险是扩展设计考虑，不宣称当前一次脚本已发生污染。

所有读取器输出必须通过单位、level、stepType、统计支持、缺失编码与空间范围验证。发布说明里的某些值可由源码启发，但必须从该实际版本元数据验证。

### 5.3 配对与目标运算

先生成候选实体和日历监测窗口，再匹配同目标预报与参考；不先看模型在哪些案例赢。事件目录用于富集诊断时另列队列。

建议实现八类通用运算：

| 运算 | 典型用途 | 缺失与边界 |
|---|---|---|
| `value_at` | 温度、流量、风暴强度、潮位 | 精确时刻或预先声明配对容差 |
| `window_exceedance` | 未来窗口越阈 | 规定采样网格，不冒充连续极值 |
| `accumulation` | 降雨、降雪 | 必须是同一累计起止和可兼容单位 |
| `duration` | 热浪、浓雾、低温 | 观测间隙可能破坏连续性，不能自动插值 |
| `rate_change` | 寒潮骤降、闪旱恶化 | 支持区间、基准与变化分母固定 |
| `spatial_extent_change` | 洪水范围/火场变化 | 两期有效公共覆盖与真实时间分开 |
| `report_occurrence` | 确认龙卷/冰雹事件报告 | 无报告不自动证明物理未发生 |
| `event_density` | GLM闪电密度 | 去重、有效覆盖、面积与时间分母 |

旧 `revision_delta`、`count_threshold`、`area_threshold` 继续作为E运算使用。以上新的F运算不自动继承旧小池证书。

### 5.4 处理回归必须绑定真实边界样例

- 历史Denver低温：负数合法，不被AWv1风速/流量约束错误拒绝。
- 原METAR的1000m：`<1000`为否；不得经四舍五入英里反转。
- TAF：INITIAL/FM/TEMPO/PROB及修订保留为结构化段；不能将prevailing_only误称完整专业基线。
- GFS APCP：读取startStep/endStep，六小时和从起报累计不混用。
- 水文：流量不套水位阈值；基准变换由双边有效元数据支持，冻结版本。
- SenForFlood：图例未明时拒绝“非零=flood”；不是靠添加模型生成标签。
- GWIS/EFFIS：共享父产品只能算同一上游的表示/交付。

上述真实问题在当前报告及所读源码中有据；本次没有重新执行这些案例。[C08–C12]

### 5.5 结果编译

主标签来自独立结果运算器，而非输入编译器缓存的“答案”。小样例可做两个独立实现，一种直接从原生值判定，另一种从规范表计算；避免两边引用同一错误业务函数后相互证明。

窗口正例可由合格越阈观测支持；负例需要足够覆盖，缺口可能隐藏越阈则unresolved。保存结果参考类型、质量成熟度和版本，不把暂定观测视为已经最终确认。

## 6. 原生多模态：把表示条件与信息条件分开

正式计划保留三种表示条件，不强制每个hazard×target都有每种条件：

- `native`：当时可用的原始公告、原生影像/图件、合格传感器产品。
- `computed_tools`：对同一合法资料执行被允许的裁剪、统计、解析；工具结果有配方与成本。
- `exact_diagnostic`：人工已有标签或更强私有事实替代的特权诊断；不进入普通部署榜。

可从公开资料确定性计算出的表格不是必然特权，前提是同一资料/工具对普通策略也可访问并按同一政策收费。反之，从结果掩膜计算出的面积不能伪装成普通图像工具结果。

图像需固定波段、校准、投影、像元映射、色表/显示范围、裁剪和无效区。测试图不能按未来标签中心裁切而对所有策略隐瞒这项先验。TCIR等既有风暴中心裁剪需审查定位信息是否来自事后分析；不明时声明条件或降级。

多模态并非天然有新增信息。同一产品图表可以帮助理解，也可能只是重复。先保留结构化强基线；没有视觉增益时报告结果，不通过移除本来存在的数值字段制造必要性。

## 7. 动态环境v2：真正允许查什么、何时等和何时停止

### 7.1 动作与时间

建议动作：

```text
QUERY(product, entity_or_region, variable, valid_window, representation, revision_policy)
READ(receipt_id)
WAIT(until_time)
FORECAST(target_id, distribution_or_point, citations)
STOP_ACQUISITION
```

D v1在deadline对共同概率规则结算；未来需要真正研究行动时机，再加单独 `DECIDE`，不能让一次STOP等同于预测、准备和退出评分三个动作。

环境维护 `available / requested / pending / completed / delivered / read`，以及追加提交。默认请求接受时锁定版本；完成前不返回内容。若采用响应生成时最新版，是另一个显式ToolSpec，不隐式混用。

事件队列有稳定同刻排序。建议所有在t时刻已完成的提交进入t的检查点评分，边界含等号政策预先固定。模型可选择等待时间，但不能调用“跳到最有用的新证据”这种隐藏事件Oracle。

固定检查点不等于固定模型动作时刻。若模型一直不提交，按统一回退计分并报告沉默率。最终结果发生后不能继续改写早期预测。

### 7.2 一次模型调用与环境时间

机制轨固定外部资料时钟和工具延迟，模型实际token/耗时单列。墙钟轨纳入同条件实际推理与工具耗时。共享集群排队不能当作模型本质延迟；一分钟查询不能为制造结果任意记成半小时。

有并发能力时各策略享有相同上限。允许提前发起的请求跨过检查点，但未完成内容不能影响之前分数。重复读、缓存命中、失败、限流与重试成本写进合同。

### 7.3 真正的隔离

字段白名单只是一层防线。工具broker可信地持有按时刻裁剪的证据存储；被测模型/执行工具进程仅可见公共输入和已经交付的内容；结果进程独立持有标签与特权证书。

不能让agent以同一个root身份读取挂载了private目录的AFS，并声称只是一个Python对象不含outcome就完成隔离。采用独立挂载/账户/容器边界，禁用外网和任意主机文件读取，配置资源限额。容器本身不是自动安全保证，必须测试越界路径、符号链接、缓存和错误响应。

### 7.4 持久化与恢复

原始请求先写request receipt；原始响应先落盘再解析。提交采用不可覆盖序号与原文hash，预算/请求状态持久化。重启不能重置时间或预算，也不能悄悄重新运行失败槽后只保留成功。

保留旧trace复算思路；完整性哈希用于检测修改，不宣称单靠同进程可改写的哈希链就完成对恶意模型的安全隔离。

## 8. 解决现有主动策略退化：拆成两种主协议

### 8.1 `forecast_fed`：推荐论文主轨

同一检查点，所有方法获得同一最新合法专业预报。其固定订阅/获取成本一致地免费包含或记为共同基础成本，不让Agent单独承担或免费享有。

额外预算只用于其他观测、地图、上游/邻站、产品质量、跨变量支持或不同版本解释。比较：

```text
最新专业预报
vs 最新专业预报 + 固定额外取证
vs 最新专业预报 + 主动额外取证
```

这直接回答已有预报上加AI是否值得。专业产品解析不完整应先修复，例如TAF TEMPO；不能把补回已有信息称为发现了新独立证据。

### 8.2 `full_acquisition`：保留并扩展现有任务

官方更新也是可查询动作，评价完整信息获取系统。允许其与forecast_fed有不同语义，但各自预算对齐、分别报告。旧v1归入它的受控小型子集，不改旧分数。

### 8.3 先做开发集证据效用诊断

冻结同一个可接受缺测模式的预测器 `g`，比较基础输入、单个额外来源、合理固定组合、全部合法可得资料。

- 全部资料也不改善：可能数据不互补、融合器不利用、样本太平静或当时专业预报已足够；不能直接断言所有信息无价值。
- 结构化正确事实改善而原生图不改善：支持该诊断条件下的感知瓶颈解释。
- 合法全读改善而主动不改善：进一步检查选择和停止。
- 只有后验最佳选择改善：仅是特权诊断，不代表存在可泛化的在线策略。

不能据此只保留Agent有优势的测试事件。自然队列保留全部预定合格窗口；诊断富集另列。

## 10. 基线、概率和决定评分

### 10.1 策略与预测器分离

同信息预算的获取对比共享：基础预报、公开字段、缺测/年龄状态、预测器与决定规则。共享预测器可以是开发拟合的简单数值后处理或冻结LLM后端，但必须能接受不同合法证据子集，不能把测试结果训练进去。

组合干预如canonical同时改变planner和forecaster应明确命名；要声称只比较获取，需要固定表示或做2×2对照。

最低基线包括：最新专业预报、持续性/气候态、合理固定轮询、随机、低成本优先、最近更新、贪心、有限两步前瞻、主动Agent，以及预算内合法全读/并行全读。没有专业同目标预报的灾种，基线身份标为research，不承诺业务增益结论。

### 10.2 集合概率

对已定义的越阈比较符，将每个有效成员的指示按声明权重汇总。窗口事件应在每个成员轨迹内先判断是否越阈，再汇总；不能对各时刻边际概率取最大来代替事件概率。

缺成员不能算0，重归一化或拒收政策事先固定。没有可靠成员ID时，单时刻分布可以保留；跨时刻成员轨迹无法恢复时不发布对应联合窗口概率。

确定性预报保留点分数。需要概率时采用分组训练/校准冻结的误差模型，称基于专业点预报的后处理，不称官方原生概率。旧v1的0/1概率保持diagnostic身份。

### 10.3 统一结果表

- F：分提前量的点误差、Brier及有依据的分布指标；事件组宏平均和区间。
- D：截止时共同规则下的损失，相对强固定策略的增量；多个预登记成本比/截止情景。
- E：支持/引用、版本与范围、未知保持、来源更新；不为未来概率指定唯一Gold。
- 资源：请求、字节、模型/图像处理token、实际时间、失败、并发和成本分别列。

不同单位MAE不直接平均。跨灾种比较优先报告分表和声明参考的skill；若skill分母为0或样本不足应标记不可用，不能用任意常数维持排名。

缺预测时继承最后合法分布或共同初始分布，另报回退率；未结算结果不算负例，数据分母完整。模型不能通过只在自选时刻提交来退出固定检查点评分。

### 10.4 截止与提前量

先以公开外部deadline测“是否在仍有准备时间时形成有效概率”。简单 `rho*a+(1-a)*y` 并不奖励所有deadline前的更早动作；免费等待到D应作为合法强基线。若研究真正告警时机，要定义并验证准备时长或有效性变化，不能由未来发生时刻反向创建任务deadline。

报告固定开发阈值下的真实测试FPR/FAR、全部正例的及时检出比例；漏报保留在分母。观测只支持窗口时，不伪造精确发生提前量。D只是研究情景，不宣称真实伤亡/经济收益。

### 12.2 四条实施工作流

- 数据工程：冻结存储、读取器、变量/QC和来源绑定。
- 任务科学：16类合同、结果、缺失、阈值、分组与监测队列。
- 运行工程：broker、时钟、权限、trace、模型接口。
- 验证研究：专业基线、独立运算、统计与发布。

一个PR只改变一个协议维度或一组共享读取器；不要一批同时改数据、prompt、概率基线和评分后无法解释差异。共享schema变更先评审，再允许各来源并行实现。

### 12.3 GPU与成本

当前阶段不启动新GPU。批准后先使用少量开发组、少数策略、2–3档预算和自然条件；机制干预单独作用固定子集，不运行16灾种×所有变量×所有时限×所有表示×所有模型的笛卡尔积。

四张H100优先独立分片；具体卡数由模型上下文和显存预检决定。预先列出 `目标数 × 每目标动作上限 × 策略 × seed` 的调用上界；不因有资源就扩大无意义重复。CPU负责绝大多数解码、结算和程序策略。
