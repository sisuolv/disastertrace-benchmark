# DisasterTrace：基于真实样例核验的整体灾种、数据与评测方案

日期：2026-09-11。本文整合用户提供的两份 Overall Hazard Data Blueprint，并根据实际样例修改数据选择。覆盖整个 benchmark 的目标结构、16 类灾害、来源、处理、抽样、实验及发布，而非仅安排下一项开发工作。

输入文件及原仓库状态的哈希见 [INPUT_BINDINGS.json](INPUT_BINDINGS.json)。逐灾种合同见 [HAZARD_SOURCE_MATRIX.md](HAZARD_SOURCE_MATRIX.md)，逐来源样例和访问限制见 [SOURCE_SAMPLE_INVENTORY.md](SOURCE_SAMPLE_INVENTORY.md)。现有 74 项登记沿用；新增/拆分产品后清单有 97 项，**不代表 97 个独立数据集，也不代表全部通过准入**。

## 1. 建议确定的整体方案

保留 **6 个组织组、16 个灾害家族、E/F/D 三个评测面板**。以已取得真实数据的站点观测、业务预报和专题产品为骨架，构建同一套可回放的信息环境。不同灾害共用协议，但各自保留变量、时间尺度、结果性质和空间范围。

论文的中心问题是：**当基础专业预报相同、资料随时间到达且存在预算与准备截止时，LLM 能否主动选择有用证据，改善对同一个未来极端目标的预测与决定？这种增量来自获取、感知、状态管理还是决策规则？**

“覆盖更多灾种”和“使用多模态”是实现这一研究问题的数据条件。论文贡献应由真实未来结果、强基线和配对机制实验建立，不能以接口数量、图片数量或套用 Agent 形式代替。

建议现在冻结的是灾种身份、来源角色和目标合同结构；随后按合同准入事件。样例验证无法直接冻结最终任务数量、未来正例比例或尚未验证的数据许可。当前没有必要让 CAMS、SMAP、M4Fog 等条件来源阻塞所有已具备样例的主线。

## 2. 本轮实际做了哪些数据验证

本轮执行 **125 次有界 HTTP 请求，保存响应内容 94,916,311 字节，约 90.52 MiB**。其中 101 次传输状态为 received、18 次为不完整或 HTTP 错误、6 次发生读取/连接失败。received 包括文档、目录及空响应，不能解释为 101 个可用数据集。

最终科学审计包含 **31 条科学内容解析记录及 2 条渲染地图记录**；科学内容包括完整文件、完整 GRIB 消息、站点文件的完整行样本及分段组装的完整文件。记录数不是独立过程数。保留所有失败、截断与重试回执，完整统计见 [CAPTURE_SUMMARY.json](CAPTURE_SUMMARY.json)。

已对既有样例清单的 375 个文件重新核验哈希，另核验 NHC/水文连接审计引用的 78 个文件；两组可能重叠，不能相加宣称 453 个独立样例。旧科学解析结论被继承，本轮未重跑所有旧解码器。

### 2.2 两个重要的长尾正例

**冻雨：** Oklahoma City 2020-10-26 至 27 的历史 METAR 样本有 47 条主天气码 `FZRA`、8 条 `FZDZ`。例如原文确实包含 `TS FZRA BR`。标签提取不把备注中的提及当作机场实际现象。

**沙尘暴：** Phoenix 2011-07-05 至 06 的样本有 5 条 `DS`、10 条 `BLDU`；其中真实原文包含 `1/4SM ... +DS VV002`。沙尘暴、扬尘和低能见度现在有可以区分的实际记录。

这些计数都是站报数，彼此可能来自同一持续过程。它们解决“是否存在可读的真实正例”问题，尚未证明极端发生率、跨地区泛化或未来任务已成立。下一批未见事件需要独立采样，不能把这些已看过的过程放入确认性测试集。

## 4. 共用数据架构及明确取舍

### 4.1 当前站点库迁移到 GHCNh

官方 2026-06-23 迁移公告指出 ISD 已被 GHCNh 替代，ISD 不再更新 2025-08-24 之后的数据。旧 ISD 资产保留兼容；新的持续获取采用 GHCNh，实时航空观测采用实际捕获的 METAR/SPECI，日极值采用 GHCNd。

本次样例证明不能把 ISD 解析器直接套上 GHCNh：329 列稀疏 PSV、数值单位、天气码结构和 QC 表达均需独立处理。例如样例温度 `13.9` 已是摄氏度，不能再除以 10；能见度单位为公里。每条规范事实保留原值、原单位、原始 QC 与转换版本。

GHCNh/GHCNd 都是整合归档。观测发生时间不自动等于原始公开时间；用于过去的实时输入时必须有当时版本依据，不能拿今天的订正归档冒充过去可见内容。

### 4.2 把通用预报和专业预报都作为强基线

GFS/GEFS 覆盖通用风温雨，HRRR 补充美国区域短时天气，SPC/TAF/NHC/NWPS/HEFS/CPC/OFS/P-ETSS 处理专业产品。当前样例证明具体字段可以读取，并不自动证明所有起报、成员、时距和版本都能完整获取。

每个预报资产必须验证 `init_time + lead -> valid_time`，累计量另有 `[valid_start, valid_end)`。比较修订时固定相同目标有效时刻，不能用两个不同未来时刻的值制造“预报改变”。SPC 区域概率、CPC 季节分类、TAF 变化组及 P-ETSS 分位/超越概率各保留原支持；不直接当通用站点小时概率。

确定性预报经开发集校准后可以成为概率基线，但必须标为“基于业务预报的校准概率”。GEFS 抽样两成员不能代替完整成员分布；HEFS 集合频率也需要成员权重及目标匹配。

### 4.3 多模态保留原生数据

原始数组/产品与可视化图片分层保存。卫星、雷达、SAR 和摄像头提供原生视觉；由表格重绘的曲线或地图只是同一事实的另一种表示。任何分辨率降采样、色标、插值、单位转换和缺测遮罩均写入渲染配置。

允许三种公平比较：原生证据接口、相同合法内容的结构化接口、替换感知或状态的特权诊断。结构化对照不能偷用未来标签或由标签定义的裁剪区。若数值输入已经包含图像全部有关信息，多模态增量可以为零；这是应测量的结果。

### 4.4 现成 benchmark 的具体位置

| 资料 | 复用什么 | 不继承为什么 |
| --- | --- | --- |
| EWB/ExEBench | 事件检索、地区/日期、已有气象字段和读取方法 | 案例条目数不等于独立事件数；事后极端筛选不能定义自然监测发生率 |
| SEVIR/TorNet | 雷达序列、作者字段/标签、合理感知基线 | VIL 不等于地面降水；同时刻龙卷标签不等于未来风险 |
| GEOID/其他洪水集 | 前后影像、掩膜、有效区、事件身份 | 外部 test 被研究者看过后只是本项目已暴露材料；负瓦片不证明地区没有洪水 |
| WildfireSpreadTS/TS-SatFire | 原生火场时间序列和已有目标定义 | 无检测不等于熄灭；相邻天不是独立野火 |
| WeatherQA/CyPortQA | 图文格式、已有产品解析和诊断设计 | 自由问答答案不自动成为未来物理结果；WeatherQA 数据文件本轮仍未取得 |
| M4Fog | 在数据可访问后复用海雾时空 cube/任务 | 目前代码可访问不等于原始数据已可用 |

数字预报、原生科学数据、事件目录、派生 benchmark、数据平台分别登记来源关系。GEE 可以是构建后端，但不是独立观测源；`filterDate` 不构成数据库的历史可见性快照。本轮没有使用 GEE 认证数据，也不把它作为主栈唯一访问途径。

## 5. 从原始数据到任务的完整流水线

### 5.1 数据层与核心对象

```text
原始字节与回执
  -> 产品/版本/单位/时空支持/质量解析
  -> 规范事实 + 来源依赖图
  -> 父事件分组与暴露登记
  -> 固定未来目标 + 合法证据到达/查询目录
  -> 公开任务包 / 私有结果包
  -> 有预算的离线回放与提交日志
  -> 自动结果结算 + 分组统计
```

| 对象 | 必须保留的字段 |
| --- | --- |
| RawAsset | provider、product、version、URL/请求、capture time、SHA256、完整/片段状态、使用条款与引用 |
| FactRevision | entity、variable、原值/标准值、unit/datum、支持窗口、空间范围、QC、source locator、revision |
| Availability | observed/valid time、init/issue time、processing time、可证明发布时刻、first_seen、delivery time、可见性类别 |
| PresentationAsset | 上游事实集合、native/derived 类型、渲染/裁剪配置、资产哈希 |
| PhysicalEventGroup | 父气旋/风暴/流域过程/火场、相关子灾种、跨区链接、分组依据与不确定性 |
| ForecastTarget | hazard/subtype、entity、variable、unit/datum、固定 `[T1,T2)` 或 T、聚合、阈值、准备截止 D、结果类型/质量政策 |
| Submission | target、外部时钟、概率/数值、已读证据引用、决定、资源与延迟日志 |
| Settlement | outcome_version、正/负/未结算、来源覆盖分母、质量原因、规则版本；不得进入模型输入 |

父事件图、资产复用图、来源依赖图是三张不同的图。多个来源属于 NOAA 不代表全部事件都应合并；同一次风暴跨多个灾种则需要防止切分泄漏。

### 5.2 固定未来目标与可见性

在 episode 创建时固定实体、范围、窗口、阈值和准备截止，初始时刻必须早于待预测的未来支持。随后“最新预报”改变的是对该目标的认识，目标本身不滚动。例如对同一机场明天 06:00-09:00 UTC 的低能见度窗口，多次提交始终针对这三个小时。

可见性分为三套独立队列：

- `verified_historical`：有当时版本/公开时间证据的历史回放。
- `archive_controlled`：使用冻结历史数据和明确人工设定的交付时间；能够研究受控机制，不能宣称完整复现了当年信息环境。
- `prospective_first_seen`：前瞻捕获，记录本系统首次见到版本的时间，等待未来结果；first_seen 不是全球首次公开证明。

现在下载的 GFS +6h、历史 METAR 和事后最佳路径均是可行性材料；日期在过去本身不建立历史 as-of。先固定前瞻站点/时次再捕获滚动数据，可减少事后反向选择，也避免 NWPS/HEFS/航空产品过期。

### 5.3 自动结算规则必须按目标类型区分

O、P、R 是结果身份，不是质量排名。第一份蓝图的 A 在新 schema 中统一为 P：分析/遥感/融合/专家产品。未来 USDM 等级、MESH 和 best track 属于 P；事件报告属于 R；站点观测属于 O。分榜报告，不能混成一个“天气真实准确率”。

| 目标类型 | 正例如何成立 | 负例或未结算如何处理 |
| --- | --- | --- |
| 未来点值 | 规定时刻/明确容差内合格观测越阈 | 缺目标值即未结算，不默认插值 |
| 窗内任一时刻越阈 | 合格观测中出现越阈；目标须声明是规定采样的最大值还是连续过程 | 若缺口可能隐藏越阈，则负例不能成立；采样不足保留原因 |
| 累计雨雪 | 完整累计支持或有可证明下界超过阈值 | 时间窗、重置或重叠无法确定时未结算；不能凭局部时段最大值拼累计 |
| 持续热浪/寒潮/浓雾 | 达到冻结持续长度与每段条件 | 一次越阈不足；缺测需按持续目标规则处理 |
| 未来产品版次 | 指定版次及合格区域内值/类别满足阈值 | 产品失效/无覆盖不是正常类；保留分析产品身份 |
| 未来报告 | 冻结截止版本内有满足标准的登记报告 | 完整报告提取中无记录只支持“无该类登记报告”，不支持物理无灾 |
| 未来合格遥感观测 | 在预先约定的时间窗内选择首个符合固定覆盖/QC规则的观测 | 窗内无合格观测即未结算，不根据火势/洪水结果向后无限找图 |

无需新增逐题人工判题。标签来自冻结程序与既有观测/产品/报告，规则不成立时输出未结算。上游 USDM、灾害调查等可能含专家工作，应如实披露；这与本项目不依赖人工逐题复核并不矛盾。自由文本解释可保留用于阅读，但不交给 LLM judge 作为主结果评分依据。

### 5.4 公私隔离及来源依赖

公开目录仅包含当时允许查询的资产元数据；未读值、私有结果、最小充分证书、未来到达表、标签生成的区域、隐藏正例比例不得泄漏。回放运行器要验证实际文件与工具权限，字段白名单本身不等于进程隔离。

同一原始站报经 GHCNh、IEM、另一个 benchmark 出现时，按上游规范事实标记相关；NHC 预报与 HURDAT2 保留同机构关系。处理同源重复时，不硬性要求重复阅读前后概率完全不变：重新读图可能修复感知错误。实验要区分“没有新增外部信息”与“模型从旧表示中首次正确提取信息”。

## 6. 抽样、地域和规模

### 6.1 两套队列保持不同统计含义

**自然监测队列**按预注册地点、季节和时次建窗，随后等待结果。保留普通天气、近阈值、高风险未发生、真实极端、缺测与未结算状态。概率校准、误报和研究情景价值主要在这一队列报告。

**配对诊断队列**可以富集极端、相似难负例与跨版本事件，对同一目标施加来源重复、旧版回放、延迟、缺失及状态修复条件。配对共享事件、结果和资源设定，用于识别机制。平衡抽样发生率不能冒充自然发生率；若使用加权评分，权重必须有明确抽样依据。

NHC 初始总体是“已经被监测的气旋”，火场扩展初始总体是“已经识别的火场”。二者都不是从全年任意地点预测首次生成。两个条件总体要在任务卡和论文中明确。

### 6.2 地域设计

首个完整发布采用“广域站点骨架 + 区域高密度专题模块”。GHCNh/GHCNd/GFS/GEFS 提供广域基础；NEXRAD/GLM/SPC/HRRR/NWPS 提供美国高密度链；MeteoNet、Caravan、HANZE 与不同盆地气旋资料提供可核验的地域补充。通过认证后再纳入 GloFAS/EFAS、IMERG、CAMS、SMAP。

不宣称 16 类在全球均衡覆盖。每类公布地区、年份、台站/流域/火场数、结果身份、产品版本、缺失比例和实际正例。优先增加独立气象过程、不同气候区及弱覆盖地区，而不是重复切同一次著名灾害。

历史范围取“可用预报版本 ∩ 当时合法证据 ∩ 可结算结果”的实际交集，各类不必统一为某一个十年。站点整体是全球产品，不代表本轮 Denver 样例验证了所有国家的数据密度与质量。

### 6.3 规模按独立过程确定

建议先按每类 2-3 个独立开发过程核对来源链，并覆盖正、负、缺测至少三类状态；这是适配验收目标，不是目前已全部达到的事实。日后开发试点尽量取得每类 20-40 个独立组，稀有类不足就如实报告。

完整版本可把 **总计约 500-1,500 个独立过程组、约 1-3 万个可结算监测窗口**作为资源规划区间。它不是发布承诺，也不是按 16 类平均分题的硬配额。最终确认性规模由试点方差、最低有意义增量、类别发生率和聚类功效分析决定；连续干旱/热浪尤其不能用相邻日放大样本量。

在产生窗口、图像切片、预算条件和随机种子前完成父事件切分。灾害跨界、流域上下游及相邻监测时间设置隔离带。已下载看过的 TorNet/GEOID/METAR 开发样例全部进入暴露登记；外部 test 标识不会使它们重新变成本项目的未见测试。

## 7. 任务、novelty 与强基线

### 7.1 三个面板各自回答什么

| 面板 | 评测内容 | 主评分 |
| --- | --- | --- |
| E：证据理解 | 变量/支持/版本/来源依赖、当前事实是否得到支持、合法引用 | 程序判定与原生值/产品标签比较；沿用现有精确证据能力 |
| F：未来风险 | 同一未来目标下，合法增量资料是否改善概率/数值预测 | Brier/log score、校准；数值 MAE/CRPS 等按变量分别报告 |
| D：及时决定 | 公开成本损失与准备截止下，最终决定有多少价值 | 截止时研究情景损失、相对最新业务规则基线的增量，单列资源 |

E 的证据充分性证书不是未来概率的唯一 Gold。F 的概率需要跨独立事件采用 proper scoring rule；没有“每道题唯一正确的 0.83”。D 只有在 F 有合格结果与公开假设时成立，不对现实撤离、关闭道路或调度水库进行无依据因果结算。

新概率协议须规定未提交/超时如何处理，例如固定检查点沿用最后一次合法概率，或使用预注册惩罚；不得通过只保留成功回答提升成绩。科学结果未结算与模型未回答是不同缺失机制，分别报告。

### 7.2 值得建立的三个论文贡献

1. **固定目标的主动预警增量。** 在相同起始专业预报、合法资料池、预算和准备截止下，量化选源、等待和停止对未来结果评分与决定损失的贡献。
2. **来源、表示、版本和状态的机制区分。** 使用自然新观测、同源重发、重绘表示、旧版本及结构化状态修复的配对实验，解释增益或损害来自哪一环。性能差只在明确干预假设下作机制归因，不把所有相关性称为因果。
3. **极端程度 × 信息条件 × 时限的失效边界。** 跨独立过程、灾种与地区测试机制是否可迁移，并区分自然缺口和人工压力条件。

这些是待验证的贡献，不是数据下载完成后自动成立的 novelty。已有文献比较沿用 [RESEARCH_PLAN_CN.md](../v6_active_warning_review_20260911/RESEARCH_PLAN_CN.md) 中的 SIREN、LEAP、AFABench 等邻近工作审查；本轮未重新进行一轮完整文献检索。投稿前需再核查最新近邻，并以实际完成的实验范围重写贡献。

### 7.3 必须保留的对照

| 对照 | 为什么需要 | 公平约束 |
| --- | --- | --- |
| 气候态/持续性/简单外推 | 证明极端预测超过廉价时序规律 | 仅用开发侧估计与当时合法历史 |
| 起始业务预报与最新合法业务预报 | 分开测量获取更新与超越业务系统的价值 | 主比较含最新版本，不能让 LLM 独占更新 |
| 固定轮询、规则选源、贪心信息价值 | 判断 Agent 规划是否有额外价值 | 相同预测器、资料目录及预算 |
| 预算允许的并行全读 | 检验是否实际上不需要复杂主动策略 | 真实能够按时读完就作为普通基线；超限只作特权诊断 |
| 同预测器主动获取 vs 固定获取 | 隔离获取策略贡献 | 输入表示、融合与决策规则相同 |
| 原生图像 vs 同源结构化事实 | 判断感知瓶颈和视觉信息增量 | 不增加未授权数值、未来标签或标签生成区域 |
| 依赖感知的融合/去重基线 | 面对 LEAP 等近邻提出足够强的比较 | 保留相关源，不能把每张卡都当独立证据 |
| 状态修复、事实替换、决定替换 | 定位多阶段错误和交互 | 特权诊断单列，不参加普通系统排名 |

预算分别报告查询次数、字节、token、模型时间和端到端延迟；除非预注册一致换算依据，不把它们和天气损失任意相加。4 张 H100 可在数据/协议冻结后并行跑模型或配对条件，复用相同事件分配与随机种子，记录跨作业资源争用。当前样例工作是网络读取和 CPU 解码，本轮没有 GPU 任务或模型调用。

### 7.4 准备截止和评分的两个重要细节

如果等待免费、任何截止前行动效果相同、等待不影响执行，那么等到截止再决定可以复制早期行动，提前承诺没有内在优势。首版按多个公开截止评估，并包含等待至截止的基线；研究真正“何时行动”时另立准备时长/效果/成本合同，不通过人为拖慢普通读取来制造优势。

对相同事件定义 `Delta_Brier = Brier(latest_baseline) - Brier(system)`、`Delta_J = loss(latest_baseline) - loss(system)`，正值代表改善。置信区间按父事件/连续过程聚类，而非按图片或调用抽样。O/P/R、不同目标支持和灾种先分别报告，再作预登记宏平均；不同单位的原始误差不直接相加。无法结算和不合法查询的分母同时公布。

## 8. 全周期实施与验收

没有硬截止日期，仍采用约 12 周的首轮节奏，并允许前瞻积累覆盖所需季节后继续扩展。以下是通向完整 benchmark 的工作包；16 类始终在总设计和覆盖台账中，某一类的接入先后不改变整体范围。

| 工作包 | 大致节奏 | 交付物 | 验收条件 |
| --- | --- | --- | --- |
| A 来源与合同冻结 | 第 1-2 周；本轮样例验证为其基础 | 来源版本/条款卡、16 类 target schema、缺口表、解码器 | 主用来源有真样例、单位/支持/QC 明确；条件来源不冒充完成 |
| B 构建与自动结算 | 第 2-4 周 | 公私数据包、事件分组/暴露表、E/F/D 合同、前瞻捕获 | 每个准入子类有可重算正/负/未结算路径；时间与泄漏审计通过 |
| C 分层开发与机制试点 | 第 4-7 周 | 强基线、同预测器获取实验、同源/状态/表示干预 | 给出正/零/负增量及区间；发现协议问题只在开发集修正 |
| D 规模与确认性冻结 | 第 7-10 周 | 功效/分层抽样方案、未见组冻结、模型/预算预注册 | 所有确认性选择在查看测试结果前完成；保留稀有类不足说明 |
| E 前瞻结算与论文发布 | 第 10-12 周及后续 | 原始提交、最终结果、数据卡、回放器、来源/覆盖/公平性报告 | 结论严格对应合格子类/地区；有复现入口和未结算分母 |

工程依赖按“能先验证协议的链”安排即可：已有 NHC/水文连接适合启动数值闭环，温度/能见度/冬季站报适合迁移，强对流、海岸、干旱和火场时序继续按各自语义门槛接入。最终产物应是共享框架下的多灾种 benchmark，而不是把首个工程链的完成度推广到全部 16 类。
