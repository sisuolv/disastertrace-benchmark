# 下一轮查询接口与机制验证建议

状态：本轮结果驱动的开发建议，尚未启动新的模型实验。本轮 288 次正式请求和两个兼容性名额已用完；旧回复、失败、动作和损失保留。

## 为什么需要这一轮

真实正式回复的合法率为 71/288。192 次不满足输出结构，另有 25 次不能直接解析为 JSON。最常见错误组合是 `forecast_handles,queries`（126 次），另有 `forecasts,queries`（21 次）及其他别名。原请求的系统消息确实明确给出了 `query_order`，因此不能把错误说成“系统从未告诉模型字段名”；输入目录叫 `queries` 与输出叫 `query_order` 是否诱发混淆，需要后续对照，当前没有因果证据。

71 次合法输出中，58 次不查询、13 次按原目录顺序选择全部三个候选，没有严格子集选择或重排。所有 288 次决策各有三个候选，每个候选服务两个当时目标，其标示费用、延迟及服务目标数量相同。相同费用不意味着相同预测信息；这组结果也不能证明没有有用的选择空间。

39 个合法选择的句柄引用对应 38 个完成的来源请求，不能把“模型选择”直接当作“取得了正确资料”。其中 37 个回执为产品事实，1 个为订正时间顺序无法证明。完整只读依据在 `SELECTOR_BEHAVIOR_DIAGNOSTIC.json`，没有读取未来标签或重放策略。

## 执行顺序与出口

| 顺序 | 实施内容 | 可放行的证据 |
|---|---|---|
| 1 | 对照本轮正式结果、原始请求、选择、取得资料及特征消费，核查动作是否存在可区分的信息作用 | 完整机会分母，合法/非法动作分层，实际取得和实际消费分开；不选择最有利日期 |
| 2 | 在新版本接口增加供应方的 strict JSON schema；保留两个原输出键，程序预测场景明确 `forecast_handles` 必须为空 | 离线运输、空选择、重复/未知句柄、额外字段、长度截断、拒答及失败记账测试；原格式解析器仍拒绝错误 |
| 3 | 固定实际模型 ID、生成参数、输出模式及 schema，建立新执行身份和完整来源绑定 | 真实天气形状提示的有界兼容性检查；事先固定通过门槛，失败原样计入，不事后重命名字段 |
| 4 | 在同一已暴露开发日历、新身份下比较受约束接口与同等资源程序方法 | 相同预测时点、共同专业信息、同一冻结预测器和结果掩膜；新实验与旧自由输出分轨 |
| 5 | 检查任务是否能区分强覆盖规则、强批量共享与模型选择；再决定是否扩展模型或独立过程 | 选择差异进入合法资料、特征、概率及损失；按正例/负例、地区和过程报告，不只报均值 |

第二个兼容性名额已在相同合成题上验证供应方 JSON schema 模式，HTTP、结构与选择检查通过。它只证明一个合成请求可用，不能替代步骤 2、3，不能声称已经完成真实天气接口修复。

## 接口应固定的细节

- schema 只约束结构与合法句柄，不包含未来标签、正确查询或推荐答案。候选枚举来自当次合法公开目录。
- 输出使用 `query_order` 数组；是否允许空数组、重复项、最大长度和未知字段必须与实际消费合同一致。供应方不支持的 schema 关键字由离线消费者检查，不能静默放宽。
- 程序预测的固定时点继续由程序驱动。保留兼容键 `forecast_handles` 时，应明确其为空；若以后删除该键，需要独立版本与独立注册，不混用评分合同。
- 无效/截断/拒答/HTTP 失败不触发免费的重试或答案改写，已消耗 token、时延及全体机会继续记账。
- provider 未公开 checkpoint revision 时如实登记；不把模型显示名当作本地权重 hash。远程推理和本地 H100 条件分别记录。
