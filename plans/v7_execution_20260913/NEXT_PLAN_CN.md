# v7 执行后的整体计划修订与下一阶段

本文件延续 `../v7_integrated_20260913/INTEGRATED_PLAN_CN.md`，保留 v7、C1/C2/C3、
六组16类灾害以及 X00--X09。它根据本轮实际下载、校准、CPU与GPU结果补充出口门槛，
不另起研究方向。实际完成量以 `FINAL_REPORT_CN.md` 和各验证 JSON 为准。

## 1. 本轮结果如何改变优先级

### 1.1 先解决可测性，再增加调用

旧主日历 27,216 次预测器调用仅产生146个不同于起始基线的概率，只有10次显式 override。
固定候选强制采用的结果仍有正有负，不能把少修订全部归因于动作开关或 wrapper。

新固定证据实验另外发现了填值示例的歧义：原示例、替换示例都成为固定输出。
这批使用普通 `model.generate`，没有 JSON const/enum 或 guided decoding 把概率锁死。
去掉示例后，模型仍大量复制共同基线并混淆“有证据”和“命题为真”。因此：

1. 新接口不再给出带具体答案的 JSON 样例；实际字段有严格类型及真值定义。
2. E 的真/假/未知/冲突与 F 的事件概率分别定义、分别判分。
3. 优先比较 E-only、F-only；联合 E/F 作为明确的对照，不能默认联合输出更好。
4. 例子敏感性、低格式错误率、E 正确率、F 增益、实际费用各自报告。
5. 不将修复有歧义的提示词包装成 C2 创新，也不将弱提示造成的基线退化当取证价值。

本轮显式真值下 E-only 为127/144，联合 E/F 为114/144。Front 的 fixed-one 条件分别
17/24、4/24，说明“读到一条否定报告，另一条未读”这个存在量词边界值得继续核验。
它仍是已暴露材料上的任务格式诊断；不能把144条相关条件当144次独立天气过程。

### 1.2 强共同基线已经能实际构建

本轮真实获取了 Front 前期原生 TAF/METAR，并拟合与 Bay 日期匹配、较长训练窗口
两种本地 R 映射。旧 January 日历、阈值和共同结果掩膜保留。

2024 年完整日历中，更长本地共同基线优于原 Bay 迁移版本，但三套映射在加入全部
登记邻站资料后都没有改善。两个 December 检查窗的1km事件又都没有正例。
因此下一轮必须同时保留地域匹配、训练长度、稀有事件覆盖及普通日历四个维度，
不能只挑低 Brier 的静态表，也不能声称“更少回退就是更好校准”。

2026 年的本地控制也已完成，单独使用2025年12月资料。结果相反：matched/expanded
的共同基线都比原 Bay 迁移版本差。matched 全读略好于自己的共同基线，仍差于 Bay；
expanded 全读更差。pooled回退从418降至32并没有降低损失。
两年度十二格及训练/检查正例支持已汇总为 `audit/two_year_summary/SUMMARY.json`，
绑定22个来源哈希。全部日历已经暴露，只用于开发，不按这些结果事后选主银行。

## 3. 接下来依次执行的工作包

### W2 收尾：把当前修复变成新冻结

- 现有 `monitoring_v1` 和全部旧运行保持原样。
- 新 `monitoring_fixed_v1` 已支持固定证据、点/区间、概率/标量、版本状态与Brier/MAE。
- 当前工作副本已修复目标时间越界、相同基线身份改变数值、persistent在途候选和截止边界；
  GPU运行继续使用各自冻结副本，旧结果不会因修复而改写。
- 后续补查还阻止了目标合法更新时间上界后的共同基线更新生效，以及派生资料把可用时间写到父资料
  之前。迟到基线保留拒绝日志；partial-window可以保留窗口开始前已发布的基线。
- 下一次执行须冻结更新后的源码与明确提示合同；恢复、失败回退、单位与目标错配继续验收。
- 这仍不意味着旧自适应引擎的所有selector、资源分额及日志都已迁移到连续量类型。
- 通用C2仍须显式桥接：新bundle中的 `bounded_error/policy_after_query` 与旧支持引擎的
  `bounded_measurement/policy` 不是可直接互换的枚举；当前 `visible_e_status` 只计算航空
  邻站存在命题。温度接口通过不意味着通用支持集合和联合可达性已接入该新类型。
- `paired_scores` 只核对完整机会分母、输出类型与损失，不携带预测提交时间。正式监测
  评分须先绑定“机会—截止—合法状态回放—有效预测”清单，不能直接给任意预测表贴上
  未来预测资格。离线数值工程表继续单独命名。
- `heads.py` 已新增独立E-only/F-only/joint调用合同与105项CPU检查。下一批冻结使用该
  接口；准备好的未发送消息绑定不算模型输出，也不把旧joint回答拆成独立F-only实验。

### W3 下一步：真正区分资料、理解与预测

先使用本轮固定输入与明确合同，预登记更长且未用于提示开发的日期/过程。
E-only 与 F-only 都必须真实运行，不用一次联合回答事后拆成两个独立推理过程。

1. 固定证据比较冻结统计预测器与一个明确配置的LLM。
2. 固定预测器比较共同资料、一个合法补证、合法批量全读。
3. 对存在量词、未读/缺报、删失阈值、真实版本替代分别报告E混淆，而非只给总正确率。
4. 统计F增益时始终附共同基线；区分“修复自己在空证据时引入的0.5”与超过基线。
5. 再加入自然完整TAF的条件段/覆盖、缺槽、订正任务，避免C2只剩一个简单邻站存在命题。

增加样本基于预先声明的日期/来源/合同覆盖。不能按LLM获胜日期、E出错题或未来正例
选择确认集。已看过的本轮材料可用于修复，但不再作为独立确认。

### W1B/W1C：第二领域按资格择先，不互相替代

温度先完成连续历史窗口与清晰的版本/补证候选，再决定能否形成非平凡E和主动会话。
水文继续查官方物理量/时间支持证据；如果合同可核准，再运行两版本对同一目标的
连续量工程链。否则保留技术配对，不给分或挪用日流量含义。

专业洪水阈值缺失时，可提出明确R轨统计极端或连续流量任务；统计阈值需要独立历史
估计并提前冻结，不能冒充官方警戒水位。水位和流量不通过任意常数换算。

### W4：只有实际机制条件成立后再跑资源实验

先固定同一廉价 selector，做 `fixed_quota/global_budget × target_private/session_shared`。
预测器、机会、共同基线、允许动作和预算向量全部一致，私有上下文须隔离。
再在相同 global/shared 条件下比较强启发式与LLM，不把选择器类型混进2×2因素。

费用以真实获取/解码/推理测量为依据；当前小站网批量下载便宜的事实必须保留。
若全读便宜且足够，就把它作为强对手，允许主动策略没有收益。不能抬高API费用制造C1。
固定快照资料响应和有真实延迟/版本更新的会话动作响应分表。后者固定初始资源、外部
档案和continuation policy，允许后续动作对合法状态作出不同响应。

在真实的小会话上显式接通provider与旧 `public_support/solve_joint`：核对原始可见
事实及误差边界转换、不同目标的支持命题、同一预算/并发/截止的联合可行见证。
单目标可达只是松弛参照；不能让每个目标各用一次完整预算，再把它们相加作为失败分母。
先用小图精确求解与完整见证复放，大图明确报告可行下界和参照上界。

### W5：独立确认与分级发布

方法和基线冻结后，按父天气过程/保守时空块分组；留出跨月、跨季节/地区验证。
purge覆盖输入回看、提前量及结果窗，多站、多阈值、seed不增加独立过程数。
全机会、共同结果掩膜、缺失原因和敏感性界继续报告；不能因共同掩膜就声称总体无偏。

工程版可以先发布可重放的真实数据、接口和负结果。机制版要求强对照和独立过程支持；
完整v7仍要求原16灾种及两类不同物理过程的原生多模态门槛逐项通过。

## 4. novelty 保留什么、现在不声称什么

继续押注三个可检验问题：

- C1：共同专业预报持续更新时，资源约束下哪些补证/修订产生超出强基线的增量？
- C2：合法证据支持集合、同一预算的联合可达性，与模型的理解和未来预测如何分离？
- C3：上述合同和规律能否跨真实过程、来源和时间尺度复现？

本轮验证了若干组件与固定快照诊断，通过数据、日志、输入冻结和实际推理暴露了
会制造虚假增益的具体问题。它没有证明LLM总体更好、所有候选均符合完整novelty，
也没有用格式修复代替机制创新。下一阶段不增加新的核心概念，补的是强对照、物理
合同和独立证据。

整体节奏仍是先1--2周开发与路线门槛，再按约12周及以后扩展；以验证出口决定放行，
不把周数、GPU数或下载体量当完成承诺。本轮之后不必等待未来灾害，也不需要人工逐题标注。
