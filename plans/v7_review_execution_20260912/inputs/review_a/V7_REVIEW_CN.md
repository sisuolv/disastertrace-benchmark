## 结论

**有条件通过研究设计评审，建议保持 v7 的 C1/C2/C3、X00–X09、P0–P7 与六组16类范围进入实施；不应据此承诺完整可执行性、模型正增量或论文新颖性已得到保证。**

工程上已经有旧闭环、读取器、来源合同和负结果，可以复用。v7 的新价值在持续变化的共同专业参照下，评价跨目标补证与有版本作用域的修订。最重要的前置条件仍未完成：首个真实区域中的完整基线、可补证且与未来目标对应的E合同，以及权限、成本和覆盖状态的可执行定义。[S01,S04,S07]

本轮读取了 v7 主计划、工程附录、16类合同、实验矩阵、近邻对照和新授权来源报告，并核对分支提交。补读 FutureSim 正文、EarthVerse/SentinelBench/SIREN/Obshazard 的相关章节及扩展 Learning-to-Defer 文献。没有运行用户的3项旧回归、没有完整重跑用户数据解码、没有修改或推送仓库、没有启动采集或GPU。

附带8个**纯合成逻辑反例**实际执行通过。它们不导入用户项目，不测试尚不存在的 monitoring_v1，不是8个已确认的仓库bug，也不是新的天气样本。作用是将协议解释风险转成可复查的逻辑。

## v7 已经修正、无需再反复提出为“缺失”的部分

- 所有方法共享持续更新强基线，不用“查到新版”充当额外智能。
- FOLLOW/OVERRIDE，base-bound/persistent 两协议分开，并承认自动失效是系统规则。
- 固定日历机会、共同结果mask、失败/超时回退、P/R与参考类型分离。
- 区分获取共享、批量缓存和联合多目标推理；保留强廉价对手。
- E有限支持/可达性只用于限定事实，不证明未来不可预测，不输出逐题正确概率。
- 16类和子类分级准入，真实原生多模态单独验收；新授权数据不等于新任务。
- 只增加 monitoring_v1，保留历史结果；单会话writer、本地状态与封存AFS的设计明确。

这些是已有计划的优点，而不是本次新发明的建议。[S01,S03,S04]

### V7-R01｜扩展 C1 的近邻核查，不把多问题修订、委托与补证本身当首次

**优先级：** `P0_scientific_contract`。**位置：** RELATED_WORK_MATRIX_CN.md §1；OVERALL_PLAN_CN.md §3。

**v7已经写明：** v7 对 FutureSim 主要读取 README/history，对 Learning to Defer 主要读取 ICML 2020 摘要。它已经承认 AFA、动态监测与证据干预并非独创。

**本次判断：** 本轮进一步读到 FutureSim 正文明确允许选择哪些问题何时修订，并对全部问题评分。DeCCaF 已有工作容量约束下的全局委托；Expert-Conditional Advice 已联合考虑专家选择与额外信息；Online L2D 已考虑动态可用性/可靠性。仅以“多目标+信息获取+保持或覆盖”解释 C1 不够。

**反例或风险场景：** 把 v7 简化为每题只有一轮、无基线变化、无来源支持关系后，会非常接近已有 AFA/委托问题；仅换成天气数据不足以建立新算法贡献。

**建议修订：** 保持 C1/C2/C3，不另换项目。C1 明确研究外部专业基线持续更新时，带版本作用域的预测覆盖与共享证据分配如何相互作用；增加有限容量的廉价全局修订/委托对手。C2 以真实、可核验的 E–F 成对数据区分一般扰动。

**验收：** 逐项写清已读近邻的正面能力、未核查部分、具体剩余差异；X01/X02 至少一个对照能排除普通批量缓存/委托解释。不要求重现所有论文，不声称系统查新完毕。

依据：S01, S02, W01, W06, W07, W08。

### V7-R02｜SPC 更新的有效窗会变，不能自动成为同一固定目标的新基线

**优先级：** `P0_before_P_track`。**位置：** HAZARD_DATA_PLAN_CN.md H03–H05；OVERALL_PLAN_CN.md §4、§7。

**v7已经写明：** v7 要求固定未来目标，同时将 SPC 原生有效窗口上的预报作为 P 轨候选。

**本次判断：** SPC 官方索引说明早晨 Day 1 与后续发布具有不同的有效起点。因此只按同日、同点、同截止终点关联“最新版”仍可能换掉所预测的事件。

**反例或风险场景：** 06Z 产品针对 12Z 至次日12Z；20Z 产品针对20Z至次日12Z。两者的概率变化不等于同一24小时事件风险变化。

**建议修订：** TargetSpec 包含完整起止窗、空间半径、事件定义和报告政策。只在支持完全兼容时替换基线；原生窗口改变则创建新 target，或留在明确的条件/剩余窗口研究轨。不得把长窗概率直接裁成短窗概率。

**验收：** 对同结束、不同开始窗口的误连接有必败测试；未来预测截止须与结果窗口的关系明确。未找到同目标基线时使用已声明的 fallback/R 轨，不改目标来凑 P 轨。

依据：S03, W09, W10。

### V7-R03｜关闭共享的控制组需要约束 selector，而不只是 predictor 的文件权限

**优先级：** `P0_before_X01`。**位置：** OVERALL_PLAN_CN.md X01、§7.4；monitoring_optimization/PLAN_CN.md §7；EXPERIMENT_MATRIX.json X01。

**v7已经写明：** v7 已分 B00/B01/B10/B11，并将禁共享明确称为机制消融；真正强对手允许合理批量缓存。

**本次判断：** 尚需定义 global selector 是否可读取各目标私有值、私有摘要及由这些值产生的预测。即使 B 的 predictor 看不到 A 的文件，selector 的动作/理由仍能传递 A 的信息。

**反例或风险场景：** selector 看到 A 的私有风险位1后对 B 发 review_now，看到0则 wait；B仅从动作即可恢复这个位。

**建议修订：** 第一版严格隔离实验用共同公开元数据驱动 selector，私有内容保留在局部状态；或将消融精确命名为“限制直接证据复用”，承认全局知识仍可能传播。记录共享文件的首个支付主体、固定分额中的共享费用归属、派生资产权利继承。

**验收：** 冻结每种 view 的字段与可达信息；对私有输入变更做跨目标输出审计；不将无法保证的信息不共享作为已经隔离的因果因素。

依据：S01, S04, S05。

### V7-R04｜基线身份、过期、同目标多个机会和覆盖有效期需要可执行定义

**优先级：** `P0_before_state_machine`。**位置：** OVERALL_PLAN_CN.md §7.1–7.3；monitoring_optimization/PLAN_CN.md §6.2–6.3。

**v7已经写明：** v7 已规定 base-bound 和 persistent 两轨，已规定同刻事件顺序、NO_CHANGE≠FOLLOW，以及旧快照费用保留。

**本次判断：** “影响目标的基线内容版本”尚需冻结成判定函数。仅用原文件哈希会被无关修改触发；仅用概率值又可能忽略条件段、校准器或合法性变化。还需说明旧基线过了有效期却无新版时如何进入 fallback。

**反例或风险场景：** 一份 TAF 修改了另一个时段，整文件 hash 变化不应使所有目标覆盖失效；同 target 在12和15两个机会，12封存不能关闭15的机会。

**建议修订：** 区分 product_revision_id、target_base_context_hash、validity/freshness、calibrator_version。定义 expire/update/late candidate 表及 target–opportunity–action 独立生命期。未来结果可作为更晚合法观测，但评价器分数反馈不自动给策略。

**验收：** 同概率但相关语义变化、无关目标更新、相同内容重发、基线过期、在途跨更新、同刻 cutoff、多机会共 target 均有确定唯一行为。D 动作不可因概率 FOLLOW 自动被抹除。

依据：S01, S04。

### V7-R05｜C2 必须绑定真实 E 谓词和 F 目标，而非只保留独立面积示例

**优先级：** `P0_before_C2_claim`。**位置：** OVERALL_PLAN_CN.md §6；EXPERIMENT_MATRIX.json X03–X05；HAZARD_DATA_PLAN_CN.md H15。

**v7已经写明：** v7 已正确限制 Y(E)、小池可达路径与事后 oracle；明确 E不足不等于F不可预测，E充分不等于停止最优。

**本次判断：** 首个机场场景的具体 E 谓词、真实查询池和同一 F 目标的绑定仍需构建。只在人工面积例题证明充分性，再在另一批数值天气上报预测分数，不足以支撑 C2。

**反例或风险场景：** 同一公开有限合同的约束交集为空时，all([]) 会同时为“均满足”和“均不满足”返回真；冲突不能误判成充分。

**建议修订：** 先选择一个真实、可复算的额外证据命题，例如预登记邻站槽位是否存在合格低能见度报告；记录当前支持、实际可达的补证、同时间输入下的下一未来风险。对空集合显式 inconsistency，不使用缺少依据的物理上限。

**验收：** 交付一份 source-bound E–query–F 成对规格；覆盖当前充分/未读可补/缺失不可补/冲突四状态；固定预测器报告补证前后的支持与损失，不强迫二者正相关。

依据：S01, S03, S05。

### V7-R06｜资源向量、共享支付与非退化性需要具体实验配置

**优先级：** `P0_before_resource_experiments`。**位置：** OVERALL_PLAN_CN.md §7.4、X00/X01/X07；monitoring_optimization/PLAN_CN.md §6.3。

**v7已经写明：** v7 已要求 spent+reserved、费用向量、实测合理预算、不紧预算、批量接口与缓存公平。

**本次判断：** 费用向量本身还不是可执行约束。需要明确哪些维度是硬上限、哪些只记录、免费预报推送和固定 tick 的解析计算如何归属；固定目标预算下共享获取如何扣费。

**反例或风险场景：** 两个目标预算各1，共享文件成本2；若任意目标均不得支付则不可获取，若联合分摊则可获取。仅写“总预算相同”不能确定结果。

**建议修订：** 冻结每个实验 profile 的 request/byte/token/compute/reserve 限额与计费函数；共同服务成本单报。以真实数据检查基础、单源、固定组合、全读的信息差异，保留无增量/全部可廉价读取的会话。

**验收：** 相同动作与回执在不同策略 worker 上计费相同；无隐藏 oracle；资源不紧条件下廉价全读合法。预算只用开发成本决定，不用确认集胜负调整。

依据：S01, S04, S05。

### V7-R07｜自动失效的直接作用与策略适应作用要分别估计

**优先级：** `P1_before_X02_interpretation`。**位置：** OVERALL_PLAN_CN.md §7.3、X02、§10.1。

**v7已经写明：** v7 已明说不能把 base-bound 自动回退收益归给模型，并要求两轨单独运行。

**本次判断：** 仅比较两套独立完整运行，仍然混合 wrapper规则、调度适应和预测候选变化；触发次数不能量化协议造成的分数变化。

**反例或风险场景：** 同一原始候选0.9，在新基线0.1、结果0时，base-bound拒绝候选而persistent接受，Brier差0.8完全不需要新增模型推理。

**建议修订：** 保存激活前的所有原始候选及成本。对固定候选/动作轨迹进行两种 wrapper 重评分，称受控直接比较；另做两轨完整重跑，称包含策略适应的总效果。两者不相加为总因果百分比。

**验收：** X02 同时输出 attempted/accepted/expired/canceled/late，固定候选差值与完整重跑差值，并将原始模型质量和系统回退结果分开。

依据：S01, S04, S05。

### V7-R08｜G_plus/G_minus 是事后损失分解，不是逐次概率合理性或不伤害保证

**优先级：** `P1_before_probability_claims`。**位置：** OVERALL_PLAN_CN.md §10.1、HYP2；EXPERIMENT_MATRIX.json X02。

**v7已经写明：** v7 正确定义了总体 Delta=G_plus-G_minus，且不只评价改写的子集。

**本次判断：** 还应在解释合同写明：一次改写接近已发生结果，不证明它提高真实条件概率估计或期望风险。

**反例或风险场景：** 真实事件概率0.2，基线0.2，改写0.4。遇到结果1时实现Brier改善0.28，但期望Brier从0.16恶化到0.20。

**建议修订：** 称 realized loss improvement/degradation；在独立块上评净损失、校准、改写覆盖、预登记非劣效界。不得要求每一项改写都赢，不用测试Y训练门控。

**验收：** 主结论没有把单次G_plus解释为合理概率更新；所有训练/校准/门控选择与确认组隔离。

依据：S01, S05。

### V7-R09｜共同结果掩膜保证可比性，不识别缺测总体上的收益

**优先级：** `P1_before_population_claims`。**位置：** OVERALL_PLAN_CN.md §10.1–10.2；EXPERIMENT_MATRIX.json X00/X06/X08。

**v7已经写明：** v7 保留全机会表、共同 mask、缺口原因和质量状态，这是正确设计。

**本次判断：** 若结果缺失与天气强度、站点、传感器或QC有关，可结算子集的净收益不能自动外推到完整自然监测总体。块bootstrap不能补出这些结果。

**反例或风险场景：** 90%样本可结算、其中Brier净改善0.01，若剩余改善仅知在[-1,1]，完整总体保守界为[-0.091,0.109]。

**建议修订：** 同时报告P(可结算|公开基线风险、地区、季节、参考类型)；统一QC并做预登记敏感性。无法识别时将主张限定到可结算总体；必要时报告保守界，不伪造标签。

**验收：** 自然总体、完整业务基线子集、可结算子集三种分母清楚；极端缺测风险明确，不自动缺失插值。

依据：S01, S04, S05。

### V7-R10｜同源特征不是天然等信息表示；需核查真正的共同可用性

**优先级：** `P1_before_native_multimodal_claim`。**位置：** OVERALL_PLAN_CN.md §8、X05；monitoring_optimization/PLAN_CN.md §5.2。

**v7已经写明：** v7 已正确要求真实同期图像、处理费用和图外/未来Gold不得作为便宜特征。

**本次判断：** 图像统计、均值和变化特征可能丢掉结构；其与原生图的差异不能自动归因于视觉理解。2024机场日期还须使用当年平台，而不是2026样例。

**反例或风险场景：** 数组[0,2]与[1,1]均值同为1，但是否有像素>=2的答案不同；均值不是该任务的信息充分表示。

**建议修订：** 严格等信息只用于可证明无损转换或限定事实的充分统计；其他比较称同源表示/工具辅助，并报告信息瓶颈。对首条机场数据实际冻结GOES平台、通道、ROI与可用性。

**验收：** 每个X05条件注明原生信息、变换损失、特权程度和计算费用；至少两类不同物理过程的真实多模态链达到完整发布门槛。

依据：S01, S03, S04。

### V7-R11｜保留16类总目标，但将数据配对供给与科学主张分开验收

**优先级：** `P1_before_16_hazard_release`。**位置：** OVERALL_PLAN_CN.md §5、§12–13；HAZARD_DATA_PLAN_CN.md；user_authorized_sources_20260912/README_CN.md。

**v7已经写明：** v7 已有工程、机制、六组、完整16类发布层级，明确新引擎未实现与86条内容不等于86条链。

**本次判断：** 这些正确的等级仍不能保证每类都有足够独立、低延迟、可校准的样本。CMA文档、xBD配准、雷电专业基线、机场罕见正例不是添加schema可解决的问题。

**反例或风险场景：** 一个可解析CMA时次没有同洋盆发行预报，或一个无损伤xBD样例，均不能填补相应主预测链。

**建议修订：** 沿用A0–A5和E/F/D/MM，不另建重复注册表。每个子任务登记实体/统计窗/阈值/原生或校准基线/结果身份/rights/独立块/输入历史。P4可并行，但不能用其名称计数替代P3机制验证。

**验收：** 完整v7达到原§13条件；部分版本准确命名。12–16周仅组织假设，按真实资源和准入证据更新，不写为保交付保证。

依据：S01, S03, S06, S07。

| X05 | 无损等信息与有损同源特征分开；原生图像合格且确实送入模型 |
| X06 | 只在合格合同与固定P/R、参考类型中比较；预算和阈值不得用确认结果选择 |
| X07 | 明确硬预算维度、共享收费、基线失效和target多机会；加入资源不紧/合法全读/总等到D |
| X08 | 结果成熟度、缺测分布和条件总体明确；到期停止收新机会，不等灾害出现再停 |
| X09 | 独立于共享获取；改变联合预测器时不再声称只改变selector |

X01建议把主要估计量单独写清：在同一全局预算、同一共享权限和冻结预测器下，比较廉价全局selector与模型selector的成对损失差。这个差值与“共享相对不共享”的差值、以及2×2交互不是同一个量。

X02建议同时报告固定动作/候选条件下的覆盖规则直接影响，以及完整重跑中的策略适应后影响。后者不减前者来自动声称得到互不重叠的模块贡献；有交互时只能按声明的受控比较解释。

## 新数据处理决定

EM-DAT：保持索引/分层/候选分组，不把event-country数量当独立气象过程，不由目录空白制造负例。  
CMA：原始内容访问成功但物理单位、风平均时长、时区、零值和可选列含义仍要官方合同；同洋盆发行预报另配。  
xBD：目前111.44像素量级残差意味着该组合尚不能进入grounding，不能推出上游哪方必错；需解释官方PNG–TIFF变换，不以确认标签拟合修补。三对样例无损伤正类，不能给出损伤召回。  
三者均不应成为首个机场内核的串行阻塞条件；获取更多这类资产也不能代替检验C1/C2。[S06]

## 关于“保证”

可以通过有限协议测试逐项验证：时间、权限、幂等、版本、预算、输出和结果绑定。数据链可通过实际取样与重建确认。模型是否有正增量、全部灾种样本是否足够、论文主张是否被近邻覆盖和评审认可，不能从规划JSON、文件hash或3项旧解析测试推导。

本次推荐的最小论文证据不是预先要求Agent胜出，而是：至少两个独立过程类型中，真实E缺口与F目标有清楚关联；合理全局共享基线与专业基线完整；协议和模型作用可分；预登记独立块结果能够支持或否定所述交互。完整16类另按现有发布级别验收。

## 反例复现

```bash
python counterexamples.py --output counterexamples_results_reviewer.json
```

8项分别说明：不同未来窗口不可合并、selector可传私有信息、自动reset可制造系统差值、实现收益与期望风险不同、共同mask不识别缺测总体、空可行集的真空真问题、target与机会生命期、同源摘要未必等信息。它们没有验证真实数据质量，不能替代monitoring_v1回归。

## 文献核查增补

FutureSim正文§1/§3明确允许选择问题与修订时刻，并对完整问题集合评分，未预测题给基准分，不能写成仅“预测了才计分”。其日历回放、记忆、检索与未来反馈已经直接邻近v7。v7仍可研究持续外部专业基线、精确传感器目标、共享获取和版本限定覆盖，但需要实验，不是改领域就成立。[W01,C01]

EarthVerse已经有主动证据组织、时间/工具上限和多种证据干预；其轨迹时间/费用列不改变主质量分，而不是“没有预算”。SentinelBench已研究反应时和资源，SIREN已有预警流程，Obshazard已有原生观测与生命周期。v7对于这些重合的承认总体正确。[W02–W05]

DeCCaF给出容量与成本约束下的全局委托；Expert-Conditional Advice研究专家–补充信息的联合决策；Online L2D研究变化中的专家可用性/可靠性。把这三类加入查新和适当强基线即可，不要求一开始重现它们全部训练。其学习一致性结论不能被误用为“v7为了归因而分离selector/predictor接口是错误的”。[W06–W08]
