## EM-DAT：广度索引已可用，时空精度必须保留

输入是用户本机的 `public_emdat_custom_request_2026-09-12_0a227307-4f08-41f6-8766-2a19b092e9c5.xlsx`，6,256,308 字节。原件与工作副本 SHA256 相同，XLSX 内全部成员 CRC 通过。

完整表包含 Natural 10,875 条、Technological 6,147 条，年份范围 2000—2026，`DisNo.` 无重复。本次将 Natural 下的 Flood、Storm、Extreme temperature、Drought、Wildfire 纳入核心天气事件索引，共 8,584 条。另有 503 条湿性滑坡/崩塌等、8 条冰湖溃决保留为条件外围来源，没有加入正式灾种。

`DisNo.` 是带国家代码的记录标识。去掉国家后缀得到 6,863 个事件编号组，仅用于候选分组；这不是已独立确认的 6,863 个物理天气过程，也不是 6,863 个 benchmark 样本。

| --- | ---: | --- | ---: |
| 河流洪水 | 2,031 | 热带气旋 | 1,469 |
| 一般洪水 | 1,446 | 山洪 | 765 |
| 干旱 | 426 | 一般风暴 | 352 |
| 热浪 | 313 | 未明确的恶劣天气 | 310 |
| 寒潮 | 216 | 森林火灾 | 195 |
| 暴风雪/冬季风暴 | 192 | 龙卷风 | 175 |
| 雷电/雷暴混合类别 | 172 | 一般野火 | 110 |
| 严重冬季条件 | 77 | 冰雹 | 53 |

| 沙尘暴 | 20 | 风暴潮 | 10 |

一般风暴、恶劣天气不能强行细分成明确灾种；雷电/雷暴混合类别也不能同时算作已确认的雷暴大风与强雷电。该导出没有补齐全部 16 类的严格标签，例如独立极端降水、强雷电和浓雾仍依赖其他观测来源。

核心记录的日期精度：7,467 条到日、1,068 条到月、49 条仅到年；表中没有精确灾害发生小时或 UTC 时区约定。7,463 条缺少经纬度，1,121 条有取值范围合法的坐标对。坐标合法也不意味着可以代表灾害覆盖范围。

发现并修复了两个实际读取问题：工作表声明 `A1:A1`，但 XML 有 17,023 行（含表头），必须重置 openpyxl 的维度；缺日期/坐标单元格常为 `""`，需转为缺失值。独立 XML 读取再次确认了完整行数、列数、天气筛选数量和缺失统计。

用途约定：EM-DAT 的记录门槛、跨国报告与更新制度会影响覆盖；2026 年导出也不是全年完整数据。不能把目录缺失解释为天气未发生，不能用后补事件记录假装决策截止前已经知道的事实。归一化完整记录保留在本地 `outputs_02/local_data/`。

## CMA：全部年度文件可读，先固定原始字段

输入 `CMABSTdata.rar` 为 RAR5，606,590 字节，包含 `CH1949BST.txt` 至 `CH2025BST.txt`，解压共 2,872,042 字节。使用本地安装的 7-Zip 25.01；压缩包完整性检查、77 个成员的 CRC/长度检查、各气旋头部声明的记录数检查均通过。

- 2,549 个气旋段，74,370 个时次；没有非递增时刻。
- 70,408 个相邻间隔为 6 小时、1,413 个为 3 小时。
- 73,636 行有 6 个字段，734 行有可选第 7 字段；没有丢弃第 7 列。
- 1 个头部缺气旋名称；5,909 行 `wind_raw=0`，尚不将其解释为真实无风。
- 在同一气旋段内按原始时钟精确配对，可得到 +6 小时 71,748 对、+12 小时 69,127 对、+24 小时 63,901 对。

这些时间对高度相关，只证明标签时间窗可以构造，没有直接生成同样数量的正式预测任务。并存气旋会有相同时间戳，连接键必须包括气旋身份，不能只按时刻连接。

保留字段为 `storm_key`、原始头部、`time_raw`、`intensity_code`、`latitude_raw`、`longitude_raw`、`pressure_raw`、`wind_raw`、`optional_wind_raw`。官方格式页 `https://tcdata.typhoon.org.cn/en/zjljsjj_sm.html` 本轮仍返回 HTTP 468，因此暂不把推测的单位/比例/平均时段写入评分合同。原始数据已获得，无需为此重新申请下载授权。

下一次接入预测评分时，应先绑定官方字段文档，然后为同一洋盆、同一气旋补充历史签发预报。CMA 最佳路径是事后分析，不能自动作为历史截止前的实时观测；IBTrACS 中的 CMA 字段也可能来自同一上游，不能据此增加独立证据数。

## xBD：官方样例已到手，但发现空间一致性问题

成功下载了完整 Geotransforms 元数据包，495,061 字节；用户提供的官方 SHA1 `0b3bda08084ac102d8b540261ebbba0094203a2f` 与实测相同，gzip CRC 通过。解析出 22,068 个图像名称对应的地理变换和 CRS。

为验证样例，只读取 Full data `part-aa` 和 Challenge `hold` 的有界前缀，没有下载完整约 51 GB 原生影像档案。选择的三个样例是完整 Florence 灾前/后对中字典序最早的三组，选择发生在查看损伤类别之前，规则保存在 [XBD_SELECTION_02.json](decoded/XBD_SELECTION_02.json)。前缀最先出现的火山影像被排除，不计入极端天气。

| 样例 | 灾前/后影像 | 灾后建筑标注 |
| --- | --- | --- |
| `hurricane-florence_00000006` | 2 张，3×1024×1024 | 114 无损伤 |
| `hurricane-florence_00000009` | 2 张，3×1024×1024 | 116 无损伤、171 未分类 |
| `hurricane-florence_00000010` | 2 张，3×1024×1024 | 56 无损伤、5 未分类 |

六张影像为 `int16`、EPSG:4326，均可完整解码；原生 affine 与官方 Geotransforms 完全一致到检查容差。原生 TIFF 和 Challenge JSON 按官方图像标识匹配，提取文件与压缩前缀内的完整成员逐字节一致。

灾前拍摄时间为 2018-08-23 16:38:58 UTC，传感器 WORLDVIEW03_VNIR；灾后为 2018-09-18 16:32:47 UTC，传感器 GEOEYE01。标签事件为 `hurricane-florence`、类型为 `flooding`，三组属于同一气象过程。这些拍摄日期不证明下载/发布可用时间。

**空间核验没有通过。** 同一 UID 建筑的 `xy` 像素多边形，经 GeoTIFF affine 转为地理坐标后，与标签的 `lng_lat` 多边形不一致。六张影像的单图中位残差约 70—84 像素，最大约 111.44 像素，远超 1 像素检查容差。数据中多边形本身有效，但这不能替代坐标一致性。

因此 `spatial_grounding_admitted=false`、`native_pixel_label_overlay_validated=false`。需要核实原始 PNG 与原生 TIFF 的转换关系、影像重投影/旋转及标签坐标定义；目前不能断言哪一方元数据错误，也不通过对测试标签拟合一个变换来掩盖问题。

损伤类别共有 462 条灾后建筑记录：286 条无损、176 条未分类，未分类保留为未知。样例中没有 minor/major/destroyed 正类，不能用于验证损伤召回率。灾前只有建筑几何，没有损伤类别。后续应按预定抽样规则补充正负类和多个独立天气过程。

它们原属发布数据的 `hold` split，已被本轮检查暴露，现只作开发可行性材料。原生格式和 Challenge 格式共享影像身份，不是独立来源，也不能把 pre/post 两套建筑数相加为独立灾后对象数。

下载账本累计 7 次 xBD 逻辑请求、280,746,018 字节响应正文（约 267.7 MiB），包含过期 403、一个超时前缀和重叠请求。5 次以 HTTP 200/206 且 curl 0 完成。该统计不含软件依赖、CMA 格式页或重定向次数。

128 MiB 的 Full part-aa 前缀和 64 MiB 的 hold 前缀已足够取出所选完整成员。前缀末尾的 tar `ReadError` 是截断边界，不表示所有档案已校验；完整分卷和完整 Challenge 档案 SHA1 均未验证。临时签名链接留在仓库外私有配置中，正文与原始影像由 `.gitignore` 排除。

## 对总体方案和 novelty 的影响

沿用此前 97 项来源/产品/交付入口登记，只更新 D39、D44、D73，其余 94 项保持字段一致。更新后为 **86 项有已解析目标内容、7 项为事件/派生目录、2 项待授权、2 项未取到目标内容**。97 不是独立数据集数量，86 不是已完成任务闭环数量。

本轮补强三个角色：EM-DAT 增强跨灾种抽样索引，CMA 增强气旋未来结果参考候选，xBD 增强灾前/后建筑影响数据适配。正式 16 灾种范围不变，也没有因为目录列出某灾种就把它升级为完整预警链。

| 研究问题 | 新数据能够提供什么 | 本轮尚未证明什么 |
| --- | --- | --- |
| N1：固定最新专业预报后，主动获取更多证据能否改善未来风险判断 | CMA 提供可配未来时窗的事后参考；EM-DAT 支持多事件抽样 | 没有新增同事件专业预报配对、历史可用时间或 LLM 获取收益 |
| N2：是否识别同源重复、表示变化、旧版本 | CMA/IBTrACS 的潜在谱系；xBD 原生/Challenge 表示关系 | 表示必须先空间一致，不能把配准错误当作模型理解失败 |
| N3：错误来自获取、感知、状态更新还是决策 | 有记录的授权失败、可重放的解析和几何失败；可形成有界诊断 | 这些是数据管线发现，尚未形成模型因果干预与收益结果 |

现有最小闭环“主动策略未显示额外取证收益”的结论没有改变。三项下载成功支持方案可构建性，不足以证明论文 novelty 有效。

后续执行顺序建议：先解决 CMA 官方字段与 xBD 配准；随后按事件分组补天气过程、损伤正类及相应业务预报；通过时点、标签和同源检查后，进入历史回放的小规模模型对照。优先用历史窗口检验，不需要等待真实未来天气。

## 复核与本机重放

`audit_user_sources.py` 解析工作副本及 CMA 解压成员；`audit_xbd.py` 重新读取已保存的压缩前缀，核对样例字节、元数据、像素数组和几何；`verify_delivery.py` 不导入两个解析器，独立读取 XLSX XML、核对 CMA 原始文本与 CRC、绑定 xBD 文件哈希并核对类别数量。`build_usage.py` 在独立验证通过且哈希一致后生成新清单。

export PYTHONPATH=plans/user_authorized_sources_20260912/parser_libs:plans/all_dataset_utilization_20260912/parser_libs:/mnt/afs/260010168/.venvs/disastertrace-multihazard-libs-20260911

输出路径必须尚不存在。验证和清单脚本默认绑定本目录最终版本 `outputs_02`、`xbd_audit_02`、`verification_01`；示例命令生成另一个复核副本，不改变冻结证据。科学重放依赖本机的原始文件、解压成员和科学依赖，轻量代码副本不能代替实际数据。

三项回归测试涵盖真实 XLSX 维度错误、空字符串缺失、CMA 同时刻多气旋下第七列保留。初始失败日志保留于 `validation/regression_before.log`：缺失值问题已修复；CMA 测试最初仅按时刻选错另一气旋，已用源文件行号定位，原解析值未改。

`outputs_01` 的 EM-DAT 缺失值统计已被 `outputs_02` 取代；`xbd_audit_01` 被含明确空间准入条件的 `xbd_audit_02` 取代。旧报告保留作审计，不再作为当前统计入口。原始文件、完整归一化记录及临时签名均留在本机；公开再分发条件需按各来源原条款另行落实。
