# v13 M01：完整天气日的查询选择器模型对照

本批依据 2026-09-16 用户继续依次执行后续计划的授权登记。它接续正在运行的 B00、B02，固定一个模型、12 个天气日、最多 288 次请求。后台作业会等待技术门槛；提交作业不表示 API 已经开始调用。

## 研究问题与比较范围

评测 `deepseek-ai/DeepSeek-V4-Flash` 能否在相同未来站报目标、共同专业资料、来源预算和固定程序预测器下，通过查询选择改进完整流程。模型只返回 `query_order`，预测概率由原年度 raw values 程序生成。不能据此声称模型自己生成天气预测概率。

完全复用 B02 在成绩揭晓前由元数据/哈希固定的 12 天：3 个地区 × 4 个季度周，5,000 米阈值，864 个未来站报机会。主比较包括 batch、coverage、轮转、公开风险/发布时间、固定哈希及预算 × 授权 2×2；FOLLOW、F_COMMON 作为不同消费者的背景对照保留，不混作同预测器的取证收益。

每个方法使用同一套结果记录和缺失掩膜。报告完整分母配对 Brier、正负例、地区/周/日期分层，以及缺失 Y 的二值敏感性界。模型非法回复、网络失败、未知费用、迟到和回退均保留。没有正收益可以正常完成，不自动换模型、换日期或追加请求。

## 自动执行门槛

1. B00 全部 168 个单元、840 条轨迹通过。
2. B02 全部 72 个新增程序方法日通过，原 60 个参考方法日身份已复核，冻结年度银行决策成立。
3. M00 的 12 个真实接口请求及独立捕获核验通过。
4. 本批执行器离线检查通过。新增 14 项检查涵盖连续生产提交、非法回复、网络未知、费用保留、完整机会分母和捕获篡改拒绝。源代码包与 B02 相同，沿用其 912 项回归结果，不冒称又重跑了 912 项。
5. 对所选 12 天的实际 B11 轨迹复算程序概率，核验取证回执在预测之前、实际证据与 bundle 一致。已有一个真实日的 72 次调用预检通过，96 个付费资产消费引用被核对；它是旧轨迹复算，没有新增科学轨迹。
6. B02 至少提供一个“查询轨迹不同且预测概率不同”的同预测器见证，排除当前已测路径全部等价的退化情况。这个门槛不要求正收益。找不到见证时记录未获资格，也不宣称已数学证明所有合法路径等价。

正式请求只能在 `GATES.json` 生成后发生。没有通过或超过启动时限时写 `NOT_LAUNCHED.json`。C00 的独立机制工作继续运行，不作为本查询选择器比较的强制完成依赖。

## 固定执行合同

- 一个已验证 SiliconFlow 模型路由；temperature=0、thinking=false、非流式、输出上限 512 tokens。
- 12 个会话，每会话最多 24 次，一次性提交、无自动重试，总上限 288；之前 M00 的 12 次已消费，不重开。
- 单个 ACP 节点提供提交权威，最多 4 个会话并行。保留原始请求、API 意图、响应捕获、独立 anchor、发布回执和实际控制器消费记录。
- HTTP 实际等待会计入执行时钟；固定的是计划预测时槽，迟到导致跳过的时槽不会删出评分分母。相同来源查询预算不代表相同总计算成本。
- 启动截止 2026-09-16 20:00 UTC，HTTP 发送截止 23:00 UTC；单日程序最多 60 次控制器步进和 3 小时墙钟时间。
- API 凭据使用仓库外的既有私有文件，不复制、不打印；不新增天气下载、拟合或确认集访问。

## 资源排队与自动衔接

11:02 UTC 的首次平台提交返回明确的 `429 MEMBER_QUOTA_EXCEEDED`：GPU 余量为 2，CPU 余量为 0，作业未被接受。7 个既有作业占用 88 CPU、2 H100；其中部分作业正在等待上游验收，不能把平台 RUNNING 等同于全部正在计算。首次错误和原提交参数保留在 `runtime/CREATE.*`，没有新增模型请求。

已启动独立的普通脚本 `wait_submit.py`（启动回执 `runtime/submission_wait/LAUNCH.json`）。它每 120 秒查询既有作业和 M01 的唯一名称，确认至少释放 8 CPU 后重新提交原冻结命令：`computing-cluster-01g-02`，1 H100 / 8 CPU / 128 GiB，`model_run.py --workers 4`。该节点用于 CPU/API 执行，本批没有本地 GPU 模型推理。原作业继续运行，不取消、不重开消费过的实验。

平台明确拒绝后才允许在新的资源释放事件上再次提交；每次都有独立的创建回执。响应不明确时仅查询已有任务，禁止重复创建；平台接受后记录 `runtime/JOB.json`，仍由原实验门槛决定是否发送 API。提交脚本的 14 项离线检查全部通过，独立于执行器此前的 14 项检查；这些检查没有真正创建云任务或请求被测模型。提交截止保持 20:00 UTC，未知提交和超时会分别留下明确回执。

`watch.py` 的启动回执为 `OBSERVER_LAUNCH.json`；它只更新状态。任务提交、资源等待和统计计算不调用 Codex，被测模型的 token 用量记录在实验自身的 API 审计里。

相邻 B02 批次的旧观察脚本将按其原登记输出 `M01_READINESS.json`；那份文件描述上一批未启动 M01 的边界。本批是在新的继续执行授权下单独登记，实时状态以这里的门槛和原始回执为准。旧冻结脚本未被改写。
