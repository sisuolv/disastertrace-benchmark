# X09：同信息下的单目标与多目标联合输出

本实验延续 v8 的 X09，区分多目标联合输出与单目标的 E/F 双头输出。
截至本文件建立时，离线构建和独立空捕获核验完成，新增模型调用为 0。
实际是否启动、完成和评分，分别以 `gpu/joint_targets_live_01/submission_01/`、
模型目录与 `audit_01/VALIDATION.json` 为准。

## 对照与分母

输入沿用已暴露的 2025-02-03 Bay 真实原生开发资料，同一截止时刻、目标时窗和阈值下，
把三个站点组成一组。每个证据条件有 16 组、48 个目标机会。

| 因素 | 配置 |
| --- | --- |
| 模型 | Qwen3-235B-A22B-Instruct-2507-FP8，四卡 TP4 |
| 证据条件 | 共同资料；全部登记补充资料 |
| 输出头 | E-only、F-only、E/F 双头 |
| 回答范围 | 三次分别回答一个目标；一次回答全部三个目标 |
| 共同输入 | 每次调用都看到整个相同上下文，含三个目标的完整共同预报和同一补充资料并集 |
| 正式请求 | 单目标 288 次，多目标 96 次，共 384 次；另允许 1 次兼容性调用 |
| 目标回答 | 576 条，按条件、输出头、回答范围重复；仍是同一批 48 个机会 |
| 上限 | 15,360 输入 tokens、512 输出 tokens，温度 0，固定 seed，不重试 |

每个头／证据条件／回答范围有 48 个目标回答；按阈值分层后为 24 个。
一个多目标请求失败，会同时影响三个已登记目标。这个失败结构是预先定义的，
不对多目标答案作选择性修补。

## 信息和费用的解释

每组的单目标与多目标请求使用完全相同的系统说明和上下文，仅 `answer_target_ids` 不同。
因此，单目标调用也能看到其他目标的专业预报和补充资料。X09 不把额外信息优势混入联合输出差异。

这是新声明的共享固定输入条件。原来各目标私有快照中的来源被显式纳入同一共享资料并集，
相同产品按身份与内容去重，冲突身份拒绝合并。它不能被冒称为原私有会话中的免费共享，
也不用于估计新的 source 获取费用。

单目标方案重复发送上下文，多目标方案只发送一次；token 和硬件批处理收益要单列。
回答质量差异、输入重复减少和业务速度是不同结论。本实验不测共享预算分配，
不要求模型输出联合概率分布，也不证明多目标边际概率已整体校准。

512 tokens 是每次请求的统一输出上限。对同一组三个目标，单目标方案的总上限为
1,536 tokens，多目标方案为 512 tokens；两者并非相同的组级输出预算。
因此先报告完整率、输出长度和逐目标质量，再讨论联合输出差异；不能把该实验单独解释为
排除了输出预算因素的纯推理能力因果效应。保留原冻结设置，不在看到结果后改预算补跑。

## 评分和独立复核

E 参考从已披露、产品精确支持的原生 METAR 区间计算，并与原批次参考逐项核对。
未来 F 使用独立保存的原生结果表，运行模型的程序只加载 `policy/` 请求；
评估器文件单独绑定清单，不由模型 worker 载入。

严格输出格式要求每个请求目标恰好一项，无重复、缺项、额外字段、布尔概率或非有限概率。
晚到、未 EOS、未持久化和无效回复保留所有目标：E 不计及时正确，F 保留共同基线。
E-only 不参与 F 评分；与基线同值的合法 F 提议仍明确记为 OVERRIDE。

独立复核重建每条实际输入 token，核对输出 token 与原文、请求/响应/提交哈希、
原模型文件和四卡硬件记录、共同上下文、时间顺序、全目标分母及成对差异。
该固定输入评分有自己的严格请求准入，不冒称已通过完整共享预算 SessionCoordinator 回放。

离线结果：384 条请求、384 次程序格式演练、96 组上下文一致性检查，最大输入 8,514 tokens；
独立空捕获核验保留 384 个未尝试请求、576 个目标回答位置和 288 个成对位置。
这些位置没有模型分数。相关代码 24 项新测试通过，当前完整相关核心回归共 485 项；
另有 5 项启动边界检查，均不调用真实模型或提交 GPU 作业。
