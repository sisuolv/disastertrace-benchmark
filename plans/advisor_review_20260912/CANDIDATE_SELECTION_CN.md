# DisasterTrace 候选数据、灾种目标与处理建议

日期：2026-09-12。配套主文：[导师讨论稿](PROPOSAL_FOR_ADVISOR_CN.md)。

这是一份建议选择表。数据事实依据 [97 项来源登记](../all_candidate_data_validation_20260912/CANDIDATE_REGISTRY_CN.md)；“有样本”只表示已取得对应记录或数组，未完成的时间、标签、质量和任务条件继续列出。`Dxx`、`AW-xxx` 是可追溯来源 ID，不是独立数据集计数。官方入口及具体样本路径在 [登记 JSON](../all_candidate_data_validation_20260912/CANDIDATE_REGISTRY.json) 中。

## 1. 选择方式与角色

建议先确定候选数据的角色，再冻结具体资产和事件：

| 角色 | 用途 | 选择原则 |
| --- | --- | --- |
| 专业预报 F0 | 共同预测基线及真实修订 | 使用实际业务版本，固定起报、有效窗和支持范围 |
| 可查询证据 X | 此前观测、其他预报、地图/影像 | 必须在合同截止前合法可得，并记录来源关系 |
| 未来结果 Y | 后续观测 O、事后产品 P、报告 R | 与目标同变量/同支持；结果身份和质量分别报告 |
| 事件索引 I | 选择过程、分组与查档 | 不能直接替代物理结果；索引选择可能造成正例偏差 |
| 感知/表示 V | 图文理解、分割及依赖诊断 | 继承标签与处理过程可追溯；若无完整未来链，不计入预警轨 |

N1 指限时取证的预测增量；N2 指来源依赖、表示与版本；N3 指到达/获取/感知/状态/决定的限定干预。下列“支持方向”是拟开展的实验，不是已测得的贡献。

H01—H16 身份沿用用户整体蓝图。同一灾种下具有不同结果语义的子类分别建立合同和评分，例如河流越阈、山洪发生与城市内涝范围。

H01 扩到 IBTrACS 时还需固定机构字段及风速平均时长；不同机构的一分钟/十分钟持续风不能未经说明直接合并。当前 NHC 的精确时刻强度链不能替代这一跨盆地核验。

地震、火山和海啸不进入当前极端天气主范围。OISST D38 对海洋热浪、Landslide4Sense D46 对降雨诱发滑坡是范围外扩展候选；后者的实际样例尚不能确认降雨成因。

## 3. 建议优先推进的三条完整数据链

### 3.1 河流水文：最贴近研究主张，但历史归档是关键条件

**首选水位链：** NWPS 业务水位预报 → USGS 同站此前水位/上游观测 → 指定未来窗的同站水位 → 经核验的同基准阈值。

**可替代流量链：** HEFS QINE 集合 → USGS `00060` 流量与相关雨量 → 指定未来流量。若没有官方流量警戒阈值，可使用开发历史期冻结的统计极端阈值，命名为“极端流量”，或先只做连续预测。

候选新增信息为上游响应、流域累计降雨、前期湿润程度和其他合法预报。它们可能已被专业产品使用，需核查 `uses_observation` 或保留 `dependency_unknown`；不能按“来自另一机构”推定独立。

处理顺序：站号映射 → 变量/单位/基准 → 预报起报/有效窗 → 观测 QC → 阈值有效期 → 流域与附加证据 → 可用时间 → 同父过程分组。水位阈值不用于 CFS 流量，站点与栅格河网不只靠最近经纬度连接。

现有 HEFS、NWPS、USGS 数字样本和模型闭环足以说明工程可行。当前普通接口的短期滚动服务仍不足以保证多年的历史业务版本。GloFAS/EFAS 已有数字样本，可研究另一条有归档的流量链；其网格支持、平均时窗、河网和结果站点也需重新核验。EFAS 公共历史获取约有 30 天延迟，实时伙伴访问没有得到验证。

NIMS 有一个站点三张实图及近时水位，但它与主候选预报/阈值站的完整交集尚未证明。摄像头作为可选证据，先检查是否只重复水位叠字；没有可客观抽取的视觉事实时，不能虚构“图像精确水位”标签。

官方入口：[NWPS API](https://api.water.noaa.gov/about/api)、[USGS 水数据 API](https://api.waterdata.usgs.gov/)、[EWDS](https://ewds.climate.copernicus.eu/)。

### 3.2 地面站温度/降水：强基线与多灾种共享数据层

专业预报选 GFS/GEFS，HRRR 用于其支持区域；观测以当前 GHCNh 和 GHCN-Daily 为主。旧 ISD 资产用于对应历史复现，不作为持续获取新站报的默认路径。EWB/ExEBench 提供事件定义和已有处理方法，主监测队列仍需包含正常时段。

处理重点：

- 温度统一高度和单位，核实产品已缩放与否；当前 GHCNh 解析样例的气温已经是摄氏度，不能再除以十。
- 站点/网格配对保留海拔、距离与分辨率误差；插值方法在看测试表现前固定。
- 降水按累计起止做差/重置处理，观测日界与 UTC 产品窗口对齐；不拿日雨量结算小时强降水。
- 气候分位数、热浪/寒潮持续天数和近阈值分层依据外部规则或开发基准期；标签完整窗必须严格晚于相应截止。
- GEFS 已抽样两个成员，正式概率需要完整且身份明确的集合或明确命名的子集合方案。确定性预报转概率的校准不能用确认集拟合。

已有真实预报/站点数组；尚未完成这些数组在多个极端过程上的逐目标配对。ERA5-Land、MODIS LST 和 WeatherBench2 ERA5 只按再分析/地表温度等实际角色使用。它们可支持背景或 P 结果，不能充当当时业务预报或独立 2m 实测。

官方/作者入口：[GFS 公开数据](https://registry.opendata.aws/noaa-gfs-bdp-pds/)、[GEFS](https://registry.opendata.aws/noaa-gefs/)、[HRRR](https://registry.opendata.aws/noaa-hrrr-pds/)、[NOAA NCEI](https://www.ncei.noaa.gov/)、[ExtremeWeatherBench](https://github.com/brightbandtech/ExtremeWeatherBench)。具体文件以已留存回执为准。

### 3.3 TAF/METAR：短时等待与停止的候选

目标先取同机场下一绝对窗口的低能见度，不直接推广为航班延误或区域道路风险。若研究雾，则再要求天气现象码与可解释成因支持。

处理重点是机场身份、发布时间与修订、FM 转段、TEMPO 暂时条件和 PROB 的原生语义；报告能见度的下限、上限、SM/km 换算要保留。只有观测区间能够确定越阈与否时才结算，其余作为区间不确定或未结算。

当前 AWC TAF/METAR 实值可读，IEM 已取到历史冰暴/沙尘过程的站报，说明长期站报接口可用于事件核查；这些记录并不自动证明历史雾窗口及对应 TAF 已配齐。下一步先取得同机场多轮 TAF + METAR，补真实低能见度/雾正例与正常窗，再考虑 GOES 视觉证据。

原生卫星若在夜间没有所需可见光信息、受云污染或晚到，作为实际可用性条件记录。M4Fog 尚未取得原生 cube，不作为首条闭环的必要依赖。

官方入口：[Aviation Weather Center API](https://aviationweather.gov/data/api/)、[IEM ASOS/METAR](https://mesonet.agron.iastate.edu/request/download.phtml)。历史 TAF 的具体可用归档仍需取样，不由这两个入口的可访问性推定。

## 4. GEE 及已授权大源如何纳入

GEE 已通过项目初始化和实际数值获取。它可以减少影像筛选、裁剪和导出成本；正式任务应冻结导出资产与处理配置，避免运行时使用随时变化的 `latest`。

| 来源/产品 | 已取得什么 | 推荐角色与必须保留的限制 |
| --- | --- | --- |
| GEE GFD、Sentinel-1、Sentinel-2 | 真实像元及可解码 GeoTIFF | 洪水空间证据/表示；GFD 样点全负，S2 样点为高概率云，需另找合格场景 |
| GEE MODIS Snow/LST、SMAP、IMERG、S5P、GFS、ERA5-Land、OISST、MTBS | 多个集合已有真实数字样例，MTBS 另有周界 | 逐产品区分预报、观测、再分析、L2/L3、聚合与事后结果；不按渠道重复计源 |
| NASA IMERG Early/Late/Final | 原生数值与质量样本 | 实际 E/L 身份和延迟以原生产品为准；GEE IMERG 不自动证明同一 E/L 产品 |
| NASA SMAP L3/L4 | 实际表层/根区湿度与相应质量/坐标 | L3 的质量位、冻土和缺测要筛；L4 是同化产品，不能作独立传感器结果 |
| ADS CAMS dust forecast | 已授权数值预报 | H14 输入候选，与地面现象/能见度配对；AOD 不能独自结算沙尘暴 |
| EWDS GloFAS/EFAS forecast | 已授权数值预报 | H08 替代/扩区路径；先核河网、时间平均与观测支持；EFAS 实时权限另论 |
| CDS ERA5-Land | 原生温度切片可读 | 历史背景/明确的 P 轨；不能作为历史实时预报 |
| CHIRPS v3 DAILY_SAT | 直接下载的完整日栅格已解码 | 降水 P/背景；本轮尝试的 GEE CHIRPS v3 路径未找到，不否定直接下载渠道 |

公开可获取不自动代表允许把所有原始资产放进 GitHub。复用优先提供许可合格的小样本、标注出处和固定下载/处理配方；逐产品记录研究使用与再分发条件。

## 5. 空间与时序 benchmark 的具体取舍

### 5.1 洪水影像库

推荐先选 **WorldFloods v2 与 KuroSiwo** 作为新的空间感知/表示适配候选，结合已有 **GEOID-Flood** 控制资产；需要建筑/道路级范围时再加入 **SpaceNet8**。这是依据样本完整度和角色互补的暂定选择，许可及事件匹配通过后才冻结具体子集。

| 来源 | 实测内容 | 暂定处理 |
| --- | --- | --- |
| WorldFloods v2 D51 | 一组完整 S2 图像、gt、元数据，网格一致 | 保留，先核水/云标签、事件时间、来源许可及正例 |
| KuroSiwo D13 | 三组完整 SAR/掩膜/info，共 24 个成员 | 保留，解析事件、前后时刻、有效掩膜与原 split |
| GEOID-Flood D12 | 三组前后 SAR/标签/有效性；同一外部 test 激活的负瓦片 | 作为已暴露开发材料；扩正例/新事件时保留原 split，不能假称盲测 |
| SpaceNet8 D16 | 完整灾前/后影像及官方映射的 GeoJSON | 保留城市扩展；预后网格不同，按预定方式配准/重采样和栅格化 |
| Sen1Floods11 D15 | 三组影像/标签、两个事件地区 | 备选；数据再分发许可解释须明确 |
| GFD D11 | 栅格与像元已取回 | 事件/范围 P；三个样点为负，不代表有正例验证 |
| UrbanSARFloods D14 | 完整 SAR chip，无配对掩膜 | 暂作补齐候选，不能当作影像—标签已验证 |
| SenForFlood D64 | 三组灾前 SAR、flood mask、LULC | 灾后影像与时刻未齐，不能称三组同期灾后感知对 |
| FloodNet D17、CEMS Rapid Mapping D18 | 尚无完整目标样本；CEMS 有部分下载字节和产品元数据 | 暂缓主实验依赖；CEMS 的自然多格式交付/修订值得后续单独核查 |

SAR/光学掩膜往往对应灾后范围。如果研究目标是灾前或未来越阈，只能把截止前已得到的影像作为输入，把后续影像作为相应 P 结果；不能把事后图和未来水位混成一个标签。

### 5.2 野火时序

推荐先核查 **WildfireSpreadTS D19 + Next Day Wildfire Spread D20** 的事件时刻与下一步标签；**TS-SatFire D21** 作候选补充，**FIRMS D23/MTBS D24** 作活动火/事后范围参考。

- WildfireSpreadTS 有同一火场三天数组；活动火像素为 4/0/0，零值还可能受探测与覆盖影响。
- Next Day Wildfire 有三个完整、CRC32C 通过的 TFRecord，包含前日/次日火掩膜及其他字段；还需证明原始地理时间身份、事件分组和 split，整个 ZIP 尚未完整下载。
- TS-SatFire 有三天 19 波段数组，未来标签通道与读取规则尚未完成准入。
- Sen2Fire D22 有三组完整 NPZ 图像/气溶胶/标签，但均为负例，先作静态感知候选。
- FPA-FOD6 D65 可帮助事件合并与起火原因核查；不能默认所有野火由极端天气导致。

GWIS AW-GWIS 只有渲染 FWI 图，EFFIS AW-EFFIS 尚无数值预报。本阶段不能用这些入口宣称已有“专业火险预报之外的增量”任务；先做明确命名的火活动/范围预测与来源机制研究。

### 5.3 图文与道路天气视觉

WeatherQA D49 已完整重建 8,511 条标注并解码三张精确匹配的配图；CyPortQA D50 有三个事件图文样本。推荐用于产品事实与表示一致性，后续只有能配对到实际结果的条目才扩 F/D。

DAWN D63 的 Fog/Rain/Sand/Snow 各三张实图均已解码。其缺少可靠事件、时刻和严重度，而且 Fog 文件名含 haze，因此仅作为视觉辅助候选，不把这四个目录直接等同四类极端灾害任务。

## 6. 暂缓项与依赖管理

候选来源没有下载齐不影响先把论文方向交导师判断。推荐优先依靠已有样本的组合，以下来源补齐后再评估：

| 暂缓原因 | 来源 | 对当前主线的影响 |
| --- | --- | --- |
| 账号/研究许可仍需完成 | EM-DAT D39、xBD D44、HKO-7 D68、ESWD D70 | 可作为事件/影响或区域扩展；不是三条优先链的必要依赖 |

## 7. 导师讨论后怎样冻结“最终使用的数据”

建议冻结三个层次，而非现在指定一个看起来完整的下载名单：

1. **研究层：** 16 类范围、首批两条主实验链、N1—N3 对应对照、允许的 O/P/R 和时间条件。
2. **数据层：** 实际产品版本、变量/单位、处理代码、事件组、阈值基准、质量政策、可用时间依据与许可。
3. **实验层：** 开发/确认切分、共同预报更新、查询预算和截止、固定后端/策略、评分与主要比较。

冻结前输出每个任务族的实际计数：候选过程数、完整配对数、可结算数、正/负/近阈值/缺测数、独立组数、具有自然修订和新增内容的组数。通过这些计数选择主实验；不能用文件数、97 项入口或模型调用数代替。

需要导师确认的重点是：哪些任务最能回答研究问题、第一版需要多大灾种广度、允许怎样的历史可用性证据，以及什么样的负结果足以构成有价值的研究发现。具体下载文件和大规模实验在这些决定明确后再冻结。
