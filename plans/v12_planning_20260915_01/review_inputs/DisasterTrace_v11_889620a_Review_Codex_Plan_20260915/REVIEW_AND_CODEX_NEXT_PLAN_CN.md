## 2. 已确认问题F01：可判定E枚举漏计

### 2.1 代码路径

- `disastertrace-starter/src/disastertrace/monitoring_v1/evidence.py::exists_report_support` 输出 `supported / refuted / undetermined / inconsistent`。
- `monitoring_v1/policies.py` 将上述值直接保存到 `frames[].e_statuses`。
- `plans/v11_execution_20260915_01/fullweek.py::audit_case` 将其作为 `ROWS[].e_status`。
- 同文件 `audit` 使用：

```python
sum(r["e_status"] in {"entailed", "refuted"} for r in values)
```

此路径没有将 `supported` 改写成 `entailed`。在四个合成状态各出现一次时，当前表达式返回1，正确的可判定数量为2。

### 2.2 严重性与影响范围

严重度P1：影响E统计及其与策略/可达性比较的解释。它不是Brier公式错误，不改变已有预测、原始结果或资源账本。若某个切片没有 `supported`，实际差值可为0。必须扫描实际行，不能凭合成例推定整个日历已受影响。

完整周仍在运行时，不修改其冻结源码或启动器。保留原程序的全部输出，在新审计目录中读取同一原始frames/ROWS进行修订统计。必要时待完整日志齐备后再形成最终影响表。

### 2.3 最小修复与验收

定义一个有明确版本的E状态集合或谓词，使用producer语义而非模糊别名。遗留数据若需要别名适配，应绑定其schema，不能全局把任意字符串都当作等价。

验收：

- 四种状态的单元测试；未知拼写应显式拒绝或标为不合格，而不悄悄归零。
- 全部状态数量之和等于登记E行数；缺frame另列。
- `determined = supported + refuted`，与逐行查询一致。
- 输出旧计数、新计数、受影响ID、方法/阈值/日期、原输入和评分哈希。
- 验证原F概率、未来参考、机会分母、Brier不因本修复变化。
- 影响分为 `affected / unchanged / not_evaluated`。

推荐交付：`E_STATUS_SUMMARY_IMPACT.json`、`E_STATUS_RECOUNT.json`。

## 3. 已确认选择边界F02：C2不应从已可投影候选反推完整版本

### 3.1 来源链及范围

`prepare_c2.py`按固定日历选择前缀，这一点应保留。但之后读取的是 `data["baseline_candidates"]`。

`build_native_v2.py`构建这张候选表时，已经尝试 `product.project(start,end)`，不覆盖目标时跳过；未解析版本也只有完整覆盖才进入候选。取消、短有效期及部分其他状态不一定留在这个表里。

原生builder同时保留完整 `NATIVE_PRODUCT_INDEX`，并以该完整目录调用 `current_taf()`生成实际当前状态。核心F版本规则是正确的；本次问题是新C2输入宇宙使用了不同上游表。

### 3.2 可复现反例

| 产品 | 签发 | 有效范围 |
|---|---|---|
| 旧产品 | 00UTC | 00—24UTC |
| 同链新版 | 06UTC | 06—12UTC |
| 目标 | 当前10UTC判断 | 15—16UTC |

完整合法目录：当前新版不覆盖目标。
仅可投影候选：新版先被排除，旧产品被当作最新可见产品。

同一签发时刻存在两个不同语义版本时，若其中一个因不覆盖被删除，也可能将原应保留的冲突变成单一active产品。

本包使用原 `current_taf` 与合成元数据复现了这些边界。没有执行整个生产C2编译器，也没有重算72个真实前缀的实际差异。

### 3.3 不应作出的过度结论

`TafEvidenceTask`明确只就提供的产品作答，因此当前144个参考可能完全符合各自输入。不能宣布它们全部错误，或声称过去模型F分数已被此新C2设计污染；C2本轮没有模型运行。

应区分：

- 已提供产品包内的事实QA，保留原结果。
- 与真实会话状态严格对齐的current-product E，需要重建其合法披露全集。

### 3.4 修改方式

从完整原生索引、原始产品回执与会话实际披露记录构建 `SOURCE_UNIVERSE_MANIFEST`。先应用截至实际状态时刻的权限/发布时间，再按原有provider规则处理版本，最后判断目标覆盖。不要从成功投影的表逆向恢复版本史。

保留所有登记来源的：active、partial、no-coverage、CNL、NIL、unsupported、同刻冲突、no-product及等价镜像。未知状态仍留在日历中。不得为了获得难题而只筛选预期产生收益的异常样例。

每个新C2参考应保存：公开资料宇宙哈希、实际as_of、允许和实际披露的产品ID、当前系列、被替代ID、解析失败与来源证据。保持提供资料范围与模型实际可见范围一致。

用完整既定日历进行普查，先报告所有状态分布，再注册机制诊断分层；自然日历与富集诊断分别报告。

## 4. C2研究结构还需补一个连接

现设计的四个动作改变的是付费邻站METAR；新增E题却问免费共同TAF的覆盖/版本。在TAF不变时，四个动作应给出相同TAF E状态，这是预期不变性，不是C2失败。

建议两个实验子轨并存：

### 4.1 TAF解释/处理子轨

固定同一完整原生TAF和目标，改变是否使用明确的解析工具、表示或模型解释。测量它们改变了哪些F实际使用的字段。程序精确处理应是所有方法可用的强对照，不是私有Gold。

### 4.2 METAR获取子轨

固定共同TAF和后端，比较少量登记邻站查询。对应E应描述这些资料本身的值、删失、报告身份、时刻、缺测、质量和合法覆盖。记录：

```text
query → acquired product/version → public native fields
      → feature vector → proposed probability
      → accepted/effective revision before cutoff → future loss
```

当前F不直接消费最终E布尔归约；只修正归约而未改变特征时，应报告无F中介变化，不能强行叙述收益。

### 4.3 同状态必须是真的同状态

72个目标引用来自24个父日会话。先恢复父会话快照，再让每条分支继承：时钟、spent/reserved、授权、缓存、pending、共同基线、override、失败政策及继续策略。不能让每个目标都重新拿到全部共享预算。

`cutoff`不是自动等于分支开始时刻。用实际checkpoint时钟定义E的as_of和可得信息；分支开始后至截止之间到达的资料不得倒灌。

若协议选择先完成原始串行pending再分叉，则所有分支必须共享完成后的同一真实状态与相应费用/时间。不要一条分支从pending前开始、另一条免费继承结果。

`no_further_paid_query`只停止新收费查询，不终止未来基线更新或公共预测日程。已取过资料的动作、重复别名、超预算或来不及完成的动作应显式保留；完全同输入路径可按预定规则识别别名，不能复制成多个独立实验。

对同一会话里的其他目标也保留评分，避免只看到某个目标变好而忽略资源转移使别的目标变坏。局部E可达、联合E可达、固定后端事后最佳F分支是不同参照；不得相互替代。

现有冻结冬季/去周期后端可先用于探索性分支联调；无需等待全年拟合才修C2。确认性结论须等最终后端与方法冻结。

## 5. 正式评分、温度和API：保留已完成保护，只补资格缺口

### 5.1 正式v2与重复重放

当前正式入口已核对原目录、data/bank身份、CONTRACT、journal、report、STOP和来源哈希；评分每臂恢复一次，再进入内部 `_score_replayed`。

内部评分保留：完整封存机会、共同基线时间线、协议、全部干预历史、同目标跨时距结果和结果版本检查。不能为了再提速去掉这些条件。

旧日志仍可显式legacy重放，但不能授予新正式v2资格。研究中的合法失败和部分结果按原契约留存；不可信或不完整比较不能叫完整通过。

数据卡在fullweek里已经作为文件纳入bound_files；剩余问题是将其schema、字段语义、parser、prompt与适用结果政策明确连接。不要重新宣称数据完全没有绑定，也不要把存在一个文件哈希当作全部科学语义已准入。

### 5.2 温度：等长与lineage不同

直接检查确认当前 `event_values`接受合法max-only产品、负温度，拒绝错UTC日窗、day0、错变量/时长、重复日期、缺日、NaN、布尔、巨大整数和成员尺寸不一致。

但同一天的成员重排可以不改变数组长度，却改变三日事件概率。这不是本次发现真实数据排列错误，而是必须由原始成员ID、起报、有效日、字段和产品谱系提供的上游保证。

建议：

- 为跨日事件记录真实member ID及共同起报；不以列号相同作为未核准的唯一证据。
- 同时重排全部日的成员应保持事件概率；仅重排单日应被lineage校验拒绝或显式失去联合资格。
- 只使用max的合法任务不因无关min字段缺失而被整产品规则错误排除。
- DWD按任务变量和原生支持完善政策；最终档案可以作参考，不能自动证明历史上当时可得。

这些是新跨过程任务的门槛，不需要让所有H15工作停等。

### 5.3 API保证范围

本地许可点已在STOP/截止/请求身份检查后持久化发送意图。它是本地许可，不是服务端确认；之后STOP无法保证撤销已经启动的传输。严格保留未知费用、截断体范围和原请求身份。

本轮没有实际API请求，不能把假运输测试叫作服务验证。无需为本次CPU/C2修复新增API调用。

## 6. 完整周必须如何收口

当前五组是FOLLOW、F_COMMON、F_BASE_ONLY、B11_BATCH、B11_COVERAGE。共同专业原始TAF保持一致；F_COMMON和values使用不同拟合银行，分开绑定正式比较是正确的。

最终检验：

- 168个日会话条件×5=840轨迹；每轨72个机会，总60,480方法行。
- 方法无关机会12,096；多个阈值、小时和地区不自动成为独立天气过程。
- 每日共享48次查询，日界无余额/paid-cache结转；这不是持续七天会话。
- 程序计算/持久化各1ms是声明情景，不是实测部署速度。
- 方法的共同基线版本、预测开始与持久化日程一致；缺结果保持共同掩膜。
- 全部原结果、失败、部分输出和原审计保留。
- 使用修复后的独立E汇总，证明F字段不变。

必须同时报告总体、地区、日期、季节周、正例条件损失、负例条件损失、各自对总体的贡献以及缺失敏感性界。不能将缺失补全界称置信区间，也不能用逐小时bootstrap把四个全球周变成大量独立过程。

主要比较：

- FOLLOW 与 F_COMMON：共同信息后处理差异，不是纯取证效应。
- 同values下 F_BASE_ONLY 与 B11_BATCH/COVERAGE：补证及预算内流程效应。
- B11_BATCH 与 B11_COVERAGE：给定后端/日程/来源预算下的策略差异。

先查实际查询ID、版本、已授权资产和输入哈希是否相同，再解释相同分数。后端不同、时间不同、表示不同的收益不混为一种“智能体增益”。

如果完整周发现平静日改善、事件日退化，应保留并研究，而不是删掉事件日或只展示平均分。

## 7. 年度数据与后端：按阶段推进，不循环重下

年度阶段链应是：

```text
逻辑请求登记 → 目录/站报取得 → 原生TAF枚举
→ 内容寻址下载 → 科学解析/质量 → 目标及版本连接
→ 完整足迹角色准入 → 拟合 → 校准 → 开发评价
```

每一步有独立计数与失败清单。71/72只表示地区月目录阶段；2,470只表示样例已枚举。HTTP次数可能超过逻辑分片数，因为有已登记重试。

当前Chicago 2023-01失败要先核实KORD具体请求及原重试范围。保持已成功五片、其他71个月及原失败回执；若原重试额度已耗尽，需要新、有界的补取记录，不重开旧全量launcher。

跨月padding去重应按原生产品ID、版本和内容哈希，而非仅路径。无法解析的产品仍作为来源事件保留，不能因为不支持语法就从版本状态与机会分母里删除。

推荐角色保持原计划：2023覆盖四季的拟合及内部方法选择；2024作为最终校准；2025已暴露资料作为开发。先固定2023内部块划分与选择规则，不把2024一边无限调参一边称最终校准。全部依赖足迹含输入回看、源版本、结果支持及会话历史，而不只是目标日。

保留common/mask-age/values、无补证、COPY和合理批量强基线，明确缺证模式权重。原始概率与后校准分别保存，嵌套阈值在相同信息下核验。新后端不以“必须获胜”为准入条件。

历史未被本项目读取，不等于大模型预训练从未见过。确认周仍封闭；有确定协议后再一次性使用，不能用一个星期支持全年全球结论。

## 8. 原生多模态与online应有独立近期出口

原用户目标不是纯文本概率校准benchmark。下一批不能把两年下载和拟合变成所有原生多模态工作的串行前置。

### 8.1 MM最短出口

复用现有图像/处理器适配器，选择有真实时空匹配的H15 ABI或已达到合同要求的H07/H01路线。路线切换依据数据资格，不看模型哪个分数更好。

## 10. 研究贡献如何验收

C1：共同专业产品、固定后端/日程、真实费用下，方法是否取得并利用了额外信息。等查询数不等于等总计算成本。简单程序胜出是合法结论。

C2：对同一真实状态，哪些公开事实能判定，哪些受资源限制；字段改变是否进入特征和预测，是否来得及采用，最终损失如何。可判定E增加不是F最优证明，TAF解释与METAR取证不能错配。

C3：同一测量问题在不同物理过程和原生模态中成立，并可独立复算。目录齐全、测试数量、参数量和大量相邻机会不能代替科学准入与独立过程。

本次没有重新进行全领域首创性检索，不提供发表或novelty保证。保留原主张，优先将这些可反驳问题做成真实实验。修复统计bug本身不是novelty；它使后续机制结论能够成立。
