## 4. C1/C2/C3 如何成为可验证的 novelty

### C1：受共同专业信息约束的多目标主动监测

共同专业预报全量、持续免费更新。额外资料、选择、处理、预测与等待分别记账。研究增量必须相对于强共同信息后端及同后端批量策略，而不能只相对于较弱 FOLLOW。

第一层先回答五臂的问题：

| 配对 | 解释 |
|---|---|
| FOLLOW → F_COMMON | 对共同专业资料换数值后端的总效果；TAF 本身不是已经校准的事件概率 |
| F_COMMON → F_BASE_ONLY | 不同拟合银行在空补证条件下的差异 |
| F_BASE_ONLY → B11_BATCH | 同 values 后端，实际补证及其到达时序的效果 |
| F_BASE_ONLY → B11_COVERAGE | 同后端的主动获取流程效果 |
| B11_BATCH → B11_COVERAGE | 固定后端、查询预算与预测日程下的策略差异 |
| F_COMMON → B11_BATCH/COVERAGE | 相对于强共同信息后端的整体效果，含后端差异 |

当前 B11_BATCH 是 **48 次/日预算内的批量策略**，不能改称无限预算全证据 oracle。固定完整证据包的信息诊断是另一条件，也不是理论最优 F 上界。

第二层固定同一个 selector，完成 `fixed_quota/global_budget × target_private/session_shared` 的 2×2；第三层固定 B11 和预测器，比较 batch、round-robin、risk、coverage、有限一步/两步程序与一个 LLM selector。目标私有条件还要隔离预测器上下文、摘要及跨目标记忆。

保持当前 `base_bound_override` 主轨。`persistent_override`、COPY_CURRENT、COPY_BASELINE 与 KEEP 的作用单独比较。保留旧值或自动回退产生的收益，不归功于生成了新概率。

### C2：同一真实状态下，可达事实与未来利用之间的可复核连接

拆成两类实验，不增加新的贡献编号：

**共同资料处理实验。** 同一完整合法 TAF、相同已读观测，只比较解析/表示/版本选择。确定性原生解析器是强基线。模型错误修复必须能由当时合法原文支持；评估侧特权修复与可部署工具分别标明。

**补充观测获取实验。** 固定共同 TAF、后端和当前状态，选择邻站 METAR。E 问该报告的数值支持、删失、身份、时刻、缺报及可用性。TAF 状态在等时条件下不变是应保留的负控制。

每条分支都记录：

```text
合法查询/处理动作
  -> 实际完成、公开可见的来源与版本
  -> 字段及其支持区间
  -> F 实际消费的特征
  -> 候选概率
  -> 是否及时接受、生效或失效
  -> 同一未来参考上的损失与资源变化
```

当前 F 不直接读取最终 E 布尔答案，因此只把 E 答案改对而未改消费字段，应允许 F 完全不变。传播链中的各环节可交互，不强行分成加总为 100% 的原因比例，也不声称天气系统本身的物理因果关系已识别。

来源顺序必须为：完整原生索引/原文回执 → 实际 as_of/权限 → 原 provider 版本规则 → 当前产品 → 目标覆盖。保留 no-product、CNL/NIL、no-coverage、partial、unsupported、conflict、等价镜像与普通 full。旧 144 题保留为“给定产品包 QA”，新任务使用新身份。

同状态分支要求：

- 使用真实 parent checkpoint，继承 clock、事件队列、spent/reserved、额度释放、授权、缓存、pending、baseline、override、版本与失败策略。
- 若需先排空原 pending，所有分支共享同一次原完成过渡，并计入实际时间；不得各自重发或把后到结果回填旧时刻。
- 停止新增付费查询不等于终止会话：共同预报更新、既定预测和截止封存继续。
- 按 `parent_checkpoint_hash + intervention` 去重；72 个目标视图不自动等于 72 个独立状态。
- 同时报选中目标和余下整个会话的效果；不能拼接每个目标各自最好的互斥路径。
- 保留别名、无新增信息、无合法动作、超预算、迟到、缺档案和失败。真有四个动作标签不代表四种信息。

小图精确求解 E 联合可达性时保留可行路径及费用—时间组合；搜索截断给上下界和未完成标记。单目标 E 可达、会话联合 E 可达、固定后端事后最佳 F 分支各自报告。任何使用未来 Y 的分支参照只在评估器侧，不能给在线 selector 当 expected value。

### 阶段 C：强后端下的机制矩阵与有限 LLM 实验

新银行用新注册完成五臂和固定 selector 的 2×2。C2 工程路径通过后，用新银行重做已登记的科学分支，保留旧后端工程结果，不混表。

先测可辨别性：预算是否约束实际选择，batch 是否已覆盖全部合法资料，动作是否等价，字段能否进入预测器。若任务退化，报告退化；不要强迫改概率或削弱 batch 来制造 LLM 机会。根据训练/开发资料预先注册少量预算情景，而不是看确认输赢后改预算。

LLM 首轮只做 **selector**，预测器和原生字段处理固定。优先沿用已验证的本地 235B 部署，具体 checkpoint/量化以现有权重清单再核验；不追逐未经验证的“最新模型”。建议上限为 **12 个开发会话 × 24 个决策 = 288 个正式请求，兼容性最多 2 次**。这是待复核的上限，不是已注册任务，也不需要用满。

保留 batch、round-robin、risk、coverage，训练/开发侧的一步/有限两步程序；如其预期损失估计缺少合法训练支持，标不适用，不用未来 Y 代替。模型失败、KEEP、不改概率及负结果都留在分母中。

来源预算相同与总资源相同分开报告。记录 selector、提取、预测、token、生成批次、排队、实际交付、持久化、漏交与回退。程序 1ms 情景不能与实测模型延迟混称部署速度。

提取器/VLM 角色另用固定资料包对照；不得在同一主实验同时换 selector、predictor、prompt 和后端。

**出口：** 能区分信息、选择、处理与采用；即使 LLM 不优于强程序，也形成完整、有限、可复算的研究结果。

### 阶段 D：独立确认与论文材料

现在即可写确认设计草案，方法锁定后才冻结实际日历。保留 Bay 2025-02-17..23 未打开；一个冬季周只能承担窄范围检查，不能作为全年跨地区确认。

用训练/开发侧的过程间变异制定区间精度、最大连续日历及不足时停止规则。不按观察到的正例数或显著性追加有利日期。未读历史可以承担确认，无需等未来天气；但“本项目没读过”不等于“模型预训练没见过”。

统计单位同时记录来源依赖块和有外部依据的天气过程组。当前四个 global weeks 主要作描述性结果；不能把小时、阈值、方法或 mask 当独立重复。

建议未来主假设先限制为：冻结 LLM 流程相对冻结强程序，在 1km/5km 两阈值的自然日历配对 Brier；两项主张使用预定多重比较规则。若增加主比较，整个检验家族同步扩大，不能只对两个阈值校正却宣称所有方法都显著。次要机制对照以效应、过程分层和不确定性报告。

统一主方向 `gain = reference_loss - method_loss`，正数表示改善。正例/负例条件损失及其对总体的贡献同时给出，不能用条件分数替换自然分布 proper score。

共同缺失掩膜保证方法间公平，不保证总体无偏。按基线风险、时段、地区、来源/质量原因分层；缺失结果敏感性界与抽样区间分开。跨阈值/时距共用同一参考时，联合补全必须满足事件嵌套和共享标签约束。

**出口：** 代码、模型、银行、提示、成本、日程、过程、结果政策与最大范围全部冻结；主张—证据—限制表齐全；精度不足如实报告，不转回开发优化同一确认集。

### 温度

raw 事件只验证消费的变量/日；EMOS/ECC 检查其全部联合输入。目标事件、提示和 DWD 结果构造使用同一冻结合同，但两条概率算术仍独立实现。通用 helper 允许合同定义的阈值；benchmark 的事件目录限制具体事件，不用硬编码 30/0 替代所有通用校验。

成员身份来自原坐标、起报、产品/变换谱系，可核对后规范排序；不能事后给数组列编造 ID。同步全日重排应保持概率，单日错排须拒绝或失去联合资格。ECC 排序/tie/min-max 修复及其概率影响单列。

DWD 最终档案可以作合格 Y；没有当时发布证据时，不通过固定延迟升级成严格历史补证。温度 F-only 可以独立推进，暂不宣称 temperature C1。

### 原生多模态

保留近期有界入口：最多 24 个按元数据预定的配对（3 区域 × 4 日期 × 2 昼夜时刻），先检查是否有同期合法 GOES ABI；路线不合格才按数据准入调查既有 H07/H01。时刻、ROI、通道和失败规则在查看模型输赢前固定。

先交付同一未来目标的图像、共同预报、时空/版本/QC、渲染和实际 processor 接图证明。文本 235B 服务不是视觉服务。专业数值处理、原图/VLM、同源结构化表达分开；新增波段/时次是新增信息，隐藏 Gold mask 不能当模型已读事实。

这条 CPU 资格支线不等全年拟合，但视觉模型批次需另冻结范围。

### D、X09 与 prospective

D 先冻结 Scenario Card、准备时间/容量/取消/资源规则，用固定天气与 F 比较程序和有限优化器。同证据同预测器仅改变偏好时，F 输入与输出必须不变；获取路径因决策需求不同而改变证据后，F 可以随证据改变。只称公开假设下的情景收益。

X09 单/联合目标推理分别控制每请求和组级总资源，不把 E/F 双头当联合目标实验。

Prospective 单独做有界 shadow：程序先提前持久化预测，再等待参考成熟，之后才加入一个冻结模型。收集在线数据本身不算在线预测；first_seen 指本采集器实际看到的时刻。历史确认不用等待未来，真实在线能力才需要事前提交和后来结算。

## 7. 资源与 Codex token 的执行安排

三本账分开：Codex 编排 token、被测模型 token、CPU/GPU/网络/存储。本轮无法读取真实 Codex 用量，不报告虚假的节省比例。

获准执行后：

- 复用现有薄协调器，依赖、唯一任务身份、重试上限、完成审计和状态汇总交给脚本；不再建一套 agent 编排框架。
- 每个逻辑任务单 owner；单 session 内顺序/预算保持，独立日期/地区/方法可并行。读取已完成回执，不因中断重开 consumed launcher。
- 脚本每 1—5 分钟检查或接收平台终态；Codex 只在完成、首个失败或合同/分母变化时读取短摘要。原始日志完整保留，按错误签名聚合但不丢任务 ID。
- 启动/恢复优先读 `STATUS.json`、`RESULT_SUMMARY.json`、`NEXT_ACTION.md`；源文件未变时不重复读七份审查包。
- 定向 red/green → 合并后一次受影响 monitoring 回归 → 有界真实复算；只有新失败或新改动才扩大/重复。测试数量去重，不固定填写旧 750。
- 原始源/角色清单按 immutable hash 检查；派生 E/配对报告复用原数据。单次评分内部复用已验证引擎，不用跨运行“永久可信缓存”跳过验证。

资源建议：CCI 留作控制，数据/解析/评分用 ACP CPU。首批最多额外 16 CPU/64 GiB，同时统计旧任务占用；当前观察到的成员 CPU 配额为 72 核，执行前再核。后续年度生产和分支可按配额安排 16—32 核任务，但不得把共享 AFS 或源站限流误认为 GPU 不够。

模型阶段最多 4 H100，235B 使用已验证的四卡并行配置并复用服务。若需要小视觉模型，可另阶段或重新划分四卡，不能叠加超过上限。纯 CPU 工作只有实测普通 CPU 配额成为瓶颈时，才考虑沿已有资源授权使用带 GPU 的计算节点，并报告它解决的瓶颈；不为制造进展空占卡。
