## 模型效果：有小幅改善，但没有超过全部强程序

模型为 DeepSeek-V4-Flash，通过 SiliconFlow 调用。模型只选择查询，未来站报概率由固定年度程序预测器生成。
12 个天气日按预先登记的元数据/hash 选定，没有按结果换日期。统一 864 个机会，其中 857 个可结算、7 个缺失、3 个正例。

| 方法 | 857 个可结算机会的平均 Brier（越低越好） |
|---|---:|
| 固定份额、目标私有 coverage（预算/授权因素对照） | 0.00476043 |
| 全局共享、固定哈希 | 0.00485923 |
| 全局共享、轮转 | 0.00486580 |
| 全局共享、LLM 查询选择器 | 0.00491526 |
| 全局共享、coverage | 0.00497894 |
| 全局共享、batch | 0.00517043 |

模型相对 batch 的平均 Brier 改善约 0.00025517，相对 coverage 改善约 0.00006367；
相对轮转和固定哈希则更差。固定份额/私有 coverage 的资源权限因素不同，不能将它视为仅选择器不同的同一比较。
上述是已暴露开发日结果，非独立过程确认；3 个正例无法支持稳健的极端事件泛化结论。
`COMPARISONS.json` 给出缺失结果敏感性界，它不是统计置信区间。

## 13 次发送前失败必须保留

288 个登记控制器调用中，275 个具有 HTTP 意图和合法响应，均通过捕获/消费审计；
另 13 个记录 `BlockingIOError`、`remote_execution=not_sent`、无 HTTP 意图。
本次未修复或重试这些调用，未删除相关预测机会。具体根因需要独立诊断，不能只凭异常类名断言是某一种锁竞争。

提供方已记录用量为 1,119,368 tokens；13 个失败没有 usage，资源账本保守保留 432,640 tokens 配额。
配额不是已消费或已收费 token。消费者将这些项记为 `unknown_execution`，与运输层 `not_sent` 存在分类差异；
应在下一轮核查发送前失败的分类/额度释放规则，保留本轮原始回执和分数。
整批 `passed=true` 表示完整分母和审计通过，不代表 288 个调用全部成功。
