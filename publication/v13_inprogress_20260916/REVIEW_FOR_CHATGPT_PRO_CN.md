# 给 ChatGPT Pro 的 v13 复查任务

请审查这个具体提交中的代码与证据，不依赖此前聊天。先读根目录 `LATEST_PROGRESS_V13_CN.md` 和本目录 `PROGRESS_SNAPSHOT.json`。本次是进行中快照；完整日历、强程序和正式模型比较是否完成，应逐项以带时间的原始回执判断。

## 研究目标与当前范围

DisasterTrace 评测 LLM 在共同专业预报、共享预算、可用时间及明确修订协议下的证据获取与预测流程。C1 关注资源分配、共享和及时采用；C2 关注有限合同内的证据支持、联合可达性，以及获取/处理/时机到未来风险预测的实际作用；C3 关注跨灾种、来源和模态的可复算落地。

当前最深链是低能见度：三地区九站的 TAF/METAR、年度冻结程序预测器、固定 1 小时未来站报目标。完整日历为三地区、四个季度周、每周七天、两个阈值，共 168 个单元、840 条程序轨迹和 12,096 个机会。这些不是 168 个独立灾害过程。16 灾种仍是总路线，不能说全部已达到这个深度。

## 需要优先检查的问题

- **比较身份与完整分母**：原轨迹继续用各自原始 ComparisonContract 重评分，不能重绑旧 journal。FOLLOW/common/values 的不同消费者应明确区分；失败、迟到和缺失 Y 不能按方法删题。
- **API 实际生命周期**：检查 `api_transport_v2.py`、`production.py` 的发送许可、原始字节捕获、可信 hash、追加恢复与实际消费者。未知远端执行不应重发或抹去费用；旧失败记录不能改写为成功。
- **查询意图与执行前缀**：`selector_contract_v2.py`、`session_checkpoint.py` 应保留模型的完整有序意图与未执行尾部原因。空选、全取、非法/超时均按冻结合同处理。
- **GET 与支持语义**：检查 `residual_query_plan.py` 与新 GET 排除逻辑，确认私有缓存不会被跨目标共享，pending/UNKNOWN 不被重复发送。E 充分与 F 可预测性不能混同；当前 GET 不是全部 PROCESS/TIMING 实验。
- **强程序与 M01 门槛**：固定程序生成 F；通过重算实际 EvidenceBundle 验证付费信息被及时消费。M01 的不同查询及不同概率见证不要求正收益；它不能证明公开查询属性一定有可学习价值，也不能证明模型将获胜。
- **来源、时间和独立性**：年度训练时点与实际调用时槽的差异已有数值影响；目前选择固定 bank 以隔离选择器，不能把它说成已消除。共同缺失掩膜不保证总体无偏，开发日和同一过程不等于独立确认。
- **执行资格与结果解释**：程序/接口检查通过不是 novelty 已验证。原 12 次 M00 不可当成 12 个完整模型天气日；最新 M01 是否有实际 HTTP/完整评分，应看本次快照而非计划额度。

## 已知限制与待完成项

首次 M01 平台提交因 CPU 配额为 0 被明确拒绝，已登记资源释放后的自动提交。模型比较不能在技术门槛之前发送请求。平台接受、实际 HTTP、模型回复合法、完整天气日评分是不同状态。

开发 Git index 曾被 10:14 UTC 的 stat-cache 刷新改变字节 hash，原 17 个暂存新增路径保留；该差异已记录，旧 finalizer 的 preservation 条件将如实反映。不要把它与源码/数据 hash 一致性混为一谈，也不要通过改写旧回执掩盖它。

M01 的最终比较、独立过程确认、多截止新银行资格、PROCESS/TIMING、第二条合格灾种主动链与原生影像消费仍需各自证据。未读 Bay 确认周保持关闭。总体没有可据此宣称 LLM 优于强规则的新结论。
