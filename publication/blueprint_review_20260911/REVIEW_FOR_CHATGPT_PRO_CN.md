# 请复查 DisasterTrace 的完整数据方案及实际样例证据

请使用 `sisuolv/disastertrace-benchmark` 的 `next-phase-v1` 分支，记录实际读取的 commit。先读本目录 [README](README.md)，再读 [整体方案](../../plans/v6_blueprint_sample_validation_20260911/OVERALL_PLAN_REFINED_CN.md) 和两张细表。

研究目标是：在固定未来目标、共同专业基础预报、异步资料、查询预算和准备截止下，评测 LLM 主动取证对预测与研究情景决定的增量。16 类灾害共用框架，但观测 O、分析/派生产品 P、确认报告 R 分别结算。主标签不依赖新增逐题人工复核或 LLM judge。

请优先检查：

1. 16 类灾害及其子类的数据组合是否真正支持所定义的未来目标；是否将河洪替代城市内涝、积雪替代暴风雪、USDM 替代闪旱、火险替代实际扩展。
2. 样例“可下载”“可解析”“语义正确”“当时合法可见”“可自动结算”“可再分发”是否被清楚区分；请引用具体审计字段，而非仅凭来源名称判断可用。
3. GHCNh 单位/QC、新版天气码、MRMS 局地表、P-ETSS 热带排除与垂直基准、TAF 时间组、GEFS 成员、CPC 季节支持是否仍有隐藏错误。
4. 监测队列、诊断队列、父事件分组和已暴露样例登记能否防止选择偏差及跨灾种泄漏；报告负例和物理未发生是否混淆。
5. 相比已有主动获取、预警 Agent、来源依赖与概率预测工作，增量问题是否足够具体；最新业务预报、固定轮询、并行全读、依赖感知融合是否构成强对照。
6. 固定未来目标、等待/准备时限、概率评分、未结算分母和状态修复实验是否支持所声称的机制解释。

建议输出：按严重性排序的发现及文件/行号；区分已证实问题、疑点和附件缺失；给出最终灾种/来源保留、条件保留或删除的建议；提出最多五项能改变研究结论的优先改动。

当前证据边界：125 次请求，31 条科学内容解析记录和 2 条渲染地图记录；97 项来源登记不是独立数据集数量。冻雨和沙尘站报已取得正例，但它们是两个已暴露的历史过程。认证来源、M4Fog、TorNet 新正例及部分专业产品语义仍有缺口。新正式预警任务及模型调用均为 0。

阅读附件不含大型原始数组。无法从随包字节重新验证的科学结论应标为“继承审计结论，原始数据未随包”，不能写成亲自完成了数组复核。也不要为复查自动启动 GPU worker、付费 API 或大规模下载。
