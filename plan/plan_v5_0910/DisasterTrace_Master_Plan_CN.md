## 1. 唯一研究主线与最终交付

### 1.1 一句话定位

> **DisasterTrace 在多灾种、异步且可修订的证据流中，检验模型能否找到值得获取的信息、只修订有依据的状态，并将这些修订转化为对固定未来目标更准确、更及时的判断。**

这是一项待数据和实验验证的贡献定位，不是“首次”或投稿保证。增加数据源本身形成覆盖和资源贡献；真正的研究增量还需要证明：时空/版本适用性、局部修订、信息选择与预测结果之间产生了以往简单最终答案分数无法区分的关系。

### 1.2 三层产品，共用一个数据与执行内核

| 产品层 | 接纳条件 | 用途与公开统计 | 不允许的包装 |
|---|---|---|---|
| **Catalog：广覆盖事件和证据目录** | 有来源、基础元数据和可说明的使用条件 | 灾种、地区、年份、来源记录、事件关联、模态资产、接入状态 | 仅登记一个网址就称完成数据集；把目录记录都算独立事件 |
| **Broad：大规模多模态任务集** | 实际输入可解、有继承标签或可复算参考、变量与范围明确 | 感知、地图/表格理解、当前陈述、空间与时间对齐 | 静态瓦片自动称时序；用不可读图片要求隐藏精确值 |
| **Trace：连续证据与预测核心集** | 资料序列、目标/时间/版本、分支开放规则及参考足够 | 状态修订、视觉记忆、持续预测、恢复与信息成本 | 所有历史资料都自称真实公众可见；把公告值当未来观测 |

**Active 是 Trace 中具有合法查询目录、时间/资源预算和固定未来结果的严格子集。Prospective 是采集与评价模式，不是将相同事件再计一次的数据层。**

某一数据源可进入多个层，但资格是逐产品/逐样本确定，不是整源自动升级。原始科学数组可用于工具辅助轨，普通 VLM 则使用记录过的图像视图；权限不同分别报告。

### 1.3 建议容量目标

| 项目 | 目标 | 解释 |
|---|---:|---|
| 候选来源登记 | 原58组全部登记 | 58是来源族数量，不是已接入独立数据集数量 |
| 灾种标签 | 19类气象/水文/气候＋3类天气相关扩展 | 拟议分类；发布时按真实准入情况展示覆盖矩阵 |
| Broad | 20,000–50,000个合格事件—区域/站点时间窗口 | 不是相同数量的独立天气系统；QA变体另计 |
| 证据资产 | 100,000级不可变资产作为工程容量目标 | 一个内容、多次引用或送达不能重复算物理数据量 |
| Trace | 2,000–5,000条合格场景轨迹 | 与Broad可共享事件；不是所有类别均有严格历史版本 |
| Active | 300–800条场景作为正式候选池 | **是Trace子集，不能与Trace数量相加**；实际规模在资料准入后冻结 |
| Prospective | 按固定地区/站点/时间窗连续形成批次 | 不承诺某期限必有足够极端事件；正常、边缘、未解析窗口全部登记 |

这些目标沿用并细化[S1]的容量规划，不是统计充分性证明，也不是这一轮的下载/运行额度。独立来源组、事件—地区记录、原始/派生资产、窗口、任务、检查点、模型调用七类数值分别报。

## 2. 如何覆盖22类，而不把普通天气和灾害代理混起来

保持提供方原始分类，另建立 `hazard_taxonomy_version` 的多标签映射。台风/飓风同属热带气旋；复合灾害用关联，不为凑类别重复计算。[S1]

| 类别组 | 类别 | 首要资料组合 | 优先形成的任务 |
|---|---|---|---|
| 风暴与大风 | 热带气旋；温带气旋/非对流大风；雷暴大风/下击暴流 | NHC、IBTrACS、Digital Typhoon、Storm Events、GFS/HRRR、站点 | 图文对齐、当前预报、空间变化、未来风/位置 |
| 强对流 | 龙卷风；冰雹；雷电 | Storm Events、SEVIR、GOES、NEXRAD、ESWD、SWDI | 多源感知、警报与报告区别、短时序推理；真值足够才预测 |
| 降雨与内陆洪水 | 暴雨；山洪/暴洪；河流洪水 | IMERG/GFS、SEVIR、洪水影像集、NWPS/HEFS、GloFAS/GFM、USGS观测 | 累计量、淹水关系、预报修订、站点超阈与主动补查 |
| 沿海与海洋 | 风暴潮/沿海洪水；极端波浪 | CO-OPS、GESLA、NHC、ERA5；另审NDBC | 水位/浪高时间序列、阈值结果；潮位/增水/波浪分别定义 |
| 温度 | 热浪；寒潮；霜冻 | GHCN、ISD、ERA5-Land、GFS、CMA、NWS | 持续时段、异常/阈值、预报修订；霜冻损害不能由低温直接推出 |
| 冰雪 | 暴雪/吹雪；冻雨/冰暴 | Storm Events、站点、SNODAS、HRRR、NWS | 相态、积雪/降雪、低能见度和警报更新；不把雪深当结冰 |
| 长期水分异常 | 干旱 | CHIRPS、USDM、EDO/GDO、站点/再分析、EDID | 周/月图文状态、趋势与来源修订；指数≠实际社会损失 |
| 空气与能见度 | 沙尘暴；浓雾/低能见度 | ISD、CAMS、GOES/风云、NWS/Storm Events | 现象识别与代理区分；可先做明确能见度测量目标 |
| 天气相关扩展 | 野火；野火烟雾；降雨滑坡/泥石流 | FPA FOD/MTBS/FIRMS/EFFIS、CAMS、COOLR、Landslide4Sense、CEMS | 火点/边界/风险区别、图文变化、触发因素与影响证据 |

**Forecast/Active准入不能仅凭灾种名称。**若龙卷风只具有报告而没有充分空间观测覆盖，先形成“报告/预警陈述”任务，不用未报告地区生成可靠负例。若滑坡瓦片缺时间/位置，先进入感知任务。若只有事后最大洪水范围，不能放进早期洪水预测输入。

多时间尺度按类别配置：强对流可为分钟/小时，气旋和河流可为小时/天，干旱可为周/月。不要让所有灾种一律五轮、每轮六小时。时间尺度由产品和目标决定，再做跨尺度的机制分析。

## 4. 数据构建：三条生成路径共用标准对象

### 路径A：目录驱动

`原生事件/警报条目 → 原ID及类别保留 → 事件—地区记录 → 跨来源关联 → 限定时空取证 → 任务候选`

用于Storm Events、EM-DAT、EONET、GDACS、FPA FOD、CEMS等。保留报告时间、事件时间、空间精度、严重性与纳入规则。县区、国家或制图AOI不可直接当独立物理过程。

### 路径B：现成数据集驱动

`原始manifest与拆分 → 文件/标签许可 → 影像/时间/几何校验 → 实际模型视图 → 新任务或原任务对照`

用于SEVIR、Digital Typhoon、洪水影像集、现场图文等。先继承清楚的原标签和时间，新增任务另外生成自己的参考。原训练集、验证集、测试集身份保留，避免把已公开训练材料当全新测试。

### 路径C：连续观测/预报窗口驱动

`站点/格点覆盖 → QC与基准期 → 冻结阈值/持续条件 → 时间窗口 → 时空过程合并 → 正常/边缘/极端/缺测分层`

用于热浪、寒潮、暴雨、大风、能见度、积雪和干旱。事件发现可以用事后观测做**回溯诊断选样**，但不得冒称前瞻样本；正式概率/虚警评价需用事先登记的固定区域/站点/时段目录。测试期信息不能用于拟合阈值、校准分布或筛选最难样本。

### 每条路径必须产生的统计

`source_rows → normalized_records → linked_event_groups → assets → eligible_windows → compiled_tasks → trace_scenarios → active_scenarios`。

每一步保存数量、排除原因、模态缺失、可用性证据比例、标签来源、地域、时间和许可状态。空集合、下载失败和真正无事件是三种不同情况。

## 5. 对现有代码的改造，不复制多个科学内核

本轮新读 `forecast_task/protocol.py` 仍将累计 `visible_source_ids` 渲染为文本，再附加方法自己的carrier。[C2] 其余下表行为来自相同提交的审查[S3]，不是本次新执行测试。

| 现有组件 | 保留/复用 | 新版需要做的事 |
|---|---|---|
| `forecast_source/pipeline.py` | 请求意图、原始字节、头信息、哈希、封存 | provider接口、滚动发现、内容版本与采集日志；不解除旧固定范围保护 |
| `forecast_task/compiler.py` | public/private分离、来源映射、编译身份 | 事件级多query、跨源同刻发布、独立目标/送达、分支Gold |
| `forecast_task/protocol.py` | 真实历史、请求记录 | Full-evidence、Streaming、Budgeted retrieval及主动访问分开 |
| `models.py` | 类型与机械状态更新思想 | 新严格类型、完整引用、未知时间、同值来源刷新、预测/结果 |
| `evidence.py` | 可用区间上界严格门控 | 工具/检索/缓存/父资产同一门控；controlled与prospective身份明确 |
| `runner.py` | carrier变换、机械应用状态 | 有序事件与动作循环；每步落盘；每轨隔离；真实与逻辑时间分开 |
| `interventions.py` | withholding等基础 | 旧版替换≠旧版再次送达；重复送达必须保留 |
| `adapters.py`/视图 | 已有图像传输思路 | 科学数组≠JPEG；记录处理器/最终图像/预算；不继承宽松修复和隐式重试 |
| 旧scorer | 原任务的严格陈述核验 | 新建预测outcome、修订、时效评分，不能偷偷改旧得分 |

推荐单个共享命名空间：

```text
src/disastertrace/active_forecast/

  registry.py              # 来源、灾种映射、权限、schema漂移
  storage.py               # 内容寻址与追加日志
  availability.py          # 按具体内容版本的时间门控
  lineage.py               # 描述/派生/替代/同内容；不自动推物理因果
  providers/               # 网络/静态档案/站点/格点共用协议
  ingestion/               # 导入、窗口生成、事件关联、分片准入
  views.py                 # 原文、表、地图、曲线/栅格的可读视图
  compiler.py              # Catalog→Broad→Trace资格与任务
  reference.py             # 参考侧事实、可支持状态和更新义务
  outcome.py               # 独立结果及更正版本
  environment.py           # GET/WAIT/SUBMIT/COMMIT
  journal.py               # 每次尝试和每轨故障恢复
  baselines.py
  interventions.py
  scoring.py
  analysis.py
```

这是建议结构，不是已存在的实现。只有需要用到的文件才创建；参数差异写配置，不能再给每种提示/格式复制一整套内核。若用户本地已经有等价新模块，迁移方案先做差异检查，不以本建议目录名重复开发。

Git只保存代码、规格、小fixture和manifest；大文件用持久数据盘/对象存储。CCI容器内本地临时目录用于缓存，实际持久根通过配置指定，不硬编码开发者绝对路径。

## 6. 必须先冻结的数据契约

### 6.1 主要对象

| 对象 | 关键要求 |
|---|---|
| SourceDefinition | 原DSID、产品、模态、许可、访问条件、更新/保留、parser版本、计数口径 |
| EventRecord / EventGroup | 提供方原ID不丢；物理过程、地区报告、compound关系与匹配依据分开 |
| ArtifactSnapshot | 内容hash、提供方item/version、观测/有效/发行/首次捕获、空间与变量定义、raw/view引用 |
| CaptureRecord | 请求/响应、分页、限流、错误、重试、具体版本取得时间；密钥和签名token脱敏 |
| DeliveryEvent | 场景/分支/序号/内容/送达类型/时间；相同内容可多次送达 |
| QueryTarget | 目标对象、变量/测量种类、单位/阈值、固定未来时刻或区间、task_kind |
| ModelCommit / Prediction | 原始响应、状态操作、完整artifact+span/region引用、预测形式、as_of/submitted_at |
| StateReference / Obligation | 私有的可支持事实、change/refresh/recheck/preserve/unknown；不注入普通输入 |
| OutcomeRecord | 未来验证来源、值、质量、解析状态、结果版本；不和公告Gold混用 |
| DecisionSpec / Record | 公开研究规则、截止D、成本假设与提交，不声称真实减损反事实 |

新对象禁止未声明关键字段静默丢失；验证时区、区间顺序、单位、有限数值与概率区间。旧通用原型的8个对象探针见[S3]；本轮未重跑，不把旧探针结果当新实现已通过。

### 6.2 时间不能只有一个timestamp

**观测时间、预报有效时间、发行/生产时间、历史可用性区间、首次实际取得该内容的时间、实验送达、模型真实提交**分别存。

`valid_at > as_of` 并不自动违规：当时已发布的未来预报是合法输入。违规的是未来才发布/才取得的具体内容版本被放进早期输入。

历史首次可用时间未知时保留空，不用现在下载时间或发行时间自动代填。三种身份：
- `historical_strict`：有足够的历史可用性证据；严格按区间上界准入。
- `controlled_replay`：声明模拟交付，不声称历史公众确实看到这些版本。
- `prospective`：基于真实捕获与真实提交时间，禁止事后回填。

Derived asset的全部必要父输入也过门控；模板渲染、摘要、索引和缓存不得泄漏未来实例信息。目录中不能先列出未来版本个数、未来才定义的受灾区域或正确待查来源。

### 6.3 去重与关联

内容相同可只存一份，CaptureRecord/DeliveryEvent仍全部保留。相同URL后来返回新内容创建新snapshot。`same_content_as`、`derived_from`、`supersedes`、`describes_event`不能用同一种边；后发布不自动更权威，同机构不同变量/有效窗不自动替代。

同源图可能提供更易读的空间信息，不预设无价值。只有经过信息等价检查的重复子集，才用于检验不应重复计证。

### 6.4 存储形式

JSONL保存记录和日志；Parquet保存大表；原始GeoTIFF/GRIB/NetCDF/HDF5等保持科学格式；模型视图保存明确PNG/JPEG等。需要时使用地理/对象目录标准做**兼容出口**，不把换格式当作论文创新。

原始字节hash、公开视图hash和渲染配置hash都保留。发布manifest绑定实际asset/query/delivery/render/compiler/scorer/split/model配置，不能只有可变远程URL。

## 7. Online实施：尽早保留短窗口版本，采集与模型分离

### 7.1 先保护容易失去的资料

| 服务 | 本轮官方文档确认 | 建议优先动作 |
|---|---|---|
| NWS Alerts | `/alerts`近7天；需标识User-Agent。[W1] | 有界地区/类型采集、完整分页、更新/取消链与原始CAP/JSON封存 |
| NWPS/HEFS | 常规NWPS不是完整历史档案；HEFS实验服务当前约10天。[W2] | 先验证站点和变量，再小范围捕获每个预报周期，不能指望任意回补 |
| FIRMS | RT/URT在对应NRT处理后或超过6小时移除；MAP_KEY。[W3] | 对确有权限和研究需要的地区保存处理层与内容版本 |
| GFS | 生产周期与有效时间分开，累计降水区间及历史band不同。[W4] | 先item/variable审查、再限定AOI导出，固定累计处理 |
| IMERG | provisional被更新；当前文档注明2025-09-30以后无permanent产品，涉及V8过渡。[W5] | 不把“最终版迟早会在此集合到齐”写成依赖；验证供应方版本/替代来源并留缺口 |

这里的产品限制是本轮核查；实际账号、下载、稳定性和费用未验证。部分数据源有提供方归档可另取，但归档可用性不等于完整保存当时每个内容版本。

### 7.2 采集器接口及状态

`discover(scope, cursor) → acquire(candidate, limits) → validate/normalize → snapshot/register → freeze(batch)`。

必须有源allowlist、AOI/站点范围、日期、最大请求/字节/像素/并发、凭据环境变量名、许可依据。无明确范围不执行。读取幂等数据GET可以按政策退避和重试；模型已dispatch但结果不明不能静默重生成。

游标需要重叠回扫，处理旧观测的新版、迟到记录和提供方订正；不能只按最大观测时间推进。记录 `empty_complete / partial / rate_limited / auth_failed / stale_cache / unavailable / schema_changed`，不要把失败解释成无事件。

调度由用户环境部署；本计划不部署后台任务。可按分钟级、生产周期、日/周更新的不同source配置节奏，具体频率先遵守API与缓存策略，不统一高频轮询所有来源。

### 7.3 GEE的位置

GEE负责数据筛选和空间计算；本地/对象存储保存已选数据与导出结果；CCI负责VLM推理。不是每个模型运行时都重新查latest，也不先全量下载全球所有波段。

查询/导出记录包含实际item列表、时间与属性、裁剪区域、CRS、分辨率、重采样、单位、波段、无效值、父源、生成代码和输出哈希。日期查询或任务提交时间不证明后来导出字节在当时已经存在；须记录取得实际结果的时间并复查版本一致性。

GFS降水累计和IMERG降水率分别写测试；S1/S2的云/轨道/极化/重访条件分别写资格规则。若一个目标只需现成配准数据，则直接用档案导入，不为“统一GEE”重新加工一遍。

### 7.4 在线健康看板

每来源报告：最新成功请求时间、最新**内容版本**时间、最新观测/有效时间、覆盖AOI、数据延迟、失败/限流/部分页、内容替换次数、预算用量、准入任务数。一个字段“last_updated”不足以代表全部新鲜度。

## 8. 从资料到任务：统一五个任务族

| 任务族 | 问题 | 可计算参考 | 可覆盖范围 |
|---|---|---|---|
| P：Perception | 读图例/区域/表格/序列中的什么事实？ | 原生标签、几何、公开数值；保留来源质量 | 广覆盖，静态资料也可进入 |
| C：Claim/Alignment | 谁在什么时间对哪个目标说了什么？ | 原文/结构化产品与明确契约 | 大部分灾种与资料类型 |
| R：Revision | 新资料改变哪些值/来源/依赖？ | 每分支三层Gold＋更新义务 | 有清楚版本或时间序列的子集 |
| F：Forecast | 对固定未来目标作出点/概率预测 | 后续独立观测或冻结事后分析 | 有可验证目标的子集 |
| A：Active information | 查什么、等多久、何时提交？ | 固定合法环境、预测结果、公开预算/研究决策规则 | 更严格的Trace子集 |

P/C的广覆盖不等于R/F/A已覆盖同样灾种。发布页按“hazard × task family × modality × temporal status”给出实际资格矩阵。若某类只能做明确的代理目标，任务名写代理，不偷换为实际灾害发生或社会损失。

### 8.1 三层状态Gold与未来结果分开

1. 基础事实：GIS/数据表/继承标签到底是什么。
2. 分支可支持状态：这一分支截至该时点实际收到的资料能支持什么。
3. 更新义务：需要改值、换来源、复核、保持、继续未知，以及公开规则下的依赖输出。

未来概率没有逐题唯一的正确值。Forecast用后续outcome评分；Delay改变当轮信息和事实参考，不改变同一未来物理结果。一次合理更新也可能在某个事件上碰巧变差，所以修订收益看独立事件汇总。

### 8.2 真正多模态的检查

状态任务采用同文不同合法图、同图不同必要文字条件的配对；核对图例、位置、精度、文件名/caption/元数据泄漏。原始图像、VLM实际抽取事实和Oracle图像可支持事实分别比较；不能把更高精度私有GIS事实当图像Oracle。

对Forecast，图是否提供额外预测价值本身要实验，不因为删图导致某模型低分就宣布视觉在信息论上必需。充分结构化空间/数值表示是强基线，不能刻意削弱以突出视觉记忆。

### 8.3 数据缺失、隐藏、遗忘的区别

从未向模型交付必要证据：状态参考按实际开放资料重算，可能未知。已经收到但模型丢弃：不降低参考免除遗忘失败。主动系统未查询的资料不能被算作其“已读”，但系统仍须对固定目标的提交覆盖/预测承担评价，不能靠少查少答刷高条件准确率。

缺少验证观测时outcome为pending/missing/disputed，不能作负例。模型没回答是execution缺失，和outcome缺测分开。

## 9. 主动环境：一个有限接口，不是自由上网代理

四个动作：

| 动作 | 实际执行 |
|---|---|
| GET_EVIDENCE | 在当轮合法目录、明确范围和预算中取得资料；记录实际内容和成本 |
| WAIT | 按冻结时间模型推进；未来资料到时才开放 |
| SUBMIT_FORECAST | 封存固定query的预测、依据、真实/逻辑提交时间；不回写旧预测 |
| COMMIT_DECISION | 在公开研究准备规则下记录截止前承诺；不执行现实应急动作 |

每步可附状态操作，程序只机械执行，不用Gold补语义。默认不提供任意shell、不提供私有目录浏览、不允许改数据或答案。

同一环境固定潜在可用资料、可用性、工具能力、价格和时钟；不同策略选择不同实际资料是被测行为，不要求读到相同内容。但不能给某策略免费预看全部文档来选查询，也不能由私有affected set替它选ROI。

### 时钟与异步请求

分别保存物理资料时刻、逻辑回放时钟、实际wall-clock、工具服务延迟和模型推理耗时。默认请求开始时绑定具体可选响应版本，按声明延迟送达；不能在完成时偷偷换成刚发布latest。若研究完成时读取，需要独立明确的模式。

在统一评测时点读取最后已封存预测，不额外赠送一次模型调用。D之后的预测可用于后续诊断，但不能回填及时准备。模拟时延不冒称历史网络延迟，不能随意设“一次调用消耗一小时”制造困难。

### 持久化与失败

`intent → dispatched → raw_response → parsed/invalid → state_applied → snapshot`。

一个轨迹失败只阻断自己；全部计划目标和原因仍在账本里。合法但错误的状态继续保留。未知提交不自动再发；如服务提供可核实的幂等恢复，使用独立登记的恢复策略。输出修复、重试、摘要和隐式SDK行为都记录并计入预算。

### 11.2 最关键的自动测试

| 抽样 | 同源实际内容/近邻/事件组和twin按声明划分；全源量不冒称独立事件 |

## 12. 实验矩阵：先估吞吐，再扩规模

### 12.1 不把数据总量与模型调用混在一起

目录可以很大；Broad可以覆盖很多变量；Trace可以有几千场景。**不意味着每个模型要对全部数据、全部模态、全部干预、全部预算跑全组合。**

建议三阶段：
- 仪器阶段：少量跨灾种场景，检验图片、协议、时钟和参考。
- 策略阶段：一个或少量固定VLM，比较同权限的不同信息策略。
- 确认阶段：冻结数据和方法后，在独立来源/事件与更多可靠后端上验证主要假设。

### 12.2 一个可计算的试点算例

建议候选：**24个场景 × 3策略 × 1后端 × 1重复 = 72条轨迹**。若设每轨最多12次LLM调用、8次工具读取，则上限分别是**864次LLM调用、576次工具读取**。所有内部摘要、抽取、路由和生成都纳入12次，不是只计最终回答。

这不是已经授权的预算，也不是统计充分性保证。被动/主动协议的实际机会数可不同，应先注册固定评价检查点，再报告系统实际调用量。超限为明确失败/终止，不能后台免费补调用。

### 12.3 基线矩阵

| 基线 | 输入权限与作用 |
|---|---|
| 公开规则/几何/结构化程序 | 状态任务的专门求解；如读取原始GIS，单列tool-assisted |
| 当前合法专业预报 | 对相同变量/目标的预测基准；不把点预测随意转0/1概率 |
| 专业预报＋统计校准/组合 | 仅训练/dev拟合，不接触test outcome |
| 完整合法证据重算 | 在所声明预算内读全；不叫作弊，也不默认免费 |
| 目标/时间/版本过滤检索 | 排除仅正确数据管理就能解决的解释 |
| 结构化状态＋依赖复核 | 对照摘要、空间状态和更新规则 |
| 状态＋模型自行保留/检索视觉证据 | 后续查询与成本权衡，不用Gold选裁剪 |
| 主动查询/等待/停止策略 | 同合法目录和预算下的信息选择收益 |
| Oracle感知/状态/事后最有用查询 | 仅诊断；有额外权限，不混入可部署排名 |

候选公开模型、框架与外部方法在接入前重新核对权重、processor、许可证、API和具体代码commit；不把旧Qwen3-8B文本成绩视作任何VLM已有成绩。BLF/PostTime/StateMem/VersionRAG等先列相关工作与适配候选，未复现不写“作者实现复现”。不依赖某个当下“最新模型名”作为计划成立条件。

### 12.4 必需的配对诊断

同原文、合法不同图；同图、必要文字条件变化；关键资料Delay/Withhold；旧版再次送达；信息等价重复/Null；自然更正；后续新目标；Actual/Masked/Sham/Edited/Oracle。

不存在真实更正记录时，受控更正单列，不伪造官方自然修订。对概率不硬性要求地理远处完全不变，也不要求每步都改善最终误差。载体敏感性不是内部记忆机制证明；Masked无变化可能是当轮可重建、探针不依赖或地板/天花板。

## 13. 评分与统计：三层主表，不用一个万能总分

### 13.1 资料与修订

报告状态/数值/空间关系、源版本、有效期、文本/视觉定位、必要更新召回、错误改写率、同值换源、未知保持、首次合法更正后的恢复延迟。非KEEP机会单独统计，避免大量平稳样本掩盖失败。重查义务不是内心过程，只检查结果/支持与配对行为。

### 13.2 真实未来预测

点预测使用与目标相容的误差：温度/风/水位等MAE，位置使用球面距离。概率使用已有proper score如Brier；分位数采用事先选定的分位数损失等。不同单位和任务不直接混平均。可以报相对明确基线的skill，基线零损失或不稳定分母必须标NA并保留原始误差。

预测增益示例：同一时刻/同一未来目标比较保持旧预测与修订后预测的损失差，按独立事件汇总，正负样本都保留。当前专业预报本身更新的收益，与某一模型状态策略的额外收益分开。

如果结果尚未解析，不强行评分；如果模型缺答，保留固定计划槽位和有效提交覆盖。只在有效预测上报proper score时明确条件性；要给端到端策略值，可使用事先公开的共同fallback（例如当时合法专业基线），fallback次数单列，不能把缺答伪装为模型概率0或删除。

### 13.3 时效、信息与研究决策价值

报告截止前提交率、达到某个预定风险规则的时间、查询/图像/推理/摘要总成本和质量—成本曲线。最终准确、截止前准确与时效不能互相替代。

公开成本—损失模型可作为附加评价：

`loss(a,y) = C*a + L*y*(1-a)`，a表示截止前完成所定义的准备承诺。

这是已有研究模型的使用，假设及时准备避免所建模的损失部分；不是实际减损验证，也不作为新公式创新。多个预先冻结C/L和截止条件做敏感性分析。可共用确定性概率→动作规则，避免让简单数学门槛变成另一个语言任务。计算成本与灾害经济损失不应无依据地换算相加。

### 13.4 分组、泄漏与两个样本分布

- **覆盖诊断集**：选择代表灾种、版本和失效关系，明确为回溯/平衡覆盖，不用它宣称真实误警率。
- **自然机会评价集**：按预定地区/站点/时段和准入规则采集，含正常、边缘、灾害和缺测窗口；概率校准/研究价值在此解释。

原始事件ID不是自动正确的独立组。关联FPA/MTBS/FIRMS、IBTrACS/NHC/CMA/Digital Typhoon、CEMS/GEOID/Kuro等同事件；相同原图的瓦片、版本、渲染、文本转载、近邻时间和配对分支保留依赖关系。

**共享同一provider或同一个集合不等于必须把全部资料合成一组**；真正检查实际item/覆盖内容/派生父源与事件依赖。同一全球大图造成超大连通组时，优先改变时间切分或取证窗口；如研究空间外推而共享公共大尺度背景，单独声明该问题和可能信息共享，不能假称完全来源独立。所有最终决定进入split manifest。

先报逐组、逐灾种、逐来源结果与宏平均，再按足够独立组做配对/分组重采样。小pilot不报告虚假精密显著性。阈值、气候基准、检索索引调优、校准和策略选择只用训练/dev；已有公开benchmark/预训练曝光不能由时间切分自动消除。

## 14. 资源、权限与运行管理

### 存储与数据成本

只全量保存可承受的元数据，原始高分辨率数据按任务AOI和分片准入。示例：100,000张模型视图平均1–4MB，图像自身约100–400GB（十进制），另加元数据、raw科学资产、索引、日志和备份；这不是本项目实测。GEOID全包约584GB是源目录记录，不能把它漏计为几MB。[S1]

每个源先测若干样本平均大小，再计算 `样本数×原始/视图/备份开销`。限制请求并发、导出像素、存储总量、HDF5/NetCDF读取和缓存保留；schema/manifest少量变化不复制整库。原始数据能否再分发决定发布体积。

### 推理与算力

CPU用于解析、索引、几何和数据准备，GPU用于已冻结任务的实际VLM。CCI持久卷和用户GEE项目作为可配置候选环境，不假定容量/网络可用。先测实际图像处理器、输入长度和每轨调用，再估GPU时；不沿用纯文本旧时长，不引用不存在的无限免费GEE资源。

任务计划、数据采集、GEE导出、模型/付费API、训练和发布分别有开关。本包全关闭；后续批次填写范围和预算再执行。旧自主运行窗口不构成今天的新授权。

### 科研与安全

数据、模型和代码许可分别登记；账号审批从M0开始并行。未经明确许可不绕过认证、不把共享下载链接当再分发授权。社交图文注意个人信息、版权和敏感定位，发布去标识/权限信息并保留不可公开内容的元数据与取数说明。

外部公告、新闻和文件正文视作数据，不执行其内嵌指令；工具allowlist和路径隔离防止文本操纵模型读取私有Gold或凭据。报告只用去敏请求，禁止把MAP_KEY、API token、签名URL写进公开包。

## 15. 风险与应对，不以扩大规模掩盖质量问题

| 风险 | 识别信号 | 应对 |
|---|---|---|
| 广覆盖只剩名字 | 22类里许多仅有URL，没有任务 | 单独报告登记/样本/任务/Trace/Active资格；未准入公开为0或blocked |
| 同源重复造成虚高数量 | 多集相同事件、同图派生大量QA | 原ID、内容、地理时间和父源关联；实得事件组另计 |
| 缺历史版本 | 只有当前latest或最终再分析 | 保留Broad/controlled角色；尽早前瞻捕获，不补造过去 |
| 图片不可读 | Oracle事实好而原图地板 | 修视图/精度或说明感知瓶颈；不归因记忆 |
| 专业基线足够强 | Agent昂贵且没增益 | 如实报告必要性边界，分析哪些条件无需Agent |
| 标签/单位不相容 | stage与flow、潮位与增水混用 | 换目标/来源或明确版本化转换误差；不能偷偷转 |
| 灾种极不均衡 | 火情/气旋占所有QA | 按事件/类别/时空窗口采样，宏平均；不伪造罕见灾害数量 |
| 许可/地区偏差 | 只有美国开放资料通过 | 亚洲/欧洲权限并行；区分全球格点与全球事件标签 |
| 配对干预变成造假 | 官方正文被改却称自然 | native/controlled_generated/official_rendered逐项标记 |
| 自由策略刷覆盖 | 少查少答但条件准确率高 | 固定评价目标、覆盖、缺答fallback和总成本共同报 |
| 公共模型污染 | 公布训练数据被当全新test | 数据使用/模型版本/时间/外部权限披露；保留前瞻批次，不宣称零污染 |
| 范围失控 | 每灾种新内核、每提示新阶段 | 一套契约/执行器；provider/task配置扩展；31工单分批集成 |

某个来源失败不意味着整个计划停止。它可以留在Catalog，或只进入较浅任务；但不得在发布时暗示它已经支持完整预测和交互。某个任务低成本被解决也应保留正结果，不通过加无意义噪声制造“难度”。

## 16. 论文、发布与终态验收

### 16.1 三条贡献契约

1. **数据贡献**：跨灾种/地区/时间尺度的版本化证据资源，能清楚说明原始记录、独立事件和实际任务规模，以及哪些资料适合在线使用。
2. **任务与协议贡献**：同一事件/未来目标中的证据对齐、局部修订、保留与主动取证；将事实参考、预测结果和研究时效分开验证。
3. **实证贡献**：在专业、确定性、完整上下文和版本检索强基线上，定位何时多模态/记忆/主动搜索有增益，何时只是增加成本、重复计证或错过窗口。

这三条需要实际结果，不保证全部预期成立。Related Work Matrix需重新核对直接近邻原文与代码，至少包含气象预报验证、多灾害工具任务、状态/版本记忆、多模态序列、持续预测和信息价值/停止策略六个方向。前文材料提到的EarthVerse、Extreme Weather Bench、SIREN、SpaMEM、StateMem、STALE、VersionRAG、BLF、PostTime、ForecastBench等作为核查入口；**本轮未重新阅读全文，不作新的首创性排他判断**。

### 16.2 建议正式结果图表

- 覆盖表：灾种×地区×任务×模态×时间依据；0和未准入不能隐藏。
- 规模表：源记录、事件组、原生/派生资产、窗口、Trace/Active子集、前瞻批次。
- 可靠性表：读图/状态/来源/修订/恢复、错误与缺失分项。
- 预测表：相同目标/提前量的专业基线、统计基线和Agent。
- 成本/时效表：相同预算下质量，截止前与最终表现分开。
- 配对图：Delay/Replay/Correction/Masked等条件与独立事件结果。
- 泛化表：同灾种新事件、新来源/地区、未见灾种；实际输入重叠说明。

### 16.3 发布包

包含data card、任务卡、来源与许可账本、全部可公开资产manifest、公开投影/私有参考分层说明、冻结编译与评分版本、模型与工具配置、独立分组清单、缺失/排除统计、完整运行及恢复日志、按许可下载/恢复脚本。

许可允许的原始资料可以共享；否则只发布元数据、可公开派生内容和用户自行取得说明。不能将受保护test答案因为“可复现”就自动公开。评测服务/私有测试必须有相应访问策略。

新版发布新manifest；未来outcome更正以新版本重算已保存预测，不更改其原提交。滚动批次冻结，不让排行榜指向一个无版本的latest。

### 16.4 整体完成的判断

“58来源登记完成”“20类有合格任务”“5000场景成功编译”“模型矩阵收齐”“结果可重建”“数据可依法公开”是六件不同的事。终态报告分别给出，不用一个passed代替全部完成。

真正的完成标准是：**广覆盖不是虚数，在线版本不是口头承诺，连续任务有合法证据边界，预测有独立结果，主动获取有公平预算，论文结论能够由保存的资料和实验重新检查。**
