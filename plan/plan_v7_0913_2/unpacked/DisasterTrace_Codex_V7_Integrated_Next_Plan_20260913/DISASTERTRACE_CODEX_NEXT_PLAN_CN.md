## 2. 两份novelty建议如何合并，而不让范围失控

用户材料一侧重：区域值班任务、资料与处理方式联合选择、从同一完整状态重跑、提醒质量、强无LLM工具流程。

用户材料二进一步提出：准备需要时间、共享执行资源、取消或改变安排有代价、准备要求决定信息价值，以及未来的共同风险任务。

本计划采用“同一基础、分层交付”，不将其中一份默默替换成另一份：

| 层 | 对象 | 主要评价 | 何时建设 |
|---|---|---|---|
| E | 当前合法证据到底支持什么 | 事实、版本、窗口、覆盖、删失、缺失 | 优先修完桥接 |
| F | 固定未来量/事件预测 | 合格观测/产品/报告上的适当评分 | 主线继续，不被D替代 |
| A（提醒记录，不另立贡献） | 研究型提醒何时出现、是否持续有效 | 冻结误报政策下的提前量、漏报、重复/撤回 | F主线齐备后并入日志 |
| D-sim | 研究性准备任务 | 按公开规则的及时完成、占用、取消与损失 | 先CPU小状态机；真实评分仅在E/F链和规则明确后 |
| D-domain | 有使用者/文档依据的准备规则 | 相同D计算，但解释范围更接近特定应用 | 条件扩展；不以逐题人工打分为门槛 |
| Live shadow | 只记录、不干预真实业务的前瞻 | 提前提交、实际处理时间、后续结算 | 与历史研究并行的有界阶段 |

D-sim使用真实天气结果和显式假设规则，不能声称减少了真实损失或伤亡。无规则依据时可发布研究性仿真结果；业务规则审核是整体规则/典型案例验证，不是逐题Gold标注。

### 2.1 稳定三项贡献

- **C1**：共同持续更新的专业或明确R基线之上，联合选择资料、处理方法、计算深度和修订/准备时机，是否产生值得成本的改善。
- **C2**：从同一真实监测状态分支执行合法替代路径，将获取、处理/感知、预测融合、修订和准备效果分开核验。不是用解释文本归因。
- **C3**：跨真实物理过程、可回放、可提前提交、可自动结算的资料和任务，报告可迁移结论与不能迁移的边界。

不声称首次多目标、首次工具路由、首次成本—损失、首次持续预测、首次加入模拟器。最终仍由近邻比较、非退化任务和独立结果建立差异。

### 2.2 优先检验的假设，而非预写的结论

H1：相同信息下，更昂贵处理有时无益；可部署的廉价触发/专业工具是必要对手。
H2：在同样原始资料和资源下，少量合法处理分支可能揭示模型在哪一环节损失预测价值。
H3：固定天气信息时，不同准备时长/容量/成本会改变合理行动或获取选择；但在信息、目标、预测器及计算均固定的受控比较中，不应凭偏好系统性改写天气概率。
H4：真正共享的区域处理结果可能改变多目标资源分配；如果普通缓存/批处理完全解释优势，就收缩“智能调度”主张。
H5：预测更准不必然使准备更有效。必须通过同规则、同机会的实际对照验证，不能靠任意延迟制造排名反转。

- 预测侧使用独立历史训练/开发块；未出现稀有正例不能宣布尾部校准。

### 3.2 H07：原生多模态与处理方式选择的重点新增链

**先固定一个能完整获得连续输入和后续结果的小区域—连续日期。**具体日期、区域、产品须由数据审计选择并冻结，不在本计划中虚构已存在闭环。

推荐候选：MRMS合格雨率/累计产品、区域雷达时序、HRRR或匹配的QPF、站点雨量；使用 `pysteps` 的平流/短临作为工具和强对照。

最小合同可选择以下其中一种，不互换：

1. 固定区域未来整段的、明确命名QPE产品面积平均累计量，结果身份P；
2. 固定站点和严格匹配累计窗口的合格雨量，结果身份O；
3. 同产品的未来雨场预测，单列产品预测任务。

必须核验：物理支持区间、率转累计积分、重置、固定网格/投影、缺帧、QC、标度/负码、边界覆盖、版本和实际输入可得时间。

VIL不等于毫米降水；任意雷达反射率不能未经标定变成雨量。输入与结果同属MRMS时披露共同处理依赖，后时刻产品是结果参考，不称独立传感器真值。被雨量站校正的QPE与同雨量站也不能称完全独立验证。

动作至少覆盖：便宜产品读取、区域概览、同资产ROI、数帧时序、专业平流/集合短临、VLM复核、维持基线。每个方法拥有同样的工具权限。

严格有同目标业务产品时进入P基线轨；无法匹配时可用预登记持续性/平流R轨。不能强拼长窗口官方概率到短窗口局地目标。

### 3.3 H08：并行推进，但先核定物理语义

复用已取得CNRFC历史QINE、USGS和站点映射；先确认瞬时/小时平均、调蓄/还原口径、单位、断面、成员身份与历史可得性。

- QINE/kcfs与USGS/cfs的乘1000只解决单位，不解决物理统计支持。
- 不用水位ft阈值给流量打分，不把SQME、SCOC1F合并成同一原始量。
- 原始成员ID未知时，跨周期可比较整个集合分布；不能逐成员相减，不能跨站强行同编号拼联合情景。

### 4.2 三种资源不可混用

1. 信息资源：请求、传输字节、权限；
2. 处理资源：CPU/GPU/工具并发、模型token、处理时间、模型调用；
3. D-sim执行资源：准备队伍、设备、资源日历与占用。

研究构建候选档案的成本另列。文件物理缓存不等于策略免费授权；同策略共享原始文件不等于重复视觉推理免费。查询、计算和准备可以在不同资源上并发，不能因LLM正在思考就冻结已经开始的准备进度。

所有动作先原子预留，再开始，完成结算；已实际消耗不因失败/取消退回。服务返回空与网络失败不同；未读不等于缺报，更不等于无灾害。

### 4.3 统一时间，不混淆四个截止

分别记录：证据可用、预测机会cutoff、目标物理支持/产品发布事件、准备必须完成时间。

固定未来目标不随新预报滚动；不同物理起止窗即不同目标。某个1/3/6h机会封存不关闭该目标的其他合法机会。预测在机会cutoff前持久化才参与该机会；截止后消息可以保存但不能回填。

事件同刻顺序先沿用既有v7合同并显式扩展：已公开release、此前开始动作的完成、基线一致性、机会/准备截止封存、到期清理、唤醒/新动作。零时长环和同刻插队须拒绝。等截止完成是否允许由冻结规则决定；没有此前START与持久化回执不能伪造及时完成。

回放的服务/推理耗时是登记的模型，真实前瞻使用实际接收、处理、提交时间；两类不混排。旧实验并未发现迟到解释低修订，不能用新时延假设倒解释旧负结果。

## 5. 先完成正式评分准入，不扩提示矩阵

### 5.1 新增不可绕过的 `AdmittedForecast` 清单

每条包含：

```text
run_id / code_sha / provider_version / policy_version
session_id / target_contract_hash / opportunity_id
cutoff / target_time_semantics
bundle_hash / baseline_snapshot_hash / baseline_context_hash
call_started_at / call_completed_at / submitted_at
receipt_ids / actual_cost / authorization_digest
state_prefix_hash / effective_forecast / effective_mode
admission_status / rejection_reason / replay_binding
```

正式入口须核验完整字段与真实回执，不仅检查JSON里自报时间。离线历史场景明确使用logical timestamp并标scenario；它不是实时签名证明。哈希链提供内容可核查性，不自动保证恶意用户无法伪造时间。

纯 `paired_scores()`继续允许作为数学工具，但正式报告必须由 `admit_and_score()`或等效管线消费通过准入的清单。每个失败保持机会分母，固定FOLLOW/回退规则单列，不能由评估器依据结果挑选回退。

### 5.2 状态边界

修复/验证迟到FOLLOW、撤销、基线更新、override过期及同刻行为。封存预测不可变；较晚合法机会可以继续更新，物理目标结束后无新有效预测。

区分：

- 精确输入快照哈希；
- 目标相关的完整内容/分布/条件/有效期/映射版本指纹；
- 原始文件版本。

镜像仅文件封装变化不一定撤销覆盖；均值一样但条件或分布不同可能必须撤销。不能根据一个概率标量来代表完整上下文。

### 5.3 三类E

- `E_certified`：公开确定产品事实或有合同测量误差界；
- `E_perception`：原始图像对既有标签的识别评价；
- `E_oracle_facts`：特权事实诊断。

原图交付不自动让隐藏mask成为已知事实。通用桥必须绑定目标/变量/空间、单位、开放闭合端点、版本、可得时间、权限及父资产。

首批从已有真实数据建立三个E类型：TAF条件段完整覆盖固定目标；降水累计缺段及越阈能否判断；同变量同支持窗口版本是否相同。保留邻站存在命题作回归，不以它代表全部C2。

`Y(E)=空集`是inconsistent；缺失上界不拿经验最大值充当硬上界；重复/重叠资产不重复累计；订正替换后支持未必单调收缩。

联合参照限定优化对象：E源查询覆盖、或包含明确处理节点的可认证事实覆盖。它不是最优F/最优D，不能把F预测错误自动归为未达到E上界。

## 6. 从“查来源”扩成“资料＋处理方法”的有限动作空间

### 6.1 `ActionSpec`

建议字段：

```text
id / family / product_or_tool_version
input_contracts / output_contract
required_parent_assets / permission_scope
legal_target_relations / release_predicate
resource_upper_bounds / duration_model / output_size_bound
shared_result_key / idempotency_key
failure_policy / cancellation_policy
proposed_or_verified_status
```

初版动作：`ACQUIRE`、`RENDER`、`RUN_DOMAIN_TOOL`、`INFER`、`WAIT`、`SUBMIT`、`FOLLOW`；D-sim再启用 `START_PREP`、`CANCEL_PREP`、`REPRIORITIZE_QUEUED`。调节参数只能来自白名单，不开放任意shell或任意网络。

把“某专家/工具处理某份信息”记成复合动作。实验仍先分解比较，再比较联合选择；模块分开不代表可以声称统计上独立优化总是最优。

### 6.2 返回值与共享

- 请求发起时固定实际产品版本；完成后才能读。
- 专业工具输出是预测/估计，不能变成Gold或精确物理事实。
- 同产品ROI/重渲染属于新处理，不算新观测；费用只免去已支付部分。
- 共享必须由真实区域覆盖、同产品、流域或目标关系证明。
- 相同公共基线本来就供所有方法使用，不以共用基线ZIP计额外取证收益。
- 专业基线、程序对照和Agent都可使用同样批量接口、缓存、工具和优化器。

### 6.3 部署策略和事后参照严格分开

学习或规则策略只能看到当时公开内容/元数据和已获取结果。不能在选动作前逐一偷读候选结果计算真实损失。

事后分支可读取合法响应并在之后用结果评价，记录为诊断。其最优分支不是可以部署的策略。BRiG风格小风险回归器仅在新授权且开发数据有足够支持时训练；不在首轮训练大型RL或VLM。

## 7. 完整状态分支重跑：本计划最关键的新交付

### 7.1 `SessionSnapshot` 不只是 EvidenceBundle

必须包含：

```text
logical_time + event_cursor + event_order_version
all targets + open/sealed opportunities + active baseline contexts
current forecasts + FOLLOW/OVERRIDE + pending proposals + expiry
spent/reserved resources + per-target quota + current concurrency
physical cache identity + policy entitlements + derived graph
in-flight acquisition/render/inference (version/start/reservation/progress)
policy-visible memory/context and RNG state
D-sim job state/progress/crew assignments (when enabled)
external archive version (evaluator-only cursor) + continuation policy version
```

未来文件索引、隐藏结果、oracle结论留在评估服务，不序列化到model view。公共切分图不能因为全用同一提供方就把全球串成一组；具体相同天气过程/资产重叠另外登记。

### 7.2 三种分支，不混用结论

| 类型 | 固定内容 | 允许改变 | 解释 |
|---|---|---|---|
| 固定证据分支 | 已获输入、目标、基线、截止 | 预测器/表示，明确记录增减信息 | 理解/融合效果，不是获取策略 |
| 固定候选回放 | 原候选、原完成时刻、输入日志 | 采用/失效规则 | wrapper直接效果，不含策略适应 |
| 完整状态分支 | 完整状态、外部档案、初始资源、继续策略 | 首个合法动作/有限动作序列 | 包括后续状态与资源变化的结果 |

相同数据包不代表状态相同；复制时钟但不复制reserved预算或准备进度，会制造免费资源。各分支内取证/模型调用照实计费；研究运行多个分支的总成本另列，不当部署成本。

### 7.3 有界分支计划

首轮每个前缀预登记不超过4–6个合法候选；最长两步。超界返回 `not_evaluated`；不能因为某分支高分才继续探索、低分就删掉。

固定继续策略必须对不同后续状态正常响应，不强迫各分支执行同样已不合法动作。外部天气轨迹不变；D-sim准备状态按动作变化。未归档响应不生成、不插值冒充真实返回。

模型输出仅在完整消息、模型/处理器/工具版本、随机参数、输入资产与合法上下文完全一致时可复用。新输入通常需要新调用；重放不是新增推理。相同随机种子用于可配对随机工具时，种子按产品/动作身份派生，避免仅执行顺序改变所有随机流。

### 7.4 分支归因表

报告共同基线、当前策略、每条可行分支的F损失、E状态、实际完成、费用和D-sim结果。

同时给出：

`gain_over_model_without_extra = L(f(B),Y) - L(f(B,E),Y)`

`gain_over_common_baseline = L(B,Y) - L(f(B,E),Y)`

不能将恢复模型自行引入的0.5退化当超越基线；不能把多个模块差值直接相加成无假设的因果百分比。

## 8. D-sim：小而完整的准备行动环境

### 8.1 先登记“谁、什么准备、什么假设”

一页 `DECISION_SCENARIO_CARD.md`必须写明：研究使用者、目标结果、准备作业、资源单位、释放/截止、准备时长、可取消性、结果生效与持续期、耗时依据、成本依据、缺失结果政策和用途限制。

场景规则来源分为：`toy_protocol`、`research_assumption`、`documented_domain_rule`、`stakeholder_reviewed_rule`。前两类可做工程和条件仿真，不称经过业务验证。不存在真实人类oracle；申请人工复核时只能消耗已规定队列资源或记录人工请求，不自动收到正确答案。

### 8.2 初版状态机

```text
NOT_STARTED -> QUEUED -> RUNNING -> READY -> EXPIRED
       QUEUED/RUNNING -> CANCELLING -> CANCELED
```

- `START_PREP`申请启动：原子分配人员/设备，不足时按明确队列规则等待或拒绝。
- 已开始作业按实际时间推进；LLM推理不暂停它。
- 第一版不支持无代价pause/resume。取消保留已耗工时和清理时间，重新启动按场景定义是否保留进度。
- `REPRIORITIZE_QUEUED`只改变排队；修改运行任务必须显式取消/迁移，并计成本。
- 完成后是否释放施工人员、是否继续占用设备，由规则定义；准备保护维持到何时必须明确。
- 预报基线更新或旧override失效不能自动撤销已开工准备。预测状态与物理准备状态分离。
- 重复start/cancel按幂等ID处理；恢复不能重复扣费或重复派队。

### 8.3 缺结果不能当“白准备”

若天气结果未知，可知的工时、违规、取消等仍报告；miss/waste/结果相关损失标未结算，必要时给界。不能将未知当无灾来奖励不准备。

首个最小D任务使用固定、预登记风险时点 `d_j` 与二元结果 `y_j`。早于 `d_j`完成即 `r_j=1`。可采用明确研究损失：

`L_D = Σ_j w_miss,j * y_j * (1-r_j) + Σ_j c_work,j * actual_work_j + Σ_j c_cancel,j * cancel_count_j`

它不是现实货币损失，参数写研究单位并单独报告各部分。正例上的未准备/迟准备、负例上的准备工时另报，避免同一耗时/惩罚重复计入。时间窗内首次越阈的D任务需要足够连续结果，不能把单个未来报告变成未知的精确onset。

### 8.4 最小非退化对照

始终不准备、按序尽力全部准备、基线阈值触发、最早截止、基线+滚动优化器、合法便宜全读+领域工具+同优化器、事件触发混合策略、有限学习策略、LLM策略。

不能要求Agent胜出；只能要求任务确实有不同可行路径、资源和时长不是虚构成特定方法有利、oracle与部署对照不混淆。小型调试可以用合成场景覆盖非退化边界，但真实确认不按哪种方法赢来选参数。

优化器使用预测分布或冻结估计，不读取未来结果。事后完美信息最优仅作下界/归一化参考。时限内只获可行解就报告可行与bound，不声称最优。

### 8.5 准备需求改变与天气信念分离

执行两种不同试验：

1. **固定信念诊断**：相同天气目标、可见数据、处理与计算条件，仅改变准备时长/容量/成本。冻结天气预测头不接收偏好字段；行动头应接收它们。这个版本检查软件隔离，不证明模型自然不受偏好影响。
2. **模型行为试验**：向端到端决策系统呈现不同需求，比较其天气概率与行动变化。用固定证据/资源子条件识别偏好污染；全策略若获取了不同资料或花了不同计算，不能要求最终预测数值不变。

不奖励每次行动变化；有些参数改变确实不改变最优策略。用程序边界/预登记参数验证预期敏感区，不按LLM结果挑条件。

### 8.6 共同风险：后置但不遗漏

首版多目标共享准备资源，可先用各目标边际概率和可加预期损失；这在定义下可能已经足够，不能为了nova强加联合分布。

只有目标包含“至少两个同时越阈”、容量溢出概率、CVaR或其他非线性共同损失时，才需联合风险。届时新增 `JointTargetContract` 和联合情景预测，不复用单目标概率字段；保留同一集合成员跨站身份。身份未知不随意拼接，不将各站概率相乘。

例如相同0.5边际对应完全相关或互斥两种联合结构，这是协议测试，不当作真实河流的已观测联合分布。合格真实联合情景仍需来源和过程验证。

## 9. 提醒与online验证

### 9.1 提醒不是准备完成，也不是自动公共预警

`AlertRecord`记录目标、阈值/规则版本、首次触发、更新、撤销、有效期、相关预测和证据。提醒层只读，不发邮件/短信、不调用现实设备、不改变河流/航班/公众行为。

误报政策在开发期选择，测试期不重调以达到相同误报率。事件匹配、一事件多次提醒合并、持续时长与提前量定义冻结。只有观察到合格onset才报告准确提前量；离散缺测情况给区间或不可计算。

准备收益属于D-sim，提醒识别属于A，预测概率属于F；不要合成一个隐藏权重的总分。

### 9.2 三种时钟与模型污染边界

历史受控回放、核准历史时间、真实前瞻分别标记。first-seen保留最后一次成功未见与第一次成功见到的区间；首轮已存在资料为左删失。不将抓取时间回填成历史发布时间。

模型输入截止隔离不能证明预训练没见过历史事件；匿名地名也不能提供该证明。前瞻使用新冻结方法和未来目标，保留所有普通窗口、失败与未结算。

### 9.3 有界影子运行

先用CPU/program shadow测试新产品发现、版本追加、截止与结算；再在单独授权下加入有限VLM。作业有明确起止/请求上限/重试退避/停止条件，不创建无限后台守护进程。模型调用不得跨过截止补写结果。

实时获取、处理、模型推理、准备推进并发时，测量真实硬件和服务开销。历史加速回放中的假设耗时单列，不声称真实部署延迟改善。

## 10. 基线、指标、统计与科学有效性

### 10.1 固定什么再比较什么

- 固定预测器比较获取：不额外取证、全读、轮询、变化/风险/覆盖规则、LLM。
- 固定已获证据比较处理/预测：领域工具、冻结统计、原生VLM、明确特权事实。
- 固定候选/完成时刻比较修订规则：两个wrapper和明确门控。
- 固定预测比较行动：阈值、调度器、LLM规划，均有同工具与约束。
- 固定行动方法比较不同预测：排除优化器本身贡献。
- 2×2分配×授权先固定同一selector；另表比较selector，不混成三因素差异。
- 端到端等总成本与固定预测机会诊断分开；后者不冒充前者。

### 10.2 E/F真实调用矩阵

先修接口，使用无填值答案的明确合同；分别真实运行E-only/F-only/joint。生成需要新推理时必须计数，不能把旧joint拆成新独立实验。

例：12个基础机会×3证据条件×3head×1模型=108次调用，只是预算算例。多表示、重复、分支和selector均另外相乘并预登记。工程smoke规模不用于显著性；正式样本量由独立过程和最低有意义差异确定。

### 10.3 指标

- F：按目标类型Brier、MAE；有合格分布时CRPS/区间覆盖等。多个阈值共享结果不增样本量，不混不同单位。
- 风险识别：AP/ROC、开发期冻结规则下召回/误报；无正例ROC等返回不可估计，不用0掩盖。
- E：按命题/缺失/删失/版本/覆盖的混淆；未请求输出不是unknown错误。
- D-sim：需要却未及时准备、准备工时、取消、资源违规、模型规则下损失。连续行动不能用静态REV替代。
- 资源：获取、处理、模型、执行资源分列，预算使用和真正binding维度报告。
- 稳定性：相同目标的候选序列和生效序列分别检查，不奖励永远不改。

`scores`可用于数值交叉验证；REV仅用于适用的简单双元成本—损失子任务，缺乏正负例或分母为零需保留不可算。它不是本项目新指标。

### 10.4 独立性与缺失

父天气过程/保守时空块切分，purge覆盖最长输入回看、目标提前量、结果窗口和准备有效期。相邻站、多时距、多条件、多阈值、多seed不增加独立天气数。

训练、基线校准、风险选择器、门控、动作成本敏感区选择和确认集分开。当前暴露日期只用于开发。自然日历为主分母，事件富集为诊断；不要求必须LLM有增益才发布。

共同结果mask只保证对照可比，不消除缺测选择偏差。按当时可见风险、区域/时期、来源、质量和成熟度分层；结果订正追加版本，不覆盖已发布标签而没有版本说明。

## 11. 开源复用边界与入口

详细机器表见 `specs/source_and_reuse_registry.json`。本次实际核查不等于已在用户CCI下载/安装/运行。

| 资源 | 使用位置 | 重要边界 |
|---|---|---|
| AFABench | act/predict解耦、同预测器预算比较 | 分类特征框架不是现成天气时钟；正常策略不传true label |
| BRiG-AFA | 可选两步风险回归参考 | 论文实验为分类、单位成本、固定获取步数；异构成本、停止、并发和D不是现成能力；首轮不训练 |
| Expert-Conditioned Advice | 复合“专家/工具＋信息”动作设计 | 不能将某类分离surrogate的反例推广为“所有模块化系统都错” |
| LEAP | 固定证据/哈希和预测对照 | 当前所读适配接口依赖外部finalizer；完整后端未验证，不自造复现 |
| ExtremeWeatherBench/EUPP | 来源、预报/结果及数值验证 | 业务forecast、reforecast、分析产品和历史可得时间分开 |
| pysteps | 雨场平流、短临与NWP融合 | 原生变量/时空合同先成立；输出为预测，非Gold；所有策略同样可调用 |
| NLDI | 水网导航和流域支持关系 | 数据关联不等于精确传播时间或动作后果模型 |
| OR-Tools CP-SAT | 准备作业资源/先后约束与强调度对照 | 工具不提供业务时长和损失规则；无结果时仅用预测估计优化 |
| scores | Brier/其他适用指标交叉核验及静态REV | 不替代动态多资源准备评价 |
| MRMS/GOES/AWC | 原始持续资料和公开元数据 | 版本、迟到、批量、QC；不能按条目数说成独立传感器 |

可按实际资源为每阶段安排工作日，但工期、卡数、调用数不是科学完成证据。若数据语义不成立则降为diagnostic，若廉价全读已足够则保留结果，不改费用制造收益。

## 14. 首轮输出与最终交接

### 14.1 第一轮必须实际交付

1. `BASELINE_STATE.json`：实际commit、工作区保护、现有测试/产物以及可复用模块。
2. `ARCHITECTURE_DECISION_CN.md`：唯一时钟、fixed层和prep层职责。
3. `ADMISSION_REPORT.json`：通过/拒绝与机会封存反例。
4. `SUPPORT_BRIDGE_REPORT.json`：真实fixture、支持合同、联合路径与未支持类型。
5. `SCENARIO_CARD_CN.md`：H15主任务与一个D-sim规则草案，来源与假设分别标注。
6. `SNAPSHOT_BRANCH_SMOKE.json`：完整状态clone与重放；尚未实际运行分支明确标planned。
7. `PREPARATION_STATE_SMOKE.json`：合成作业测试，不计真实天气任务。
8. `NEXT_EXECUTION_REQUEST.json`：下一批具体资产/命令/费用上限，不自行使用旧授权。

### 14.2 每次交接格式

报告代码、fixture、运行回执、哈希、失败、未完成项和下一最小动作。测试应分别标合成/真实小样例/模型实际运行/离线重放，不写笼统“全部验证”。

报表列出：独立过程、session、目标、机会、证据条件、分支、模型调用、token、可评分量、未结算量。任一维度不由另一维度代替。

发布包不得含模型权重、账户凭据或不可再分发资料。保存输入源、许可、获取脚本与公开重建边界；没有权利的原始文件保留本地引用而非上传。包一致性检查不是模型或科学验证。

### 14.3 最终验收底线

- 最少一条真实多目标、多模态、固定未来结果链，强程序/专业工具基线可运行。
- 至少一组完整状态真实分支可复算，所有替代返回都有真实来源。
- D-sim有公开状态/资源/成本规则，和E/F结果分开，模型不影响真实业务。
- 首版有不同准备需求的配对测试；同信息下概率/行动分离得到清楚检查。
- C2不止一个邻站存在命题，并且有真实provider桥和联合路径。
- 完整版逐类推进16类、至少第二物理过程原生MM与独立时段结论；不虚报当前覆盖。
- 允许方法失败和净收益为零；不允许依靠弱基线、泄漏、后验选题或人为昂贵API获得优势。
