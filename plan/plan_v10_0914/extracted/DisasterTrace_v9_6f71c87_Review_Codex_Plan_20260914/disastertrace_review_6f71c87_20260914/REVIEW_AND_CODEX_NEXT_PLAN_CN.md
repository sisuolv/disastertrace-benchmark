## 2. 本轮最重要的发现

### F01 / P1：分别校准的嵌套阈值存在概率不一致

依据 `calibration.py::predict`、`regional_calibration.py` 和发布的Denver `BANK.json`：同一 `0-3/no_low/no_low/false`基础单元，在1km与5km任务中都是n=589、positive=0，因此原始p均为1/591。经过分别拟合的base后校准：

| 同一语义输入 | 输出 |
|---|---:|
| P(V<1000m) | 0.009375 |
| P(V<5000m) | 0.005952380952380952 |

在同地点、同报告窗、同cutoff、同一信息条件下，小阈值事件包含于大阈值事件，应满足 `p1000 <= p5000`。这里出现了约0.003422619的反向差。

**解释边界：**这是已发布参数和原函数可复现的校准一致性缺口，不是原始METAR错误，也不是官方概率错误；现有每阈值Brier仍然可以合法计算。需要在将结果用于多阈值一致性、联合风险或决策之前修正或分轨。独立阈值的模型轨迹如果看到了不同证据/不同调度，也不能强行做相同条件一致性判断。

**最小处理：**先只读扫描实际机会，形成相同信息的coherence group；保留原方法，再新增标签无关、规则预先固定的有序投影作强基线，或训练相容的有序类别概率。不要在测试标签上挑投影权重或重新命名旧成绩。拟合函数沿raw score单调，不代表分别拟合的多个事件阈值共同单调。官方IsotonicRegression接口可作实现核对，但不是这个问题的新理论。

### F02 / P1：内容收益与后校准分支切换需要分开

`predict()`在非空`disclosed`时选择evidence后校准，即使对应证据单元样本不足、已经回退到相同base cell。使用同一已发布参数和一个注册但缺报的合成查询：

| 阈值 | 原始cell/raw p | 查询前 | 查询后 |
|---|---|---:|---:|
| 1000m | 同一n589/pos0，1/591 | 0.009375 | 0.014545454545454582 |
| 5000m | 同一n589/pos0，1/591 | 0.005952380952380952 | 0.015772870662460595 |

这不是自动判定算法错误：**缺报模式可能携带信息，条件校准也可能合理。**但此时没有新的观测值被原始频率单元使用，数值变化的直接实现原因是切换校准器，不能径直称为新天气内容的收益。

新增预测路径账本，保存raw cell、fallback层、raw p、校准family/hash、有效查询/缺报模式、映射后p。分开比较B、f(B)、缺失/读取模式、内容融合，以及固定相同后校准规则的诊断。异步或主动选源可能改变校准分布；均匀枚举视图的校准并不自动保证任意策略后仍校准。

直接callee还接受范围外但非空disclosed而切换校准器；它是已复现的接口风险，尚未证明当前provider允许该输入。应先查真实调用路径，不升级为既有成绩错误。

### F03 / P1研究依赖：修复E最终汇总，不会自动改善F

原生E02记录中，Pro聚焦逐槽126/126槽位全部正确，但最终E101/126；25个错误在最终聚合。全量逐槽也有18个同类型错误。其分析代码保留原始成绩，处理合理。

但是现有 `FrozenFrequencyPredictor -> evidence_features` 使用 `read/low/not_low/unresolved`，不使用最终 `fact_truth`。只改final字段并不会改变当前f(B,E)。因此不得预写“确定性汇总提升E，所以预测必改善”。

建议把三种对象分开：原模型结果、程序汇总模型槽位的新混合输出、对合法原始报告的确定性reducer。新预测管线明确选择哪类槽位特征进入固定fuser，禁止绕过模型错误后继续把结果叫模型理解能力；Gold和合法工具结果也必须分开。

### 没有确认的严重错误

本轮没有证据证明已发布F使用了未来标签、篡改结果，或616项测试只是虚假记录。也没有完整journal来独立认证其全部正确。API费用/恢复代码已经比前版改进，不应为凑问题重复旧问题。下一步优先是可测量的数据/校准/归因边界，而不是再堆通用工程功能。

## 3. 当前结果可以支持什么结论

普通日历中，两模型直接F预测与FOLLOW/COPY在汇总Brier上几乎一致，未出现与两个可见概率都相差超过0.005的提议。精确差异、1e-6和0.005阈值必须分别保留，不能把“无较大新概率”改写为“全部bitwise复制”。

5km普通日历431可结算、47正例时：FOLLOW约0.064305；batch_program0.069353；Flash selector+program0.068081；Pro selector+program0.066889。程序补证与LLM选源在该切片总体更差。1km普通集零正例，不支持罕见事件识别结论。

DenverJan9探索日：1km FOLLOW0.039654、batch0.038161、Pro selector+program0.037827；5km FOLLOW0.138021、batch0.136583、Pro selector+program0.135428。这里相对强batch的差异比相对FOLLOW小；且它是结果选择的单日，不能证明独立正收益或自然总体收益。不同费用、资料集合和相关目标也必须核实。

**正确定位：**已能观察程序、接口、取证和预测的具体差异，但尚未建立跨过程的主动多模态增量。零收益不使benchmark自动无价值；通用布尔聚合错误本身也不构成充分的气象benchmark novelty。

## 5. 数据与模型接口的下一步

### 5.1 E/F特征链必须显式可替换

冻结相同原始合法输入，比较：

```
共同基线B
  ├─ 直接沿用 / COPY
  ├─ 冻结fuser(B, 合法原始资料的确定性槽位特征)
  ├─ 冻结fuser(B, 模型逐槽特征)
  └─ LLM直接读取B和原资料输出概率
```

程序汇总原模型槽位可先离线计算，但它是新混合方法的估计，不重新命名原始E成绩。后续闭环需真实执行该方法，记录其自己的耗时和输入；不能剪短原API轨迹当作新实验。

特别注意：最终E命题是对过去资料的事实判断，不是未来事件真值。E全部正确但F无改善完全可能。E错误与F偶然得分更好也不矛盾。

### 5.2 H15仍是稳定底座，但应补非退化信息条件

当前注册邻站槽位相对cutoff较早，且统计特征压缩成少数计数。不要因为更大模型仍复制基线，就宣布天气资料没有价值。

先登记真实可得的最新同站/相关邻站信息、趋势、完整TAF条件支持与质量，再用程序验证数据链。相关性不等于未来保证；不按测试增益挑资料。新增证据要与共同TAF的已知信息范围对齐，并保留无法确定同源依赖的情况。

合理批量数据读取应保留：AWC提供整批METAR/TAF缓存，不能人为把每站读取拆成高费用来制造主动优势。历史2025任务需已有档案，不由当前滚动API保证。

### 5.3 温度不再停留在CPU类型展示

继承完整2017–2018月度连续版本和程序结果。下一出口是适配温度的模型或合法补充取证，完整共同成员产品免费，预测合同/误差/参考身份明确。

当暂时没有合法补充资料，允许先完成模型F迁移并将C1标未验证；不要把免费基线中的成员切开收费。三日事件保留同起报内成员轨迹，不凭跨起报相同member编号拼接。不把TNK<0称真实霜冻影响。

### 5.4 多模态不能再次后置到全部数值研究完成

近期独立交付一条同目标MM链：合法同期ABI/H15最快复用；H07作为原生降水时序与专业工具重点，端点/单位/网格不合格就停在该门槛，按预先规则选候补而非按模型胜负选。

每张图应绑定原文件、产品版本、波段、物理时间、覆盖、质量、裁剪、渲染、实际模型输入和视觉预算。原始图像不是隐藏mask的公开事实。先固定供图/同信息表示，再开放少量概览/ROI/多时次/专业工具选择。

`pysteps`可以作强短临对照，但需要合格降水场、规则时间间隔与空间尺度；它是预测器不是Gold。所有方法同工具权限。VIL/反射率/滚动累计雨量不混作瞬时毫米雨率。

### 5.5 Online：远端API模型调用不等于在线天气预测

当前DeepSeek通过网络运行，但天气任务仍是2025归档回放。只有预登记未来机会、真实资料接收、实际提前提交和后来结果结算连通，才能声称前瞻模型运行。

新source-only采集不等于该闭环。先有界固定站点和时段，不对外告警；普通窗口可验工程，极端技能还需相应事件支持。first-seen仅是本采集器收到的边界，模型服务端计算未知不伪装为已测GPU成本。

### 第二轮：小型可识别机制

固定一个模型设置，先同输入比较解释/融合，再闭环比较策略。不要立刻恢复完整235B矩阵或再扩多个API模型。适当保留Flash/Pro的既有设置对照；思考模式变化需要独立实验，不能根据开发输赢择优混报。

### 第三轮：多过程、MM、温度与前瞻

至少一条真正原生多模态预测链与一条不同物理过程的机制链，方法和取样冻结后进入新过程。使用父过程/保守时空块区间，富集与自然队列分开。样本量由精度和独立过程覆盖决定，不由调用数决定。

D-sim继续保留现有准备器：先固定F比较安排，再分析需求怎样影响取证。真实天气不提供所有行动的反事实损失，因此规则明确标研究假设；它不阻塞核心E/F/MM。X09在信息和总输出预算的对照下单独登记，不用“多目标同时输出”冒称联合风险分布已经完成。

## 7. 新报表必须同时给什么

1. 基线：原始/后校准/内容模型、单元样本数、稀疏fallback、阈值一致性和可靠性，不只一张Brier表。
2. 数据：机会、唯一结果、物理窗口、相关块、真实过程资格、缺失/曝光/许可，不能用多阈值或模型视图放大独立数。
3. 获取/解释/预测漏斗：查询机会→得到何种证据→合法理解→提议→采纳→截止生效→未来损失。
4. 效果：相对FOLLOW、COPY、强batch与固定融合；model自身补证效果和系统增量分别报。
5. 成本：数据、处理、客户端等待、token、费用上界、未决预留；服务端计算未知单列。
6. 结论资格：工程/领域开发/跨过程机制/MM/online/D/确认分级，负结果保持原样。

“新概率”不是新信息。保留精确、1e-6和0.005三个数值差异，不用阈值切换掩盖结果。多阈值一致性只有同信息支持时才强制。

## 8. 如何运行本审查的定向检查

```
python scripts/reproduce_review_checks.py
```

Python标准库即可。运行器先核对四个Git blob，随后运行合成输入与真实银行参数子集的11项检查。它不会联网、下载数据、调用模型或访问用户旧工作区。输出写入本包`results/`，可在副本中运行以保留原始审查产物。

包含的正控制验证了正见证+未读、反证不足、完整反证、冲突、开闭端点、隐藏标签不可作公开支持，以及单调回归沿单一分数的单调性。这些不是616项项目回归，更不替代真实calendar/journal审计。
