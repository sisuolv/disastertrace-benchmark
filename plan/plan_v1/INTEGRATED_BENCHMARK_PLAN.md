# DisasterTrace：无需新增人工复核的 LLM 极端天气 Benchmark

日期：2026-09-06。版本：v0.3，已有 benchmark 复用与程序评分方案。

用户已确认评测 LLM，并提出希望避免人工复核、结合已有 benchmark。本版将“无需新增逐题人工标注或专家复核”作为主流程约束，替代 v0.2 的人工审核前置要求。v0.2 原文保存在 references/plan_history/，用于追溯方案调整。

本文是研究规格。2026-09-06 已进入首个工作包的实现：`disastertrace-starter/` 已具备真实来源的自动准入、离线 build/run/score/report 和程序对照；实际产物与测试记录见 `disastertrace-starter/IMPLEMENTATION_STATUS.md`，复现入口见 `disastertrace-starter/README_AUTOMATED.md`。尚未运行真实 LLM 实验，也未完成正式测试集冻结；不能把程序对照成绩当作模型成绩。

后续执行更新：已按预先固定的 12 个气旋事件取得 36 份 NHC 公告；冻结解析器接收 32 份，形成 10 个完整事件、20 个分支和 100 个检查点，实际划分为 3 个开发事件与 7 个留出事件。新增事件级评分、模型接口和顺序采集器，322 项测试通过；没有调用真实 LLM。当前入口为 `disastertrace-starter/README_COHORT.md`，样本范围与排除理由见 `disastertrace-starter/DATA_CARD_COHORT_V1.md`。该留出划分属于气旋 pilot，不等同于已完成全域、去污染的正式 benchmark。

API 前准备更新：首轮 LLM pilot 所需的独立工程准备已完成。三种输入方式、跨集合重复审计、采集日志独立校验、安全续跑及请求/输出预留限制均已实现；443 项测试通过、零跳过。冻结包 `disastertrace-starter/work/pre-api-v1/` 包含 18 组动态程序对照、2 组规划对照、3 组离线恢复演练和可校验日志。首轮清单固定为两个待配置模型、三种方法、Ida 开发事件，共 60 次计划请求；没有调用真实 LLM。新入口为 `disastertrace-starter/README_PRE_API.md`。下一步需要实际模型服务、环境变量凭证配置和试运行费用上限；多灾种、多模态及 Frontier 搜索仍属于后续研究阶段。

## 1. 推荐结论与研究边界

可以采用零新增逐样本人工标注/复核的路线。推荐组合是：

**已有 benchmark 的标签与原始证据 + 可由程序验证的字段/计算 + 受控时序与证据干预 + 确定性评分。**

这里不要求我们重新请专家逐题签字，但仍继承上游标签的来源和可能的误差，也需要设计规则与验证程序。不能宣称数据历史上没有任何人工参与，或程序通过就证明现实语义绝对正确。

项目名称继续使用 DisasterTrace；DisasterFrontier 负责后续自适应压力测试。核心问题为：**面对逐步到达、更新、失效和缺失的极端天气证据，LLM 能否回答当前可支持的事实，完成正确的状态修订，并遵守显式规则？**

主轨采用相同英文文本、表格或标准化记录，不要求图像能力。LLM 型号、状态管理方法、自适应搜索分别比较。研究交付按可复现论文标准组织，但创新性与总体结论须由真实实验支持。

## 2. 已有 benchmark 的具体结合方式

本轮结合前次快照，进一步查看了模板、实际题目片段、参考答案及评分代码。详见 SOURCE_REVIEW.md 与 references/no_manual_review_2026-09-06/。

| 资源 | 实际已确认的内容 | 推荐用途 | 必须保留的边界 |
| --- | --- | --- | --- |
| CyPortQA | 现成 answer、编码场景、文本 advisory 与表格题型、原始 NHC 文本 | 气旋题目与原始材料候选；原标签对照；可核验字段的动态派生 | 部分题目存在语义/选项问题；图像题不能删图后保留原任务 |
| EarthVerse | 原题、computed_gt、部分数值/容差/来源路径；真实事件计算任务 | 后续真实资料计算子集，适合热浪等跨灾种扩展 | 官方 answer correctness 与 rubric 均由 LLM judge 评分；新确定性子集需另写计算器 |
| DisasterBench_Open | 完整233条 task_desc + structured_plan，工具接口与确定性计划比较代码 | 可直接复用标签的灾害工具规划对照 | 涵盖多种灾害；不全是极端天气，计划匹配不等于真实工具执行成功 |
| STATE-Bench | StateDiff、状态约束及 missing/unexpected 比较 | 借鉴确定性状态评分与协议组织 | 企业合成任务不是天气 Gold；完整官方评分还含 LLM judge |
| STALE | 旧状态、状态失效和后续探测设计 | 借鉴更新、旧前提抵抗与下游使用测试 | 原生成/评分含 LLM，不直接作为天气真值来源 |
| ExtremeWeatherBench | 天气预测事件目录、案例与气象指标组织 | 后期事件覆盖参考 | 评测天气预测场，不能直接提供 LLM 动态推理评分 |
| Obshazard-bench | 卫星/站点 VQA 设计及自动评分代码 | 暂缓到多模态扩展 | 本轮未取得实际数据；依赖图像，数据许可尚未核实 |

推荐组合优先级：**CyPortQA/NHC 可核验文本字段 + 自建确定性时序协议**作为核心；**DisasterBench**作为现成标签外部对照；**EarthVerse 可复算子集**作为第二来源候选。其余资源提供方法或事件组织参考，不全部变成硬依赖。

### 2.1 复用时不能跳过的具体问题

- CyPortQA 实际数据前缀中，Q17 问登陆地点，但参考内容是更广的受影响海岸；Q18 的问句选项范围与实际列表不同。Q28 模板把开始经历热带风暴条件的时间绑定到距登陆时间，不能假定两者相等。它们不进入新主轨默认题型白名单；原版对照若包含，报告继承标签与题型结果。
- CyPortQA Q16 的答案直接是 context 中港口名。可以保留作简单控制，但不能把高分解释为复杂气象推理。
- EarthVerse 的 judge.py 明确没有 deterministic exact-match scorer。结构化 computed_gt 可供派生，但“有JSON答案”不表示原框架采用程序真值判分。
- EarthVerse 抽读热浪题有峰值、三日均值和湿度等目标及容差，但对应原始事件包尚未在本轮取得并复算；该题提到的 compute_gt.py 在已核查 GitHub 树中未找到。因此它是待通过自动准入的候选。
- DisasterBench 的原评分对步骤顺序和一个参考计划敏感。保留原分数用于原协议对照；若另做依赖图等价判定，必须另起评分版本，也不能假定穷尽所有合理计划。

这些发现说明应复用适用部分，而非把所有上游 answer 默认升级成新 benchmark 的无误真值。

## 3. 数据来源等级与三类评测任务

先区分数据依据，再组织任务；不要按来源混成一个大总分。

### 3.1 每个样本记录三组独立来源属性

| 属性 | 可取类别 | 用途 |
| --- | --- | --- |
| source_origin | 原始官方记录 / 上游benchmark记录 / 合成记录 | 说明材料来自哪里 |
| gold_origin | inherited / independently_recomputed / generated_by_spec | 说明答案继承、重算或由受控规格生成 |
| schedule_origin | verified_publication / issued_time / controlled_release | 说明顺序与时间来自历史依据还是实验设计 |

相同真实记录可以用于人工设定的交付顺序。这类任务标为“真实材料上的受控回放”，不能称为精确历史回放。对源值做合成更正、取消或改写时，还须标记内容编辑及具体位置，不能伪装成官方发布过的事实。

### 3.2 三类任务共享运行时，分别出结果

| 任务 | 主要输入与 Gold | 目的 |
| --- | --- | --- |
| A. 既有任务对照 | 保留原题、原证据、原标签及可用官方评分；确定性字段子集另标 derived | 了解模型在既有灾害任务上的表现，提供可比锚点 |
| B. 动态证据主轨 | 通过准入的结构化字段/记录，程序定义交付与修订语义、计算分支答案 | 评测当前状态、时序更新、必要修改与状态保护 |
| C. 固定鲁棒性与 Frontier | 在B轨合法变换空间中生成固定对照或自适应查询 | 测缺证、旧版、顺序、无关更新，发现可复现失败 |

A 轨若选取官方依赖 LLM judge 的开放题，其结果只能单列原协议/辅助结果；首版主指标采用确定性可评分子集，不以“需要换一个大模型裁判”代替人工复核。

已有任务若改了题目、输入、输出格式、评分规则或许可范围，就记录 adaptation_type，标明派生版本，不能把新分数称作原作者官方成绩。

## 4. 无人工复核的数据构建流程

流程为：

    来源与版本锁定
      -> 候选题型/记录扫描
      -> 原始证据解析与自动准入
      -> 分流：继承标签对照 / 可重算主轨 / 隔离池
      -> 版本化事实记录与受控交付
      -> 独立 Reference Compiler
      -> 固定任务与干预对
      -> 程序评分和报告

### 4.1 自动准入检查

1. 原题/原记录、所需证据、来源URL与内容哈希可关联；许可证条件可明确适用。权利不清的材料不自动复制进发布包。
2. schema、单位、数值范围、缺失值、来源时区和日期合法；解析存在歧义时拒收，不让模型凭置信度填补。
3. question 与模态兼容。表格题若实际只提供截图，需要可验证原表或另入视觉轨，不能仅凭 modality 名称断言可文本作答。
4. 对新主轨，字段语义、主体、阈值、有效窗口、版本键和支持定位可明确计算；原文中的“登陆地点”和“影响区域”等不同变量不能相互替代。
5. 数值/类别题有冻结匹配器和容差；多解有允许集合。原题选项与标签冲突时隔离，不静默修正后继续称原版。
6. 需要动态自然顺序时有可核验的时间依据；否则明确采用 controlled_release。距离登陆的12h/24h索引不能直接当公开时间。
7. 不含未来答案、私有标注、筛题标记、未释放版本关系或事后结果泄漏；记录真正发送给模型的 bytes/记录ID。
8. 编译新 Gold 所需的计算能完成；如果没有可取得的原数据、公式定义或唯一解析，不能进入 independently_recomputed 主轨。

这些检查提供工程可验证性，不保证所有自然语言语义都已被证明。继承标签的 A 轨仍标为 inherited，并说明其可能噪声。两套解析器结果一致只增加程序检查证据，不能冒充两个独立事实来源。

### 4.2 准入失败的处理

失败样本进入带原因的隔离池，例如 SOURCE_MISSING、AMBIGUOUS_SCOPE、LABEL_OPTION_MISMATCH、TIME_UNRESOLVED、MODALITY_REQUIRED、RECOMPUTE_MISMATCH。无需等待人工逐题裁决；继续处理其他候选。

报告原候选数、通过数、各类排除数量与来源/灾种/难度覆盖。不能仅报告剩下题目的高质量，隐藏大量难题被过滤的事实。筛选规则只依据资料和协议，在正式模型结果之前冻结。

LLM 可用于检索候选或辅助开发，但模型生成的事实、解释、同义改写或多个裁判的一致意见，不能直接成为新主轨 Gold。首版自然语言呈现使用固定模板；复杂自动改写留作无真值保证的探索内容。

### 4.3 参考答案的生成与验证

- inherited：原标签原样记录；原标签与题型协议的自动检查结果另存。不声称独立证明其正确。
- independently_recomputed：从可取得的源记录按冻结定义重算，并保存公式、输入行、单位及计算结果；与上游答案不符时隔离并报告，不自动选择有利于被测模型的一方。
- generated_by_spec：程序明确构造事实、版本关系和交付日程，答案由这些规格决定；如果源值来自真实记录，说明哪些内容未改、哪些是人为模拟。
- Renderer 与 Scorer 分离：模型只见证据和任务规则，不见目标答案、必要修改集合、适用性标签或未来日程。
- 采用解析边界测试、独立小型参考实现、有限空间穷举和性质测试来发现软件缺陷；不能只让同一个函数生成答案再与自身输出比较。

这里的程序测试和规则设计属于工程工作，不增加逐样本人工标注/专家复核任务。

## 5. 动态主轨的最小任务规格

首版优先做气旋预报/警报记录的时序推理，初期每条事件轨迹3–5个 checkpoint；空间业务范围仅使用源记录明确提供或合成规格明确声明的 entity_id，不要求隐含地理常识。

主字段优先选择可直接定位的发布/有效时间、中心位置、最大风速、移动方向/速度，以及来源明确编码的目标状态和警报字段。复杂港口限制、自由行动解释、仅在图上的 cone 关系不作为必答核心。

四类任务：

1. **当前与指定时刻查询**：指出某变量在指定有效窗口的最新可支持值，提供支持记录ID。
2. **选择性修订**：局部更新只修改对应主体/变量/窗口，保留其他正确状态；检查更正、取消和重复副本。
3. **信息充分性**：缺少必要记录时回答未知；新版被延迟时根据该分支可见证据作答。
4. **公开规则执行**：依据明确规则与可见事实，计算研究任务中的允许标签或行动集合，区分已知未来生效与当前生效。

“最新”只在同一产品流、主体、变量和有效窗口内定义；新的预报周期不自动覆盖旧预测的不同目标时刻。缺证和取消不同，历史记录可以合法引用。

### 5.1 受控任务示例

下面是明确的合成协议示意，不是历史官方公告：

| 步骤 | 交付记录 | 程序规定的正确行为 |
| --- | --- | --- |
| t1 | 目标A的同一有效窗口风速记录70；目标B记录40 | 保存两目标状态和来源 |
| t2 | 对目标A该记录发出明确更正为45，B无变化 | 只修改A，保留B |
| t3 | 再次提供A的旧版70，并明确版本身份 | 当前值仍为45，旧版可作为历史说明 |
| t4 | 另一个查询所需字段未提供，协议无缺省值 | 对该字段回答未知 |

公开研究规则可以定义“已知风速达到某阈值则返回 prepare，低于阈值则 monitor，否则 request_evidence”。阈值是题目给定的测试规则，不能冒充实际海事安全标准；request_evidence 不参与风险高低排序。

在此基础上逐步加入多条件、有效区间、不同变量和例外，规则必须仍可由程序判定。简单规则基线若已经能高分，应如实报告并检查任务难度，不能通过换 Gold 制造模型失败。

### 5.2 未知与证据支持

题目默认问“给定可见证据支持什么”，不是要求模型猜真实世界的未提供结果。对受控封闭任务，协议明确事实缺失后的语义，才可以生成 UNKNOWN_REQUIRED。

数据构建方缺少原材料或无法判真值属于 NOT_SCOREABLE，不是模型应该回答未知。继承 QA 若没有语义支持定位，只报告标签准确率和可验证的引用合法性；不能把引用ID存在称为证据确实支持答案。B轨可借事实谱系和允许支持集合做更严格的 grounding。

## 6. 固定干预与自适应搜索

首版采用有程序适用条件的变换：

| 变换 | 可以复用原答案的条件 | 何时需要重算 |
| --- | --- | --- |
| 重复副本、排版规范化 | 语义、版本、任务及有效时间完全相同 | 改变了单位、脚注或记录解析时不可视为不变 |
| 顺序置换 | 问题按显式版本/时间定义当前值，置换不改变交付语义或依赖 | 多轮到达顺序、政策状态或“最后收到的记录”语义改变时 |
| 无关记录 | 显式任务依赖图证明主体/变量与答案无关 | 自然语言只是看起来无关时不自动使用 |
| Delay / Withhold | 通常不能沿用原答案 | 按各分支实际证据重新编译 Gold；隐藏完整信息bundle |
| Stale-copy | 旧版不恢复新版未覆盖的信息 | 新旧有效窗口、范围或来源权威不可比时不套版本主导 |
| Cancel / Correction | 显式关系和作用域由来源或受控规格给定 | 重新计算有效状态、必要修改与允许行动 |

Withhold 必须发生在首次暴露前，不能从模型历史中抹掉已知信息。已知未来生效/失效时点可以触发无新文件的 clock-tick，但证据到期不能自动推断现实已经恢复正常。

固定核心先成立，再比较 Random、Canonical Suite、BFS、FrontierSearch-Lite。所有查询、重试、补齐配对、独立确认和缩减都受预算约束；搜索器不访问未查询答案、私有 Gold 全表或完整反例目录。

模型行动改变不等于失败；所有答案都错或始终未知也可以高度一致。因此同时报告准确性、应答覆盖、合理未知和变形违规率。没有完整参照分母不报告搜索召回率。反例去重键与1-minimal范围在开发阶段冻结。

## 7. 模型、方法与评分

pilot 用两个不同家族的 LLM；正式扩展目标4–6个，涵盖不同规模以及商用/开放权重模型。统一英文输入，固定真实模型版本、提示、输出schema、推理预算和上下文限制。

模型主表采用统一 Structured State 协议，并报告 Snapshot 对照；方法表在同模型内比较 Snapshot、Answer History、Structured State，Guard后加。开放工具或多模态输入另外分轨，避免不同辅助能力混入模型排名。

核心程序指标：

| 维度 | 指标 | 边界 |
| --- | --- | --- |
| 既有任务 | 原标签准确率、数值容差命中、计划匹配 | 分来源/题型报告，注明 inherited 或 derived |
| 当前状态 | 值与范围正确率、证据支持率 | 语义支持只在可程序追踪时评分 |
| 修订 | 正确更新率、必要修改召回、正确状态保护率 | 同时报终态与模型先前错误情况 |
| 未知 | 信息充分时应答率、合理未知准确率、无依据断言率 | 防止“一律拒答”获得高稳定分 |
| 规则 | 相对Reference的允许结果命中、对自身状态的规则一致性 | 不称现实最优决策正确率 |
| 鲁棒性 | 两端正确且满足关系的pair success、性质违规率 | 一致不等于正确 |
| 效率 | 请求、tokens、费用、延迟、搜索发现曲线 | 工具、重试、确认及构表成本另记 |

格式失败保留并进入 attempt-level 成功率；不从分母中消失。格式有效但语义错误的状态继承到下一轮，环境不自动纠正。Reference计算修订义务时考虑模型自己的前态，同时报告当前绝对准确率，防止先犯错再修复获不公平高分。

主要计分不用 LLM judge。已有官方 judge 结果若需要复现，单列附属表，并记录评判模型和波动；不影响主程序分数。解释文字可留作案例材料，首版不评分其现实业务合理性。

## 8. 样本量、划分与研究结论

保留“1个来源/事件贯通 -> 4个独立事件开发 -> 额外约8个独立事件留出”的 pilot 目标，但不保证现有自动准入能留下该数量。气旋轨按 storm 分组；其他来源按各自事件组分组，DisasterBench 按可恢复的任务来源/模板族分组，不能把233道计划题算作233场独立灾害。

原题、衍生时间序列、所有版本、模板变体、翻译和反例在同一组；共享文件与近重复证据跨事件时合并依赖组或隔离。开发和测试还可增加模板族留出，用于检验是否只记住固定表达。

结果按来源、Gold类型、日程类型和任务分表。先按事件聚合，再按独立组统计；重复采样和衍生题不能增加独立事件数。小样本展示逐事件结果，置信区间不作过强解释；正式规模依据pilot方差、覆盖和来源准入率决定。

自动筛选可能偏向容易解析的数值和规范文本，必须披露覆盖限制。继承 benchmark 也可能被训练语料收录；组合新时间线并不能消除污染。无证据对照、新记录与模板族留出可作诊断，但不能保证完全无污染。

如果只复用已有问答和报告原分数，主要是评测整合工具；研究贡献应来自新增的动态协议、可计算分支Gold和可复现失败分析，而不是单纯重命名题库。跨风暴结果只能称事件泛化，跨灾种须有独立新领域验证。

## 9. 开源适配与实现边界

一个核心运行时，多个数据 adapter，统一 manifest 与来源声明：

    adapters/      cyportqa / disasterbench / earthverse_numeric
    admission/     schema、来源、时间、模态与可重算性检查
    records/       事实、主体、变量、单位、版本与有效区间
    generator/     模板、受控日程、合法变换、split继承
    reference/     独立真值编译与状态机
    runtime/       LLM适配、真实输入、状态、预算、缓存、恢复
    evaluation/    来源指标、动态评分、统计与报告
    search/        Random/BFS/Frontier与配对缩减

这是目标模块划分，尚未实现。基于实际存在的 Trace starter 评估增量复用，不假设 Frontier starter 已在工作区。Inspect只作为模型接口候选；STATE-Bench仅借鉴明确的状态评分部分；不同时整合多个完整Agent框架。

上游原题、私有答案、解析产物和实际模型输入分目录并采用允许字段视图。数据预处理可以读取源事实，模型运行时不能读取目标答案、标签校验结果、未来版本或完整生成日程。缓存包含模型/配置、输入哈希、父状态、分支和replicate；独立重复不能复用同一回答冒充新采样。

版本、来源URL、选取文件哈希和许可记录均冻结。EarthVerse原创标签/Gold等为CC BY-NC 4.0；其脚本与第三方材料适用不同条款。DisasterBench有MIT LICENSE，但底层工具示例/关联材料仍按实际来源记录。许可不清时可保留本地元数据或跳过发布，不用自动审批假装已取得权限。

## 10. 实施顺序与自动验收

参考4–6周完成小型自动化pilot，以1–2名工程/研究人员为资源假设；不再要求领域专家逐题复核。第三方事件包不可得或有效候选不足时，调整来源与规模，保持失败记录，不编造数据。

| 阶段 | 工作 | 自动验收产物 |
| --- | --- | --- |
| P0 来源与题型扫描 | 锁定已有资源、统计可用题型/模态/标签、记录已知不适用模板 | source_inventory、candidate_profile、许可/版本清单 |
| P1 最小继承对照 | 一种来源的原题/原标签运行与确定性评分，保留原协议差异 | 完整输入输出、失败分母、来源分层报告 |
| P2 可重算字段与自动准入 | 原文/表格解析、字段定位、唯一性和时间规则、隔离池 | admission_report、recompute_report、通过候选列表 |
| P3 动态主轨闭环 | 明确事实规格、3–5个checkpoint、分支Reference、状态基线 | 无网络fixture和真实源字段派生的可重放样例 |
| P4 固定压力与搜索 | Delay/Null/Stale等；Random/BFS/Frontier；确认与缩减 | 有适用条件的配对记录、预算日志、反例包 |
| P5 留出pilot | 冻结协议、运行新事件组、披露过滤与噪声 | 逐事件结果、成本、数据卡和复现说明 |

最低工程检查：解析歧义拒收；发布与生效分离；局部更正不覆盖其他变量；无未来信息；删除私有标注不改变模型输入；真实历史与合成编辑可区分；两分支各自评分；错误状态不被环境修正；每个模型请求可追溯；生成器/评分器有独立参考和已知边界测试。

首个任务包优先扫描CyPortQA的模板与候选文本题，以及已下载的DisasterBench结构化计划；新增动态闭环优先采用实际可解析NHC文本字段。EarthVerse在证据包能合法取得且成功重算后接入，不阻塞前两条来源。

## 11. 成本与完成定义

先用离线fixture验证程序，再用约50–100次请求的小规模模型试运行测量成本。首轮只做两个模型与三个状态方法，不展开模型、工具、来源、搜索策略的全部组合。

请求规模按事件数 × 每事件checkpoint × 模型 × 方法 × 重复次数估算，干预、搜索、独立确认和重试另设边界。货币预算取决于实际模型和端点；本计划没有进行付费实验或默认用户已具备额度。

完成分三层：

1. 工程完成：自动准入、生成、评分、恢复、报告和边界测试可运行。
2. 数据完成：每条纳入记录有明确来源等级、可追踪证据、日程类型和评分依据；所有过滤原因可导出。
3. 实验完成：冻结协议后的真实模型结果、有效事件数量、来源偏差和费用公开记录。

无需新增人工复核并不保证研究覆盖所有现实灾害判断。首版结论限定为继承任务标签表现，以及程序定义/可重算的动态证据推理。现实港口行动合理性、模糊自然语言因果解释和未验证的视觉判断留到独立扩展。

## 12. 当前默认决定

- LLM文本主轨、英文输入、中文文档。
- 零新增逐题人工标注与专家复核；不以LLM投票代替Gold。
- 核心为可自动评分的气旋时序证据任务，复杂真实港口政策退出首版必做。
- 上游标签、独立重算、受控合成三类Gold明确分开。
- 既有任务、动态能力、工具规划及搜索效率分表，不混成一个不透明总分。
- 无法自动确定的样本隔离，继续构建可验证部分；报告准入率和覆盖损失。
- 下一工作包是已有题型自动盘点、准入契约与一个动态样例，而不是招募逐题审核人员。
