## 1. 总体判断：保留研究框架，缩短实证主线

建议继续沿用原来的 C1/C2/C3、E/F/D/MM、X00—X09 与六组十六类灾害目标，不重新命名 benchmark，也不把“机场查询选择”永久替代原来的选择性预测修订任务。[G14]

当前最值得推进的主线是：

**已有 H15 数据与回放 → 同日历、同后端的信息价值桥接 → 多来源状态的 C2 GET/PROCESS 机制 → 强廉价选择器 → 新接口下的一个模型比较 → 两条冻结确认协议。**

温度合同、第二物理过程、原生多模态、受控行动和 prospective 采集另设有界支线。它们是 C3 和实用性的必要发展方向，但不应全部成为 H15 下一次科学比较的串行前置条件。

最重要的改变不是再写更多任务，而是给每个阶段设置能改变下一步决策的产物：

- 工程阶段回答“下一轮数据和结果是否可相信”；
- 信息价值阶段回答“这个环境是否真的存在值得选择的不同证据”；
- 模型阶段回答“模型有没有超过同条件的强程序”；
- 确认阶段回答“上述机制能否在没有参与开发的过程上重现”。

模型胜出不应成为 benchmark 的预设结论。负结果可以有价值，但前提是任务本身非平凡、对照足够强、机制可辨识，并有独立支持。

### 1.1 保留原贡献的精确定义

| 原贡献 | 不变的研究对象 | 下一阶段最小增量 | 不应替代成什么 |
|---|---|---|---|
| C1 | 持续专业预报上的共享资源分配与选择性修订 | 同预测器下的获取、分配、共享、时效与修订收益分离 | 一般 JSON 工具调用成功率 |
| C2 | 有有限可达性参照的证据诊断，并连接未来 F 损失 | 多来源状态、同父状态的 GET/PROCESS/到达历史干预 | 只统计特征哈希是否变化 |
| C3 | 真实多灾种、跨过程、可复算的监测实验体系 | 第二条物理链、原生模态、分级发布与跨过程确认 | 候选来源数量或未合格的 16 个灾种名称 |

这是对原计划的执行聚焦，不是把其余贡献删除。[G14]

## 2. 当前事实基线：哪些不再重复，哪些不能混合

### 2.1 已完成的工程和开发工作

仓库发布报告登记：72/72 个地区月份的原生数据构建；52,548 个新增原文；2023 拟合、2024 年 1—11 月校准的年度 bank；840 条完整周轨迹；6 个 C2 父状态、24 条分支；288 次 selector 请求；108 个方法运行、24 个正式评分组。完整 16 类、独立过程确认及 LLM 优势并未完成。[G02,G03,G10]

这些工作不能在新计划里再次写成“首次实现”“首次采集”或再次消费原实验身份。需要修复的旧结果派生逻辑必须输出新版本报告，不覆盖旧报告。

### 2.2 两批结果的研究口径不同

| 项目 | 旧后端的完整周程序结果 | 年度后端的 Stage C 模型比较 |
|---|---|---|
| 日历 | 四个全球周的完整日历 | 12 个地区×日期会话 |
| 5 km 结果支持 | 6,048 注册、6,008 可结算、307 正例机会 | 每方法 864 注册、861 可结算、16 正例机会 |
| 方法角色 | 主要为程序策略 | LLM 仅选择查询，冻结程序输出概率 |
| 同 values 后端的信号 | F_BASE_ONLY→B11_COVERAGE：Brier 改善 0.00449050 | LLM→强 coverage/batch 没有优势 |
| 不能声称 | 307 个独立天气过程 | 16 个独立过程，或年度 bank 单独造成表间差异 |

Stage C 的 16 个正例集中在 Chicago 同一天。LLM 相对 F_BASE_ONLY 的平均 Brier 改善为 0.0000319736，来自负例；缺失结果敏感性界 `[-0.0000576464, 0.0000339670]` 跨零，这不是置信区间。71/288 个输出符合旧契约，其中 58 个不查询、13 个原序全取，没有严格子集或重排。[G03,G10]

**研究推论：当前不能断言“补证没有用”，也不能断言“LLM 已经会主动分配”。** 已有整周开发资料足以开始做更清楚的程序桥接和状态分析，无须首先扩张下载或挑选容易出效果的灾害日。

### 2.3 三种增量必须分开

定义相同日历、合法输入、预测时点、采用规则、结果掩膜和预算下的损失 L：

```text
获取增量    = L(同一 values bank，不查询) − L(同一 values bank，查询策略)
选择器增量  = L(冻结的强程序选择器，同一 bank) − L(模型选择器，同一 bank)
后端增量    = L(旧 bank，同一策略) − L(新 bank，同一策略)
```

不能把 `F_COMMON` 和 `F_BASE_ONLY` 当成只有查询不同。`FOLLOW` 也有自己的研究概率映射。当前派生分析仅用“是否 F_COMMON”标记 bank 差异，不能完整表示消费者身份；应记录具体不同因素，而不只生成一个布尔标签。[G03,G07]

### 3.2 修正几个过强或过早的执行门槛

**第一，P0 应按路径定义。** API 缺陷阻止新 API，但不阻止只读的 CPU 数据普查；温度合同阻止温度实验，不阻止 H15 程序桥接。内容寻址和 portable qualification 应先完成最小输入角色绑定，再做发布扩展，避免为了一个未来大框架停止所有研究。

**第二，不把严格子集或重排作为模型合格条件。** 在某些真实状态下全取/不取可能正是最优动作。应检验状态条件化决策及其收益，而不是奖励输出看起来“复杂”。不能为制造排名反转随意改成本、删数据或压缩预算。

**第三，12、48、288 都是范围上限，不是统计证明。** 本方案采用 12 次真实形状接口小试作为默认提案；48 是另一个可独立预登记的预算方案，不把多个 ZIP 的额度相加。288 次后续比较也不是自动批准，不能因为小试成功而自动启动。

**第四，不因为时点不一致立即训练新 bank。** 先做配对时钟审计，才决定是否需要新的拟合。当前差异是待测风险，不是已经证明的数据泄漏或当前失败的唯一原因。

**第五，不把既有合法回复重放当新方法。** 它只能用于 posthoc 诊断模型延迟、无效输出 fallback 与 query schedule 各自的贡献；不重新计算一个“修复后 v12”正式成绩。

**第六，不让状态文件陷入 SHA 自指要求。** 受版本管理的 CURRENT_PHASE 宜指向最新批次与报告；运行时单独记录 `evaluated_source_sha`。不要要求一个正在被提交的文件包含其自身未来提交 SHA。

## 4. 最新相关工作：借模块，不换掉现有内核

### 4.1 Novelty 不能停在“多灾种 + Agent + 动态 + 证据链”

EarthVerse 已经研究多灾种、异构资料调查、可执行答案单元与过程依据；SIREN 已经覆盖多个预警步骤及端到端预警链；FutureSim 已经按真实时间回放世界事件并持续更新预测；SentinelBench 已经联合测量长期监测、反应时间和资源。因此不应提出“首次动态灾害 Agent”“首次证据干预”之类宽泛优先性主张。[R01,R02,R03,R04]

建议将核心问题收紧为：

> **在共同专业预报持续更新、多个目标竞争有限资源的条件下，新增证据何时值得获取、处理和采用；其收益或伤害能否沿同父状态的受控回放链解释，并在独立过程上复现？**

这是一项需由实验证实的组合定位，不是本次检索已经证明的全球“首次”。

## 5. 主线 A：有界工程修复与可信起点

### A0. 基线与证据保护

记录本地/远端 SHA、dirty/index、既有运行与消费过的 call IDs、确认日历角色、源文件和原结果哈希。只允许在新批次目录写派生产物。工作区不干净时保留用户改动，不 reset、不强制覆盖。

首批离线时不执行 git fetch/ls-remote；远端身份使用本次已核验的参照及现有tracking ref并标注新鲜度。当前实现的允许修改清单与历史冻结源码快照分开：可更新新的生产实现，但不能破坏旧运行所绑定的不可变实现/工件，也不能直接改写已消费的v12批次脚本来覆盖旧分析。

将 v11 的 750 与 v12 的 628 作为两个测试集合的历史报告，不能直接相减为遗漏数。采集 node IDs 后列为“仍存在并通过、改名、合理删除、计划附属、缺 fixture、未重跑、新增”。当前回归数量以真实去重集合为准。[U09]

### A1. C2 完整性与资格

在当前源码上先写能失败的测试：缺一分支、全部报告缺失、缺一必需 trace、重复机会、错误 parent hash、别名未绑定。实现注册集合与实际集合核验，并显式输出：

```text
registered_parent_ids / registered_branch_ids / registered_opportunity_ids
present / missing / duplicated / unauthorized / unavailable_with_reason
qualification = formal_bound | legacy_replay | engineering_diagnostic
terminal_class = completed | failed_with_registered_fallback | incomplete_not_comparable
```

不得以“有非零特征变化”作为完整性准入；零信息价值、零概率改变、零收益都可能是有效研究结果。允许的“无 trace”必须来自预登记的分支语义，不是事后把缺失当合理。

### A2. API 许可、捕获与恢复

建议抽取共同 worker 逻辑，不再每批复制一份 transport。接口可分为：

```text
claim → bind request/execution → prepare payload/credential
→ final dispatch permit → durable dispatch intent → send once
→ durable capture → validate/decode → settle or fail
→ optional append-only reconciliation (zero new HTTP)
```

最终 permit 必须与 STOP、截止及一次性执行共享一致的本地同步语义。共享文件系统上的多节点锁语义未验证时，首个真实小试限制单一 dispatch authority；不把本地mock通过当AFS双节点竞争已验证。截止检查应靠近实际发送，并涵盖此前 claim、序列化、凭据读取、I/O 等耗时。区分 API 授权截止与天气预测截止，二者不互相替代。

不能承诺无 provider 幂等支持的“外部服务严格 exactly-once”。最多保证本地不重复 dispatch；发生“可能已发送但未保存回复”时保留 UNKNOWN，禁止自动重发。STOP 在许可前生效应拒绝发送；许可后已在途请求只能保留在途/终止边界记录，不能伪称从未发出。

捕获协议至少包括：

```text
captured_bytes_before_redaction
capture_limit_bytes
capture_truncated
captured_body_sha256
stored_redacted_bytes_sha256
utf8_decode_status
full_body_sha256 = null if incomplete else verified hash
request_sha256 / execution_sha256 / call_id / provider_model
```

截断由脱敏前实际读取情况判断，不能由脱敏后长度判断。脱敏后的文件验证自己的哈希；不能要求它与脱敏前哈希相等。完整原文可能有敏感值，不得为复现把凭据写入仓库。

恢复时保留 `.failure.json`，追加绑定原 capture 的 reconciliation receipt，定义可消费的有效终态。恢复不得重新发送 HTTP、重复收费或把晚到结果倒填为先前已及时采用。原始时点、失败、未知费用和迟到状态均保留。[G05,G06]

### A3. selector_query_only.v2

新主输出：

```json
{"query_order": ["q0", "q2"]}
```

共享契约同时生成 system、输入说明、逻辑 JSON schema、provider 支持的 response_format、离线 parser。query-only 路径不再要求一个实际被忽略的 `forecast_handles`。旧解析器保持 legacy；旧字段别名、code fence、原失败按原契约复算，不事后洗成新接口成绩。[G12,U09]

验证空数组、全取、子集、重排、重复句柄、未知句柄、额外字段、重复 JSON key、前后说明、拒答、截断、编码异常、模型身份不符及持久化故障。逻辑契约与 provider 支持的 schema 子集分开：provider 不支持的 uniqueItems 等限制仍由本地严格执行，不能取消语义检查。

候选为空时明确允许且仅允许空动作，避免生成空 enum 之类不合格 schema。句柄与可用性按请求动态绑定，不硬编码永远只有三个候选。

### A4. residual 与配对身份

新增 `residual_query_plan.v2`：`none / first_new / second_new / all_new`；相关、可得、未缓存、未请求四项同时满足。缓存权益须按目标私有/会话共享判断，不能简单全局去重。明确 second 不存在、late、不可负担和执行尾部停止的 disposition。

`ComparisonFingerprint` 绑定 consumer、bank、calibration、as-of clock、evidence representation、query policy、forecast schedule、adoption protocol、数据/目标/结果角色。输出 differing_factors；不再以方法名字猜归因。[G07,G11]

### A5. 第一批退出

先对旧工件做只读影响扫描和算术复算，再执行当前代码回归及可得 capsule。缺依赖或私有 fixture 时记录 NOT_RUN/BLOCKED，不联网补包或假装通过。对新缺陷测试保存 red/green 的准确命令、node ID、退出码、日志及哈希。

完成后交付 STOP：数据下载=0、远程模型/API=0、GPU=0、训练=0、确认结果访问=0。整个“第一批”不包括后续完整周重放、重拟合或小试 API 的自动启动。

## 6. 主线 B：先证明环境存在可用的信息价值

### B0. 时钟与消费普查：先审计、不重拟合

在已暴露开发资料上，为同一机会生成 fit-clock 与 actual-clock 的合法输入对照，至少包括：

```text
issue_time, valid_start/end, declared/observed available_at
cutoff, forecast_started_at, evidence completion/adoption time
selected TAF version, source ages, lead_hours, legal query set
feature hash/delta, logit delta, probability delta
region/season/threshold/process/calendar block
```

有结果时再在 evaluator-only 层计算损失差。不要把后一个时点才可得的资料倒填到早时点。训练 cutoff−600 秒与实际预测 slot 的差异可能影响时龄、TAF 版本和 evidence subset，大小及方向必须由该对照测量。[U09]

同时检查 evidence-subset mixture：训练子集分布与 no-query、batch、coverage、LLM 实际取得的子集分布是否不同。若生成多个时点和子集训练样本，同一个信息单位的总权重应归一，防止枚举更多的样本被重复加权。

### B1. 用已有后端做完整日历桥接

先冻结比较清单，仅在相同日历、结果、slots 和 adoption 上比较：

| 维度 | 受控比较 |
|---|---|
| 后端 | 旧 frozen bank vs 已有 annual bank |
| 获取 | 同一 values bank 下 no-query / budgeted batch / coverage |
| 时间 | 同一 bank 下 fit-clock 特征 vs actual-clock 特征诊断 |
| 支持 | region、阈值、来源状态、正负例、calendar/process block |

不必先跑完整笛卡尔积：先用 no-query 和 coverage 的旧/年度后端桥接确定主要差异，再在年度后端的同日历上补 batch 与其他基线。所有新运行使用新 run IDs，旧840轨迹不覆盖。

这个阶段是新 CPU 程序实验，须作为第一批之后独立登记的范围执行，不应和纯只读审计混写。

### B2. 是否建立新 bank 的条件

只有审计显示明显时点错配、有效证据被系统性忽略或部署子集分布明显失配时，才提出有界新拟合。新 bank 保留：2023 的训练/内部选择；2024 年 1—11 月的既定校准角色；2024 年 12 月既有排除；2025 已暴露开发；另行密封确认。

建议最多比较少量有清楚理由的候选：已有 common、已有 values、slot-aligned values、common-anchored residual。不得在 2025 损失上无界调模型后再称它是未见验证。拟合与校准必须另有授权和新身份，旧 bank 与旧分数不改写。

可考虑的 anchored residual 为：在共同基线映射上，只允许经开发期验证、由额外合法证据支持的有限修订；没有证据时回到共同信息预测。这只是候选设计，不预设它优于现有 bank。

### B3. action-space census 与可利用性

对每次 decision 统计候选数量、发布时间龄、位置/目标关系、共享覆盖、费用、延迟、缓存、可得性、到截止剩余时间、历史训练期可靠性。相同费用和相同候选数并不证明候选等价；只有候选名称不同也不证明模型有可学信号。

分两层验收：

**物理/程序作用层。** 实际合法返回的来源是否不同，是否进入特征、概率、采用或全会话资源竞争；不同动作是否对最终 loss/timing/cost 产生有意义差异。

**公开可利用层。** 用只在训练角色数据上建立的简单规则/浅层模型，检验公开状态是否足以区分值得做的选择。有限 hindsight 最优动作只是 evaluator 诊断，不能进入在线选择器，也不能仅凭 oracle 存在就宣称任务可学。

三个一次性候选最多有 8 个无序子集，若顺序有意义则有 16 个不重复的有限有序动作（包含空动作）。可枚举的是这个局部动作集，不是整个 24-tick 会话的完整策略树。跨时点效果用有界一/两步 lookahead，不伪称全局 oracle。

若真实来源在当前范围内几乎不提供差异，停止扩大 LLM；进入第二条已合格的物理/证据链，而不是人为改变世界制造优势。

### B4. 强而便宜的参考策略

保留 no-query、预算内 batch、round-robin、risk、coverage，增加 matched-count hash/random 诊断，以及一个一/两步预期最终损失策略。AFABench 的模块化策略和预算评价值得借鉴，但不先训练整个 RL 系列或重写现有环境。[R05]

建议的价值量仅依赖公开状态 S_t：

```text
V(q | S_t) = E[剩余会话风险(不查询) − 剩余会话风险(查询 q 后)]
             − 预登记的查询/延迟机会成本
```

估计器只使用训练/校准角色的历史支持；方法拟合严格限训练角色，校准角色仅按已登记用途使用。若以历史分支损失作价值监督，使用训练角色内部的分块交叉拟合或独立内部验证，避免让预测器自身的训练拟合误差伪装成可泛化的信息价值。主报告保留损失、请求、token、wall time、bytes、迟到等多轴曲线；不为了单一好看分数临时挑 λ。若采用单一 cost-loss 场景，权重/单位必须在评测前固定。

## 7. 主线 C2：从“链条接通”走到有限、可解释的机制

### C2-0. 重新强调 E 与 F 的区别

E 任务在有限证据合同下回答“目前能断言什么、什么尚可及时弥补”；F 回答“未来会发生什么”。E 已经充分不意味着 F 一定准确，E 尚不充分也不意味着 F 必须输出0.5。

至少区分：当前不足但可及时取得且未取得；只能迟到或超预算取得；已经足够但读错；字段读对但表示丢失；候选概率改变但未及时采用；概率及时改变但未来仍不确定。这比“36 对有哈希变化”更接近原 C2 贡献。[G14]

### C2-1. 两个队列，不混一个总分

**自然日历主队列**保留连续时间、背景负例、缺报和真实发生率。

**来源状态诊断队列**按公开输入的 TAF full/partial/none、订正、撤回、冲突、删失、报告数量、临界范围、late/unavailable 分层。在冻结的候选范围内用公开身份与固定 hash 取父状态，登记各层 prevalence。未来 Y、当前损失和赢家方法不得参与父状态选择。

下一轮机制开发可先提议**最多24个父状态、每父4条GET加最多1条真实可用的PROCESS分支，总上限120条分支尝试**，覆盖若干公开来源状态及多个日历块/地区。这个上限是控制工作量的建议，不是已批准预算或统计功效证明。某层不存在合格样本或处理替代时登记不足，不按结果补选；实际roster在运行前固定。

状态富集属于诊断，不冒充部署发生率；需要代表性总分时按既定抽样机制处理，不能把正例富集分数直接拼进自然日历。

### C2-2. 三类真实干预

**GET：相同处理器，改变新获取的资料。** 从同一 quiescent parent fork：none、first_new、second_new、all_new。父费用、缓存、权限、公共唤醒、后续预算均继承。

**PROCESS：相同原始资料，改变处理方式。** 固定同一份有版本和合法时点的 TAF/METAR，在 native parser、另一合格程序处理器或后续登记的模型提取器间比较。必须真实运行处理器，不能手写一个“理想模型输出”冒充系统效果。

**TIMING/HISTORY：相同世界，改变有依据的到达/采用历史。** 区分实际历史差异和声明的 latency sensitivity scenario；比较当前/过期版本、及时/迟到、同源重送与真正新增信息。不能把人为移时后的资料称为已证实真实 first_seen。

GET 的总效果含获取延迟和资源挤占；固定输入和时刻的 PROCESS 是机制拆解；二者不能直接相加为无条件因果贡献。C2 识别的是受控软件/信息策略效果，不是“改变天气”的因果效应。

### C2-3. 不只评分被查询的目标

令 U_s 为父状态之后登记的全部剩余机会，比较：

```text
Δ_session(s,q) = Σ_{i∈U_s} w_i [loss(p_i^none,Y_i) − loss(p_i^q,Y_i)]
```

一个查询可能服务多个目标，也可能耗掉其他目标需要的资源。只比较被选目标会遗漏共享外溢与机会成本。另列 selected-target、served-target、unserved-target 的描述性分解，但完整 U_s 为主分母。

每一行保留：query/result/version → native field → typed E state → feature → proposed probability → completion → admission/adoption → effective probability → outcome/loss → resource delta。

### C2-4. 三个真正有论文辨识度的配对问题

1. **相同最终资料，较早到达是否更有价值？** 控制最终信息，观察最后可采用时间及旧修订失效的作用。
2. **同一证据给不同目标，共享何时有利或有害？** 保留 B00/B01/B10/B11 的预算×权限解释，固定预测器。
3. **相同合法证据，处理更准确为何仍可能不改善 F？** 分离支持、表示、概率映射、采用和随机结果；不要求每次事实改善都换来更低损失。

它们应在多个来源状态和过程上复现，而不是对同一天切更多视图。

## 8. 主线 C1：新接口、一个角色、一次受约束模型比较

### 8.1 小型兼容性范围

默认提案为 12 个预登记的真实天气-shaped 请求，覆盖空候选、不同句柄长度、合法空/非空输出条件、较长 context 等接口情况。它们只检验结构和运输；不以选择好坏作接口门槛。用真实存在的合法状态构造请求；某一边界在实际资料中不存在时记未覆盖，其合成测试仍归离线矩阵，不伪称真实天气覆盖。

冻结 model ID、provider、logical schema/provider schema、prompt hash、请求清单、token 上限、截止、停止规则和重试规则。无效输出不能自动生成“补偿请求”，也不能把 v12 消费过的兼容性名额当新预算。

即使全部通过，这也只是 smoke qualification，不证明生产故障率足够低。

### 8.2 有界开发比较

只有后端、可选信息、强程序、C2 多状态和新 transport 全部满足所需门槛，再提出最多288请求、单模型、query-only角色的比较。确切日历和每时点调用规则须重新登记；若改为事件触发、改会话数或改成本安排，应使用另一协议身份，不能称为原288的直接重跑。

所有方法共享 source universe、bank、public baseline、forecast slots、adoption、结果和预算口径。query-only 是为了隔离选择能力，不意味着原 E/F/D/MM 总体框架被删掉。

主表保留所有无效/拒答/运输失败及预登记 fallback。诊断表可分：结构合法→动作合法→可执行→真实取得→E支持→特征改变→概率改变→及时采用→损失改变，但 conditional-on-valid 不得替代 end-to-end 主表。

### 8.3 不把论文成败绑定于一个 LLM 赢不赢

- 若接口仍失败：停止扩大，发布接口/工具适配局限，重新开新契约时保留历史失败。
- 若接口合格、程序有信息价值、LLM无优势：这是选择能力的可信负结果，而不是继续无限换模型。
- 若有可重复的模型优势：在封闭确认集上检验，而不是再调提示词放大开发差值。
- 若查询本身缺少价值：优先换到已合格的证据/物理过程，不用模型规模掩盖任务设计问题。

### 8.4 后续再开放模型 E/F 角色

原 benchmark 还应评测模型提取证据、KEEP/OVERRIDE 和生成有限概率修订，但要在 query-only 因子被隔离之后单独做。

固定查询轨迹、证据包和预测时点，对比程序 E、模型 E、程序 F、模型有界 residual F；每个新增模型角色独立登记调用与预算。不能同一轮同时换 selector、提取器、后端、提示词和采用规则，否则无法知道收益来源。

模型 F 的概率必须绑定合法 evidence、当前专业基线版本和 forecast target；动作偏好不得改变同一气象问题的概率。此阶段不属于首批，也不预设其一定优于程序 F。

## 9. 统计与确认：过程支持优先于更多小时数

### 9.1 ProcessRegistry 与时间角色

将 source event ID、地区、起止范围、源证据和跨区域关系记录为 evaluator-side ProcessCard；能证明属于同一系统的片段不能拆进不同确认单元。尚无独立天气系统依据的只称 calendar block，不换一个名字就声称独立。

ProcessCard 不必暴露给 agent。以标签或权威事件目录作事后 evaluator 分组可以明确登记，但不得把这些分组标签送入选择器或用于事后挑选有利父状态。

多变量、多个阈值及同一观测的复用，要记录 outcome lineage。相邻小时不是自动独立样本。[G03,G10,R06]

### 9.2 主评分与辅助评分

推荐5 km 的自然日历、配对会话 Brier为一个首要端点；1 km、区域/季节/来源状态、正负例贡献及可靠性作为预登记辅助。不能依据当前最好的阈值临时替换主端点。

保留失效、缺失与成本；同一结果掩膜保证比较一致，但不保证缺失无偏。预测值相关的缺失结果敏感性应与抽样不确定性分开报告。多个机会复用同一缺失 observation 或事件嵌套时，应按共同结果/可行标签集合给界，不能任意把同一个未知标签独立翻转。

对 visibility 同时输出两阈值时应满足 `0 ≤ P(V<1km) ≤ P(V<5km) ≤ 1`。这是新输出合同的建议；不能事后投影旧概率然后覆盖历史分数。

少数开发周只做分块描述、leave-one-block-out 稳健性分析。只有过程数和设计支持时，才采用预登记的成对过程块重采样。确认范围应由开发方差、最小有意义效应和过程支持规划，不由“运行几次直到显著”决定。

### 9.3 两条确认协议同时冻结

A：同 bank 下模型选择器相对冻结强程序是否有增量。

B：C2 field→feature→probability→timely adoption→loss 的预登记机制是否跨过程重现。

共享一个未读日历时两者先同时冻结；否则用隔离的日历。不能先读取 A 的结果，再选 B 的父状态或新增解释假设。Bay `2025-02-17—23` 保持密封直到相应授权；它只支持窄范围确认，不能替代跨地区/跨季节支持。[U09]

未读历史确认可先行，不必等待未来；prospective 轨道是另一种资格，用于真实 first_seen 和现实运行边界，不能与 archive 声明时延混为一谈。

## 10. C3 的推进方式：不放弃16类，但不同时建16条深链

### 10.1 温度：先完成 F-only 的正确资格

目标动态阈值、比较操作符、统计量、duration、UTC 支持和 prompt 必须来自一个版本化 contract。raw 最大温度任务只要求自己实际需要的最大温度成员；ECC 的 min/max 一致性处理才要求两种变量齐全。[G13,U09]

跨日 duration 事件必须验证 issue、ensemble、member IDs、日支持和顺序的 lineage。数组长度一致不证明第 i 项是同一成员。无法证实的旧记录标为 UNAVAILABLE_TO_VERIFY，不武断判错，也不升级为正式联合概率。

温度 F-only 可作为跨物理过程的第一步，但没有合格补充证据链就不声称 temperature C1。

### 10.2 主动扩展优先选一个：降水 H07 或水文 H08

按现有获取与物理合同的完成度选择，不按当前损失挑选。

| 链 | 先冻结的合同 | 最小主动闭环 |
|---|---|---|
| H07 降水 | 累积窗口、issue/valid/available、空间 support、QC、同目标观测与预报 | 同目标预报 + 合法时次额外观测/雷达 → 概率或数值修订 → 独立结果 |
| H08 水文 | 流量/水位、瞬时/均值、断面、QINE 等字段意义、成员身份、调度影响、阈值与 availability | 同河站合格预测 + 上游/降水等额外证据 → 同目标未来结算 |

不要把网格降水、雷达产品或调度后流量误当无条件独立物理真值。已有来源样例只减少获取风险，不能自动满足这些合同。[U09]

### 10.3 多模态最小可交付

为同一合法 source/time/space 建三个明确条件：原生图像、相同信息的程序数值/结构表示、图像加真正新增的另一来源。这样才能区分“表示方式”和“新增信息”。

图像必须实际进入模型请求，并保存 crop/transform、band、单位、时间范围、地理范围、源版本和图像哈希。只生成可视化示例或把 parser 数值转写进 prompt 不算 VLM 评测。

优先选已有来源可得、参考可自动计算的小切片；不先在所有16类上铺视觉模型。跨模态输出沿 E→F 消费合同运行，而不是另起一个无法连接主线的图片问答榜单。

### 10.4 分级发布

保留原 A0—A5 与 E/F/D/MM 资格含义。本方案不创建一套替代等级。每个灾种记录当前最高已验证级别、数据与许可证、目标合同、独立结果、执行回执、过程支持、失效分母和重建办法。

可以发布明确标为 H15 或双过程的版本，但不得把它叫完整16灾种发布；原六组迁移和全部资格建设仍在长期路线中。

## 11. 实用性增强：让“还来不来得及行动”决定信息价值

这应是稳定 C1/C2 之后最有价值的扩展之一。ScenarioCard 和程序原型可并行写，完整 action LLM 比较后置，不必等待所有灾种。

固定一组研究性资产/准备任务，登记准备时长、容量、成本、截止、取消或撤回代价、可逆性及损失规则的来源和假设。比较“天气一样，但准备需10分钟/2小时”“同样预算但容量不同”等配对场景。

三部分分别接收：

```text
F predictor: 气象问题 + 同截止合法证据 + 冻结预测器
Acquisition: 公共气象状态 + 剩余资源 + 已声明行动可行性
Decision: 已采用 F + 准备状态 + 固定 DecisionSpec
```

硬测试是：**同气象目标、同合法证据、同预测器、同 cutoff，改变 DecisionSpec 不改变 F。** 不要求不同查询策略在拿到不同证据后仍产生同一概率。

先跑无动作、阈值、最早截止优先、滚动两步和小规模精确优化器，确认确有等待、准备、撤回与容量竞争的非平凡权衡。后续才比较 action agent。

评价包括截止前准备完成、错过需准备目标、无效资源占用、取消、反复切换和违反约束。所有“减损”限定在声明的研究场景，不对外发布真实预警或声称现实减灾效果。[U09]

## 12. 前瞻时间记录：元数据采集可早，评测承诺不能晚

历史 archive 通常能提供 issuance/validity，但并不自动提供历史第一次可见时间。建议单设轻量 first_seen 记录器，在网络/平台授权后开始保存不可变的访问时间、源版本、body hash、HTTP/失败与重复观察，不运行模型或对外发送预警。[U09]

它不必等待16类或 action agent完成，但必须隔离“用于设计的元数据”与“确认 outcome”。真正 prospective 模型比较要在时间窗口开始前冻结方法、预算、日历、结果访问和停止规则。不能先采到或看过有利结果，再把那段时间登记为前瞻确认。

运行中同时记录 wall-clock 与 replay-clock、单位、映射与倍率。任何缩放都要登记；不可直接套用网页模拟器的 speed_factor 然后把模型响应延迟解读为真实业务时效。[R03,R04]

## 13. 执行 DAG 与每批完成定义

### 第一批：仅工程修复及只读诊断

```text
A00 基线/保护/node IDs
 ├─ A01 C2完整性/资格
 ├─ A02 API许可/capture/恢复
 ├─ A03 query-only v2离线契约
 └─ A04 residual/ComparisonFingerprint
         ↓
A05 时钟、已有回执、动作空间的只读普查（不新跑天气分支）
         ↓
A06 回归/历史影响/只读算术复算/STOP
```

第一批没有授权新的 full-calendar程序实验、bank训练、API小试、GPU、真实数据下载或 confirmation。缺本地资料就报告阻塞，不自动补下载。

### 第二批：冻结后进行 CPU 研究实验

B00 固定 bank 的同日历程序桥接；B01 source-state census 与 C2 多状态 GET/PROCESS；B02 轻量预期价值程序策略；B03 只在必要且授权时建立新 bank 并重新冻结。B03是条件插入节点，不由编号决定必须最后执行；需要它时，后续B01/B02必须采用重新冻结的同一bank，不需要则出具SKIPPED_NOT_NEEDED回执。执行范围、候选和日历先写入 proposal，批准后才跑。

### 第三批：有界模型

C00 小型真实接口范围；C01 单模型 query-only 比较。两者独立授权，不把接口预算和科学比较预算相加，也不自动重试补齐成功数。

### 第四批：确认与交付

D00 两条协议、process/缺失/端点冻结；D01 密封日历执行与结算；D02 可重建发布切片。确认的 outcome 首次访问单独有回执。

### 并行支线

T00 温度资格；M00 一个原生多模态切片与第二主动物理链设计；E00 后续固定轨迹的模型 E/F 角色；V00 ScenarioCard/程序行动；P00 first_seen recorder设计。它们不自动获得网络、训练、模型、GPU或确认权限。

每一包必须报告：输入身份、实现文件、测试和失败、历史影响、科研主张新增/未新增、下一道门槛。依赖是证据依赖，不是“前一包写完文档即自动通过”。

## 14. 避免 Codex 继续消耗在重复工作上

当前仓库已经有大量历史计划、报告和已完成批次。建议只保留一个短的 mutable 当前入口，历史入口归档但不删除；当前计划指向机器可读工单和真实结果。

定期数据处理、统计、状态轮询由普通程序完成；Codex 负责有限代码改动、测试和门槛判断，不逐条让语言模型解释数万条原文或轮询任务。

只读派生分析可使用以输入/代码/schema哈希为键的缓存；不能绕过正式原始记录验证，不能用 path/mtime 代替内容身份。独立任务可有限并行，但 worker、schema、formal API 等共享接口应先冻结，避免多个执行器同时修改同一核心文件。

不启动全模型排行榜、不迁移完整第三方 Agent 框架、不全仓库格式化、不无限扩充 PDF 审计报告、不将每个日期都变为新一轮人工提示词调试。每个工作包必须产生一个代码/数据合同/机制表/比较表或明确的 STOP，而不仅是另一份计划。

## 15. 最终建议与可用于汇报的主句

当前最合理的优先级是：**先证明增量价值可识别，再证明模型能取得它，最后证明这种规律不依赖某一天、某一个消费者或某一种灾害。**

建议论文中心句：

> 面对专业预报持续更新、多个目标竞争有限资源的场景，DisasterTrace 通过可追溯的时序监测与同状态对照回放，评测智能体能否选择并及时利用值得获取的证据，带来可归因、可跨过程验证的预测与受控行动增益。

“评测能否”是目标，不是既成结论。当前可支持工程闭环、有限开发信息价值和模型负结果；下一阶段需要多状态机制、同条件强对照、独立确认与合格跨过程证据。[G03,G10,G14]

完整出处和各材料去向见本包来源表与合并矩阵；所有新工单初始状态为 `PROPOSED_NOT_RUN`。
