## 2. 分级发现

### R01 / P1：两个温度概率入口的准入不一致（已复现）

位置：`monitoring_v1/feature_tasks.py:45-100` 与 `temperature_postprocess.py:11-77`。

前者只验证窗口长度是整日，没有验证起止各自对齐 UTC 零点；构造日期字典时会覆盖重复日期；阈值缺少有限数值/布尔排除；day_index 没有严格整数检查。后者已有相应保护。

| 合成输入 | feature_tasks 函数 | temperature_postprocess 函数 |
|---|---|---|
| UTC 12:00到次日12:00的一日窗 | 返回0.5，实际取原日极值 | 拒绝非完整UTC日 |
| NaN阈值 | 返回0.0 | 拒绝 |
| 同日期两份不同产品 | 返回1.0，交换顺序变0.5 | 拒绝重复日期 |
| day_index=True | 返回0.5 | 拒绝非整数索引 |

这是数值辅助入口的已证实边界，不是已证明生产 FormalSession 可被绕过。已发布温度数据由上游固定 UTC 目标构建，当前没有证据说明存在上述非法记录。必须先扫描冻结 POLICY/目标和调用方，报告影响为零/非零/无法判断；不可直接宣布既有分数全部失效。

建议复用物理输入合同校验，保留独立成员事件计算作为交叉验证。候选补丁 `temperature_contract_guard.patch` 未应用到仓库；完整导入、循环依赖和生产回归需要 Codex 验证。

### R02 / P1：重复完整重放是扩展前的可执行性问题（源码确认，耗时未量化）

`formal_session.score_formal`先重放首个日志一次，再重放N个日志；最后`score_admitted`又重放N个。正常九臂入口共19次。`admission.score_admitted`还在每个结果机会重新构造包含所有目标的 OutcomeRegistry，应一并剖析；不预先宣称其为主要瓶颈。

优化应在同次评分中复用“已完整验证的引擎＋内容/合同/代码身份”，而不是把路径、mtime、摘要分数或任意内存对象当作可信入口。保留原提供方、全部机会、完整共同基线轨迹、每次分支干预、事务链和结果冲突校验。缓存仅优化验证重复，不减少验证语义。

先记录调用栈和计时分项，再量化同工作量前后差异；模型generate197秒不能直接换算GPU利用率，余下110.6分钟不能全部归因CPU或AFS。

### R03 / P0-确认前：总体正收益不能推出事件块受益（报告已披露）

预算首日5km coverage总体Brier0.00962590略优FOLLOW0.00983541，也略优batch0.00975196；但所有16正例在12月块，该块coverage相对FOLLOW增益为-0.010882，相对batch为-0.001222。其余3块无正例的收益抵消了退化。

不要删正常时段，也不要反过来只算正例宣称业务价值。主监测均值和完整天气块/事件阶段诊断并列；新的确认主次指标、权重和停止规则须在结果打开前冻结。缺失敏感性界只对缺失标签取值稳健，不提供抽样置信度。

### R04 / P1：强后端、信息增量和主动策略仍需分开

去年周期特征的全周5km raw Brier：FOLLOW0.043130；common0.036448；values无补证0.038827；同values全补证0.033218。common改善是后端作用；values同后端差是该条件的信息作用；全读不是预算内策略或预测上界。

235B选择器仍用旧冬季bank：5km0.103349，batch0.104359，无补证同values0.100600，FOLLOW0.064305。略胜部分取证策略，仍不能证明它值得额外计算。正确计划是先锁合格强后端，再比较取证；旧批次不得替换bank重写。

当前新增native_feature_forecast已使用真实数值并区分common/mask_age/values，不应再把v9的“nonempty disclosed切换校准器”当作这个新主路径的未修复事实。历史路径及归因对照保留即可。

### R05 / P1：字段正确性改善与F改善没有闭合

统一澄清后普通144槽能见度25→140、主报文温度49→141、露点59→142，但5km流水线Brier0.070288→0.070545，接近原生解码后端0.070546，仍差FOLLOW0.065545。这是显著的合同解释修复，不是新增独立确认；旧模型字段误差可能偶然使概率更接近结果，不能据此保留错误提取。

现有数据卡是描述性记录；下一批将主报文/remarks、10SM报告标签/P6SM删失、9999/CAVOK编码例外、字段缺失、格式政策和精度绑定到运行合同。原生解析、模型提取和特权修复分开；同失败掩膜只用于明确的归因对照。

### R06 / P1：全年拟合/校准与独立过程仍是待完成科学门槛

2025四季已被用于模型选择/消融诊断，永久保留开发身份。去掉year_sin/year_cos是看过开发结果后的选择，即使优化器未看新季节标签，也不是确认。

当前P1建议2023全年度拟合、2024全年度校准是合理候选，不是已下载事实。先metadata/质量/依赖清单，按月有界复用下载；拟合缺证模式权重在运行前明确，每个目标不能被枚举视图无意重复增权。日/周/区域分组不能等同真实独立天气系统。

### R07 / P2：EMOS/ECC实现边界需要保持

当前实现按原成员秩把Gaussian边际分位数映射回成员，三日事件用同一成员路径；本地测试通过此范围。随后min>max会将两者投影到平均数，trace已记录。该投影能改变边际和秩，因此不应对修复后的整个产品宣称“严格保持原秩且保证联合校准”。应统计实际修复次数及分数影响；不是据此认定当前实现错误。

温度729天最终DWD观测可作结果，却没有历史逐版本公开时间，不能重命名为严格as-of补证。声明情景可以另轨研究，不能伪造历史可用性；F-only先独立发布。

## 3. 结果驱动的后续结论

新主线不应是“必须找出能赢的LLM”。应依次回答：冻结强后端是否跨季节可靠；补充资料是否在同后端下有作用；预算策略是否优于同日程batch/RR；模型解析/选择增加什么；对结果与成本的结论能否在独立块复现。

对同一评价分母，可写描述性分解：

`L(FOLLOW)-L(h,E_policy) = [L(FOLLOW)-L(h,empty)] + [L(h,empty)-L(h,E_all)] + [L(h,E_all)-L(h,E_policy)]`。

这是配对损失的恒等式，不是互相独立的因果贡献；all-read可能更差，不是信息论上界。跨批次、bank、时间、失败掩膜不同不能直接相减。
