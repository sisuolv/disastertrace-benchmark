## 3. 已复现问题与最小修复

### V10-R1 / P1：温度科学输入合同存在分叉

位置：

- `monitoring_v1/feature_tasks.py::temperature_ensemble_probability`，约46—100行。
- 对照 `monitoring_v1/temperature_postprocess.py::validate_products` 与 `event_probability`。

弱路径仅检查持续时间是整日倍数，然后把 `target_date` 转为字典：

1. 中午到次日中午的24h窗口被按某日00—24h产品计算；严格路径拒绝。
2. 同一天出现两个产品，弱路径静默使用最后一个；反转列表会将合成概率从0变1；严格路径拒绝重复日期。
3. `day_index=True`、布尔阈值和NaN阈值被弱路径接受；NaN样例给出0概率。
4. 正常UTC日、负温度、同成员三日事件两路径一致；三日成员依赖不应由边际相乘替代。

**后果：**未来新增任务或构建错误可能静默改变科学目标／基线。尚未证明当前已发布128个温度题、11644机会有非法记录，也没有证明FormalSession顶层允许这些输入。

**修复：**增加一套具版本身份的温度合同校验，两入口共同调用。校验目标整数UTC微秒、午夜端点、正的1日或指定3日长度、cutoff、变量、单位、有限非布尔阈值、严格正整数day_index、目标日期唯一、相同起报/成员身份、连续覆盖及有限完整数组。多个起报版本先由显式版本裁决选择，不能在同一次快照中按列表顺序覆盖。不要为重用校验而删除独立数学实现：独立审计仍须另算成员事件/概率。

**回归：**本包六个差异输入、正常与负温度、同一成员置换不变、三日依赖、day0、缺日、重复日、起报混合、午夜跨月/年、阈值相等、布尔与非有限量。模型输出不应改变目标。

**影响核查：**只读扫描已冻结模型输入、温度日/月POLICY与共同产品；逐条输出 `valid_unchanged / affected / unavailable_to_review`。无命中则记录无已知数值影响；有命中时另存规范拒绝/派生评分和原分数，不重写旧答案，不自动重跑模型。

### V10-R2 / P1：STOP/截止只在claim时检查，不覆盖发出前的等待

位置：`monitoring_v1/api_ledger.py::ApiLedger.claim`；`api_capture_v2.py::capture`约29—74行。

实测条件：claim时合法，读取模拟密钥期间产生STOP，或模拟时间从1秒推进到4秒而截止为3秒。当前代码仍构造dispatch并调用模拟HTTP。claim之前已存在STOP或截止已过则正常拒绝。

**合同先决：**明确 `deadline_wall_ns` 是领取许可的截止还是“不可再开始新请求”的截止。若只约束claim，不可声称覆盖最后HTTP发送；建议正式执行采用有明确线性化点的no-new-dispatch政策。已经提交给提供方的调用，不承诺能被STOP撤销或免费的exactly-once。

**修复：**在最终发送许可阶段重新检查契约哈希、STOP、deadline，记录原请求与最终许可时刻，再按持久化先后发送。claim后的慢文件I/O、校验和准备不能免除检查。若要求强本地多进程停止顺序，STOP和发出许可通过同一小型原子协议串行化；不要长时间持有共享费用锁等待HTTP。第二次检查无法消除外部网络的一切竞态，保证范围必须写清。

**回归：**STOP/截止发生在claim前、claim后/密钥读取时、请求准备后、许可后/HTTP已开始；错误许可不发HTTP、不生成伪成功；已发送仍保留原费用与未知状态；拒绝不创建替代逻辑调用。故障注入使用虚拟时钟，不访问真实密钥或提供方。

**历史影响核查：**比较冻结call deadline、claim、dispatch、STOP已知时刻和wire时间；未保存的阶段标为无法判断，不凭无错误日志推断未越界。未发现实际违规前，不作废整批实验。

### V10-R3 / P2：新的温度输出头仍有超大整数异常

位置：`feature_tasks.py::parse_temperature`约33—43行。

401位整数概率在 `math.isfinite` 处抛OverflowError而非统一的invalid_probability。正常小数、布尔、负值、NaN、重复key控制均已运行。

Bay2025-02-17—23继续不读取载荷。先冻结主/次目标、模型/提示、后端、资源、格式/失败、准入、分组、统计精度与停止规则。该周不能独自承担全年多地区确认；可预先登记其他尚未读取完整历史块，不必等待现实未来天气。确认结果不足时依预注册日历扩展而非挑阳性日；未预先规定时作描述性结论并另建研究批，不把反复查看测试冒充一次性确认。

缺失敏感性界与采样置信区间分开。v10八种缺失补全核对只讨论三处缺失结果，不能证明四天气块的泛化。区间和显著性按独立/保守块估计；只有4块时坦率报告不稳定，不bootstrap相邻小时造窄区间。

### 5.5 P3.1 / N4：完整周的预算控制，不再仅首日

当前216条首日会话为已完成证据：5km所有16正例在12月，coverage相对FOLLOW该块增益约-.010882；三个无正例块的改善抵消了它。coverage相对同values-none在四块均改善，说明后端迁移和补证作用必须同时解释。

下一批先在本地可复算的现有资料中预注册完整周控制。按完整时间网格保留所有机会；从首日扩到全周时明确预算释放节奏和会话重置/跨日缓存规则，例如原48/day规则是否形成7天总额336，不能把新全周总额仍默认为48，也不能无解释地将每日私有缓存清空/共享缓存保留。两种设计若都研究，单列intervention。

同一coverage selector下保留quota/global × private/shared四格，再在B11比round_robin、risk、coverage、batch。始终包含FOLLOW、相同values后端no-evidence、COPY/KEEP资格对照。所有方法共享完整TAF、结果掩膜、预测机会和原生工具许可；不得向部分方法再次收费共同基线。

记录每个机会的原概率、候选、最终有效值、基线版本、查询/处理/排队、错过槽位、失效与回退；当前和最新基线数值等价不等于FOLLOW动作。原始数据库、报告选择和静态提取不能由后见标签决定。

主表同时给相对FOLLOW、同后端no-evidence和强batch的差。先按日期/区域/保守过程展开，再给总体均值；没有正例的1km切片不能宣称严重事件识别优越。

数据和程序成本与生成延迟是不同条件。固定查询计划在声明时延下重放可以分离调度影响，但应标明诊断，不能改旧回执当真实新部署实验。任何新的CPU会话使用新冻目录；静态已有回答重评分不计新模型调用。

### 5.6 P3.2 / N3,N4：有限模型机制矩阵

不重复v10已经做完的COPY/E归约/84题澄清/128题温度模型诊断。下一项新模型比较应回答未解决问题，而非扩大模型名称列表。

建议先固定查询计划和新后端，在未用于提示优化的开发任务上比较：

- 原生程序提取 → 固定后端；
- 清楚初始合同的模型提取 → 相同后端；
- 模型逐槽事实 → 可计费确定性汇总 → 相同后端；
- 直接F与B-only/FOLLOW作为关联对照，而不是强制模型修改概率。

原生解析工具只使用合法已读内容，作为正常可用工具时对所有策略开放并计相同处理成本；使用评估侧Gold修复仅作特权诊断。模型无效时所有相关目标保留；格式、字段、缺失、最终逻辑和F分别评分。固定输入与连续主动会话不能互称复现。

若后端与事实利用已被清楚验证，再固定后端只换selector。模型额外调用/tokens/等待计入总资源。现有48source相等不等于等算力、等钱或等等待，最终质量—资源关系和统一总预算轨分开。

新调用必须预先冻结任务、数量、角色、max_input/output、模式、失败规则和费用；余额不足/模型不可达标NOT_ATTEMPTED，不当模型错题、不自动切换为更有利模型。沿用已验证本地27B/235B即可，不默认下载新大权重。兼容性、正式回答、GPU生成批次和API尝试分开计数。

## 6. C2 与 C3 分支：避免重新建设与越界

### C2现有机制继续使用

19个真实pending前缀、8资源配置的有限联合参照已经做过。新后端/工具/时效改变后，需要相应新见证；不重新实现另一套oracle。缓存权益、已花/预留、在途剩余、版本冲突和截止全部绑定同一prefix。

E的联合可达最优不能解释为F上界。每目标独占预算的最优值不可相加。全读是信息条件，不保证预测最好。有限档案的后见见证不能进入策略输入；开放世界或未知耗费时给合法界/未知，不冒充精确最优。分支诊断固定完整状态及续行策略，用新回执和真实费用，不篡改历史时钟。

### 温度保持F-only，不强行制造历史补证

保留EMOS/ECC原方案：2017拟合、2018开发，UTC完整日、同一成员连续轨迹、原生六小时max/min而非瞬时采样极值。检查两个年角色之间跨年三日结果和源版本足迹；不得只按起报年切分后默认结果不重叠。

同时验证ECC稳定tie规则、成员轨迹、min>max修复数量与影响；该修复改变边际，不能单凭ECC名称宣称联合校准。修复前后可派生诊断，不能替换原成员或标签。高温日EMOS/ECC变差必须保留，不按事件选择赢家后再在原开发集称优胜。

### H07/H08、MM、D、X09、online

H07先核精确累计区间/端点、质量、同窗预报与结果；H08先核QINE物理变量、成员、调控、断面、流量/水位/空间淹没各自合同。资料不足依据预登记数据门槛择路，不因模型分数换主灾种。

## 7. 具体退出条件与停止分支

| 状态 | 合理下一步 |
|---|---|
| 边界修复后旧输入合法、旧分数不变 | 记录无已知历史数值影响，继续，不重跑模型 |
| 新全年后端并未改善某事件 | 保留负结果；按预注册范围检查误差与证据相关性，不修改确认集 |
| values-all优于values-none但预算策略未达到 | 检查信息是否能及时取得、选择/处理代价与固定F利用，不先加模型 |
| 模型提取近原生但F差 | 后端/任务瓶颈而非默认感知失败；看同信息程序对照 |
| E支持好但F不改善 | 合法研究结果；C2与F分开，不强造因果提升 |
| 总平均改善、含事件块退化 | 分层披露，不能以总体选定部署；继续自然完整块与强基线 |
| 调用被402或授权阻断 | 保留NOT_ATTEMPTED，做离线分析；不开新key/作业绕过 |
| 数据或独立过程不足 | 如实限制主张，按预注册连续计划补，不以模型规模替代样本 |

退出不要求LLM获胜，但需要数据足以检验目标能力、强对照完整、非法记录被正确拒绝和他人能够复算。
