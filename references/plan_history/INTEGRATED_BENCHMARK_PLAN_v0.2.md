# DisasterTrace：面向 LLM 的极端天气动态证据 Benchmark

日期：2026-09-06。版本：LLM 主线推荐方案 v0.2。

用户已明确最终评测对象为 LLM，并将其他范围选择交由方案推荐。本文据此采用文本优先的主评测，保留多模态扩展；具体推荐与资源假设见第 14 节。本次交付仍是研究与实施计划，不代表系统、数据集或实验已经完成。

## 1. 建议定位：一套底座，两条评价线

建议保留 **DisasterTrace** 作为主 benchmark 名称，将 **DisasterFrontier** 作为其中的自适应压力测试模块，避免维护两套数据、Gold、运行时和排行榜。

核心研究问题：**当同一极端天气事件的官方预报、警报和业务公告不断更新时，LLM 能否形成有证据支持的当前状态，修正失效判断，并据公开任务规则做出一致的行动建议？**

主评测对象确定为 LLM。LLM 也可以是具备图像能力的型号，但所有模型在主轨使用相同文本输入，以便比较证据推理与动态更新；图像理解进入独立扩展轨道。气象预测场精度不在当前目标内。

推荐定位为可用于论文研究的领域评测基准，先完成可审计 pilot。论文主贡献聚焦“真实灾害证据中的时间、版本、适用范围与选择性修订”，最终结论限定在经验证的任务覆盖内。

输入轨道与固定/自适应评价线是两个独立维度，不合并成总榜：

| 输入轨道 | 模型实际获得什么 | 定位 |
| --- | --- | --- |
| Text Core | 官方原文、公开表格及审定的忠实文本抽取 | 首版唯一必做主轨 |
| Tool-assisted，后续可选 | 相同原文加公开、冻结的 OCR/GIS/检索工具结果 | 评价带指定工具的系统，工具能力和费用单列 |
| Multimodal，后续可选 | 匹配版本的原始图像与文字 | 仅比较可接收图像的模型，单独研究视觉贡献 |

两条评价线共享数据及评分规则：

| 评价线 | 内容 | 可以回答的问题 |
| --- | --- | --- |
| 固定核心评测 Canonical Core | 自然时序回放，以及事先冻结的缺证、旧版本、顺序等对照 | 在相同任务上，哪些模型和系统配置更可靠？ |
| 自适应压力测试 Adaptive Stress | 在合法证据空间中选择下一项测试、确认失败并缩小反例 | 用相同查询预算，哪种方法更有效地发现和解释失败？ |

自适应发现的失败率不能当作自然场景错误率，也不能直接取代固定评测的模型排名。搜索算法是否有独立方法贡献，须由对 Random、固定测试集和 BFS 的实验决定。

优先争取三个可检验的贡献：可追溯的真实事件证据序列；覆盖证据、修订和行动的固定评价协议；可复现、预算公平的失败诊断。RevisionGuard、状态使用探针和可视化案例是支持这些贡献的组件。首版不以“多模态必要性”作为完成条件。

需要显式解决的冲突：

| 分歧 | 本计划推荐决定 | 原因 |
| --- | --- | --- |
| Ida 或 Ian 作为第一场事件 | 优先审计 Ida 2021 × New Orleans 明确辖区/航段，Ian 为备选；最终按覆盖纳入 | 已发现可核查的 Ida 分发记录及分区域生效公告，仍需完整来源审核 |
| 官方标题时间是否足以叫 Strict Release-time | 区分 verified-availability、issued-time 和 interval 三类回放 | `issued_at` 不能自动证明首次公开可见时间 |
| FullHistory 的含义 | 分开命名证据历史、模型回答历史与有限记忆 | 避免把额外证据或更长上下文误解释为状态能力 |
| 不同版本的“六槽” | 按第 5 节冻结 Text Core registry；细粒度业务限制进入主任务，视觉字段另轨 | 字段数量不是科学约束，含义和可评分性才是 |
| 四臂或五臂 carrier 实验 | 首版 OWN/NONE/ORACLE/STALE；局部 EDITED 延后 | 先证明探针依赖外部状态，再增加细粒度归因 |
| 当前状态读出或下一轮续写 | 分成两个实验；首版只做隔离的当前状态读出 | 二者的干预位置和结论不同 |
| 格式无效后是否终止 | 保留失败记录和上一有效状态继续；连续失败上限预先冻结 | 保留错误传播轨迹，同时防止无限重试 |
| Trace 与 Frontier 的优先级 | Trace 固定协议先成立，Frontier 后接 | 搜索无法补救不可靠的 Gold 和评分器 |
| 多模态是否首版必要条件 | Text Core 为主；工具辅助与原图评测后加 | 用户确认 LLM 目标，先统一可比较的输入能力 |

本地现状：找到 `disastertrace-codex-handoff.zip`，其中为 `disastertrace-starter`，包含源码、示例、测试和历史审计；未找到 Frontier starter。压缩包自述的新功能未实施、已知缺陷未修复。材料中“6 tests passed”等为原审计记录，本次没有运行这些测试，也没有验证 Frontier 文档所述的另一份 starter。

## 3. 研究问题与首版范围

建议预注册以下问题，允许实验得出无提升或负结果：

1. **当前理解**：模型能否提取正确的时间、地点、预报窗口、警报和港口限制，并引用实际获得的证据？
2. **状态修订**：新版本、取消或局部解除出现后，模型是否修改必要字段，同时保留仍正确的字段？
3. **下游使用**：事实更新后，行动是否满足公开 Policy Card，而非继续沿用已失效的前提？
4. **信息与历史鲁棒性**：合理缺证时是否保留未知；无关更新、旧版混入和不同顺序是否导致不应出现的变化？
5. **诊断效率**：在预算一致时，自适应搜索能否比简单方法更快发现经确认的不同失败？

首版推荐以美国大西洋及墨西哥湾沿岸的热带气旋与港口为领域切片，输入为官方文本、原始表格和港口公告。使用英文原文与统一英文任务提示，中文用于项目说明；中文翻译与跨语言等价性另作后续实验。每个 episode 是“一个 storm × 一个明确目标区域/港口 × 一项决策任务”，初期设 3–4 个可核验 checkpoint。

阶段性规模：

| 阶段 | 推荐规模 | 定位 |
| --- | --- | --- |
| 工程 smoke | 4 类合成事件：升级、撤回、旧版冲突、无关更新 | 验证评测器，不能计入真实数据量 |
| 真实可行性 | 1 个 storm，1–2 个目标 episode | 证明原文、时间、范围与 Gold 能贯通 |
| 开发 pilot | 4 个独立 storm，优先每场一个 episode | 调整协议、标注指南、提示和预算 |
| 留出 pilot | 额外约 8 个独立 storm | 冻结后的初步验证；仍是小样本研究 |
| 正式扩展 | 可先按总计 20–30 个独立 storm、约 30–60 个 episode 做资源估算，实际据 pilot 调整 | 属于目标规模，尚未验证可恢复性或统计充分性；已用于开发的事件保持开发身份 |

同一 storm 的多个港口不能增加独立灾害样本数。所有衍生图片、checkpoint、干预和反例继承 storm 的数据划分。开发集允许改协议；留出集一旦看过结果用于调参，就必须明确降为开发数据。

另做原始文件及实际呈现内容的哈希、近重复和共享来源审计。多风暴地图或共同公告可能跨 storm 重复暴露任务相关信息；存在这种依赖时合并事件组、隔离材料或记录不可独立比较，不能仅按 storm ID 分组后宣称无泄漏。

候选筛选依据包括来源质量、时间连续性、文本与原始产品一致性、升级/降级/无变化覆盖和区域多样性；扩展轨再增加图文配准要求。需包含持续监测、预报威胁减弱或未达到行动条件的片段，才有机会测过度反应；刻意平衡的挑战集不能代表真实灾害发生率。

另外冻结 `event_qualification`：记录纳入事件所依据的官方灾害分类、警报或影响证据，以及事件范围和时间窗口。气旋存在不表示每个目标港口都经历了极端天气；首版可表述为“高影响气旋事件下的决策场景”，目标位置未受显著影响的对照仍可合法纳入。扩展热浪/暴雨时应定义当地季节基准、阈值和持续时间，不能只按新闻标题判断“极端”。

首版不训练大模型，不做全灾种数据工程，不建立完整物理因果图，不推断最优关港时间。未来扩展到暴雨洪水、热浪、寒潮时，重用核心运行时，另建领域字段、极端事件定义、数据源和行动规则。

建议在固定开发集覆盖四类困难：多文档联合支持、局部撤回与适用范围、已知但尚未生效的限制、证据不充分或相互冲突。不同难度的划分由审核后的证据结构决定，不按被测模型是否失败倒推。只把输入加长不能充分体现极端天气任务的独特性。

## 4. 数据建设：先证明两条真实证据链

### 4.1 来源分工

- **CyPortQA**：用于发现 storm–port 候选、模板和原始文件；原 QA 答案仅作标注草稿线索，图像材料保留给扩展轨。
- **NHC 官方归档**：Text Core 优先恢复 advisory、警报和可核验的文字/表格概率产品；轨迹图与 GIS 后续接入。历史 best track 和事后总结只进入独立 outcome 区域。
- **USCG 官方公告与可核查发布记录**：用于港口条件、限制、例外、生效与局部解除；聚合 CSV 的 effective time 不代替发布时间。
- **人工审核**：确认原文抽取、地点与辖区、局部替代语义、可断言值和可接受行动集合；图文版本匹配仅用于扩展轨。

首轮先对 Ida 2021 × New Orleans 候选做来源矩阵：产品、版本、原 URL、文件哈希、发布依据、有效区间、地理范围、可读取性、许可和缺失原因；Ian 2022 为备选。此前只抽查过部分官方页面，尚未证明首事件的全部时间线合格。优先选择证据完整者，缺失材料保留记录，不补造恢复阶段。

HTML/PDF 转文本保留标题、时间、单位、表格表头、脚注、例外和跨页关系，提供中性行号并映射回原文件。对采用的 OCR/抽取文本进行人工核验；Text Core 的主实验使用审核后固定文本，OCR 鲁棒性另测。不得把参考答案、更新义务、推荐行动或私有 GIS 结果混入“文本整理”。

### 4.2 时间与版本

至少区分 `issued_at`、`availability_interval`、`valid_from/to`、`effective_at`、`retrieved_at` 和 `delivered_at`。全部运行时间带时区并规范化 UTC，保留原始字符串及转换依据。

| 回放轨道 | 可见时间依据 | 可以使用的表述 |
| --- | --- | --- |
| Verified availability | 经审核的公开发布/分发证据，分辨率足以判定 checkpoint 前后 | 经核验公开可见时间的历史回放 |
| Issued-time | 官方产品头部时间，首次公开时间未独立证明 | 以产品标注时间为条件的回放 |
| Interval robustness | 可核验的上下界 | 分别按保守上界和乐观下界报告敏感性 |
| Unresolved | 无可靠可见时间依据 | 候选或静态理解数据，不进入时间效应主评估 |

今天能下载历史页面不等于知道它当时首次公开的时间。未来有效的预报只要已经可见就可以输入；不能用“有效时间不得超过 checkpoint”禁止合法预报。

默认先构建明确标为 Issued-time 的主数据集，以降低历史分发记录不足对首版的影响；满足额外证据标准的记录进入 Verified-availability 子集另表。使用 effective time 猜发布时间的记录不因此获得纳入资格。不同时间依据不能混算精确历史响应延迟。

不可修改的 Artifact 保存原文件；Evidence Unit 引用整文件或精确片段；Delivery Event 记录在某分支何时实际交付，可表达旧文件重复到达。分别记录已公开可用、已交付、已呈现以及当前有效的证据集合。

版本按产品流、变量、地点和有效窗口判定。更正、新预报、重复副本、取消、局部覆盖使用不同关系。新版公告不自动覆盖所有港口，未来版本关系不能进入早期模型视图或提前影响公开过滤器。

时间流逝本身也会改变状态：在已知生效/失效时点可设置没有新文件的 clock-tick checkpoint。未来生效限制先表示为 scheduled，到生效时刻再变为 current；有效期结束不能自动推断恢复正常，缺少新证据时按任务规则保持历史值或转为未知。

对同内容 HTML/PDF、OCR、缩略图和重复截图建立信息 bundle。若干预目标是隐藏一项信息，必须检查所有可替代载体是否仍泄露它；只改变一种呈现形式的消融则保留其他载体，并明确测的是呈现差异。

### 4.3 空间范围与视觉扩展

NHC cone 表示气旋中心可能轨迹，不能推出 cone 外没有风、雨、风暴潮或港口影响。Wind watch、wind warning、surge 产品和港口 condition 也不能直接转换成一个通用风险等级。

Text Core 的地点匹配依赖模型可见的原文以及统一公开的地名/辖区词表。若任务需要行政边界或航段背景映射，该静态背景应对所有模型公开并版本化；不能要求模型猜测私有地理映射。原文未支持的 cone 空间关系从主轨必答字段中移除。

未来视觉 Gold 来自匹配版本 GIS、合法空间运算和人工核对。必须声明目标是港口点、设施边界还是航道范围；记录投影、边界容差、栅格分辨率与产品适用年份。文字已重复视觉答案的样本标记为“模态冗余”，不能用它证明视觉必要性。

Multimodal 轨提供原图或一致的公开渲染；从私有 GIS 计算出的答案不附作图片 caption。Tool-assisted 轨若提供“目标位于某区域”等工具结果，该值是公开感知输入，评分侧重后续时间、证据和规则推理，不再宣称评测了模型自己的空间识别。工具结果与私有评分答案须有独立来源和权限边界。

## 5. 数据契约与 Gold

统一对象链：

```text
原始 Artifact + 来源/许可记录
  -> Evidence Unit + 版本/时间/范围关系
  -> Episode + Checkpoint + Delivery Schedule + Public Policy
  -> Snapshot / Pair / Sequence 输入
  -> Model-owned State + Action + 定位引用
  -> 独立私有 Reference 与 Scorer
```

Text Core 的核心字段为 `storm_class`、`wind_watch`、`wind_warning`、`official_port_condition`、`operational_restrictions`。每个字段都绑定主体/位置、变量、单位和有效窗口；按 episode 的公开任务 schema 声明必答范围，不能支持的必答字段允许显式未知。

`operational_restrictions` 结构化记录航段、适用对象、限制、例外和生效区间，独立于 condition 标签。首版只评分经审核的子字段；不能把“condition 正常”直接等同于全部航道恢复。跨 episode 的字段组合不同，报告时按字段/任务分层，避免通过选取更容易的字段改变主分数。

`wind_probability_34kt` 仅在可见原文/表格有明确位置、阈值和有效窗口时启用；`cone_relation` 属于工具或视觉扩展。不能将仅存在于图片的答案偷偷转写进 Text Core，也不能按模型未收到的图像内容罚分。

`action` 根据公开规则返回可接受行动集合中的选择。`information_status` 和 `request_evidence` 独立表示信息是否充分，不能把请求补证排成比 monitor 更低的风险级别。所有行动均是研究任务定义下的建议。

私有参考分三层：

1. **来源事实与事后记录**：保存实际文件和可核验记录；不直接当作各时点可知答案。
2. **分支可断言 Reference**：根据该分支实际获得的证据，判断当前可支持的状态及支持集合。
3. **Policy Oracle**：以明确、公开的规则将可断言状态映射为允许行动；允许多解和信息不足。

区分 `KNOWN`、`UNKNOWN_REQUIRED`、`ACCEPTABLE_SET` 与 `NOT_SCOREABLE`。未知不是 false、无警报、无风险或已撤回；评测方缺少可靠 Gold 也不是模型应该回答未知。

事实和行动的审核相互分开。历史官方关港行为可以是事实标签，但不能自动作为在不完整信息下的唯一最优建议。没有海事审核条件时，行动任务采用声明为研究规则的 Policy Card，结论限于规则遵循。

初期对纳入正式 pilot 的 Gold 全量审核，对版本替代、时区、空间边界、撤销、关键行动规则实行双人复核并保留分歧。LLM 可生成候选，不担任唯一 Gold 来源或核心裁判。

## 6. 固定核心任务

| 任务 | 输入与操作 | 关键判定 |
| --- | --- | --- |
| 当前证据理解 | 当前时点合法的原文、表格与公开任务规则 | 正确事实、范围、时间、定位支持、合理未知 |
| 自然时序回放 | 按真实或明确声明的时间协议逐步交付证据 | 更新必要状态、保留正确状态、使用有效状态作决策 |
| 固定证据干预 | 从共同前缀分叉，执行 Delay、Withhold、Stale-copy、Null | 各分支正确，以及应变/应不变关系正确 |
| 固定呈现与历史对照 | 合法重排，或最终规范有效信息一致的不同到达路径 | 超出模型自身随机波动的顺序效应和无依据残留 |

实施顺序：自然回放 + Delay/Null；再加 Stale-copy/Withhold；最后做严格匹配的顺序和历史实验。

一个示意 episode：第一轮说明两个航段即将限制通行；第二轮只解除其中一段，另一段保持限制；第三轮没有新公告，但已声明的措施到达生效时点；第四轮重新出现旧版副本。检查模型是否只更新相关范围、正确区分 scheduled/current，并保留有效依据。这是任务设计示意，不能冒充已恢复的真实历史记录。

每个模型维护自己实际提交的状态，评测器不替它纠正事实。格式有效但语义错误的状态必须继续进入后续轮次。格式失败保留原始响应、失败标记和上一有效状态；不得记作成功 KEEP。

修订义务取决于“模型上一次真实状态 + 当前分支 Reference”。同时报告终态准确率、此前正确/错误分层和 Oracle-prev 诊断，避免先犯错再修正获得不公平高分。状态操作包括新增、保留、更新和撤回；支持来源改变但语义未变，不强算错误修改。

干预要求：

- Delay 改交付时间，不能改原公告时间；每个 checkpoint 重新计算可见集和增量。
- Withhold 在首次暴露前发生；已经看过的证据不能靠后续不重发被当作从未见过。
- Stale-copy 加入真实旧版，允许用于历史说明；只有它错误地覆盖当前支持时才构成陈旧污染。
- Null 必须经依赖检查确认与当前问题无关，不能仅靠作者标签判定。
- 每个分支独立生成可断言 Reference；缺证时回答未知可能正确。
- 最终路径比较还要匹配时间、任务、政策状态及资源条件；合法的政策迟滞不能判为模型错误。

## 7. 模型与系统 baseline

先用 1 个真实模型做有限 canary，pilot 用 2 个不同模型家族。正式扩展建议覆盖 4–6 个 LLM，包括强商用模型和至少两个不同家族/规模的开放权重模型；开放权重模型可以通过托管服务评测，首轮不以购买或配置 GPU 为前提。确切型号在执行前按可用性、预算和固定版本确定，本计划不假定某个当前型号已获验证。

模型与方法分成两张表：**模型主表**为所有模型使用同一个固定 Structured State 协议、相同英文文本、公共规则和单轮调用上限，另外报告统一 Snapshot 对照；**方法表**在同一模型内比较下列历史/状态处理方式。不能用某模型配 Guard、另一模型不配 Guard 的结果直接宣称前者模型能力更强。建议在 pilot 的两模型上完成方法对照，正式新增模型优先只跑固定主协议与 Snapshot，控制矩阵大小。

所有模型提交统一的当前状态、来源引用、行动和简短依据；完整思维链不作为必交产物。主状态与修订指标根据实际前后状态及 Reference 计算，显式 KEEP/UPDATE 等操作标签只作辅助测量，避免把任务变成输出格式竞赛。实际格式失败仍保留并进入完成率统计。

冻结 provider、实际模型版本、提示、采样、推理预算、上下文上限和输出 schema，不使用会变化的模型别名作为唯一记录。主轨在所有模型能容纳的共同输入长度下比较；长上下文压力另设固定长度档位，规则仅在开发数据上制定。模型特有推理设置与费用如实记录，不假定不同供应商的同名参数产生相同计算量。

主比较使用相同证据包，首批 episode 尽量确保全部证据能放入上下文：

| Baseline | 每轮证据 | 额外上下文 | 解释 |
| --- | --- | --- | --- |
| Snapshot | 相同截至当前已交付证据包 | 无过去模型输出 | 独立重建状态的强基线 |
| Answer History | 同上 | 自身过去回答 | 观察历史判断帮助或污染 |
| Structured State | 同上 | 自身上一版完整结构化状态 | 观察显式状态组织的作用 |
| RevisionGuard，后加 | 同上 | 结构化状态 + 公开规则检查，最多一次修复 | 参考方法，额外调用和工具能力单独计费与报告 |

证据包保留旧文件时用公开元数据标识版本，不通过私有 Gold 选择“最相关证据”。主比较相同的是外部证据，不是总 token：历史表示本身增加的上下文和调用成本需要显式报告。

Delta-only / Memory-budget 是第二条系统实验：仅给新增证据，统一持久记忆容量及旧证据读取规则，比较有限回答历史、文本摘要和结构化状态。不同信息预算的结果分表，不能声称主比较的差异完全来自记忆效率。

每次请求由显式上下文重建，不依赖 provider 隐式会话历史。Snapshot 不继承前态，不能与有状态方法直接比较操作 F1；所有方法仍可比较当前状态和行动质量。

另加入两个诊断控制：只保留旧状态的 No-update 控制，用于验证任务确实要求修订；依据可见版本/范围规则选择材料的简单规则基线，用于检查是否大量任务只靠机械替代即可完成。它们的能力边界公开，不作为暗中帮助所有模型的 Gold 提取器。Oracle-prev 或 Oracle-extraction 只用于定位误差来源，不进入普通模型排名。

## 8. 自适应压力测试与状态使用诊断

### 8.1 Frontier 模块

基于同一 episode 生成合法 snapshot、pair 和 sequence。静态证据子集相同不代表历史状态相同，序列身份必须包含父状态、时间和到达历史。

每条待测性质包含可自动检查的适用条件：无关证据不变性、有效新版主导、条件单调性、证据充分性、顺序效应、撤回后残留。Text Core 的可操控单元是文档或经审核的文本 bundle；模态充分性留到扩展轨。更多证据不总意味着更高风险；模型行动改变也不等于错误。

先在约 6 个可操控单元的小空间做合法枚举。固定顺序的纯子集最多为 64 个状态，这是校准子任务，不代表所有顺序和历史也只有 64 种。真实模型得到的是固定采样协议下的经验响应表，不能称永久精确边界。

搜索 baseline：Uniform Random、固定 Canonical Suite、BFS、FrontierSearch-Lite。全部通过同一预算服务，只看到自己查询过的输出；开发集冻结策略，测试集不调权重。

搜索器只可读取公共候选约束、已查询结果对应的预定义反馈及剩余预算。私有 Gold 全表、未查询候选的性质标签、Oracle 最小充分证据集和完整反例目录均不可访问；各方法获得相同类型的反馈。公开反馈若包含已查询结果是否违规，也要在协议中声明，不能仅限制模型调用而放任免费读取其他答案。

搜索输出优先关注经确认、去重后的不同失败及其发现曲线。确认、补齐 pair 另一端和反例压缩也消耗预算。反例压缩必须保留输入对、失败性质和适用条件；局部一步不可再缩只能称 1-minimal。

开发阶段冻结反例去重键，至少包含事件、性质、关键变换及规范证据组合，同时报告原始失败边数与去重失败数。没有穷举参照分母时不报告反例召回率；搜索还需覆盖行动未变但 claim 错误的情况，不能只追逐行动变化边。

比较两种使用场景并分开统计：冻结响应表上的搜索效率，以及真实调用的端到端成本。构表成本计入总实验费用；缓存命中不让搜索算法免费获得新信息；重复采样不能反复使用同一个缓存回答冒充独立运行。

### 8.2 状态使用诊断

首版可选 OWN/NONE/ORACLE/STALE 四条件，在同一 checkpoint 的隔离会话读出状态或检验旧前提；当前输入不能已完整包含可重建目标状态的证据。ORACLE 不写回主轨迹。

分开评分事实正确性与忠实使用所给状态。状态更改影响输出，仅支持外部状态载体的行为作用，不能据此证明内部信念变化或对物理灾害的因果作用。下一轮 continuation 和局部 EDITED 探针留作后续独立实验。

## 9. 指标与统计

建议主表保留三个能力维度与可靠性分解，不把全部指标相乘成唯一总分：

| 指标组 | 核心结果 | 必要补充 |
| --- | --- | --- |
| 当前状态 | Grounded State：值、范围、时效与证据支持同时成立 | 纯值正确率、有效引用率、未知保持、无依据断言 |
| 时序修订 | Transition Success、必要修改召回、正确状态保护 | 非 KEEP 操作 F1、陈旧状态率、错误持续时间 |
| 行动 | 基于 Reference 的允许行动命中率 | 对自身 claims 的 Policy 一致性、过度反应、遗漏升级/降级 |
| 固定对照 | 两端均正确且满足应变/不变关系的 pair success | 性质违规数、适用分母、不适用原因、重复波动 |
| 运行质量 | 格式成功率、未完成率和可恢复性 | tokens、请求、延迟、费用及截断情况 |
| 自适应搜索 | 固定预算的独立确认失败数和发现曲线 | 首个失败成本、失败类型覆盖、缩减程度、构表与确认成本 |

每项给出分子、分母、缺失和排除原因。解析失败不能从主结果中静默删除，纳入 attempt-level 完成率/成功率；仅对有效输出计算的条件指标另表。合法未知按参考评分，`NOT_SCOREABLE` 排除并报告覆盖率，空分母为 NA。

引用检查分开处理“ID/定位存在”“该材料实际呈现或合法读取”“确实支持该 claim”。只有定位合法不能证明语义支持。历史引用合法性与当前支持有效性分别判定。

行动延迟同时报告小时和 checkpoint 数；观察结束仍未恢复的记录为右删失，并报告未恢复比例。只读取官方概率时评分读取误差；模型答题置信度和未来天气发生概率不能混用。后者需要另外设计足量事件/非事件与观测验证，首版不作概率预报校准主张。

聚合先在 episode 内，再在 storm 内，最终对 storm 做宏平均与成对分析。置信区间按 storm 聚类，不能把数千个 slot、pair 或子集当作数千个独立事件。4 或 8 个独立 storm 的区间很不稳定，应展示逐事件结果并限制总体推广。

若共享证据审计要求将多个 storm 合并为依赖组，则划分和重采样使用该更大的独立组，并报告 storm 数与独立组数。

重复次数建议从 3 次用于估计初期波动，再按 pilot 冻结正式确认规则；3 次不是自动充分的统计保证。对大量候选搜索产生的失败采用独立确认数据，并事先声明多重比较处理或探索性定位。测试结果不能反过来决定事件去留、Gold、容差和 prompt。

## 11. 实施路线与验收门槛

以下是以两名工程/研究人员加领域审核支持为假设的约 6–8 周 pilot 路线，非工期承诺。单人、历史资料难恢复或审核不可用时，优先缩小数据与轨道数量。

| 阶段 | 工作与交付 | 进入下一阶段的依据 | 参考时间 |
| --- | --- | --- | --- |
| P0 研究定义与来源审计 | 定位、任务、字段、Policy 草案；优先 Ida 来源矩阵、Ian 备选；上游版本/许可记录 | 至少一条真实文字预报与业务证据链有恢复路径，无法评分部分明确 | 第 1 周前半 |
| P1 统一合同与最小闭环 | 审计 starter；时间/版本/状态/Gold 合同；4 类 fixture；mock run/score/report | 能识别植入错误，Gold 隔离、实际输入记录、状态与预算语义可验证 | 第 1–2 周 |
| P2 首个真实 episode 与固定核心 | 经审核的原文/表格及范围映射；自然回放、Delay/Null；前三种 baseline | 无未解决关键时间/范围错误，真实数据可离线回放和评分 | 第 2–3 周 |
| P3 开发 pilot | 4 个独立 storm；有限真实模型；旧版和缺证对照；噪声估计 | 冻结纳入准则、提示、主要指标、干预适用条件与预算 | 第 3–4 周 |
| P4 搜索与诊断 | 小空间经验表；Random/Canonical/BFS/Frontier；确认和 pair shrink | 所有方法同预算、无未查答案访问；确认失败包可重放 | 第 4–6 周 |
| P5 留出 pilot 与交付 | 新 storm 测试；误差与成本分析；数据卡、版本锁、复现报告 | 区分工程通过、数据审核与真实结果；局限和负结果如实报告 | 第 6–8 周 |

P0 数据可行性与 P1 离线合同可并行；Gold/scorer 合同冻结后，再分工文本数据/标注、runtime、evaluation/search。接口字段只保留一个负责人，避免三条支线生成三套协议。GIS、多模态、中文翻译和多灾种扩展不阻塞首版。

关键验收用行为表达：future/hidden metadata 不能影响模型输入；删除私有标注不改变 rendered request；错误状态不会被评测器偷偷修复；缺证不会被 full-evidence Gold 错罚；相同查询重复与独立 replicate 不混淆；所有搜索调用都受预算约束。

本轮仅制定计划。下一步最小工作包是 P0 的来源矩阵和协议冻结草案，随后才进入 starter 改造。

## 12. 成本、扩展和研究风险

先计算请求规模再安排模型矩阵：

```text
自然回放请求数约 = storms × episodes/storm × checkpoints
                   × baselines × models × repeats
```

例如 12 storm、每场 1 episode、4 checkpoints、3 baseline、2 model、3 repeat，约为 864 次自然回放请求。若每条都做包括 base 在内的 4 条完整轨迹，上界约为 3,456 次；共同前缀可按预定配对协议复用，实际数量依干预设计决定。格式修复、Guard、探针和搜索另计。

推荐分阶段预算：先做约 50–100 次请求的 canary 测量实际输入长度、失败率和成本；pilot 的自然/固定干预先按不超过约 3,500 次主生成规划，重试与诊断另设明确限额，不默认展开所有组合。以上为规划容量，不是已经发生的调用或费用估计。

搜索更容易扩大调用量：8 个留出 episode × 2 model × 4 方法 × 3 seed × 每次 128 查询，已有 24,576 次逻辑查询，尚需说明预算内如何分配确认和缩减。优先用开发小空间的冻结响应表验证，再选择有限真实调用；构表成本不隐藏。

Text Core 费用按实际输入/输出及适用的推理用量计算，图像费用仅涉及后续扩展轨。货币预算在确定 endpoint 和型号后由 canary 测量制定，当前不虚报价格或默认资源已具备。预算同时限制请求、token、费用、时间与重试；并发调用先预留预算。每个缓存键包含实际输入哈希、模型配置、提示/schema、父状态、分支和 replicate；扩展轨再加入图片/工具结果哈希。恢复任务不删除历史结果。

主要风险与调整方式：

| 风险 | 早期检查 | 调整方式 |
| --- | --- | --- |
| 严格公开时间难恢复 | 两场候选的发布依据覆盖 | 使用明确标注的 issued-time 主样本，严格子集另表；未来增加前瞻采集 |
| 行动 Gold 分歧大 | 双人审核规则和多解情况 | 核心聚焦状态与公开规则，现实政策合理性单列 |
| 文本整理代替模型完成推理 | 核查抽取文本与原文逐项对应，特别是空间关系、例外及行动 | 主输入不含 Gold 或派生状态；工具产生的事实进入独立辅助轨 |
| 视觉扩展中图像内容被文本完全复述 | text/image/full 的支持充分性标注 | 区分冗余与必要样本，限制视觉能力主张 |
| 样本被模型预训练记住 | 无证据回答、非法引用、去身份诊断及事件时间记录 | 标为污染风险诊断；适时采集新事件，匿名化不能保证消除记忆 |
| 不同模型使用不同状态方法或信息预算 | 核查实际证据、运行协议、推理设置与成本 | 模型主表固定协议，方法改进在同模型内比较，辅助工具和长上下文单列 |
| Frontier 不优于 Random/BFS | 开发集和留出集同预算曲线 | 将其保留为诊断工具，不强行主张搜索创新 |
| 反例主要来自随机波动 | 相同输入重复、独立确认 | 按随机系统报告，不能把单次翻转都计为稳定缺陷 |
| 数据太少或采样偏差过大 | storm 数、地域/强度/阶段/负例覆盖 | 明确 pilot 定位，用覆盖和精度目标指导扩容 |

模型很强、状态方法无收益、某模态冗余，都是允许的结果。扩容依据测量可靠性和覆盖需求，不能以必须产生低分或排名反转为成功标准。

## 13. 最终交付

1. **协议包**：任务定义、字段、Policy Cards、时间轨道、合法变换、指标和统计预注册。
2. **数据包**：事件清单、来源与哈希、公开证据、审核记录、私有 Reference、storm 级划分和数据卡。
3. **运行包**：统一 CLI、模型 adapter、状态/预算/缓存/恢复、固定评测与搜索组件。
4. **验证包**：合成与真实测试记录、泄漏和适用性检查、固定配置、可重放反例。
5. **报告包**：逐事件与总体结果、模型/系统/搜索分表、成本、置信区间、失败分类和结论边界。

公开发布前重新检查代码与证据的再分发条件。不可直接重发的材料提供来源清单及合法获取步骤。公开开发集与私有留出评测分开，发布版本后不根据测试成绩静默修改评分规则。

## 14. 已确认方向与推荐默认值

用户已确认评测 LLM，并允许根据现有方案推荐其他选择。以下作为后续协议细化的默认方案；资源需求是建议，不是声称用户已拥有对应人力、专家、API 或设备。

| 决定 | 推荐默认值 | 依据 |
| --- | --- | --- |
| 研究对象 | LLM 的证据理解、动态修订与规则决策 | 用户已明确；与 Trace 任务直接对应 |
| 研究交付 | 按论文可复现标准组织，先做 pilot | 先验证测量与数据，再扩大结论 |
| 领域与地域 | 美国大西洋/墨西哥湾气旋与港口 | 现有资料和已核查 NHC/USCG 来源可复用 |
| 首事件 | Ida 2021 × New Orleans 明确辖区/航段优先，Ian 备选 | 已找到含分发时间和分范围生效规则的公告 |
| 语言 | 英文原文 + 英文提示；中文文档 | 减少翻译对证据语义和模型表现的混杂 |
| 输入 | Text Core 必做；工具和多模态扩展后加 | 主轨支持不同 LLM 在一致输入能力下比较 |
| 时间协议 | Issued-time 主轨，Verified-availability 子集另报 | 保留时间依据差异，降低资料恢复对首版的阻塞 |
| 决策 Gold | 官方状态跟踪 + 显式研究 Policy | 不把历史实际行动等同于唯一最优建议 |
| 样本 | 1 事件贯通，4 开发 + 8 留出 storm pilot | 先测方差和审核成本，再决定总计 20–30 storm 的扩展是否可行 |
| 模型 | 1 个 canary、2 家族 pilot；正式目标 4–6 个 LLM | 覆盖能力/规模差异，同时控制调用矩阵 |
| 模型比较 | 固定 Structured State 主协议 + Snapshot 对照 | 将模型差异与方法差异分开 |
| 方法比较 | 同模型内 Snapshot / Answer History / Structured State，Guard 后加 | 先证明状态组织是否有作用 |
| 搜索 | 固定评测成立后做 Frontier 与 Random/BFS 对照 | 不让搜索方法成为 benchmark 成立的前提 |
| 人力与排期 | 推荐 2 名工程/研究人员，另有双人标注复核及领域顾问；6–8 周 pilot | 审核与来源恢复决定实际速度，专家可兼职 |
| 计算与预算 | CPU 数据工程，托管推理优先；canary 测量后冻结费用上限 | 首轮不依赖本地 GPU，也不虚构模型单价 |

进一步扩大到其他灾种或中国场景时，优先验证迁移到新来源、新规则的能力；不能仅靠增加同一风暴的 QA 数量扩大 benchmark。可在后续选择一个新领域做独立留出集，迁移前冻结通用协议，并提供该领域必要的公开规则与背景映射。

资源接入时只需补齐实际 endpoint/版本、调用额度和审核人员等执行信息；不再将已确认的 LLM 方向及已委托推荐的普通范围选择作为反复确认事项。本轮仍停留在计划更新，下一工作包是首事件来源矩阵、标注规范与两条示例轨迹。
