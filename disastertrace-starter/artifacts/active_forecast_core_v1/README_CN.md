# DisasterTrace：正式证据内核第一阶段完成说明

本轮执行最终方案第一周的 D1-D2：将可行性原型迁入正式 Python 包，并核验迁移。
新的代码位于 `src/disastertrace/active_forecast/`。此前 12 小时可行性任务已经关闭，
本轮是独立工程阶段；没有重开旧实验或重新计算并覆盖历史模型成绩。

## 本轮完成的工作

### 1. 把证据、目标和评分规则变成明确的契约

`schema.py` 定义任务、证据卡、记录、来源捕获、定位符、时间、目标和模型答案。
结构禁止额外字段；卡片成本和预算必须为整数；无穷值、NaN、布尔数值、
重复版本、重复支持、无效分区和含糊的记录融合会被拒绝。
Pydantic 对象冻结，内部集合使用 tuple。模型输出协议仍为决策与引用两个字段。

首版保留三类任务：

| 操作 | 测量内容 | 不确定性如何保留 |
| --- | --- | --- |
| `revision_delta` | 同一有效时刻、指定两个产品版本的数值差 | 缺少任一合法版本则不能得出差值 |
| `count_threshold` | 固定日期/支持单元中，达到阈值的数量 | 未读、缺测或无效项保留为可能取值 |
| `area_threshold` | 固定帧中达到阈值的像素比例上下界 | 缺测像素留在完整分母中，不计为负例 |

面积任务还检查矩形边界、重叠、覆盖面积与同帧有效时间。当前比例定义在均匀像素网格上，
不是地球表面的等面积地理测量。

### 2. 分开时间概念，处理精确边界

签发时间、有效时间、可证明的公开时间区间、实际捕获时间、逻辑交付步各自保存。
所有真正的时刻都转换为带时区的 UTC 对象；站点日期和 USDM 图件日期保留为日历日期。
归档回放只按逻辑交付步决定材料是否进入池，不给它补造一个历史时刻。

104 个冻结样本都继续使用归档回放模式；未证明的历史公开时间全部为 null。
本轮还纠正了字段分类：NHC 有可恢复的签发时刻，SEVIR 的帧时间、USDM 的图件日期、
GHCN 的归档标记则不再当成产品签发时刻。旧标签仍能在冻结原始样本中追溯。

计算使用 `Fraction`，JSON 小数先以 `Decimal` 读取。Python 调用接口拒绝二进制 float，
序列化结果使用 `n/d` 有理数字符串。这样，`0.3 - 0.1 >= 0.2` 和
`1 - 9/10 == 1/10` 不会受到浮点舍入影响。
`INTENTIONAL_COUNTEREXAMPLES.json` 保存了这类合成反例，不能计为真实天气样本或模型成绩。

### 3. 让证据能回到来源字节

定位符支持 SHA-256 绑定的完整文件、JSON Pointer、字节区间和 uint8 帧内区域。
路径越界、哈希不符、选择器不存在、数组形状不匹配都会报错。

| 来源 | 本轮实际核验 | 次数，包含重复变体与干扰资料 |
| --- | --- | ---: |
| NHC | 从原始公告字节定位风速行并比较数值 | 659 |
| GHCN-Daily | 比较原始 JSON 中的站点日值和质量标志 | 112 |
| USDM | 比较冻结点位计算并核对原始 ZIP 文件绑定 | 56 |
| SEVIR | 从原始事件字节定位帧/区域，重算正、负、缺测计数 | 118 |

共核验 68 个绑定文件、解析 1,724 个不同定位符。上述次数是导入核验次数，
不是独立事件数。USDM 本轮没有重新执行点位几何解析；此前的几何边界限制仍适用。

### 4. 隔离模型可见字段

`public.py` 通过白名单构造精确产品值轨道的输入。目录包含范围、版本等元信息，
只有已读取的卡片才包含值与质量标志。私有来源定位符、文件哈希、组别、split、
完整池结论、充分证据集合和最低成本不进入公开 DTO。

测试覆盖了未来卡片不可见，以及改变未读卡片的值或质量不会改变当前公开输入。
这是字段投影层的保证；模型运行器、工具访问权限和读取回执仍需在后续阶段实现并测试。
当前公开结构也尚未经过新一轮 LLM 格式试跑。

| 验收项 | 实际结果 |
| --- | ---: |
| 冻结开发样本 | 104：NHC 24、GHCND 32、USDM 16、SEVIR 32 |
| 完整池最小充分证据集合比较 | 104 / 104 一致 |
| 原有 92 个试点的冻结结论及证书 | 全部一致 |
| 所有合法阅读子集的决策、理由、充分性、额外成本 | 1,296 / 1,296 一致 |
| 答案、引用、预算组合的评分比较 | 41,600 / 41,600 一致 |
| 公开 DTO 序列化回放 | 1,296 / 1,296 一致 |
| 新增自动化测试 | 59 项通过 |
| 原型历史测试 | 10 项通过 |
| 新模型调用 / GPU 作业 | 0 / 0 |

评分比较覆盖每个阅读子集的全部已读引用子集，以及未读引用、不存在的引用和无效输出；
预算使用可行的两类设置。原型展示用浮点上下界允许 `1e-12` 的数值比较误差，
决策、证据集合、成本和评分字段则要求一致。没有用这种误差容忍放宽新内核的阈值判定。

测试还包含独立可能世界枚举：216 个计数状态和 1,728 个空间状态，检验充分性判断。
它们是合成语义测试，不扩充真实样本量。

当前继承的分组标签为 NHC 4 组、GHCND 4 组、SEVIR 11 组、USDM 1 组。
这些标签尚未经过新的正式分组器与交叉泄漏审计，因此不据此作独立样本统计推断。

## 保留的失败与解释

`01_regressions_before.log`、`03_provenance_before.log`、`06_cli_before.log`
记录了相应模块实现前的测试失败。首轮核心测试随后通过。

`replay_01/` 与 `08_replay_01.log` 保留第一次兼容性审计失败：审计脚本把冻结报告的
浮点数转为 `Decimal` 后直接比较，产生误报；报告写出又遇到 Decimal 序列化错误，
留下不完整的 `COMPATIBILITY.json`。该目录不是验收结果。
`11_replay_regressions_before.log` 保存针对这两个问题的失败回归测试。

修复后，原型及旧报告用其原本的浮点 JSON 语义读取；新内核仍使用精确数值。
JSON 写出先完成序列化，再排他创建文件。全量回放在新目录 `replay_02/` 成功，
没有覆盖或删除第一次失败。

本轮使用已有 `.venv`：Python 3.10.12、Pydantic 2.13.5。通过 `PYTHONPATH=src`
运行，没有安装或升级依赖；不声称已完成全新环境安装或完整历史仓库测试。

## 入口与复现

从 `disastertrace-starter` 运行：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m pytest tests/active_forecast

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover \
  -s ../plans/v5_0910_feasibility_12h_20260910/code -p test_evidence_core.py -v

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m disastertrace.active_forecast replay-legacy \
  --bundle ../plans/v5_0910_feasibility_12h_20260910 \
  --output artifacts/active_forecast_core_v1/reviewer_01
```

复现目录必须是不存在的新目录。`SCHEMAS.json` 保存结构契约；
`CLI_EXAMPLES.json` 保存四个实际执行的命令、退出码和输出位置。
`examples/` 是确定性程序示例，没有伪装成模型输出。
`EPISODES_PRIVATE.json` 和 `EPISODE_AUDIT_PRIVATE.json` 是离线私有材料，
不能直接送给被测模型。库接口与命令行说明见源码目录的 `README.md`。

`MANIFEST.json` 绑定代码、测试、报告和保留的失败记录；
`VERIFICATION.json` 保存本轮完整性核验。可在不运行模型的情况下再次检查：

```bash
python3 artifacts/active_forecast_core_v1/verify_milestone.py \
  --output artifacts/active_forecast_core_v1/verification_reviewer_01.json
```

该命令核对原始基线、来源字节、交付文件及已记录的验收，不替代新的科学参考计算。

## 下一步执行顺序

1. **D2-D3：来源准入与分组。** 分别保存 raw、product、capture、delivery、target、outcome；
   形成有接受/拒绝理由的来源清单。用来源链和父变体关系固定组别，检查跨组共享事件、
   日期、站点、帧和源产品；继承既有开发暴露记录，保留原 heldout 隔离。
2. **D3-D4：按预先规则扩样。** 扩展 NHC 自然版本变化、GHCN 历史气候相对阈值、
   USDM 时间/地区分块、SEVIR 自然覆盖层次；保留所有资格判断和拒绝分母。
   本轮导入的 104 个样本不算新扩样。
3. **D4-D6：完善评测接口。** 分开原生表示、精确产品值、工具输出三轨，加入获取回执、
   公共输入可解性验证、固定预算和程序基线，之后冻结任务与输入协议。
4. **D6-D7：运行模型开发矩阵。** 先做两个开发模型的小规模格式试跑，协议通过后再执行
   配对矩阵。可沿用最多 4 张 H100 并行的授权，任务按模型和条件分片；
   继续保留无效输出与失败分母。

本轮完成的是经过核验的第一阶段内核。数据扩样、正式分组、多模态运行器、
新 GPU 结果和最终 benchmark 发布均未在本轮完成。
