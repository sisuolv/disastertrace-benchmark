protocol-specific capture, independent provenance/budget audit and direct
captured-result scoring. There are zero actual model calls in this stage.

## Result boundaries

The correct program can pass all P2 opportunities. This checks the execution and
scoring pipeline; it is not evidence of a model's update or memory ability.
Neither a diagnostic origin label nor a changed report manifest can qualify a
fixture for the LLM scoreboard. Actual model results require the separate frozen
P2 execution, authorization, price evidence, captured responses and audit.

The default next-model proposal has 270 attempts and a common 8192 output cap,
with an independent USD 3 conditional allowance. It reserves 2,211,840 requested
output tokens; this is not T6's mixed-cap budget. No second model, heldout run,
additional canary or automatic retry is included in this proposal.

## Archive

Delivery files: [offline result archive](p2_execution_offline_v1.tar.gz),
[archive manifest](archive_manifest.json), and [executed verification](verification.json).

After successful full acceptance, `package_results.py --run <acceptance-directory>`
creates an immutable archive with source, tests, semantic package, execution,
journal, raw captures, audit, direct scores, reports and command evidence.
The archive verifier checks member hashes, archive hash and historical files
without extraction. The final archive requires full-suite evidence; an explicitly
skipped test run cannot satisfy that condition.

```bash
.venv/bin/python artifacts/p2_execution_v1/package_results.py --verify-only
```

The archive requires the installed project environment for replay. Environment
and registry paths participate in execution identity; relocating a run does not
grant a new production claim. A fresh reproduction uses a fresh execution identity.
Git publication and remote CI are separate from these local validation records.
