# 共同输出契约 v2：离线结果与解释边界

## 结论

共同输出契约 v2 已实现并通过离线验收，可以作为下一轮独立开发筛选的候选。它统一三种方法收到的 system 输出说明，保留公开任务、Gold、严格解析和评分规则。本阶段新增真实模型 API 请求为 **0**，不新增逐题人工标注或 LLM judge。

这不是 v2 模型效果已经改善的结论。首轮 P2 的两个失败格式单元、六个无效回答和三项引用错误均保持原状，仍是历史实测结果。

## 改动及其原因

首轮六个无效回答中，四个可解析为 JSON，却缺少 `state/action`、错误复制输入对象或添加额外根字段。新版把根对象、四个天气字段、slot/citation 的嵌套结构、类型和 action 枚举完整放入 system 消息，明确禁止复述输入容器。三种方法收到完全相同的说明。

引用部分说明 `record_id` 对应来源记录，`delivery_id` 对应投递事件；引用行号必须是该记录中支持当前字段的 ASSERT 行。它没有提供题目的正确值、正确记录编号或具体正确行号，仍由模型依据公开证据完成任务。

`parse_decision` 与评分器没有放宽。结构错误仍是整答失败；格式正确但引用错误仍按原规则失分；已知值配空 evidence 仍可通过结构检查、但不得 grounded 分。有效事实错误继续原样进入载体，无效整答继续保留上次有效载体。

版本身份贯穿准备、传输验证、采集、恢复、审计与报告。v1 默认接口继续产生旧准备格式和请求哈希；v2 显式绑定 system 文本哈希，无法将旧捕获响应当作新条件的响应。旧执行用其冻结源码继续复核。

## 诊断成绩的含义

主程序诊断的三种方法均为：90/90 格式有效，282/282 已知且引用正确，78/78 正确未知，90/90 检查点全部正确。九个格式单元均通过程序检查。

这些回答由公开规则程序产生，只证明管线能执行预定协议。诊断 usage 是测试夹具给出的数值，其时延和费用不能当作 DeepSeek v2 的真实资源消耗；`model_calls=0`，不进入 LLM 排行榜。

## 请求大小和预算

system 文本从 132 增加至 2,488 个 UTF-8 字节。在首轮全部 270 份实际公开请求及其原载体的未发送投影中，provider 请求每份增加 2,449 字节，最大为 12,600 字节，小于 262,144 字节的请求保护阈值。JSON 转义使 wire 增量与纯 system 字节增量不同。

这个对照没有重新调用模型，没有将旧载体灌入新运行，也没有估算 token 数。新版模型可能生成不同长度的载体，实际 prompt/completion tokens、费用以及长度失败率仍待测量。

下一轮提案为最多 270 次、8192 输出上限、high/thinking、无 temperature、无重试、独立 USD 3 条件预算。最大请求输出总额为 2,211,840 tokens；每次按完整上下文上界预留 USD 0.47218688，再按可信 usage 保守结算。如果每次都达到该预留上限，270 次理论合计为 USD 127.49045760，显然不由 USD 3 覆盖；运行必须在下一次预留不足时停止。该理论极值不是实际费用预测，也不是新的预算申请。

## 保留的工程检查历史

首次静态检查发现新增脚本的一行过长，修正后通过。新对照工具起初未遍历列表，三个回归用例复现配对分母遗漏；修正后补充逐检查点机会对照。

第一次外层终验又发现评分 JSON 的字节不同。检查确认 30/30 组分数内容完全一致，差异来自未排序计数字段的键顺序；原流水线本就按规范化内容比较分数。对照工具现保留双方原始哈希，并使用严格 JSON 内容比较，新增测试确保键顺序可以不同、实际数值变化仍被拒绝。任务、评分器和原分数文件均未修改。

上述失败日志与修正记录都保留在 `validation/`，第一次外层终验的退出码 1 不被包装成通过；第二次终验重新核对现有 13 步记录、日志哈希、当前实现/环境与报告，再完成后续对照。核心回归无需因验收工具的这个修订重新执行。
