# 给 ChatGPT Pro 的复查说明

## 请复查什么

本轮希望评估：共同输出契约 v2 是否构成一个边界明确、可复现的接口修订，足以进入下一轮 LLM 开发筛选。请以可执行代码和实际验收记录为依据，指出测量、版本隔离、泄漏、恢复或报告方面的实质问题。没有必要新增逐题人工标注或用模型给模型打分。

建议先读 `../../README_P2_OUTPUT_CONTRACT_V2.md`、`FINDINGS.md` 和 `NEXT_PHASE_PLAN.md`；再按需查代码、对照记录和旧版完整结果。

## 背景

研究目标是测试 LLM 接收分轮天气证据时，是否能够更新事实、保留未变字段、抵抗旧版本重放、恢复缺失事实，并提交正确来源与行动。这里的 P2 是初始数值继承自 NHC、后续更新受控生成的任务；不能把它等同于完整自然灾害观测或数值天气预测准确率评测。

首轮矩阵为 18 个 episode × 3 方法 × 5 检查点，共 270 次真实 DeepSeek 响应，审计完整。两个 U2 单元只有 28/30 格式有效，没有通过所有单元至少 29/30 的共同门槛。六次格式错误中四次已经是合法 JSON，另外两次为空内容的 length 结束；还有三项引用错误。旧回答、原始分数和门槛完整保留。

三种方法分别使用完整公开证据、完整公开证据加最近有效状态、完整公开证据加有效回答历史。每个检查点都以新消息发送，只携带所声明的载体。评测的是这个显式外部载体条件下的表现，不能直接推断模型内部记忆机制。

## 优先检查的边界

| 检查对象 | 应当成立的约束 | 代码/证据入口 |
| --- | --- | --- |
| system 输出契约 | 三方法一致；完整字段、嵌套类型和引用说明；没有填好的题目答案 | `system_message.txt`；`src/disastertrace/controlled/output_contract.py` |
| 请求对照 | 相同公开请求和载体下，provider payload 仅更换 system 内容；参数未变 | `equivalence/`；`scripts/verify_p2_output_contract.py` |
| 版本绑定 | 不可把 v1 抓取数据、v2 文本或不匹配哈希混在同一准备/执行中 | `provider_adapter.py`、`provider_capture.py`、`execution.py`；新增测试 |
| 严格评分 | 不修复无效 JSON 结构，不自动转换 delivery_id，不删除失败分母 | 七个未改动语义模块的哈希；30 组分数/轨迹对照 |
| 载体与恢复 | 无效整答保留上次有效载体；有效事实错误原样传播；已抓取响应离线收尾，不重发 | `live.py`、`live_audit.py`；两版的五个中断边界测试 |
| 独立审计 | 由日志重建实际暴露、载体、usage 和预留；两版分别用冻结源码重算报告 | `validation/acceptance/`；`diagnostic_report/audit.json` |
| 实验设计 | 固定全部 270 槽位、九单元门槛；不只补失败题、不以历史差异证明因果关系 | `proposal.json`；`NEXT_PHASE_PLAN.md` |
| 历史保护 | 旧模型回答、原分数、授权、登记与归档原字节不变 | `baseline/protected_files.json`；历史复核结果 |

## 已知研究限制

目前仍只有一个模型家族。当前来源与情形并非完全交叉：Ida、Florence 使用 primary，Dorian 使用 secondary。分支和检查点相关，270 个调用不是 270 个独立风暴样本。单次开发筛选不能支持稳定排名、跨灾种泛化、内部记忆结论或论文级显著性声明。

输出说明更清楚仍可能改变方法间差距，这正是需要重新冻结与实测的原因。保持 system 对所有方法一致不等于已经消除了提示与方法的交互。若研究结论依赖契约的因果效果，应另设计同时间交错的两契约实验。

新版仍固定 8192 输出上限。离线验证无法证明原来的两个 length 问题已解决；也不能根据四个结构错误已经是合法 JSON，就认定任何额外 JSON 模式会自动提供严格 schema。
