# 输出契约 v2 之后的可执行计划

## 1. 下一轮优先执行 270 次开发筛选

目标是检验共同 v2 契约能否在完整开发矩阵达到既定格式门槛，同时报告语义、引用和资源消耗。实际身份与预算提案以同目录 `proposal.json` 为准。当前该提案未启动，授权模板为 false。

| 项目 | 固定方案 |
| --- | --- |
| 数据 | 与首轮相同的 18 个受控 development episode |
| 方法 | snapshot、structured_state、answer_history，共用同一 v2 system |
| 矩阵 | 18 × 3 × 5 = 270 次；54 条独立载体轨迹；一次重复 |
| 模型 | `deepseek-v4-flash`，`https://api.deepseek.com` |
| 推理与输出 | high、thinking enabled、8192；无 temperature；不增加 JSON mode |
| 传输 | 180 秒 socket/总时限、1 MiB 响应限额，原有请求字节保护 |
| 调度 | 相同轮换顺序，不插入额外探针，不自动重试，不复用旧回答 |
| 条件预算 | 独立 USD 3；最多请求输出 2,211,840 tokens |
| 格式门槛 | 九个 family × method 单元各 30 点；每单元至少 29 个格式有效、最多一次 length，且全轮审计完整 |
| 结果处理 | 保留每个响应与失败；完整分母评分、引用诊断、成本/时延与配对描述 |

启动前将本次实际批准记录绑定到新 execution ID，确认当前官方价格及参数仍匹配冻结快照，并核对新生产登记未消费、真实输出目录不存在。如果价格或设置改变，应重新冻结，不能修改现有 manifest。无需额外付费接口探针；若确实需要，先列入新的调用清单和预算。

预算是条件保护，不是最坏情况下完成 270 次的承诺。当前每次按完整 1,048,576 prompt tokens 与 8192 output tokens 预留 USD 0.47218688，收到可信 usage 后再保守结算。USD 3 不覆盖每次都达到完整上下文的极端情况；若后续预留超额，发送前停止，报告未提交槽位，不偷偷追加预算。首轮费用可作背景，不能作为新版的报价或实际账单。

## 2. 预先约定如何处理结果

完整审计与九单元格式门槛均通过时，报告全分母的事实、引用、更新、保留和未知恢复指标，再推进跨模型开发比较。格式通过不等于事实、引用或研究设计全部合格。

若仍有结构错误，保留该版本结果，继续统一的接口诊断。若长度问题仍造成门槛失败，单独版本化输出/推理预算试验；不同时改提示、cap、证据数量和载体策略，不降低 29/30 门槛，不剔除失败项。

若发生发送后未确认响应，保留未知费用预留并停止；已捕获但未完成处理的响应先离线恢复，不能因为重启或日志锁释放就重新发送。

## 3. 何时需要 540 次两契约实验

本轮 270 次仅检验 v2 是否达到开发筛选要求。与先前 v1 分数作描述性比较时，应注明采集时间不同、每条件仅一次采样，不能把差值全部归因于 system 改动。

如果后续论文要研究契约效果及其与方法的交互，再冻结 2 契约 × 18 episode × 3 方法 × 5 点 = 540 次的同时间对照。每个契约臂独立维护载体，预先确定交错顺序与分析单位；不能把旧回答作为其中一臂，也不能跨臂传递历史。该设计需要自己的范围、重复数、执行包和预算。

## 4. 第二模型与平衡设计

格式设置稳定后，选择另一个模型家族。先确定实际 provider/model、参数支持、输出/推理限额、价格、速率限制和可用凭据；相同的 high 标签或数值 cap 不表示跨模型等量计算。公开任务和确定性评分沿用冻结版本，模型接口单独验证。基础开发矩阵仍为 270 次，任何额外探针单独计数。

若需要分离来源组与 primary/secondary 情形，另建每来源组同时包含两种情形的平衡版本：3 来源组 × 3 任务族 × 2 情形 × 2 分支 × 5 点 × 3 方法 = 每模型 540 次。此扩展先离线冻结，不替换当前矩阵，也不根据模型是否答错来筛题。

## 5. 留出评测最后启动

在开发设置和测量规则稳定后，明确三种泛化目标：新来源组、新生成种子、未用于开发的操作组合。新种子不是新增独立天气事件；仅做风暴 split 不能证明未见模板泛化。

冻结协议、生成器、组合模板、split、scorer、指标、模型参数、重复数、执行顺序与分析单位，再准备七个留出风暴的调用。NHC 与 P2 分表报告，当前开发筛选不作为最终测试成绩。整个流程继续使用自动 Gold 和确定性评分，不要求新增逐题人工复核或 LLM judge。
