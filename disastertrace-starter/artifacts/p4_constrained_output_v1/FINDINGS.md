## 2. 为什么说 benchmark 得到了优化

这次新增的是独立的解码轨道，原来的自由输出实验及其失败保持原样。相同的
36 episodes、108 trajectories、540 slots、公开证据、自动 Gold、输出提示词
v2、解析器、评分器和基础采样设置继续使用。

grammar 只规定容器、必需键、类型和合法字面量。它没有指定正确数值，没有枚举
当前 record ID 或正确行号，没有把风速与动作的关系编译进解码，也没有替模型
处理未知状态一致性、数值范围或精度。因此，格式约束并不保证语义正确。

本轮由自动评分识别出 54 处字段错误：15 处值/状态不匹配，39 处当前版本引用
缺失或错误。另有 6 个动作错误，都发生在已经存在风速字段错误的 checkpoint，
不能把它们直接相加为独立错误题数。

| 方法 | 值/状态错误 | 值正确但当前引用错误 | 完整错误 checkpoint |
| --- | ---: | ---: | ---: |
| snapshot | 2 | 15 | 13 |
| structured_state | 2 | 0 | 2 |
| answer_history | 11 | 24 | 35 |

这说明引用评分在本轮提供了明显的区分信息。structured_state 的观测结果最好，
answer_history 的引用与状态错误更多。但三个来源组和一次采样不足以证明普遍
的方法优越性；所有方法都能看到累计公开证据，也不能据此推断内部记忆能力。

对照程序核对了相同任务文件、Gold、调度、7 个语义/提示词模块、模型快照、包
版本清单和原始采样参数，并核对每种方法的 116 个指标分母以及全部 checkpoint
机会。两轮 540 条请求的公开证据均一致。

实际输入 token 完全相同的数量为 snapshot 180/180、structured_state 103/180、
answer_history 78/180。后两者的差异来自模型过去的合法回答变化，不能把两轮
所有 prompt 都说成逐字相同。相同 seed 也不表示受约束与自由采样结果等价。

本轮三种方法的观测排序相对于 P3 改变，进一步说明自由输出中的格式失败会
影响总体分数。应把两条轨道分别报告，不用本轮结果覆盖 P3，也不把原来的
“仅合法答案”诊断当成公平的新旧语义比较。

## 4. 实现与实际验证

新增 `src/disastertrace/constrained_eval/`，保持旧模块不变。使用 vLLM 0.10.2 V1
和 XGrammar 0.1.23，明确禁用解码后端 fallback，保留 Qwen3 thinking。真实
reasoning gate 先开放思考阶段，直到生成 `</think>` 后才应用 JSON token mask。
GPU 加载核验确认实际引擎配置与冻结设置一致，核验阶段禁止调用 LLM.generate。

schema 的属性顺序被单独固定。XGrammar 对属性顺序及整数的词法表达有额外
限制；最终 grammar 接受 EOS 151645，而模型还有 EOS 151643。解码差异都保存
在能力与配置记录中。prompt 中预先出现关闭思考特殊 token 时会被明确拒绝，
以免后端提前启用 grammar；程序不清洗或丢弃历史来绕过该保护。
