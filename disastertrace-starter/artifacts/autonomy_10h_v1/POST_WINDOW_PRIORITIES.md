# 本轮之后的候选优先级

本文记录后续工作的建议顺序，不增加本轮 P14 之后的模型实验，也不授权重跑已经消耗的
执行声明。编写时 P11 仍在收集，P12–P14 尚未产生最终模型结果；具体实验选择应结合
本轮最终结果和研究复查意见。所有历史任务、原始回答与评分保持冻结。

## 1. 先解决轨迹之间的故障牵连

P9 和 P11 已经实际出现：一个 answer_history 请求超出上下文上限，导致整个 worker
退出，同批可容纳的请求以及后面的其他轨迹也不再执行。固定分母正确地保留了这些缺失，
但无法消除调度顺序对方法结果的影响。正式 heldout 之前应先解决这项工程问题。

新版本应在请求进入批处理之前逐条检查上下文。若某条轨迹不能继续，保存明确的
`context_blocked_before_dispatch` 记录，并保留该轨迹后续所有计划槽位；其他独立轨迹
继续执行。不要自动截断历史、给失败轨迹更换方法、注入程序答案或补答历史实验。

必要的软件验收包括：超限出现在批次第一条或最后一条时，其他轨迹的调度相同；不同
worker 分配不改变失败归属；超限未提交与模型实际输出失败可区分；后续槽位保持在
分母里；断电恢复不会重复提交。用确定性的程序对照和故障注入先完成这些检查，
随后才登记新模型矩阵。这一改动属于收集器的新版本，不能修改 P7–P14 的旧报告。

## 2. 根据本轮分项结果决定输出协议

主分数继续要求完整正确，但应同时展示回答覆盖、结构合法、风暴与时刻、状态、数值、
单位、来源版本和行号分项。P9 的单位字符串错误、长度失败和上下文失败已经表明，
单个总分不足以说明模型究竟错在哪里。当前分项已经可用，不需要事后改写主分数。

P12 检查默认 JSON 格式空白，P13/P14 检查同文字的提示角色位置。它们分别生成自己的
历史，后者还改变原生聊天模板的 token 序列。根据结果选定下一版共同协议时，应公布
选择所依据的开发结果，再冻结协议。不能把选出的最好配置在同一开发集上的分数
当作未调参的最终泛化结果。

若需要容许确定性的单位等价表达，应另行规定新评分版本、等价集合、符号转换和
引用检查，并用独立反例测试。在旧版本上追加一个明确命名的诊断层可以帮助解释，
但不能覆盖原分数，也不能通过新语法强制写出答案来宣称模型原本掌握了该能力。

## 3. 扩展真实情境与时间依据

下一次数据扩展应预先固定取样规则，覆盖早期发展、成熟期、登陆附近以及终止阶段，
避免仅由最初编号公告代表整场风暴。优先补充真实的终止状态修订、同一绝对时刻的
预报覆盖变化、跨月和跨年、不同半球或经度符号的记录。软件 fixture 与真实来源
覆盖要分别统计。

自动 Gold 继续从可追踪的原始产品生成。两套解析器一致只是一个检查条件，还应
检查它们共享的规范化步骤，并使用可获得的独立结构化产品核对明确字段。若没有
历史公开可见时间的证据，继续标记为受控 issued-time replay；不要把获取时间或
模型初始化时间替代为历史可见时间。

现有 heldout 分组保持未调用。先完成协议选择、解析规则冻结和故障隔离，再准备
独立的 heldout 执行计划。公开历史文本存在训练语料污染的可能，不能仅凭时间切分
宣称已经去污染。

## 4. 基线、重复与统计

公开 latest-explicit resolver 已能满分完成当前任务，应始终与 LLM 结果一起报告。
下一步有价值的基线是相同证据和预算下的明确检索/版本选择流程，以及架构来源更独立
的模型家族。DeepSeek-R1-Distill-Qwen 与 Qwen 的对比不足以证明跨架构泛化。

额外重复用于观察采样不稳定性，更多独立风暴用于观察来源差异，两者不能互相替代。
统计单位优先是风暴组；正式区间或检验之前需要明确研究问题与配对结构。当前六个
开发风暴和大量相关检查点适合描述性结果，不应使用逐检查点独立假设制造精确显著性。

例如，在当前 804 个检查点上，三个方法、两个模型、两个重复需要 9,648 个回答；
再增加一个协议条件会翻倍。这只是预算公式示例，不是本轮已经启动或承诺启动的任务。
新实验应先固定总请求数、输出上限、时限、GPU 分配和失败规则。

## 5. 工程整合与交付

历史版本命名空间保证了可重建性，但也带来重复代码。未来可把任务、提示渲染、解码、
调度和审计配置成明确版本的接口，再为每次执行保存不可变源码包。重构应先用旧产物
做兼容性验证；不得为减少重复文件而改写历史源码快照或让旧报告读取新默认值。

后续 GPU 队列适合使用一个持久协调器管理所有申请与释放，并将待启动申请计入同一
容量账本。这样可以在独立任务允许时提前完成预检，同时避免多个提交器同时看到空闲
资源而超过四卡上限。失败后的恢复应查询原作业身份，不自动创建替代模型作业。

最终对外材料应区分：阅读附件、可恢复的完整证据、实际模型回答、程序诊断以及
仅准备好的计划。发布具体 commit、验收清单和依赖版本；科研结论以可复核的实际结果
为依据，不以测试数量或某个 `passed` 字段替代研究有效性。
