# 本轮之后的候选优先级

本文记录后续工作的建议顺序，不增加本轮 P14 之后的模型实验，也不授权重跑已经消耗的
执行声明。具体实验选择应结合 `AUTONOMY_FINDINGS.md` 中的最终结果、各阶段实际完成
比例和研究复查意见。所有历史任务、原始回答与评分保持冻结。

## 1. 先解决轨迹之间的故障牵连

P9、P11、P12 和 P13 已经实际出现：一个 answer_history 请求超出上下文上限，导致整个 worker
退出，同批可容纳的请求以及后面的其他轨迹也不再执行。固定分母正确地保留了这些缺失，
但无法消除调度顺序对方法结果的影响。正式 heldout 之前应先解决这项工程问题。

冻结调度表与实际停止前缀的进一步对账如下。每行汇总该阶段两个 DeepSeek worker，
详见 `context_censoring_v1.json`；构建与独立核验均通过。

| 阶段 | 未尝试槽位 | 属于最先超限轨迹的剩余槽位 | 属于其他轨迹的剩余槽位 |
| --- | ---: | ---: | ---: |
| P11 | 808 | 5 | 803 |
| P12 | 418 | 3 | 415 |
| P13 | 348 | 2 | 346 |

“其他轨迹”不表示这些请求一定可容纳或会答对。已单独重建的六个下一批次中，每批有
三个请求可以容纳；更远的未执行结果没有被模拟成真实回答。上表量化的是整 worker
停止扩大缺失范围的现象，而非修复后准确率的预测。

新版本应在请求进入批处理之前逐条检查上下文。若某条轨迹不能继续，保存明确的
`context_blocked_before_dispatch` 记录，并保留该轨迹后续所有计划槽位；其他独立轨迹
继续执行。不要自动截断历史、给失败轨迹更换方法、注入程序答案或补答历史实验。

必要的软件验收包括：超限出现在批次第一条或最后一条时，其他轨迹的调度相同；不同
worker 分配不改变失败归属；超限未提交与模型实际输出失败可区分；后续槽位保持在
分母里；断电恢复不会重复提交。用确定性的程序对照和故障注入先完成这些检查，
随后才登记新模型矩阵。这一改动属于收集器的新版本，不能修改 P7–P14 的旧报告。

对已落盘提交标记、却没有原始返回的请求，恢复后应保留 `unknown_outcome`，禁止把它
当作未提交请求再次发送。它所在轨迹也不能假装已经获得答案而继续构建历史；除非新协议
预先定义了这种情况的处理，否则应停止该轨迹，继续其他可独立执行的轨迹。对应故障注入
应覆盖“提交标记之后、原始返回之前”和“原始返回之后、评分之前”两个不同断点。
后者可以从原始字节恢复评分，前者不能通过再次推理补齐。

## 2. 根据本轮分项结果决定输出协议

主分数继续要求完整正确，但应同时展示回答覆盖、结构合法、风暴与时刻、状态、数值、
单位、来源版本和行号分项。P9 的单位字符串错误、长度失败和上下文失败已经表明，
单个总分不足以说明模型究竟错在哪里。当前分项已经可用，不需要事后改写主分数。

P12 的实际停止前缀进一步表明：默认 JSON 空白规则仍允许极长的整数。DeepSeek 的一个
超限历史包含两条未完成的引用行号整数，尾部连续数字分别长达 7,498 和 7,811 位，
各自只有 6 个空白字符。详见 `../p12_compact_grammar_v1/CONTEXT_STOP_WORKER0.md`。
下一版可研究预先声明的公共整数/字符串表示界限，但需要新的协议和反例测试，不能将
正确引用行号编码进语法，也不能事后修补本轮答案或将限制空白等同于保证长度有界。

当前三个方法都看到全部累计可见公告。它们比较附加历史载体的帮助或干扰，不构成
必须依赖记忆的任务。如果后续研究确实需要“仅新增证据”的条件，应另行规定证据预算、
允许保存的状态和可验证的逐步程序基线，再将它与累计证据条件分开登记和报告。

P12 检查默认 JSON 格式空白，P13/P14 检查同文字的提示角色位置。它们分别生成自己的
历史，后者还改变原生聊天模板的 token 序列。根据结果选定下一版共同协议时，应公布
选择所依据的开发结果，再冻结协议。不能把选出的最好配置在同一开发集上的分数
当作未调参的最终泛化结果。

若需要容许确定性的单位等价表达，应另行规定新评分版本、等价集合、符号转换和
引用检查，并用独立反例测试。在旧版本上追加一个明确命名的诊断层可以帮助解释，
但不能覆盖原分数，也不能通过新语法强制写出答案来宣称模型原本掌握了该能力。

## 3. 扩展真实情境与时间依据

下一次数据扩展应预先固定取样规则，覆盖早期发展、成熟期、登陆附近以及终止阶段，
避免仅由最初编号公告代表整场风暴。优先补充真实的终止状态修订、同一绝对时刻的
预报覆盖变化、跨月和跨年、不同半球或经度符号的记录。软件 fixture 与真实来源
覆盖要分别统计。

自动 Gold 继续从可追踪的原始产品生成。两套解析器一致只是一个检查条件，还应
检查它们共享的规范化步骤，并使用可获得的独立结构化产品核对明确字段。若没有
历史公开可见时间的证据，继续标记为受控 issued-time replay；不要把获取时间或
模型初始化时间替代为历史可见时间。

现有 heldout 分组保持未调用。先完成协议选择、解析规则冻结和故障隔离，再准备
独立的 heldout 执行计划。公开历史文本存在训练语料污染的可能，不能仅凭时间切分
宣称已经去污染。

## 4. 基线、重复与统计

公开 latest-explicit resolver 已能满分完成当前任务，应始终与 LLM 结果一起报告。
下一步有价值的基线是相同证据和预算下的明确检索/版本选择流程，以及架构来源更独立
的模型家族。DeepSeek-R1-Distill-Qwen 与 Qwen 的对比不足以证明跨架构泛化。

额外重复用于观察采样不稳定性，更多独立风暴用于观察来源差异，两者不能互相替代。
统计单位优先是风暴组；正式区间或检验之前需要明确研究问题与配对结构。当前六个
开发风暴和大量相关检查点适合描述性结果，不应使用逐检查点独立假设制造精确显著性。

例如，在当前 804 个检查点上，三个方法、两个模型、两个重复需要 9,648 个回答；
再增加一个协议条件会翻倍。这只是预算公式示例，不是本轮已经启动或承诺启动的任务。
新实验应先固定总请求数、输出上限、时限、GPU 分配和失败规则。

本轮接续条件共享一个绝对截止时间，因此越晚启动的条件可能获得越短的收集时间。
若最终出现截止导致的不完整矩阵，固定分母只能保留失败，不能将时间截断与协议效果分离。
下一次正式条件比较应给各组相同且足够的完成预算，并单独说明平台延迟或截止造成的缺失。

还需要在登记时明确研究问题：如果比较固定资源内的端到端效果，则各条件使用相同的
资源计时起点与独立时长上限，未完成槽位计入失败；如果比较完整任务上的准确率，则为
所有条件预留完成整个矩阵的时间，并把实际资源消耗作为另一个结果报告。不要混用两种
问题，也不要让后启动的条件继承更短的剩余时限。加载、排队是否计入资源预算应提前写明。

本轮新增的 `pair_coverage_v1.json` 将配对槽位分成双方返回、仅前组返回、仅后组返回、
双方均缺失，并把原始正确数差异分解到这些组。共同返回子集仍由运行时长、历史长度和
问题难度共同选择；它有助于解释缺失，不能当作已经校正时间差异的无偏结果，也不能
替代全计划分母。新协议不应仅凭这个子集选出赢家。

## 5. 工程整合与交付

历史版本命名空间保证了可重建性，但也带来重复代码。未来可把任务、提示渲染、解码、
调度和审计配置成明确版本的接口，再为每次执行保存不可变源码包。重构应先用旧产物
做兼容性验证；不得为减少重复文件而改写历史源码快照或让旧报告读取新默认值。

后续 GPU 队列适合使用一个持久协调器管理所有申请与释放，并将待启动申请计入同一
容量账本。这样可以在独立任务允许时提前完成预检，同时避免多个提交器同时看到空闲
资源而超过四卡上限。失败后的恢复应查询原作业身份，不自动创建替代模型作业。

最终对外材料应区分：阅读附件、可恢复的完整证据、实际模型回答、程序诊断以及
仅准备好的计划。发布具体 commit、验收清单和依赖版本；科研结论以可复核的实际结果
为依据，不以测试数量或某个 `passed` 字段替代研究有效性。

## 6. 建议的下一轮执行顺序与停止条件

| 顺序 | 交付物 | 进入下一项的条件 |
| --- | --- | --- |
| 1 | 新版本的逐轨迹故障隔离和统一 GPU 预约账本 | 混合正常/超限请求、进程中断、未知返回和容量竞争的故障注入通过；不调用模型 |
| 2 | 一个共同输出协议及其公开表示边界 | 边界不包含正确答案或候选引用集合；错误但格式合法的反例仍可生成；旧分数保持可重建 |
| 3 | 预先固定的阶段分层开发数据和独立程序基线 | 每条参考答案可追溯；缺失与终止状态有真实覆盖；时间依据不足的记录明确标注 |
| 4 | 等完成预算的新开发模型对照 | 固定模型、提示、采样、失败规则、请求总数和四卡分配；明确哪些比较属于协议选择 |
| 5 | 协议冻结后的独立 heldout 计划 | 先通过开发集运行可靠性验收，再决定 heldout 样本量和按风暴分组的统计方法 |

若某一步仍存在导致其他轨迹无故停止、答案进入 Gold、未知请求被静默重发、或者数据
时间依据混淆的问题，就停在该步的离线修复，不通过扩大模型调用来掩盖问题。新实验的
启动、参数和资源预算应形成单独执行记录；本文的候选顺序不自动消耗新的模型范围。
