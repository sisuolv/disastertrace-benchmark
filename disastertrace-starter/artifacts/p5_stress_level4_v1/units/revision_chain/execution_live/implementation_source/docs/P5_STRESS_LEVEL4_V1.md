# P5: Predeclared Level-4 Stress Profiles

This protocol extends the completed P4 constrained-output development track.
The user authorizes continued work and local GPU use, plus publication to the
existing private GitHub repository. The next scope comprises three separate
factor units: revision_chain, irrelevant_scope and late_stale_replay at level 4.
Each unit has 36 episodes, 108 trajectories, 540 responses and one repeat. The
combined maximum is 1,620 responses, without retries, extra probes, paid API calls,
heldout inference, training, per-item human labels or an LLM judge.

## Data and selection

Use the unchanged P3 predeclared 216-candidate stress package, with its original
level-4 and level-16 candidates. Independently regenerate all candidate records
from the sealed balanced parent and select every level-4 episode for the named
factor. Do not select episode IDs based on P4 model failures. Reject reordered,
missing, duplicate, altered or substituted candidates, even after resealing.

Regenerate all 180 private checkpoint references in each factor. Their values,
statuses, current citations and research actions must equal their matched base
references exactly. Independently reconstruct each answer using only the rendered
public request, across all three methods. Score all ten program controls with the
unchanged scorer. Verify every metric denominator and checkpoint opportunity
against the base dataset, including intentionally invalid controls.

Report added record and delivery counts per episode. Six revision-chain controls
have zero effective additions; retain them and report the count. The variants are
derived from three development source groups, not new independent weather events.

## Execution isolation

The `stress_eval` namespace adds a dataset verifier and execution identity. Its
collector and auditor are explicit versioned P4 forks, using the original P4
adapter, structure-only grammar, public renderer, parser, scorer and carrier policy.
Historical P3/P4 source files, results and archives remain unchanged.

Preserve the balanced trajectory ordering and checkpoint waves. Each stress slot
records its base identity and receives a distinct factor-specific slot/trajectory
identity. The original seed derivation therefore produces new per-slot seeds;
this is not an identical-sample comparison with P4. Each batch remains within one
checkpoint wave and has at most one request from each trajectory.

An offline freeze has no production authority, path or deadline. A later live
freeze must bind a new absolute canonical run path, a future aware deadline, the
accepted dataset, implementation hashes, model snapshot, tokenizer, environment,
backend sources and exact P4 settings. Full diagnostics run separately. Actual
GPU execution must verify the unchanged environment/backend/weights and consume
the new claim exactly once. A stopped run retains its raw prefix and the complete
540-response scoring denominator; never reset, repair or selectively retry it.

## Output and context

Keep BF16 Qwen3-8B, vLLM V1/XGrammar, reasoning enabled, temperature 0.6, top_p
0.95, top_k 20, 8,192 total generated tokens and 16,384 context. Constraints cover
containers, keys, types and allowed literals only. They do not encode Gold values,
record/line membership, numeric ranges/precision, unknown consistency or action
relations. Reasoning stays unconstrained until the generated closing delimiter.

The prior 32,400 program-carrier context checks support level 4 for all three
factors. This does not guarantee that arbitrary LLM-generated histories fit. Keep
the adapter's full-output reservation and fail before dispatch when preparing a
request would require truncation. Record the stop reason and preserve all missing
opportunities. Do not silently lower output caps or truncate public evidence.

## Acceptance and interpretation

Require targeted profile/source/tampering/origin/carrier/stopped-prefix tests,
full dataset and public-oracle regeneration, all program controls, separate
540-slot diagnostic collection and independent report reconstruction per factor.
Before a live launch, bind those results to its freeze and verify the historical
preservation baseline. Each factor retains the nine predeclared format cells:
at least 58/60 schema-valid responses and at most two length finishes per cell.

After actual collection, independently audit captures and reconstruct scores,
then compare matched base/stress checkpoints by factor, source, method and effective
intensity. Keep invalid, missing, context-stopped and length-limited outcomes in the
primary denominator. Report JSON syntax, structural schema and strict task-contract
validity separately, along with values, current citations, unknowns, actions and
tokens. Independent CPU review must require no model generation or credentials.

One repeat and three dependent source groups support descriptive development
results. Factor variants and checkpoints are not independent storms. Do not infer
general weather forecasting accuracy or causal internal-memory superiority.
