# Next phase after the P5 ACP experiment

The next research step should improve repeatability and source coverage while
keeping automatic Gold and deterministic scoring. Preserve the completed P4/P5
tracks, fixed denominators, raw failures and one-use claims. Nothing in this plan
launches additional model calls or reopens the current 1,620-response phase.

## 1. Establish a repeatable comparison on one hardware profile

P4 uses an H100 MIG partition; P5 uses full H100s on ACP. The model, Python/package
inventory and base decoding settings match, but hardware and factor-specific slot
seeds differ. Current base/stress comparisons remain descriptive.

Prepare a new profile that evaluates the balanced baseline and all three level-4
factors on the same ACP image/spec. Predeclare three independent repeats. A full
matrix would have 4 conditions x 540 responses x 3 repeats = 6,480 responses.
This is a proposed future scope, not a launched job or an extra current allowance.
Use at most four H100s concurrently if the user's resource limit still applies.

The current frozen execution deliberately accepts only one repeat. Implement
repeat identity, trajectory isolation, seed derivation, schedule and budget as a
new version; do not duplicate old slot lists or reuse canonical runs. Preserve
the full output/context reservation, grammar and failure accounting. Recompute
format-screen denominators and thresholds before dispatch. Run full diagnostics,
cross-repeat history-isolation tests and CPU reconstruction first.

Report paired outcomes per source and distributions across repeats. Checkpoints,
matched branches and transformed variants are not independent storms. Three
source groups cannot support strong population-level significance claims merely
because the number of model calls increases.

## 2. Expand development sources before making broad claims

Add independently sourced development events with traceable structured records,
keeping the seven existing heldout storms outside tuning. Declare source/event
selection before generating new task variants, and check separation by actual
event identity rather than filename. Retain acquisition timestamps and distinguish
issue time, effective time and proven public availability.

Each new source must pass parsing/provenance checks, automatic Gold construction,
public-oracle reconstruction and predefined incorrect controls. The current
constructed update tasks should remain labeled as constructed; new source text
alone does not make their PATCH records official weather corrections.

Keep four reporting views: all planned checkpoints, post-evidence checkpoints,
task-family opportunities, and results per source. The empty-evidence c0 slice is
useful as a control but should not be the only explanation of an aggregate score.
Do not silently change the existing main denominator.

## 3. Add a second model on the identical task version

Full balanced/stress model coverage currently centers on Qwen3-8B. Historical
DeepSeek 270-response results use an older task version and cannot fill cells in
the new matrix. Prepare an adapter for a clearly identified second model, with
its tokenizer, weights or provider revision, decoding capabilities and token
accounting bound before evaluation.

For a remote API, independently verify structured-output support and current
pricing, then establish a new bounded budget. A generic JSON-object mode is not
automatically equivalent to strict grammar decoding. Keep capability differences
as separate tracks. For local models, preserve license/model provenance and test
the real runtime with generation disabled before the new one-use evaluation.

## 4. Increase difficulty with a separately versioned context design

Level 16 does not fit the existing full 8,192-output reservation inside 16,384
context for many program carriers. Do not truncate records or reduce per-item
output caps to make it appear comparable. First decide on a new common context
profile or a different controlled difficulty construction, then calibrate it
offline and evaluate matched baselines under the same new settings.

Use the current factor breakdowns to formulate hypotheses about update chains,
scope interference and stale replay. Do not select individual successful variants
or replace observed failures. Retain zero-effect controls and show both directions
of paired change. Add more complex operations only with explicit executable
semantics, an independent public oracle and targeted negative controls.

Current methods all receive cumulative public evidence. A future experiment with
incremental evidence or restricted observation windows needs a separate
information-access and citation protocol; it cannot be described as a direct
measurement of internal memory using today's scores.

## 5. Freeze before heldout or wider-hazard evaluation

Freeze task distribution, numerical seeds, templates, factors, model settings,
repeats, output tracks, scorer and failure handling on development data. Then
prepare a distinct heldout execution, separating new-event, new-number and
new-operation generalization targets. Preserve all failed or missing outputs.

Flood, heat and cold-event extensions should prioritize official structured
observations or alert revision chains with executable labels. Keep structured
record reasoning, extraction from real text and forecasting as distinct tasks.
Open-ended advice without verifiable labels remains outside the automatic primary
score. No per-item human annotation or LLM judge is required by this plan.
