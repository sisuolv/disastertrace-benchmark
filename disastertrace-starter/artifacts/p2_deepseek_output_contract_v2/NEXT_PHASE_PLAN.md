# 本轮 v2 筛选之后的计划

本轮已完成 270 个真实响应，独立报告重建通过，九个格式单元全部通过。
三方法在当前开发矩阵上均为满分，下一步进入跨模型比较的离线准备，并处理
天花板效应与来源/情形混淆。最终记录见 `FINDINGS.md`、`FINAL_STATUS.json`
和独立报告。以下后续矩阵是计划，不在本轮调用额度内。

## 1. 本轮采用第一条路径，其他结果保留分流原则

| 本轮结果 | 后续优先工作 |
| --- | --- |
| 审计完整且九个格式单元全部通过 | 固定 v2 接口，进入第二模型的离线适配与研究设计冻结 |
| 格式门槛未通过，主要是结构错误 | 保留本轮；离线定位接口契约问题，形成新版本及完整复测提案 |
| length 仍造成门槛失败 | 单独版本化输出/推理预算试验；避免同时改变证据、载体和评分 |
| 发送结果未知或预算保护停止 | 审计已捕获前缀，报告未提交槽位和未知预留；不自动补发 |

所有路径都保留完整分母，不用失败样本补跑覆盖原结果。格式门槛通过后，事实、
引用和研究设计仍须分别评估。已有历史 v1 分数仅用于描述性比较。

## 2. 推荐下一项离线交付：跨模型比较准备包

优先选择另一个模型家族，先检查用户实际可用的接口或本地部署条件。可优先考虑
开放权重模型家族，以便说明模型版本和部署配置；实际 provider/model、参数能力、
当前价格及凭据来源需要在启动前落实。本计划不使用占位模型名或假设价格报价。

准备包应包含：

1. 接口能力表：system/user 角色、输出长度参数、是否计入 reasoning、模型版本
   标识、停止原因、usage、超时和速率限制。相同 high 标签或数值 cap 不能被解释为
   相同推理计算量；支持程度不同须明确记录。
2. 独立适配与离线 HTTP fixture：保持相同公开任务及 v2 输出规范，验证真实发送
   字节、响应捕获、错误分类、usage 结算、断点保护和报告来源，避免依赖某一家
   provider 的偶然返回格式。当前 DeepSeek 冻结实现保持原样。
3. 对每个方法独立维护载体；不得把 DeepSeek 的旧答案、程序诊断答案或另一模型的
   状态作为新模型历史。校验 private Gold、未来记录和任务分组标签不进入模型输入。
4. 固定模型参数、矩阵、重复数、顺序、格式门槛、报告指标和条件预算。任何必要的
   接口探针单独列数，不能隐藏在 benchmark 调用量中。

若沿用当前 18 episode 的任务版本，基础矩阵为每模型 270 次。该版本仍可用于
同一来源/情形内的方法配对比较，但无法独立区分来源与 primary/secondary 情形。

## 3. 在正式留出评测前消除来源与情形混淆

推荐另建平衡版本，使三个来源组都包含 primary 和 secondary：

`3 来源组 × 3 任务族 × 2 情形 × 2 分支 × 5 checkpoint × 3 方法 = 每模型 540 次`

该版本有 36 个 episode、108 条方法载体轨迹，仍只有三个开发来源组，不能宣称
新增了独立天气事件。它应作为新数据/执行版本离线冻结，不能替换本轮已完成的
270 次版本。跨模型比较必须使用同一任务版本，不能拿旧版 270 次与新版 540 次
直接混合排行；因此模型适配可以先完成，真正调用前应确定要使用哪个数据版本。
平衡版本的每个 family × method 单元有 60 个机会，格式门槛应在新协议中提前
定义；不能直接套用本轮 30 个机会的分子门槛，更不能看到成绩后再调整。

平衡版本仍采用事件结构 Gold 与公开文本 oracle 的独立一致性验证，完整检查
作用域、引用、分母、载体隔离和预定分支关系，不新增逐题人工标签或 LLM judge。
不能根据某个模型是否答错来筛选保留的题目。

## 4. 将“格式可靠”与“任务有区分度”分开

若多个方法在当前小矩阵接近满分，先报告这种天花板现象。不要仅凭极少数错误
排序，也不要持续修改提示词直到开发集全对。当前三方法均获得累计公开证据，
结果只支持显式回答载体在该条件下的附加效果。

如需更有区分度的新版本，可预先设计几个相互分开的难度因素：更长修订链、更多
无关实体/时间窗口、多个 fact key 的交错更新、或较晚送达的旧版本记录。先给出
每个因素的语义定义、独立控制条件及自动验证，再冻结生成分布；这些都不改变
本轮的证据、Gold 或评分。新增操作若超出现有单链和可恢复缺失语义，必须另立
任务规格，不能默默扩展现有 parser/scorer 的含义。

## 5. 需要因果契约结论时才做新的两臂实验

若论文要研究 v1/v2 契约差异，再准备同时段交错执行的完整两契约实验：
`2 契约 × 18 episode × 3 方法 × 5 checkpoint = 540 次`，另定重复数和预算。
两臂分别维护历史，全部答案重新采样；旧批次不能充当新实验的一臂。
如果目标只是获得可靠的开发接口，不必默认追加这项实验。

## 6. 留出评测最后冻结与启动

明确区分新来源组、新生成种子、未用于开发的操作组合三种泛化目标。
新 seed 不等于新天气事件；仅按风暴划分也不能证明未见过生成模板。
冻结生成器、模板组合、split、scorer、指标、模型配置、重复数及执行顺序后，
再准备七个留出风暴的调用。

统计分析应尊重来源组、匹配分支和连续 checkpoint 的依赖关系，报告分子/分母、
来源组内的配对结果及不确定性限制。三个开发来源组不足以支持稳健的广域结论。
NHC 自然文本轨道与 P2 受控生成轨道分表报告，当前开发筛选不作为最终测试成绩。

下一项工作的完成标准是可审阅的接口能力表、离线适配验证、数据版本选择依据、
新冻结执行和明确的调用/预算提案。它不要求先购买 API 或为题目增加人工复核。
