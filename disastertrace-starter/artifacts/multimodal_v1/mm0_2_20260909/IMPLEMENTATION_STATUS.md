## 4. 输出、故障与评分

输出为完整 JSON `state`，每个已揭示地点含 relation、watched、inspection_required、
map_source、map_locator、rule_source、rule_locator。三值逻辑包含 `false AND null = false`。
接受公开网格定位和等价的 `point:<site_id>`，要求适用来源版本；整图引用不算充分定位。

运行器按轨迹隔离，先保存请求与提交 intent，再保存原始回答，最后解析。超限发生在
prepare 阶段则不提交；已经提交但没有正式 raw 的机会保留 unknown，不自动重发，其余独立
轨迹继续。原始回答之后崩溃可直接恢复解析。临时文件不算正式回答。

合法但错误的回答和格式错误的原文均进入本轨迹的后续载体，附 invalid 标志，无 Gold 修复。
当前运行器只接收离线程序 callback，没有模型 API/ACP 适配器；不能把本次故障测试称为
已经验证了真实 GPU worker 的中断恢复。后者在 MM-3 接入时仍需测试。

主指标保留计划分母，分别记录值、依据、必要修订、未知断言和完整分支成功。稳定字段退化
只在上一轮对应值正确的合格子集计数；纠正自身旧错误不算过度更新。空分母为 null。
依赖复核义务由参考推导，不根据模型自称“已复核”判断内部行为。

## 7. 保留的开发失败与边界

首次 `python3 -m venv` 因 ensurepip 缺失退出 1；随后用已有 pip 的 `--python` 功能安装到
该独立虚拟环境，未修改旧环境。使用清华镜像成功取得依赖；机器原先配置的额外 NVIDIA
索引出现 DNS 重试，后续依赖安装显式清空额外索引。

初次隔离环境导入项目因 pydantic 缺失退出 1，补齐与旧项目一致的 2.13.5 后解决。
初步检查脚本分别遇到单记录 `record(-1)` 索引错误及将 ISO-8859-1 XML 当 UTF-8 读取的错误；
正式实现逐记录枚举并依据 XML 声明解析。这些是检查工具问题，未据此修改官方资料。

首次运行器测试在新模块实现前因找不到模块退出 2，保留 `runner_before.log`；实现后 7 项
通过。初步完整测试有旧 pytest 配置引用未安装 asyncio 插件的警告；新增专用 `pytest-mm.ini`，
不更改历史配置，最终 96 项测试没有该警告。初次静态检查发现 9 个未使用 import，已清理。
没有声称所有探索命令都被完整录屏；已有日志及工具观察分别标明，不补造缺失 stdout。

`build_01` / `diagnostics_01` 是开发过程的初步产物，保留原字节。新增公开输出契约、
独立源核验和冻结后产生 `build_02` / `diagnostics_02`，正式复查只使用后者及其源码快照。
