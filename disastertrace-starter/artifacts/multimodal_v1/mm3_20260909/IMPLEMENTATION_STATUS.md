# MM-3 实施与结果记录

截至 2026-09-09，本批真实视觉模型试跑、输入核验与离线结果重建已完成。
工程执行闭环通过，预先登记的输出接口门槛未通过。下一版契约已完成离线准备，
尚未产生 V2 模型回答。

## 实际完成

1. 重新核验 MM-0–MM-2 的 1,016 个本地绑定文件及原复查 ZIP 的 SHA-256。
2. 从 Qwen 官方 ModelScope 仓库固定 Qwen3-VL-8B-Instruct；16 个文件共
   17,545,914,437 字节，全部通过文件大小及 SHA-256 校验。
3. 新建 VLM 环境，固定 Transformers 4.57.3、Torch 2.8.0、BF16、SDPA、
   图像尺寸、贪心输出和 token 预算。旧环境仅以只读依赖路径复用，未升级。
4. 新增独立 live adapter/runner/auditor，真实解码 PNG，保存图像、模板提示、
   输入 token、网格、张量摘要、原始输出、生成 token 与完整失败记录。
5. CPU 和 H100 分别验证真实 processor，27 个图像–查询点检查通过；处理后 RGB
   可逐像素还原。每张图 1,024 个视觉 token，双图 2,048 个。
6. 使用真实 H100 80GB 完成零图、单图、双图的前向计算，输出 logits 均有限；
   这些预检没有生成模型回答。
7. 执行全部 12 个已登记生成机会，随后在 CPU 重建评分、验证实际输入与输出 token，
   并在禁止原路径和网络的迁移副本中重建同一报告。

从空历史开始。没有将程序诊断答案或参考答案填入模型历史。

其余 11 个虽然可以解析为无重复键的 JSON，仍不符合地点 ID 到记录的对象契约。
没有进行数组转对象、按顺序猜地点、补键或重新打分。

旧提示写了根对象包含 `state`，但没有明确规定 `state` 本身的容器类型与键结构。
因此当前 0/12 是严格协议结果，不能解释为“模型完全无法看图”或广义天气能力为零。
输入张量存在与 processor 可读性通过，也不证明模型已经正确利用每个视觉位置。

## 验证与保留的失败

- 96 项原多模态回归测试通过；16 项新增 live capture/audit 测试通过。
- CPU 重放全部 12 个实际输入的 processor 张量摘要与 token 序列，逐个一致；
  1,383 个输出 token 解码后与原始回答一致。
- 迁移副本核验 151 个文件，并在未导入 Torch/Transformers、禁止网络和原路径读取
  的条件下重建相同报告。Python audit hooks 不等同于针对恶意代码的操作系统沙箱。
- 最初模型清单程序误将逐文件最后变更 revision 当作必须一致的仓库 revision，
  在下载权重前退出。修正为固定快照并验证全树清单，原错误日志保留。
- 首次 lint 的导入排序与异常边界提示已处理；冻结 live 源码的最终 lint 通过。
- 第一次 CPU 迁移复查已完成分数比较，但将收据写向被禁止的原目录，触发
  PermissionError。第二次使用相同复查代码，在迁移目录写收据，退出 0 后再复制。
  第一次退出 1 的记录保留，不计为通过。
