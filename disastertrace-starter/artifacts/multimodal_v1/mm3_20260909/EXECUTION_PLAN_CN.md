# MM-3：首轮真实视觉模型开发检查

本批承接已验收的 MM-0–MM-2，使用 `build_02` 的公开请求。旧批次的源码、
参考答案、离线记录与验收文件保持冻结。本文件在首轮模型生成之前编写。

## 本批要验证什么

1. 模型真实收到图片，图像身份与公开证据对应。
2. 图片经过实际 processor 后仍能读清选定位置。
3. 单张 H100 可以完成加载、前向计算和规定格式的输出。
4. 模型保留自己的错误历史，遇到新版、旧图重放和证据缺失时的行为可重建。

## 固定模型与执行条件

- 模型：Qwen/Qwen3-VL-8B-Instruct；官方 Qwen ModelScope 仓库。
- 仓库快照：`5d854aab08710c16b980ec6d603d863b3821b915`。
- 权重的最后变更：`1610d9f98460d59272cd9963efdf92f0cd3c8dc9`。
- README 声明 Apache-2.0；仓库没有独立 LICENSE 文件。保存原始模型卡和文件清单。
- 后端：Transformers 4.57.3、Torch 2.8.0、BF16、SDPA；不执行远端自定义代码。
- 新 VLM 环境有独立的 Transformers/tokenizer 等包；通过只读路径复用旧环境的
  Torch/CUDA 依赖。旧环境没有升级。完整版本与关键实现哈希单独保存。
- 图像保持 1024×1024，每张 1,024 个视觉 token，最多两张；不裁剪，不叠加查询标记。
- 贪心自由输出，最多 2,048 个新 token，总上下文限 16,384；每次生成限时 120 秒。
  这是开发接口设置，不声称复现模型卡推荐的随机采样最优表现。
- 单 worker、单张完整 H100，作业至多 3,600 秒；提交前冻结新的绝对截止时间。
  不复用历史十小时窗口，全局仍最多四张 H100。

## 门槛与记录

CPU 阶段先验证实际 processor：PNG 解码后进入图像部分，文字提示不包含 base64。
保存公开文字、模板化提示、原图、输入 token、图像网格、张量大小和哈希。
实际处理后图像可逐像素恢复；已选查询点的 27 项检查保持一致。

GPU 阶段重新核验冻结源码、运行库、全部模型文件、GPU 身份和显存。
对零图、单图、双图请求分别运行真实无生成前向计算，验证 logits 有限。
完成全部预检后才进入已登记的 12 个生成机会。

接口门槛预定为 12 个回答全部通过严格 JSON 契约，且全部以 EOS 完成。
语义正确率另外报告；错误答案不修复，不用像素程序替模型补答案。
不做按题人工复核，不调用 LLM judge，不训练，不访问 heldout，不调用付费 API。

每次生成之前先持久化请求与 dispatch intent，随后先保存原始文本，再解析。
无结果或结果不完整时保留 unknown，并停止该轨迹后续检查点；其他轨迹可继续。
不重试、不选择性替换。运行声明和提交目录都只能创建一次。

## 本批之后

使用 CPU 从原始回答和各分支参考重建报告，再用固定 tokenizer/processor 检查
token 解码与真实输入是否一致，核实 ACP 终态和资源释放。
之后根据感知、格式和版本修订错误分布，冻结下一小批原子感知诊断。
大规模四卡比较、第二模型与多事件扩充需要独立的设计和运行身份。
