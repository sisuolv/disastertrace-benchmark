## 空间结果不能按表面正确率乐观解释

有图条件实际只有六个地图-地点单元：5 个 inside、1 个 outside。模型预测全部为 inside，
因此 inside 是 5/5，outside 是 0/1。另有三个无图对照正确输出 unknown，总体才得到 8/9。
这批成绩不能证明模型已经能可靠区分图内与图外。

事后增加的简单程序对照只看“有没有图”，有图一律答 inside，无图答 unknown，
同样得到 8/9，且九个关系预测与模型一致。它在观察结果后加入，明确标为 posthoc；
没有追加模型请求，也没有改变预先冻结的分母或评分。证据见 `POSTHOC_PRESENCE_CONTROLS.json`。
预测模式相同不证明模型内部采用了这一规则。

map-01 / A 的参考为 outside，模型为 inside；来源和定位引用本身正确。参考由原始
GIS 几何计算，公开图像像素程序独立一致；实际处理器还原出的像素也一致。
图像解码与传递核验通过，不等于模型能够读对地图。grid 已在查询中给出，引用成功也
不能单独用来证明定位能力。

## 名单读取与引用是优先排查项

五个有明确 WATCH 行的请求严格正确为 0/5；watch-01 未列出的 C 也错误。
三个完全缺名单、仅保留强度摘录的对照严格正确为 3/3。

典型结果包括：

- watch-02 / A：参考 `false, watch-02, L2`，输出 `true, benchmark_rule, watch-02`。
- watch-01 / C：参考三个 null，输出 watched=true，并给出了不符合契约的引用。
- watch-02 / B：watched=true 和来源正确，但行号字段写成 `WATCH B true`，未提供 L3。

所有有名单请求的 watched 都为 true；没有名单时为 null。只按名单是否存在生成的
事后简单程序对照同样答对 6/9 个 watched 值，并与模型的九个 watched 预测一致。
这是观察到的输出模式；当前实验不能将其解释成确定的内部机制。

后续应检查输入呈现是否能让模型稳定区分 artifact_id、origin 与行号，
并保留 true、false、名单内缺地点、完全缺名单四种情况。不能把原有引用错误改判正确。

## 逻辑错误与版本错误可以独立出现

逻辑题直接提供明示事实，排除了本题中的视觉读取需求，但不属于正常视觉赛道。
三个失败为：

| 输入 | 正确 inspection_required | 实际输出 |
| --- | --- | --- |
| outside，watched=null | false | null |
| boundary_ambiguous，watched=true | null | true |
| unknown，watched=true | null | true |

版本任务不附图，只提供元数据。base c3 和 c4 在旧图重投后选了 map-01，参考为 map-02；
without_watch_list c4 还错误地将 context-05 当成 rule_source。新地点 C 在这批静态任务中
没有遗漏，但这不能推翻 MM-3 V2 完整轨迹中两次遗漏 C 的结果。
静态累计投递记录上的版本选择也不等于沿自己历史完成了状态修订。
