# MM-4 之后：先检查测量有效性，再扩展模型与事件

当前证据：40 个原子任务全部正常返回，但空间 8/9、名单 3/9、逻辑 9/12、版本选择 7/10。
空间及名单的值预测与只看证据是否存在的简单事后程序模式一致。
因此不把任务结构通过当作 benchmark 已经有效，也不沿用原批次追加修订请求。

## 第一步：做等信息输入表示对照的离线版本

新建 MM-5A，保留 MM-4 的科学记录。目标是检查输入表达是否影响引用与规则读取，
而不是用参考答案引导模型。准备两个统一条件：原 JSON 表示、确定性显式字段/行号文本表示。

1. 公共语义数据、40 个任务、图像字节、输出结构、引用判分、参考和模型参数保持一致。
   文本表示显式区分 Artifact ID、Origin、Issued At、Version、完整 Target 与 Delivery，
   将已有数组行序号展示为 L1、L2 等；不增添 watched 值、空间关系或已选来源。
2. 为表示转换编写等信息与确定性检查，覆盖 bool/null、坐标精度、字段顺序、投递顺序、
   缺失名单、空查询缺陷，以及 artifact_id 与 origin 混淆。正常任务仍不包含 Gold 或 oracle。
3. 两个条件都保留既有自动参考和独立程序控制；先核验 CPU 处理器实际曝光、上下文预算和引用约定。
   不只挑本批失败题，也不只修改其中一个条件的输出说明或预算。
4. 离线验收后再冻结新的模型执行：建议 40 题 x 2 条件 = 80 次新请求，每题每条件一次。
   旧 40 次输出只作历史参考，不作为新条件的重复样本。既有 GPU 授权继续适用；不涉及付费 API。
5. 四个一卡 worker 各 20 次，条件和任务类型在 worker 内混合分配，顺序预定。
   使用已验证的 requested-replica 计数；对 QUEUEING/STARTING/RUNNING/终态与未知提交先做自动测试。
   记录实际峰值并发、加载开销及吞吐，不预先承诺四倍加速。

这 80 次是建议的新批次预算，**尚未运行，也不是在 MM-4 冻结文件上追加调用**。
任何表示上的效果都属于新条件的描述性比较，不把旧错误重新归类为成功。

## 第二步：修复空间样本覆盖不足

在一个单独的离线数据版本中自动增加图内和图外坐标，并覆盖边界邻近、图外范围、
inside→outside 与 outside→inside、值不变但版本更新。先固定候选网格、类别配比、
边界容差、冲突处理和去重规则，再生成坐标；不得根据模型回答选择点。

每个坐标保留原 GIS 几何结果、公开像素结果、坐标变换与边界距离。边界样本需要独立定义
像素与几何容差的一致性规则，不能直接套用现有“只接收远离边界点”的预检后宣称覆盖边界。
保留所有候选的接纳/排除原因。恒答 inside、恒答 outside、仅依据证据存在性的程序基线
应在下一批模型调用之前声明，按类别报告召回与误判。

如果比较无标记图与叠加查询点标记图，把它作为独立的可读性条件，保持坐标和关系参考一致。
标记只能编码当前公共查询位置，不得编码答案。它不能与文本表示改动一起混作一个原因。
新增同事件坐标仍只是一事件内样本，不可算作事件扩充。

## 第三步：独立模型复验与完整修订任务

先根据 MM-5A 的结果确定公共输入契约，再选择一个不同家族的开放权重 VLM，
核验许可证、快照哈希、处理器与实际 GPU 可运行性，冻结等任务、等预算比较。
不能只对第一模型失败项试更大模型并称之为公平比较。

MM-4 的修订入口门槛是 40/40 严格成功；本批未满足。若后续需要采用不同阶段门槛，
必须作为新协议在新调用前声明，保留旧门槛结果，不事后降低门槛。
完整轨迹继续传自己的原始回答；独立检查点每次历史为空；oracle 历史只能属于特权诊断。
整条轨迹分配给同一 worker，检查点保持顺序，不跨卡拼接模型历史。

## 第四步：扩大独立事件与确定正式统计方案

在已登记的 development split 内扩充真实天气事件及预报时段，复用来源双解析、
发布/有效/已知可用时间区分、证据变更和无效输入失败规则。先确定事件集合、来源与时间
选择规则，再取数。以事件为独立单位报告，不将同事件地点数当成独立天气过程数。

只有多事件、多模型和测量契约稳定后，再冻结 heldout 及统计方案。当前不做排行榜，
不把 hurricane 风圈读取推广为洪水、热浪等所有极端天气能力；其他灾种需要各自的数据与任务定义。
上述阶段仍不需要逐题人工 Gold 或 LLM judge。
