# MM-4 原子诊断：预先固定的执行计划

本阶段接续 MM-3 V2 的真实结果：12/12 结构可解析、10/12 地点覆盖完整、0/12 全字段正确。
目的是拆分错误来源，不能将后续简化任务的成绩视为对旧失败的修复。

## 范围与问题

| 任务 | 数量 | 输入 | 输出与目的 |
| --- | ---: | --- | --- |
| 空间读取 | 9 | 2 张图 x A/B/C 六个单元，加 3 个无图对照 | relation、map_source、map_locator |
| 名单读取 | 9 | watch-01/watch-02 各查询 A/B/C，加 3 个仅含强度摘录的缺名单对照 | watched、rule_source、rule_locator |
| 三值逻辑 | 12 | 4 种 relation x true/false/null；明示的合成诊断事实 | inspection_required |
| 版本选择与查询覆盖 | 10 | base c0-c4，加其余 5 分支的 c4；仅公开元数据和投递记录 | 每个当前地点的 map_source、rule_source |

总计 40 次独立请求，每个请求历史为空，不使用旧模型回答或程序答案作 carrier。
同一任务只分配一次，无重复采样、选择性重试、答案修补或格式强制解码。
名单是 benchmark exercise rule，并非真实官方警报。逻辑输入属于 privileged_logic_facts，
单独报告；它们不证明模型读懂地图。版本任务只选择整个名单文件，不判断其中是否有某地点行。

真实空间数据仍仅来自 Francine/AL062024 的两个预报版本。六个图-地点单元中有
5 个 inside、1 个 outside；无图对照预期 unknown。名单本身缺 C 与完全缺名单分别保留。
静态任务可以明示查询 C；源检查点在 c0-c3 的版本任务仍只公开 A/B，不提前泄露 C。
旧图重放只在静态累计投递记录中出现，本批不评估模型沿历史修订状态的能力。

## 自动参考与测量

- 空间 Gold 由冻结的 NHC GIS 几何与已知坐标自动生成，独立的公开像素程序检查一致性。
  仅使用远离边界的既有锚点；不增加事件或伪称新增独立样本。图像为官方数据渲染图。
- 名单参考通过完整 WATCH 行匹配生成，另一条分词程序核对；无匹配行时三个字段均为 null。
- 逻辑参考采用穷举表，由现有三值逻辑函数交叉检查。它不是从模型回答提取的参考。
- 版本参考按完整目标、modality、已投递集合过滤后排序；现有 typed selector 独立核对。
- JSON 结构、当前查询集合、引用合法性、字段正确性、EOS 与严格成功分别报告。
  结构检查允许缺地点通过，覆盖指标必须将这种情况判错；空对象不能获得完整成功。
  合法旧引用可能不再权威，合法行号也可能不支持答案，因此合法性不能替代引用正确性。
- 严格成功要求结构有效、恰好覆盖当前地点、全部任务字段正确并以 EOS 正常结束。
  缺失、无效、未知、长度/时间中止均保留在预定分母中。无逐题人工 Gold 或 LLM judge。
- 只有 40/40 严格成功才通过本批保守的后续修订诊断门槛；这是工程门槛，不是统计显著性。
  不论门槛结果，都先做报告重建与错误分类，不能自行追加模型请求。

查询中已提供 grid 与 pixel，map_locator 正确只说明按约定引用，不能单独证明视觉定位能力。
最终按任务组及缺证据条件报告，不汇成模型排行榜总分，也不跨旧版本汇总为能力提高。

## 四卡执行

4 个独立一卡 H100 worker，每个恰好 10 个请求，各自混合四种任务，任务类型顺序轮转。
无跨 worker 的模型状态；未来完整轨迹应整条分配，不能拆开轨迹内的检查点。
本轮使用四卡是已准备好的独立诊断分片，不为填卡增加样本。小任务的模型加载成本仍需报告，
没有单卡对照时不能声称获得四倍加速。

- ACP 集群：computing-cluster-01g-02；规格 N6lS.Iu.I10.1.8c128g，每 worker 一张 H100 80GB。
- Qwen3-VL-8B-Instruct，继续使用已固定的模型文件和环境；BF16 / SDPA / greedy。
- 每请求最多 2048 输出 token、120 秒生成，输入加输出预留不超过 16384 token。
- 每 worker 最多 3600 秒；本批执行文件冻结后 7200 秒内有效；平台 retry-times=0。
- 全局上限 4 张 H100，排队、预检、加载也计入槽位。已有作业和未知提交均先核验。
- worker 入口：`python -m disastertrace.multimodal_atomic_v1.worker --batch <本目录> --execution-sha <冻结 SHA> --worker 0/1/2/3`。
- 每张卡先核验文件与运行环境、GPU 型号、真实 0/1 图 forward，再执行其固定任务。
- 所有原始文本、token ID、输入张量哈希、PNG、请求与提交意图都保留；提交成功不等于评测完成。

执行输出在本目录 `gpu_runs/0` 到 `gpu_runs/3`，ACP 记录在 `acp/`。
不调用付费 API、不训练、不进行 heldout 推理。历史运行、接受记录与归档保持冻结。

## 交付条件

离线测试与程序对照通过后，冻结代码、请求、参考、运行环境与预算。GPU 完成后执行
CPU 输入张量与输出 token 重放、从原始回答重算报告、搬迁后的无网络 CPU 重建、
历史哈希复核，以及四个 ACP 终态和资源释放核验。最终撰写结果及下一步文档，
生成可供 ChatGPT Pro 复查的源码与证据包。一次性准备、提交和工作进程不得重复启动。
