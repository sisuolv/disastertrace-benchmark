# V2 模型验证：生成前登记

本批执行用户明确要求的输出契约 V2 模型验证。使用已验收的 V2 候选请求，
保留首轮 MM-3 的全部 12 个失败，不覆盖、修复或替换旧答案。

## 范围与条件

- 模型：Qwen3-VL-8B-Instruct，官方 ModelScope revision
  `5d854aab08710c16b980ec6d603d863b3821b915`，复用已校验文件并在 GPU 重新校验。
- 同一 Transformers 4.57.3 / Torch 2.8.0 环境，BF16、SDPA、贪心自由输出。
- 单张 H100 80GB，每次最多 2,048 个输出 token，16,384 总上下文，120 秒生成上限。
- 新的一小时执行窗口、一次性提交与运行声明；平台和模型重试均为零。
- 最多 12 个生成机会：base c0–c4 共 5 个，without_maps c0–c4 共 5 个，
  watch_missing_c4 与 new_map_missing_c4 各 1 个独立检查点。
- 每条轨迹从空历史开始，之后仅传递本轨迹自己的上一条原始回答，包括无效回答。
- 唯一任务变化是明确地点 ID 到对象的输出结构及附加结构 JSON Schema；不使用
  约束解码，不嵌入正确答案。证据、查询、时间、规则、参考与 scorer 保持原版本。

## 预检与门槛

先验证旧验收文件、候选请求、运行库和冻结源码，再用真实 processor 在 CPU
检查 12 个请求和 27 个地图–查询点。在 H100 重新验证硬件、模型文件、processor，
对零图、单图、双图分别进行无生成前向计算，全部通过后才能开始采集。

接口门槛：12/12 回答均满足严格 JSON 契约，且全部以 EOS 结束。
语义正确性另按每个分支自己的参考计算。固定分母保留所有无效、失败和未尝试项；
遇到 unknown 停止该轨迹后续检查点，其他独立轨迹继续。没有额外探针或补跑。

本批只有一个 Francine/AL062024 开发事件，四条轨迹不是四个独立事件。
新旧两批的差异只作描述；本批不是预先平衡、独立重复的提示方法因果比较。
无地图分支按自身信息集评分，不能把分支准确率差当作纯视觉贡献。

## 交付

完成采集后，从原始 token 和回答重建结果，CPU 重放实际 processor 输入与输出
解码，在迁移副本中重建报告，并确认 ACP 终态与资源释放。分别报告格式、空间
关系、关注名单、版本来源和行动逻辑错误。是否推进原子感知和多事件扩充，依据
本批实际结果决定；不在这 12 个机会内临时加入其他模型、任务或调用。
