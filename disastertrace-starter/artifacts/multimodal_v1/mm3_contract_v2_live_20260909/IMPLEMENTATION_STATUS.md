## 输入、复现与边界

- 模型 revision、权重、BF16/SDPA、贪心自由输出及 2,048 token 上限与首轮一致。
- 只使用已准备好的 V2 输出契约；图片、时间、查询、规则、参考与 scorer 不变。
- 四条轨迹按 5+5+1+1 分配；独立从空历史开始，后续只使用自己的原始回答。
- 生成前核验上一批 557 个绑定文件；CPU 与 GPU 均通过 27 项实际 processor
  图像可读性检查，GPU 完成零图、单图和双图的无生成前向计算。
- 每个实际模型请求的图片、token、网格及张量摘要通过 CPU 重放；所有输出 token
  解码后与原始回答一致。CPU 迁移副本在禁止网络、模型和原路径访问的条件下重建报告。
- 没有改变已冻结源码，不升级环境，不训练，不做 heldout 推理，不调用付费 API，
  不使用人工逐题 Gold 或 LLM judge。既有 16 项采集测试与 41 项契约测试按哈希复用，
  不将它们表述为本轮新执行的测试。

## GPU 使用与四卡问题

作业 `pt-yc7yhd4r` 在 `computing-cluster-01g-02` 使用一张完整 H100 80GB，
终态为 SUCCEEDED，平台重试为 0。创建于 09:10:10 UTC，开始于 09:10:22 UTC，
终态更新时间为 09:13:36.630775 UTC。创建到终态更新约 206.63 秒；其中模型加载
约 44.685 秒，生成合计约 34.703 秒。峰值已分配显存约 19.00 GB。

此批的两条长轨迹各只有 5 个顺序依赖检查点，另两条各 1 个。四卡可以并行独立轨迹，
但无法把同一轨迹的依赖检查点同时生成；重复加载与预检占总耗时的大部分，因此首批
单卡更合适。这里的终态时间核算不是 GPU 利用率或账单测量。

用户希望充分使用四卡加速的偏好继续有效。后续数据和模型形成足够独立工作后，采用
最多四个单卡 worker，按完整轨迹分配任务、平衡比较条件并共用冻结配置。不要为了
占满四卡把当前一个事件重复成多个“独立事件”，也不应把当前 12 次范围临时扩容。
