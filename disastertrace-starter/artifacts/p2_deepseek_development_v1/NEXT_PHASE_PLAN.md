# P2 首轮实测后的后续计划

这份计划延续四方案整合计划中的 T7/T8。本轮已完成 270 个真实响应并通过独立审计，但 9 个格式单元中只有 7 个通过。具体结果见 [FINDINGS.md](FINDINGS.md)。下一步先处理输出契约，再推进第二模型和留出评估。这里列出的后续请求规模是计划，不启动新的付费请求。

## 1. 已完成本轮结果交付

本轮已经执行完同一份 270 槽位矩阵、8192 输出上限、high reasoning 和独立 USD 3 条件预算，全部响应收到，没有未知预留。6 个格式无效回答及 3 个引用错误保持原样，不追加补跑。

最终交付包括独立审计、9 个格式单元、每方法及每来源组的分子/分母、格式错误原始结构、值/当前版本引用错误、配对方法比较、usage、时延、费用和完整原始记录。错误清单来自确定性程序，不增加逐题人工标注或模型判分。

## 2. 下一项优先做输出契约修订的离线准备

最终 U2 × snapshot 和 U2 × answer_history 均为 28/30 格式有效，未达到至少 29/30 的既定门槛。structured_state 的三个单元均通过，但不能据此忽略三方法共同门槛。

6 个失败中有 4 个可解析 JSON、正常 stop 的结构错误，涉及输入式对象、额外字段和缺失 state 容器；另有 2 个 completion=8192、length 且 content 为空的失败。需要分开诊断结构和长度，不能把全部失败归因于 8192 不足。官方 `json_object` 模式保证 JSON 语法，不保证必有 state/action 或禁止额外字段；不把它当作严格 schema 保证。

建议先准备一个共同输出契约 v2：

1. 在 system 消息中直接列出完整字段、嵌套层级和类型，强调根对象只能有 state/action、action 必须是枚举字符串、不能复述输入容器，并解释 record_id 与 delivery_id 的不同作用。三方法使用完全相同的契约。
2. 保持当前公开证据、任务语义、Gold、检查点和指标不变；不放入当前题目的正确状态或从失败样本抽取的正确答案。
3. 先固定 high/thinking、8192 和传输/重试策略，以共同输出契约改动作为候选。不同时改 cap、方法载体、证据数量和评分器。两个 length 失败仍列为待观察的问题，不声称 8192 已经充分；若新版本仍未通过，另立统一输出/推理预算试验。
4. 对新请求做精确字节、角色和 schema 检查；测试旧/新版本隔离、无效输出保留、载体原样传递、泄漏防护和全部 270 槽位的诊断闭环。
5. 为新实现和执行设置生成新身份、独立生产登记与输出目录；本轮冻结代码、回答、分数和授权记录保持不变。

离线验收要证明输入证据与语义机会集没有变化，不能仅以“测试通过”替代实际对比。程序预演通过后，再准备下一轮具体模型范围和预算。

## 3. 后续真实验证有两个不同目的

| 目的 | 候选矩阵 | 可以回答的问题 |
| --- | --- | --- |
| 检查共同 v2 契约是否达到开发格式门槛 | 1 契约 × 18 episode × 3 方法 × 5 点 = 270 次 | v2 在预定开发矩阵是否满足共同格式要求 |
| 研究旧/新契约差异及方法交互 | 2 契约 × 18 episode × 3 方法 × 5 点 = 540 次 | 在预先固定、交错执行的两臂实验中描述契约差异 |

优先推荐第一种作为下一轮开发筛选。它不能仅凭与旧批次的差值就声称识别了契约改动的因果效应；若论文需要这种解释，再考虑第二种。两种都不使用本轮旧回答替代新条件，也不只补跑失败项。费用必须按届时价格和完整矩阵另行计算，不沿用本轮已消耗的启动额度。

若新的共同设置仍未通过格式门槛，先继续版本化接口诊断；不降低门槛或从分母中删去失败题。若格式稳定，则继续报告所有语义和引用失败，不把格式通过等同于能力通过。

## 4. 再完成第二模型的开发比较

优先选择另一个模型家族，复用冻结的公开任务和自动评分。先确认实际可用的 provider/model、参数支持、最大输出、价格、请求限制和凭据来源；这些信息不足时只推进可独立完成的离线适配。

第二模型使用自己的接口契约、内容来源验证和预算账。相同的数值 token cap 或 high 标签不等于跨模型相同推理算力。正式请求和任何额外接口探针都应列入预先固定的调用清单。

一个相同单契约开发矩阵仍是 270 次；额外探针记为 Q2。先确定 Q2、预算和配置，再启动。第二模型结果也必须使用固定分母并通过独立审计。

## 5. 在留出评估前补齐研究设计说明

当前三个来源组并非完全交叉设计：Ida、Florence 使用 primary 情形，Dorian 使用 secondary 情形。因此，同一来源组内的方法比较有配对基础，但不能把来源组之间的差异纯粹归因于风暴差异，情形本身也不同。

如要独立比较这两种情形，另建每个来源组同时覆盖 primary/secondary 的平衡版本：3 来源组 × 3 家族 × 2 情形 × 2 分支 × 5 点 × 3 方法 = 每模型 540 次。该扩展应在模型调用前固定，不以让某个模型出错为筛题条件，也不覆盖当前 270 次版本。

继续明确三种泛化目标：新来源组、新生成种子、未用于开发的操作组合。新 seed 不代表新增独立天气事件，仅有风暴 split 也不能证明未见模板泛化。

完成协议、生成器、模板组合、split、scorer、指标、模型配置、重复数与执行顺序的冻结之后，再考虑七个留出风暴的模型调用。NHC 与 P2 分表报告；不把当前开发筛选结果包装成最终测试成绩。

## 完成标准

下一项离线任务的完成标准是：共同输出契约 v2 的可检查实现、与 v1 的语义/证据对照、完整诊断与恢复审计、不可重复使用的执行登记，以及新的真实测试提案。这个任务本身无需模型 API。

后续实测是否启动、选择哪个矩阵以及具体预算，应基于该可复核交付确定。当前批次不会自动扩展为这些后续实验。
