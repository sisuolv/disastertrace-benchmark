## 4. 六个格式失败分别是什么

以下 `slot_index` 从 0 开始，对应原始日志和自动错误清单。没有修改或修复这些答案。

| slot_index | 方法 / 来源 | 检查点 | 失败性质 |
| --- | --- | --- | --- |
| 32 | answer_history / Ida | U2 active c2 | 正常 stop；根对象混入输入式字段，缺 action |
| 57 | answer_history / Ida | U2 control c2 | 正常 stop；返回输入式对象，缺 state 和 action |
| 143 | structured_state / Florence | U2 control c3 | completion=8192、length，content 为空 |
| 157 | answer_history / Florence | U3 active c2 | 正常 stop；state/action 外多出 answer_history 根字段 |
| 218 | snapshot / Dorian | U2 active c3 | completion=8192、length，content 为空 |
| 229 | snapshot / Dorian | U2 control c4 | 正常 stop；四个字段直接放在根对象，缺 state 容器 |

四个非截断结构错误的 completion tokens 分别为 1532、1712、514、1338，都是可解析 JSON。它们与两个达到上限的空回答是不同问题。`schema-invalid=6`、`length=2`、`empty=2` 相互重叠，不相加为 10 个独立失败。

官方 `response_format={"type":"json_object"}` 只保证 JSON 语法，不能保证根字段、嵌套层级和禁止额外字段；本轮四个结构错误原本就可以解析为 JSON。因此下一步不能仅靠打开 JSON 模式或盲目增加 token 上限。

完整清单及原始 parser 原因：[schema_inventory.json](runtime/schema_inventory.json)。

## 5. 三个引用错误也不是数值错误

三个错误均来自 snapshot，涉及两份格式有效回答：

- Ida / U3 active c4，风速 85 和气压 983 均正确，但把可见输入中的 `delivery_id` 填进了回答的 `record_id`。引用没有绑定到正确的记录身份。
- Dorian / U3 control c3，经度 -57.7 正确，record_id 也正确，但引用了第 2 行的风速断言；正确经度断言在第 4 行。

它们不应统一描述为模型虚构天气数值，也不能事后替换成正确的 ID 或行号提高成绩。全量自动字段错误清单见 [analysis.json](runtime/analysis/analysis.json)：24 个字段因整份答案格式无效未成功，另有 3 个当前引用错误，没有格式有效回答中的数值/状态不匹配。

三方法在同一 90 个检查点配对时，以“四字段与 action 全对”为标准：structured_state 对 snapshot 有 4 个单独成功、1 个单独失败；对 answer_history 为 3 对 1。这里只作描述，不做统计显著性或内部记忆机制结论。
