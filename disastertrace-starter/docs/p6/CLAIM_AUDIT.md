# P6 主张审计

| 主张 | 当前判定 | 证据与边界 |
| --- | --- | --- |
| P5 的 1620 条真实回答均契约合法 | 支持 | 独立复验原 capture、trace、report；不把程序回答计入 |
| P5 有 320 个字段错误 | 支持 | 90 值/状态错误 + 230 值正确但引用错误；260 个错误 checkpoint |
| 主要问题全是数值推理 | 不支持 | 230 引用错误中 109 个为同值旧版本，另有未知 ID、错键和行号问题 |
| grammar 已解决事实正确性 | 不支持 | grammar 只规定结构；错误数值/ID/动作仍可表达，旧错误未修复 |
| structured_state 总是最好 | 不支持 | 历史各 factor 的方法排序不同，重复与来源覆盖不足 |
| 多条记录迫使模型理解复杂版本图 | 不支持 | 合法按键 latest-issued 程序在四组任务上均满分 |
| 历史处理条件差异就是压力的直接效应 | 不支持 | seed/hardware/历史 carrier 均可能不同；6 个 revision episode 实际无处理 |
| 当前测的是内部长期记忆 | 不支持 | 三方法都收到累计证据，额外载体可观察，内部机制不可据此识别 |
| 2 repeats 就能给出总体显著性 | 不支持 | 仍只有 3 个相关来源风暴，派生样本不是新独立事件 |
| 不依赖逐条人工复核即可评分 | 当前受限域支持 | 严格公开语义 + 私有 compiler + public oracle + 确定性 scorer + 行为测试 |
| 已接入真实多版本 forecast 轨 | 尚未完成 | 本轮只登记设计，未获取新官方原文或核验时间配对 |
| 新 P6 已测模型可靠性 | 尚未完成 | 本轮仅程序演练；所有报告 origin 为 diagnostic，模型调用为 0 |
| 新 P6 已具备全部 live 启动条件 | 尚未完成 | 缺新 live 后端、单次 launcher、实际 H100 预检和 live scope freeze |
| 已复现所有参考 benchmark | 不支持 | 本轮依据用户方案借鉴设计，没有下载/执行上游框架 |

引用细类描述可观察到的错误位置与版本关系，不是对模型内部出错原因的心理归因。
自动评分的可信度来自可检查的规则和反例；“不做人审”不意味着真实资料歧义可以
忽略。后续双解析器不一致的来源应自动 quarantine，不能任意选一方或交给 LLM judge。
