# P7 新增进展怎么讲

本说明补充 [更新版汇报 PDF](DisasterTrace_P6_P7_Progress_CN.pdf)。P6 的详细研究动机、方法和错误分析仍可参考 [原完整讲稿](../PRESENTATION_CN.md)，但其中“原生任务尚待离线实现”的进度描述，以本更新版为准。

## 汇报主线如何更新

可以把阶段成果表述为：

> 我们已经完成受控任务上的配对模型实测，并在真实官方预报原文上建立了独立任务。原生任务的公开求解器、评分和软件对照已通过离线验收，下一步是建立原生采集与四 worker 独立聚合，然后开展首次模型实测。

这比“已经有真实来源，下一步设计任务”推进了一步。仍需明确：P7 暂无 LLM 成绩。

## 第 11 页：从来源资料到可执行任务

> P7 沿用已经采集的 12 份官方公告，没有增加下载或独立风暴来源。我们从全部明确预报行的有效时刻构建 46 个目标，每个目标与该风暴的六次交付组合，得到 276 个候选查询。排除查询时刻已不属于未来的 19 项后，纳入 257 个查询。这个过程没有根据模型表现选择样本。
>
> 257 个查询中，有 176 个数值状态、26 个明确终止状态、55 个尚未陈述状态。这里的“尚未陈述”来自目标时刻的预报尚未在可见公告中出现；目标日期本身是公开的任务设计输入，未来公告正文、答案与来源版本信息不进入请求。
>
> 三种方法、两个重复身份对应 1,542 个计划机会，但还没有模型采集。每条目标 episode 的长度为两到六个检查点，不能沿用 P6 固定五轮的运行假设。

数字的统计单位必须分开：95 是来源预报行，49 是同一有效时刻的版本对，46 是目标 episode，257 是查询检查点，1,542 是每种程序策略或未来模型矩阵的计划回答机会。它们都来自两个风暴。

## 第 12 页：公开求解器与错误程序证明了什么

> 原生任务的参考编译器从双解析入库结果建立 Gold。独立公开求解器另行解析模型实际可见的完整带行号公告文本，二者在全部 257 个查询上对账一致。合法程序在扩展调度中的 1,542 个机会全部正确。
>
> 我们还保留了八种错误或异常策略。例如，只取最新文档有 900 个完整正确，按相对时效错配有 606 个，取最后展示行只有 72 个。不同错误策略仍可能在部分自然样本上碰巧正确，所有这些一致项都保留，没有人为把错误策略打成零分。
>
> 这些实验验证任务公开可解、评分器具有实际区分度，并检查无效或缺失回答仍保留分母。它们不是模型表现，也不估计随机模型的重复可靠性。

完整九策略的固定分母均为 1,542，共 13,878 个程序机会。缺失策略只有 780 个收到的答案，但分母仍为 1,542；无效策略收齐 1,542 个，只有 780 个结构合法。这两种策略各保留 762 个失败机会。

## 第 13–14 页：下一步为什么改变

现在原生任务定义、编译、公开求解和评分已经完成，因此近期执行顺序更新为：

1. 新增原生 collector、独立 worker 日志和全局聚合；处理可变 episode 长度、缺失、重复、未知尝试和部分失败。
2. 完成后端离线检查与不生成的真实 H100 预检，核对 tokenizer、结构约束和 token 到文字的渲染策略。
3. 预检后新冻结最多 1,542 个模型机会的运行，优先沿用固定 Qwen3-8B，最多四张完整 H100、四个独立 TP=1 副本。
4. 首次原生模型结果审计后，继续等信息载体控制、匹配第二模型及更多独立开发来源。

已有四 worker 预览分配 390 / 390 / 384 / 378 个机会，整个目标 episode 的方法和重复由同一 worker 承担。它没有调度路径，也没有实际多卡加速比。

## P6 与 P7 的差异

| 维度 | P6 | P7 |
| --- | --- | --- |
| 输入任务 | 受控生成的天气记录更新 | 官方 NHC 完整预报公告文本 |
| 当前结果性质 | 2,160 条真实模型回答 | 离线软件诊断，模型调用为 0 |
| 独立风暴来源 | 3 个 | 2 个，其中 Ida 与既有开发来源重叠 |
| episode | 固定五个检查点 | 两到六个检查点 |
| 条件 | base / irrelevant_scope level 4 | 首版为自然发行顺序的受控交付，无 P6 压力分支 |
| 变量 | 风速 mph、气压 mb、纬度、经度及研究动作 | 纬度、经度、最大持续风速 KT；没有研究动作 |
| 缺失语义 | 字段级 known / unknown | numeric / DISSIPATED / ABSORBED / not_stated |
| 载体规则 | 依 P6 契约传递合法模型答案 | 原生契约显式处理无效/缺失标记，历史保留原始最终文本 |
| 上下文 | 16384，输出预留 8192 | 离线共同上下文 32768，输出预留 8192；待实际后端绑定 |

当前 2,831 个不同程序请求的最大 prompt 为 16,059 tokens，加完整输出预留共 24,251，低于 32,768。任意未来模型历史仍需要运行时逐请求检查，不能由程序载体的通过结果推断永不溢出。

## 核验范围

本次读取 P7 的最终发现、契约、后续执行计划、数据清单与九份程序评分报告，重新核对 327 个验收文件哈希，并对查询、状态、episode 长度、分母和程序结果进行算术对账。未重新运行诊断或模型；原始 P6/P7 实验文件和已完成 P6 PDF 保持不变。

正式研究表述仍需区分任务内来源规则与气象业务有效性。“最新明确覆盖目标”是已声明的任务规则，不能推导出旧公告的某个时效在实际业务中一直有效。官方档案、查询设计、受控交付与模型能力四个层面应分别说明。
