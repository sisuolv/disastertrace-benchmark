## 4. 关键阶段如何讲

### P1：先发现“答不出来”与“答错”不同

模型为 `deepseek-v4-flash`，high reasoning、thinking enabled，输出上限 4096。snapshot / structured_state / answer_history 的契约合法数分别为 **14/30、30/30、24/30**，完整正确分别为 **13/30、30/30、24/30**。22 条无效回答中，20 条达到输出上限，2 条结构错误。合法回答中另有一次来源行定位错误。

这轮不能证明结构状态方法普遍优越：公共格式说明不够明确，历史合法答案为两个载体方法提供了格式示例，执行顺序和机器重启也引入其他差异。实际结论是需要先测量输出交付可靠性。中断后的补发有独立修订记录，原始失败和未知收费记录仍保留。

### T6：共同选择 8192，而非按方法挑最优参数

三条件是 `legacy_4096`、`explicit_4096`、`explicit_8192`。明确说明 / 4096 的三方法合法数为 27、30、28；明确说明 / 8192 为 30、30、30。预定共同门槛要求每方法至少 29/30 合法、至多 1 个 length，选择合格的较小共同 cap，实际为 **8192**。

格式通过不能替代语义正确：8192 条件的三方法完整正确分别是 **26/30、27/30、30/30**；已知值与来源联合正确为 91/96、90/96、96/96。因此应说“共同格式门槛通过”，不能说“T6 的 8192 全部回答都正确”。

### P2 v1 → v2：契约修订后全对，但不是跨模型结论

两轮都是 18 个受控 episode × 5 checkpoint × 3 方法 = 270。v1 格式合法分别 **88/90、89/90、87/90**，完整正确 **86/90、89/90、87/90**；v2 三方法均 **90/90**。v1 六个无效回答含四个结构错误、两个 length/空回答；三处引用字段错误集中在两个合法 checkpoint，所以完整失败是 **8 个 checkpoint**。

v2 保持任务语义和评分机会，统一公共契约，未修复旧答案。两次采样时间不同，只能描述改善；全对的开发矩阵又提示区分度不足。下一步采用每来源同时覆盖两种 case 的平衡 36-episode 版本，并实际运行 Qwen3。

### P3 → P4：格式失败被分离出来，语义错误仍然可测

P3 / P4 都是同一平衡 540 槽位任务。P3 **200/540 合法、193/540 完整正确**；P4 **540/540 合法、490/540 完整正确**。三方法完整正确：P3 为 75、68、50；P4 为 167、178、145，每方法分母 180。

P4 结构 grammar 限定最终 JSON 的容器、字段、类型与枚举，未提供正确数值、当前记录 ID/行号集合、数值范围精度、unknown 一致性或动作规则。仍有 **15 个值/状态错误、39 个纯引用错误**，对应 50 个错误 checkpoint；6 个动作错误与字段错误重叠。两种解码轨和模型派生历史不同，应分轨解释。

### P6：先解释 P5，再做配对重复

P5 的 230 个纯引用字段错误中，109 个为同值旧版本，占 **47.39%**；完整七类计数见主报告。公开 `latest_issued_per_key` 与 oracle 在 base 和三因素上都为 180/180，限定了当前任务可支持的能力主张。

当前实测矩阵为 **2 条件（base/scope4）× 36 episode × 5 checkpoint × 3 方法 × 2 repeats = 2160**。共有 432 条隔离运行轨迹、1080 对条件机会，仍只有 3 个来源风暴。跨条件匹配 seed、同完整 H100、顺序平衡，条件/方法/repeat 的历史各自隔离。

截至 **2026-09-08 12:52:04 UTC**，只读记录已保存 **1680/2160（77.8%）**。未在本材料中计算或公布临时 P6 能力分数。计划报告 checkpoint 全对、整条 episode 成功、pass^2、双向配对及逐来源/重复范围，之后还要检查最终作业状态、审计、token replay 与 CPU 重建。
