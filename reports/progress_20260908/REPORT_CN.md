# DisasterTrace 最新进展：汇报解释与后续计划

**状态快照：2026-09-08 12:52:04 UTC（北京时间 2026-09-08 20:52:04）。以最新记录为准。**

## 1. 可以直接用于开场的介绍

DisasterTrace 是一个面向 LLM 的动态天气证据可靠性 benchmark。当前聚焦 NHC 热带气旋资料派生的受控记录任务，要求模型在局部更新、同窗口修订、证据缺失与旧资料重放中，维护当前状态并引用当前有效来源。参考答案、负例和主评分由可执行规则生成，不新增逐题人工标注，也不使用 LLM judge。

项目已经走过方案、离线实现和多轮真实评测。最完整的 P5 压力实验收齐并验收 **1620 条真实 Qwen3-8B 回答**，全部契约合法，其中 **1360 条完整正确（83.95%）**。P6 完成了错误归因与配对框架，当前新的 **2160 槽位实验已保存 1680 条回答**；最终能力报告尚待完成。后续重点是官方多版本预报原文、可靠性重复和同协议模型比较。

当前定位应写作“天气证据更新与显式状态维护”，不要称为已完成广域、多灾种天气预报榜单。

## 2. 任务究竟让模型做什么

每次检查点输出完整四字段状态：最大风速 mph、最低气压 mb、纬度与经度。每字段包含 `status`、`value` 和 `evidence`；引用使用 `record_id` 和正整数行号。支持尚未到达时输出 `unknown / null / []`。任意已提交引用都要支持当前权威字段版本；数值相同的旧版本也会在当前来源评分上失败。

公开研究动作由风速唯一确定：已知风速至少 100 mph 为 `prepare`，低于 100 为 `monitor`，未知为 `request_evidence`。这不是实际防灾决策质量，也不是独立于字段正确性的任务。

事实键包括实体、变量、有效窗口起止和 measurement kind；单位另行严格校验。判断“最新”应先过滤正确事实键，再比较合法版本。不能选择整篇最新文档、最后送达资料或另一个时刻的最大风速。

任务族为 U1 局部更新、U2 同窗口修订、U3 支持恢复。平衡矩阵是 3 来源 × 3 任务族 × 2 case × 2 branch = 36 episode，每条 c0–c4 五个检查点。primary/secondary 覆盖异值更新与同值换源等不同情形，active/control 提供受控对照。

初始气象值分别源于 Ida 2021（AL092021）、Florence 2018（AL062018）、Dorian 2019（AL052019）的真实 NHC 准入记录；后续实体、有效时间、PATCH 内容和交付计划都是明确标记 `controlled_generated` 的研究构造。三个来源派生出的几百条轨迹不等于几百场独立天气事件。

## 3. 三种输入方法怎样比较

| 方法 | 每轮公共证据 | 额外载体 |
| --- | --- | --- |
| snapshot | 截至当前已交付的累计记录 | 无之前模型答案 |
| structured_state | 相同累计记录 | 本方法上一份结构合法完整答案 |
| answer_history | 相同累计记录 | 本方法之前全部结构合法答案 |

每轮都是新请求，未来证据、Gold 和私有家族标签不进入模型输入。模型推理文本不传到下一轮。合法但错误的答案继续影响后续载体；无效答案保留为失败，不修复后补入历史。方法间并非等 token 或等历史信息量，因此当前比较应表述为“累计证据下显式答案载体的附加效果”。

## 4. 不做逐题人工复核，如何建立可信评分

流程为：保存原始来源与散列 → 私有编译器生成受控事件的 Gold → 独立公开文本 parser/oracle 重建应答 → 实际采集请求、原始响应和 token → 严格 scorer → 独立 auditor 和 CPU 迁移重建。

程序正例检查任务可解；刻意错误策略检查评分能识别数值、作用域、引用版本和缺证处理错误；性质测试检查重命名、时间或行序变换等不应改变的行为。Gold 与模型可见输入严格隔离。保留原始失败、停止前缀与固定分母，避免选择性修复或补跑。

“无需逐题人工标注”是一项任务设计选择，不等于无需检查定义或代码。两条实现可以有共同语义假设；真实原文遇到歧义时应自动隔离并报告准入率，修复通用 parser 后另立版本，不手工改某一题 Gold。

## 5. 已经跑了什么，以及为什么逐轮迭代

完整逐轮表见 [ITERATION_RESULTS.md](ITERATION_RESULTS.md)。核心逻辑如下：

1. **P1 → T6：解决输出交付。** P1 有 22/90 无效答案，主要是长度问题；T6 用新鲜 270 回答验证公共说明与 4096/8192，统一选择 8192。
2. **P2 v1 → v2：明确共同契约。** v1 262/270 完整正确，但共同格式门槛失败；v2 270/270 全对。旧结果原样保留，新成绩来自新采集。
3. **P3 → P4：分离格式与语义。** 平衡 Qwen3 自由输出仅 200/540 合法；结构约束后 540/540 合法、490/540 全对，语义错误仍可观察。
4. **P5：测试更新与干扰压力。** 三因素共 1620 回答，1360 完整正确，90 处值/状态错误、230 处纯引用错误。
5. **P6：提高结论解释力。** 先做只读错误归因与简单程序策略审计，再以统一硬件、配对种子与两次重复检验 scope 条件。

每轮改变的是测量中的一个问题，不能跨版本直接排名，也不能把 API 调用数量当成独立样本数。

**发现二：来源版本是重要失败点。** 320 处字段错误中，230 处是值正确而当前引用错误，占字段错误的 71.88%。其中七个互斥主类为：

| --- | --- | --- |

| 未知记录 ID | 48 | 20.87% |

**发现三：方法优势随条件变化。** structured_state 在本次基础、修订链和旧记录条件较高，scope 下却比 snapshot 少对一个 checkpoint。所有源组只有三个且每 P5 条件一次重复，不能建立稳定总体排名。

**发现四：当前任务有简单合法解。** 在受限线性版本链中，按完整事实键选择已交付断言的最大 issue time，就能得到当前值和来源。该公开程序与 oracle 在四条件均 180/180。这保留了状态更新、作用域过滤和来源定位的研究价值，也要求收窄“复杂图推理”和“内部长期记忆”的主张。

## 7. 一个真实可讲的错误案例

源组 AL052019、U1 secondary active、c2、scope 压力、answer_history。模型返回：

```json
{"status":"known","value":60,"evidence":[{"record_id":"record-62dacf3b5260c5a4f615951f","line":2}]}
```


## 12. 汇报时最容易被问的问题

**Q1：这还是极端天气 benchmark 吗？**

当前是极端天气资料场景下的 LLM 动态证据任务，主要覆盖热带气旋。应明确这是现阶段实现范围。官方多版本预报轨会增加天气时间、单位和状态语义的实质性，但还需要更多独立事件和灾种来支持更广名称。

**Q2：不做人工逐题复核，Gold 可信在哪里？**

受控轨依靠精确定义、独立程序路径、负例和性质验证；真实轨依靠原始资料、两套解析与自动隔离。可信性来自可检验契约，不能保证语义设计不会错。对代码和主张的复查仍然有意义，它不同于为每一道题人工判分。

**Q3：简单程序能满分，为什么还测 LLM？**

它检验 LLM 在有充分公开证据时是否可靠执行更新、作用域与当前来源规则，并提供透明上界。但这不自动构成复杂推理或记忆创新；需要用真实文本、合理语义、负例和外部模型验证该诊断价值，不能故意构造非法题来让简单策略失败。

**Q4：DeepSeek 满分而 Qwen3 较低，可以直接比较吗？**

当前不能。P2 是 18 episode 的旧受控版本，P3/P4 是 36 episode 平衡版本，解码方式和实际执行也不同。下一步必须在同一冻结任务、证据预算和清楚区分的输出轨上比较。

**Q5：structured_state 是不是已经证明最好？**

没有。scope 条件 snapshot 比它多对 1 个 checkpoint；三个来源和一次 P5 采样不足以给稳定排名。P6 用匹配重复重新检验表现差异，之后还需扩大独立来源。

**Q6：grammar 是否泄露答案？**

当前约束是结构层，不含 Gold、正确记录 ID/行号、正确值或动作。真实错误保留证明语义仍可错。但约束改变采样分布，因此应单独报告受约束轨，不能当作完全相同自由输出条件。

**Q7：错误为什么不直接相加？**

字段、checkpoint 和动作有不同层级。P5 的 90+230=320 处字段错误落在 260 个 checkpoint；29 个动作错误已与风速错误重叠。P2 v1 三个引用字段错误落在两个 checkpoint，加六个格式失败共八个错误 checkpoint。

**Q8：c0 的未知控制是否抬高了成绩？**

它属于预定主任务，应保留。同时公开 324/324 的 c0 与 1036/1296 的 c1–c4 补充结果，让读者理解控制题贡献；不能看完结果后只挑某个分母作为主分数。

**Q9：P6 同 seed 是否解决了所有因果问题？**

它减少条件间随机身份差异，同硬件也减少一个执行差异；仍有随机实现、后续载体分叉、输入长度和来源依赖。需要报告双向变化与重复/来源范围，不能据此自动宣称普遍因果记忆效应。

**Q10：pass^2 与 pass@k 有什么区别？**

当前 R=2，pass^2 要求同一 episode 在两次运行中都五个 checkpoint 全对；一次成功一次失败时为 0。它测重复稳定成功，不是多次尝试挑最佳。一般定义为 C(c,k)/C(R,k)，R<k 时为未定义。

**Q11：最新代码在 GitHub 上吗？**

P5 已发布并验证；P6 本地进度更近。汇报材料的数字使用本地最新证据，GitHub 链接只代表指定提交覆盖的阶段，不能把分支名当作不可变版本。

**Q12：现在最该做哪一步？**

先完成既有 P6 作业的审计和配对报告；随后执行官方预报原文的有界获取/双解析，建立离线 forecast-claim 任务。先得到可信任务与固定数量，再确定下一轮模型实验。
