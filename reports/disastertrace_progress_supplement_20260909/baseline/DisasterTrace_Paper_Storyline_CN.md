# DisasterTrace：面向动态天气证据的 LLM 状态与来源追踪评测

英文工作标题：**DisasterTrace: Evaluating LLM State and Provenance Tracking over Evolving Weather Evidence**。

这是一份按论文论证组织的 pre 底稿。先说明研究问题为何成立，再说明任务为何这样设计，随后用实验回答问题。开发阶段编号只用于附录中的证据定位。

证据快照：2026-09-08 16:51 UTC。受控任务的已验收模型结果、原生任务的离线验证和正在进行的原生模型采集分开标注。本文是对已有工作的研究叙述重组，不声称下列全部研究问题都在早期实验之前预注册。

## 一、整场汇报只围绕一个中心问题

**当支持答案的天气资料持续更新时，LLM 能否持续给出与目标相匹配的答案，并把每项结论绑定到按公开规则应选取的来源版本？**

这一问题包含三个不可相互替代的要求：内容正确、来源正确、连续过程可靠。DisasterTrace 围绕这三个要求建立任务、数据、运行协议和测量工具；三种历史输入方法是用于检验系统表现的实验条件。

一条完整的论证链是：

> 天气资料有连续发布、不同有效时刻和版本变化 → 单次答案比较无法描述整段更新过程 → 需要明确“当前可支持的事实”与来源选择规则 → 通过受控诊断和官方原文任务构建可复算的评测 → 同时测量内容、来源与重复整段成功 → 用实测分析能力缺口，并通过原生数据、更多事件与匹配模型继续检验外推范围。

这里每一个箭头都应在汇报中解释。比如，从“持续更新”推到“多轮评测”，是因为上一轮正确的答案可能在下一轮需要修改；从“多轮”推到“来源评分”，是因为数值不变的修订也可能要求更新依据；从“受控任务”推到“官方原文”，是因为程序构造的修订无法单独证明自然文本中存在同样的任务结构。

## 二、可以直接使用的论文式引言

### 2.1 背景：天气信息的使用依赖持续更新的证据

大语言模型可以被用于检索、解读和组织天气资料。此类用途的一个基本前提是：模型能够依据所提供的资料形成正确判断，并在资料更新后同步修订判断。尤其在热带气旋场景中，同一机构会连续发布公告；公告具有发行时刻，其中的预报又指向不同的未来有效时刻。用户关注的往往是某个风暴在某个目标时刻的状态，而不是文本中最近出现的任意数字。

因此，研究重点落在一个可以独立测量的环节：模型如何处理已经发布、已经交付给它的证据。长期应用价值是提高天气信息使用的可靠性；当前实验直接测量的对象是资料理解与更新行为。实际天气预测误差、撤离决策质量和经济损失改善仍需要各自的任务与观测证据。

### 2.2 问题：答案正确可能掩盖证据更新失败

设一份记录支持目标风速为 60 mph，随后新版本仍给出 60 mph。只比较数值时，继续使用旧答案和真正处理了新版本会得到相同分数。如果要求同时指出当前支持来源，二者就可以被区分。另一方面，一份更晚的公告可能报告其他有效时刻、更大的阵风或其他对象；简单选择“最新”“最大”或“最后看到”的数字也未必满足原查询。

这一观察说明，数值匹配不足以完整描述动态证据使用。评测还需要回答：模型是否识别了正确目标、选择了正确版本、保留了未被更新的字段，并在资料尚不支持答案时明确表示未知。一次检查点上的成功也不能说明整段过程中持续成功，因此评价单位还必须扩展到完整轨迹和重复运行。

### 2.3 相关研究：已有基础与我们的具体测量目标

已有研究分别提供了重要基础。ALCE 将答案正确性与引用质量分开；LongMemEval 纳入知识更新、时间推理和拒答；StateMemBench 直接区分当前状态与被替代状态；STALE 研究过期记忆识别及后续行为；tau-bench 强调多次尝试的一致成功。Extreme Weather Bench 则围绕高影响天气事件组织预报验证。动态状态、引用和可靠性都已有研究先例。[R1–R6]

DisasterTrace 的具体目标，是将**天气资料中的对象与绝对有效时间对齐、内容与来源版本分离、逐轮证据交付、可定位支持和确定性评分**组织成一套可运行的评测。这里提出的是一组明确的测量要求。它能否构成足够独立的论文贡献，还需结合更完整的近邻文献比较和更广泛实验判断；当前不以“首次提出动态记忆”作为论证前提。

### 2.4 设计挑战：可诊断性与自然资料约束需要同时考虑

如果只使用自然资料，某次失败可能混合解析、时间对齐、来源选择和状态更新，难以判断是哪一项要求没有满足。若全部使用程序构造的记录，又无法说明任务是否反映官方天气文本中的真实结构。基于这一张力，我们把 benchmark 组织为两个互补部分：受控更新诊断任务明确操纵变化及无关信息；官方预报原文任务保留自然形成的产品、时效网格、覆盖缺口和终止状态。

两个部分共享“公开证据到当前可支持答案”的评价框架，但保留各自的来源选择和输出契约。受控任务提供可解释的行为诊断，原生任务检验这些测量要求能否在自然资料上被明确实例化。原生任务未来的模型结果，才进一步回答受控观察是否在自然资料中出现。

### 2.5 方法与当前发现

我们建立了来源保存与自动准入、任务编译、独立公开求解、逐轮模型采集、确定性评分和独立结果重建流程。参考答案留在评测侧，模型输入仅包含公开任务规则、截至当前交付的证据及该方法声明的自身历史。主评分不依赖新增逐题人工标注或 LLM judge；代价是首版任务必须限定在规则明确、可自动验证的范围。

当前已验收的受控配对实验获得 2,160 条 Qwen3-8B 回答。8,640 个字段机会中出现 123 个值或状态错误，以及 259 个数值与状态正确但引用不满足要求的错误，其中 116 个属于同值旧来源。检查点正确率与重复整段成功率也存在明显差异。官方原文部分已从两个风暴的 12 份公告形成 46 个目标、257 个查询，并完成独立求解和程序对照。证据快照时，原生采集工程与硬件预检已经通过，四个模型 worker 正在运行，尚未形成已验收的原生模型成绩。

### 2.6 本文要支持的结论

现有结果支持：**对动态天气证据的 LLM 评测，需要同时观察内容、当前来源和持续可靠性；这些维度在当前任务与模型上确实可以分离。** 原生任务的构建为进一步验证提供了载体。跨模型排名、跨灾种能力、业务收益和模型内部记忆机制仍是待补充证据的问题。

## 三、把整个 benchmark 作为一个研究对象介绍

### 3.1 统一任务定义

在检查点 t，给定查询目标 q、截至当前已交付的证据 E，以及某种方法规定的历史载体 H，模型输出答案状态、数值和支持来源。查询需要明确对象、有效时间、变量、测量种类和单位。

```text
q = (event/entity, target valid time, variable, measurement kind, unit)
model input = public task rule + q + delivered evidence E_t + declared history H_t
model output = status + value(s) + supporting record and location
reference = resolve(E_t, q, public selection policy for this task)
```

“当前”由任务公开的选择规则定义，并且只在相同目标键和已交付证据内计算。受控记录使用显式修订关系；原生预报任务选择最新且明确覆盖同一目标的可见公告。这不是一个跨所有真实业务情境都自动成立的来源权威定律。

模型的状态历史来自它自己的实际回答。结构合法但语义错误的答案会继续进入对应载体，因此错误可能在后续轮次延续。两个任务的无效或缺失历史处理各自冻结，不能因为方法名称相同就认定输入契约完全一致。

### 3.2 为什么选择这几项设计

| 需要排除的解释或解决的问题 | 设计选择 | 能够得到什么证据 | 仍然不能据此推出什么 |
| --- | --- | --- | --- |
| 只看数值，分不清是否处理了新版 | 值与当前来源分开评分，包含同值修订 | 识别数值正确的版本追踪失败 | 来源评分本身就是全新研究问题 |
| 更新可能属于不同对象或有效时刻 | 显式事实键与作用域检查 | 分开目标错配与数值错误 | 已测量完整地理或气象推理 |
| 真实资料的变化难以单独控制 | 受控更新与等 Gold 无关干扰 | 在公开语义下诊断行为变化 | 隔离了模型内部单一机制 |
| 受控文本的结果可能依赖构造方式 | 保留官方完整预报原文作为独立任务 | 验证自然文本中有可评分的同目标更新 | 已完成跨来源或自然资料上的模型泛化验证 |
| 没有可见来源时，模型仍可能猜数值 | 明确未知、未陈述和终止状态 | 检查何时应给值、何时应留空 | 世界本身不存在该事实 |
| 自动 Gold 和评分可能共享实现错误 | 编译器、公开求解器与评分器分工 | 检查可解性及实现一致性 | 两个程序一致就证明任务定义绝对正确 |
| 单次局部高分可能掩盖过程失败 | 检查点、整段轨迹、重复整段指标 | 测量不同粒度的可靠性 | 各轮独立，或可外推总体显著性 |
| 仅统计有效返回会低估失败 | 缺失、无效与未尝试保留计划分母 | 反映完整执行的结果 | 基础设施失败与语义错误可以不作区分 |

### 3.3 两个互补任务部分

| 项目 | 受控更新诊断 | 官方预报原文 |
| --- | --- | --- |
| 研究作用 | 明确控制应变与不应变，分析失败类型 | 检查自然资料中的时间、覆盖与来源更新 |
| 材料 | 真实来源初值，后续变化明确由程序构造 | NHC 官方 Forecast/Advisory 完整文本 |
| 变化来源 | 局部更新、修订、作用域干扰、支持恢复 | 连续公告的原生预测行、缺口与终止陈述 |
| 主要答案 | 四字段及公开规则动作 | 纬度、经度、持续风速、状态与引用 |
| 当前规模 | 36 条基础 episode，3 个独立来源组 | 46 个目标、257 个查询，2 个风暴 |
| 模型证据 | 已完成配对、重复和错误分析 | 快照时已启动采集，待验收 |

统一的是问题和测量框架。两个任务使用不同材料、单位、长度、目标和输出契约，应分别报告成绩。将它们组织成整体，不要求把分数合成一个总榜。

### 3.4 早期工作在整体中的位置

最初探索过更宽的灾害问答、港口业务和工具规划。用户提出无需新增逐题人工复核后，设计收敛到可自动准入、可复算、来源可定位的任务。复杂港口例外和开放行动质量需要额外语义判断，因此没有成为当前动态主轨的必答 Gold。

已有 DisasterBench 适配保留了 230 条获准的继承标签规划任务；它为早期离线流程提供对照，不属于当前动态天气模型结果。CyPortQA 的题型和 NHC 原文帮助确定材料入口，48 个模板的 profile 也不能当作 48 道已经完成的新 QA。EarthVerse、多模态和自适应 Frontier 搜索仍有未实现或未完成验证的部分。

这些工作的共同作用是帮助选择可行的材料、输出和评测边界。汇报主线介绍当前已经成立的动态证据任务，附录交代这些资产的来源和状态，避免把探索过的方案都写成已完成能力。

## 四、实验围绕哪些问题展开

### RQ1：内容正确是否足以代表动态证据使用正确？

比较同一组字段机会上的值/状态正确性与包含当前引用的正确性，并对引用错误分类。真实同值旧来源案例用于解释评分区别，全量统计用于说明该区别并非只存在于教学样例。

### RQ2：在无关信息加入后，模型能否持续保持正确状态与来源？

比较基础条件与无关作用域条件；三种历史输入配置各自执行完整轨迹并重复两次。保留检查点、轨迹和两次均成功指标，并核对新增干扰出现前的请求与结果。三方法比较是这一问题的组成部分，不是预先宣布某个新记忆算法优胜。

### RQ3：同一测量要求能否在官方原文上明确成立？

先验证绝对目标时间对齐、公开可解性和来源支持可定位；再用简单错误策略检查评分能否区分不同失败。这个问题的当前已完成部分是任务与测量工具验证。自然资料中的模型表现、以及它与受控发现的关系，要等原生实测与独立核验完成。

实验配置中，snapshot、structured_state、answer_history 都看到截至当前累计交付的原始证据。额外附加的历史分别为无历史答案、上轮状态、此前答案历史。当前配置同时改变了历史信息量、表示和长度，不是纯粹的 JSON 与文本表示消融，也没有剥夺 snapshot 的旧证据访问。

结构约束轨约束的是答案形式。早期自由输出中存在大量格式失败，所以单独设置这个轨来观察形式交付可靠时仍然存在的语义错误。它会改变解码过程，必须保留自由输出结果，不能把约束后的结果称为同一批答案的无偏修复。

## 五、如何从数据推到结论

### 5.1 发现一：值正确仍可能缺少合格的当前引用

受控配对实验的 8,640 个字段机会中，值或状态错误为 123，值/状态正确但引用错误为 259。因而在同一字段分母上，值/状态正确为 8,517/8,640，约 98.6%；包含当前引用的字段正确为 8,258/8,640，约 95.6%。这两个比例可以直接比较，因为分母相同。

259 个纯引用错误中有 116 个同值旧来源。一个实际例子里，模型与 Gold 都是 known、60 mph；模型引用的记录存在、行号合法、目标键匹配且字面支持 60，但该记录已经被同目标的新版本替代。这个例子直接回答 RQ1：值正确与版本追踪正确确实是可分离的。

完整回答还联合要求四字段与动作，故 1,861/2,160、约 86.2% 是另一种粒度的指标。不能把 98.6% 到 86.2% 的全部差额都归因于引用，因为两者的分母和成功条件不同。

### 5.2 发现二：局部较高正确率没有转化为同等的重复整段可靠性

以上轮状态方法为例，基础与干扰条件的检查点完整正确率为 96.9% 和 88.6%；要求同一 episode 的两次运行都在五个检查点全部正确时，比例为 83.3% 和 41.7%。前者每格分母为 360 次回答，后者每格为 36 条基础 episode。

这说明需要直接报告整段与重复表现。它不意味着每一步错误独立，也不能把单点正确率平方或五次方当成实际轨迹成功率。这里的 pass^2 是“两次都完整成功”，不等于“两次至少一次成功”的 pass@2。

### 5.3 发现三：输入历史会改变表现，但当前比较不能单独解释内部机制

| 历史配置 | 基础检查点全对 | 干扰检查点全对 | 基础两次均整段全对 | 干扰两次均整段全对 |
| --- | --- | --- | --- | --- |
| 仅证据 snapshot | 340/360，94.4% | 309/360，85.8% | 22/36，61.1% | 11/36，30.6% |
| 上轮状态 structured_state | 349/360，96.9% | 319/360，88.6% | 30/36，83.3% | 15/36，41.7% |
| 全部历史 answer_history | 279/360，77.5% | 265/360，73.6% | 13/36，36.1% | 10/36，27.8% |

上轮状态在这个固定模型、任务与设置中表现最高。额外历史没有保证更高分。要进一步讨论表示形式或错误携带的因果影响，需要在相同证据和相同保存前缀上只改变一个因素。

无关作用域干扰从 c2 开始。c0/c1 的 432 对请求和最终文本全部相同且正确；曝光后，三种方法中“仅基础对”分别为 45、37、38，“仅干扰对”分别为 14、7、24。反方向的改善也保留，不能把所有配对都写成受害样本。后续轮次的载体会受到先前输出影响，所以这里测量的是闭环过程表现。

### 5.4 原生资料证据：自然文本确有同目标更新与覆盖缺口

对 Francine 的 2024-09-10 18:00 UTC 目标，第 005 号公告给出 75 KT，第 006 号没有这一目标的明确行，第 007 号给出 70 KT。两份公告都出现“12H”时，通常也不代表相同绝对有效时刻。目标时间对齐因而是任务的一部分。

在 12 份官方公告的 95 行预报中，可得到 49 对同绝对有效时刻的相邻覆盖版本：23 对风速变化、24 对风速不变、2 对涉及终止状态。风速不变不保证经纬度也不变。

独立公开求解器在全部 257 个查询及展开后的 1,542 个计划机会中与参考一致。按最后一行、相同相对时效或最早覆盖来源选取的程序策略分别只有 72、606、1,044 个完整正确机会；错误策略的真实成功也保留。这说明任务可解、部分捷径可以被区分，不等于模型已经在原生任务上得到这些分数。

原生“最新明确覆盖”政策保留较旧公告中尚未被新公告明确覆盖的目标陈述。这是可复算的已发布陈述选择规则；不能据此宣称旧预报在 NHC 业务系统中始终当前有效。历史首次可用时间仍未知，发行顺序仅用于声明的受控交付。

### 第 1 页：DisasterTrace——动态天气证据中的持续可靠性

## 七、讨论、贡献表述与答辩准备

### 7.1 为什么要测试 LLM，明明程序可以满分？

公开求解器用于检查材料和规则是否足以确定答案。如果程序都无法从相同可见输入得到答案，模型低分可能只是题目不可解。它满分不证明应在生产中用 LLM 代替解析器。研究问题是：当 LLM 被用作统一的资料接口时，在这些明确要求上会怎样失败。程序也提供一个诚实的参照：对严格结构化来源，专用解析器可能更合适。

### 7.2 这个 benchmark 的“天气性”在哪里？

目前最有依据的部分是官方预报产品里的发行时刻、绝对有效时刻、相对时效、风速/阵风/观测的区分、覆盖网格变化及终止状态。受控记录的核心也含有通用状态追踪成分。后续中性领域显示对照可以检验天气背景是否带来额外难度；当前不能仅用风暴名称证明气象专业推理贡献。

### 7.3 数字没错，为什么还扣旧来源的分？

因为任务明确要求当前应选来源，引用版本是评价对象的一部分。为了让读者判断这个要求的作用，报告同时给出值/状态分数和严格引用分数。旧来源可能仍然字面支持同值陈述，也可能是有效的历史记录；扣分理由应说成“不满足本任务的当前来源要求”，不能一概说它是虚假信息。

### 7.4 没有逐题人工复核，是否意味着完全不需要人判断？

主流程可以不依赖新增逐题标注和 LLM judge，但研究者仍须审查任务语义、准入规则、代码和效度。确定性评分通过限制任务的开放性换取可复算性。复杂隐式业务冲突没有被悄悄当作已经自动解决。

### 7.5 与 StateMemBench、STALE 相比，贡献是否足够？

这是必须继续验证的问题。当前可以明确提出天气目标时间对齐、来源定位、同值版本区别和双任务测量体系，但不能以名称或领域包装代替实质差异。完整投稿应补充逐项协议比较、近邻 baseline 的匹配适配，以及自然资料和更多独立事件上的模型证据。

### 7.6 能否说 structured_state 是最好的方法？

目前可以说它在已验收受控矩阵中高于另外两种输入配置。配置同时改变历史长度、信息量、表示和错误携带，且只有一个匹配模型。等信息固定前缀对照和跨模型重复结果完成前，不能将差异归因为某种内部记忆机制或普遍最优方法。

### 7.7 哪些措辞适合当前论文稿

| 有证据支持的措辞 | 需要更多工作才能使用的措辞 |
| --- | --- |
| 提出并实现一套面向动态天气证据的可验证评测框架 | 首个全面解决极端天气推理评测的 benchmark |
| 在固定模型与受控任务上观察到内容/来源及局部/整段表现分离 | 所有 LLM 都存在相同失败机制 |
| 建立官方原文任务并通过程序验证，模型采集中 | 已在真实天气任务中证明同样的 LLM 失败率 |
| 减少新增逐题标注需求，以公开语义和确定性评分为主 | 完全没有人工判断，或绝对无标签噪声 |
| 为天气资料解读系统提供一个可诊断的评价切面 | 已证明应急决策安全、预测准确或业务损失降低 |
