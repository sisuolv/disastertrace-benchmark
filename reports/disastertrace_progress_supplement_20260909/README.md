## 最重要的更新

两风暴官方原文 Qwen3-8B 实测已收齐：1,542 份回答全部结构合法，527 份严格正确，276 条轨迹中 19 条整段正确。422 个同历史前缀的 JSON／文本表示配对也已收齐：文本比 JSON 多 25 个正确答案，差 5.92 个百分点，但文本请求也更长。

另有六风暴、36 份原文的开发队列，以及两个本地模型的多组协议结果。新增证据说明，方法排序会随检查点与整目标指标改变，总分会受状态构成影响；单条历史轨迹超限还会牵连其他轨迹停止。未收齐的 Qwen user 条件主分数为 952／2,412＝39.47%，返回子集的 58.48% 不能直接与完整条件的 43.95% 比较。

因此后续优先级是：逐轨迹故障隔离、共同公共协议冻结、按生命周期扩展资料、等完成预算比较，再进入独立 heldout。详细稿区分了这些建议与已执行工作。

## 完成与验证口径

截至快照，P7—P14 相应阶段验收均存在并通过，包括 P14；部分模型矩阵仍未收齐。本包核对了 125 个来源文件，并完成 178 项收集时一致性检查：报告／分析身份、绑定哈希、计划分母、互斥错误和分析总数、关键成功回执及被引用文件的验收覆盖。

制作核验记录在 `evidence/document_validation.json`、`pdf_validation.json` 和 `bundle_validation.json`。PDF 检查包括 15 页文字完整、页面边界、字体嵌入、书签与逐页视觉检查。实际检查状态以这些文件为准。

本包使用已有独立 CPU 重建和 token 回放成功回执，没有在本次制作中重新执行全部研究审计，没有调用模型或启动 GPU，也没有重写历史分数。它是**便于阅读与复查的汇报附件**，不是完整科学证据归档：不含全部原始回答捕获、模型权重和冻结环境。名称带 `excerpt` 的 JSON 是节选，来源完整路径与哈希保留在快照中。六风暴分析 JSON 保留了逐槽位描述性评分记录，可独立复算本包表格与配对统计，但不是原始模型文本。

P11 原验收漏绑定的 14 个分析／命令文件有独立补充；本包保存其小型完整验收记录。全局资源核算、完整归档恢复与最新 GitHub 发布闭合未在本包制作中核验，不据此声明全部新结果已经上传。

## 文件完整性与重建

`MANIFEST.sha256` 覆盖包内交付文件（清单自身除外），`bundle_validation.json` 记录打包前的证据、PDF 和制作检查。压缩包外的 `ZIP_RECEIPT.json` 另记录 ZIP 哈希、CRC 检查与抽取后逐文件核对结果。交付 ZIP 为 `DisasterTrace_Latest_Progress_Supplement_20260909.zip`。预览目录保存每页 PNG 和两张联系表，便于快速查看；PDF 本身不依赖预览。

重建 PDF 只需本包快照与字体，不读取实时研究结果。字体默认使用原工作区的 Noto Sans SC 文件；也可通过 `--font-dir` 指定含 Regular 与 Bold 两个 TTF 的目录。字体文件没有放入 ZIP。当前工作区已有以下可用环境：

```bash
cd /mnt/afs/260010168/extreme_weather_benchmark/reports/disastertrace_progress_supplement_20260909
PYTHONDONTWRITEBYTECODE=1 /mnt/afs/260010168/.venvs/disastertrace-presentation-v1/bin/python build_pdf.py
```

构建依赖为 ReportLab、PyMuPDF 与 Pillow，实际使用版本记录在 `evidence/build_inputs.json`。`validate_documents.py` 使用标准库核对表格、配对分析、关键数字与来源副本；不运行研究模型。`package_bundle.py` 生成清单、压缩包及抽取验证回执。重建后 PDF 视觉检查会回到待检查状态，应重新查看预览并更新交付清单。

`collect_evidence.py` 是从原研究工作区只读收集本包来源的脚本，已有快照时拒绝覆盖。若未来出现新结果或全局发布回执，应创建另一个快照版本。本包保留固定截止点，使这次汇报中的每个数字都能追溯到同一批证据。
